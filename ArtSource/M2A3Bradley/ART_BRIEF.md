## 발견한 원인과 수정

기존에는 RimThunder 부품별 명도 중앙값에 높이 계수를 곱했다. 기본색 차이가 높이 보정을 압도했다.
최종 표시 명도가 차체 지붕 211, 포탑 지붕 204, 그 위 곡면 해치 197로 역전됐는데도, 검사는 높이 계수만 보고 통과했다.

- 부품별 기본 명도·높이·카메라 배율의 중첩을 제거했다. 월드 높이에서 최종 표시 명도를 계산하고 선형 RGB 코너 색을 Emission에 직접 연결한다.
- TAN 상면의 높이 순서를 먼저 지키고 벽·경사는 별도 방향 대비로 구분한다. 낮은 면은 채도도 낮춘다. 밝은 장비의 RGB 클리핑은 최종 명도를 보존하면서 채도를 낮춰 방지한다.
- 명도 4단위의 재질 양자화와 딱딱한 법선 임계값 때문에 끊기던 곡면은 연속 코너 색으로 바꿨다. UV 경계는 위치 기준으로 연결하고 50도 이상 모서리는 보존한다.
- 해치 03의 원본 손잡이·힌지를 복구했다. 누락된 형태를 밝기만으로 해결하지 않는다.
- 128샘플·16비트 PNG로 마스터를 렌더한다. 256/512px는 선형 RGB·float·알파 선곱 Lanczos로 축소해 밝은 가는 부품과 경계의 색을 보존한다.
- Blender가 16비트 PNG를 선형 float로 읽는 경우 중복 sRGB 디코딩을 하지 않는다. 합성 PNG의 불투명 픽셀은 원본 레이어와 같은 색이어야 한다.

## 레퍼런스와 검수

RimThunder M2A3 대응 부품 20개 영역의 명도 측정은 `rimthunder_palette_samples.json`에 남겼다.
이 값들은 재질·가독성 참고 자료이며 현재 부품별 기본색으로 직접 사용하지 않는다. 사용하지 않는 이전 부품별 채색 알고리즘은 제거했다. 과거 구현은 Git 커밋 `63b47c69`에 남아 있다.
실제 설정은 `part_contrast.json`, 최종 색 계산은 `height_palette.py`, 코너 색 적용은 `face_depth_tone.py`에 있다.

현재 검수는 `Audit/HeightQuality/REPORT.md`와 원인/최종 색/PNG 측정 JSON을 기준으로 한다.
`recolor_validation.json`은 최종 Emission RGB의 높이 순서, 곡면 연속 색, 원본 부품·부모 보존, 손잡이 위치를 검증한다.
`Audit/validate_height_renders.py`는 가려지지 않은 상면의 실제 PNG 픽셀과 합성 색을 검사한다.
`validation.json`은 면적 0 면 없음, 4개 애니메이션, 무광원·투명 배경·GLB unlit/vertex color·ERA 제외를 검증한다.

그림자·AO 없이 투명 배경을 사용한다. GLB는 최종 코너 색과 unlit 재질을 포함하되 절차형 그릴은 단색 대체다.
EAST 차체 64도/포탑 90도, 앞뒤 등각 뷰, 포탑 확대와 256px/512px를 확인한다. 실제 게임 drawSize·줌 검수는 미실시다.
