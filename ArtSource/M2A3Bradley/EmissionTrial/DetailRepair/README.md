# 관측장비와 안테나 2 디테일 복구

기준은 `38a4fd44`의 고정 Emission 시험본이다. 사용자 제공 M3A3 OBJ를 직접 읽어 대상 형상을 복구했다. 원본 경로·SHA256은 `../../ReferenceFit/manifest.json`으로 확인한다.

- TOW 정면 보호판 `WT_roll_04`는 `../TOWDeploy/`에서 포탑 고정으로 수정했다. 이제 `WT_roll_05` 본체만 전개된다.
- 포수 관측장비의 좌우 개폐판·힌지, 상부 관측부 받침·덮개·캡, 뒤쪽 연결부와 앞 포트를 9개 독립 메시로 복구했다.
- 좌측 상부 지휘관 관측장비 `WT_bone_commander_sight_v`는 덮개 가장자리·외피·손잡이/연결부를 원본의 주요 연결 영역 712면으로 복원했다. 별도 초소형 나사 머리는 계속 생략한다.
- 안테나 2의 포탑 내장 부품인 받침판·스프링·상단 연결부·케이블 클램프를 4개 독립 메시로 복구했다. 두껍게 정리된 기존 안테나 봉은 유지한다.

`WT_bone_turret` 본체의 기존 면을 잘라내거나 다시 단순화하지 않았다. 새로 복구한 13개 부품은 원본에서 빠져 있던 연결 영역이며 기존 원본 좌표와 겹치지 않는지 빌드 중 확인한다. 지휘관 관측장비 외의 기존 102개 메시 형상·색·부모·변환은 기준 커밋과 같다.

복구 부분은 기존 고정 Emission 팔레트를 재사용하고 필요한 밝기만 추가했다. 작은 힌지/포트의 측면은 단색으로 두고 덮개·상면은 더 밝게 구분한다. 원본 유리 면은 `Restored Optics` 암색을 유지한다. 이 포탑 복구 단계의 결과는 54,680면·116개 메시·28개 페인트 색이었다. 이후 차체 복구 결과는 `../HullRepair/README.md`를 따르며 포탑 형상/색은 그대로다.

- `source_details.py`: 원본 메시의 연결 영역 선택과 복구/채색. 상위 `build_trial.py`가 호출한다.
- `source_audit.json`: 원본 연결 영역·면 번호·위치와 수정 전 좌표 잔존 현황.
- `before_objects.json`: 변경 전 오브젝트별 형상/색/부모 SHA256. 덮어쓰지 않는다.
- `validate_details.py`, `validation.json`: 원본 면 좌표 일치, 양수 면적, 중복 면 없음, 고정 Emission/유리 보존 검사. 처음 보존한 102개 메시 중 이후 의도적으로 수정한 차체 13개는 `HullRepair/validate_hull.py`에 넘기고 나머지 89개는 종전 해시로 검사한다.
- `current_front/rear.png`: 수정 전. `source_front/rear.png`: 원본 형상 비교용. `after_front/rear.png`: 복구 후 동일 카메라.
- `before_after.png`: 복구 전후 정면/후면 비교. 원본 비교 렌더의 색은 형상 확인을 위한 임시색이며 최종 팔레트가 아니다.

256px에서는 관측장비의 열린 보호판, 상부 덮개와 안테나 받침 위치가 드러나고, 512px에서는 연결부와 겹침을 확인했다. 상위 `VF_East/256`, `512`와 `TOWDeploy/256`, `512`를 함께 갱신했다. 확대 검수 이미지는 안테나 봉이 화면을 길게 가리지 않게 봉 오브젝트만 숨기며, 새 받침/스프링은 숨기지 않는다. 최종 모델과 EAST 텍스처에는 안테나 봉도 유지한다.

재생성은 상위 `build_trial.py` → `render_trial.py` → 네 검증 스크립트 → `compare_trial.py` 순서다. 이 폴더의 검증은 Blender에서 `--python-exit-code 1 --python DetailRepair/validate_details.py`로 실행한다. 비교용 복구 후 렌더는 `render_audit.py -- --after`다. 수정 전 기준은 다시 캡처하지 않는다. 실제 게임 내 검증은 미실시다.
