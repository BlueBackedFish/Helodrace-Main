# 원본 대조를 통한 차체 복구

기준: `cbf17877`의 포탑 복구 완료 시험본. 제공된 War Thunder **M3A3 OBJ**를 직접 읽고, 기존 M2A3 청사진의 해치·견인 고리·측면 손잡이 배치를 함께 확인했다. 두 차종의 형식 차이는 기존 `../../Audit/Stage1/FORMAT_BASELINE.md`를 따른다.

포탑과 같은 순서로 차체를 검수했다: 원본/현재 정면·후면·상면 비교 → 빠진 주요 연결 영역과 받침 선택 → 원본 좌표 복구 → 고정 Emission 역할색 → 256/512px 확인.

## 문제와 변경

| 문제 | 복구 내용 |
|---|---|
| 조종수 해치가 뭉개지고 앞쪽 정비 패널의 연결부가 생략됨 | 원본 주요 연결 영역으로 해치 외피·뚜껑·힌지·잠금부와 정비 패널/손잡이 복구 |
| 후방 지붕 해치에 큰 면만 남음 | 상부 덮개와 가장자리 잠금부, 세 힌지 및 차체 쪽 고정 받침·연결봉 복구 |
| 전조등·후미등 부속/유리가 빠짐 | 원본 조명 몸체·가드·렌즈·지지부 복구, 앞 유리와 뒤 붉은 렌즈를 고정색으로 구분 |
| 앞뒤 견인 고리가 비어 있음 | 앞 고리 4개, 뒤 고리 2개와 중앙 연결부 복구 |
| 차체 측면·상부가 너무 비어 보임 | 좌우 스커트 손잡이 14개, 네 인양 고리, 상부 캡/덮개와 측면 손잡이 복구 |
| 후방 출입문·램프의 조작부 생략 | 출입문 외피/손잡이/힌지와 램프 잠금부 복구, 기존 경첩 부모 유지 |

13개 기존 오브젝트를 원본 주요 영역으로 교체하고, 빠진 영역 30개를 독립 메시로 추가했다. 총 **70,380면·146개 메시**이며 TOW 브래킷 분리 모델은 같은 면 수에 147개 메시다. 전체 차체를 원본 고밀도 메시로 되돌린 것은 아니다. 초소형 나사·반복 힌지 배열·배선·내부 현가 장치는 계속 생략한다.

## 유지한 부분과 채색

차체 복구 단계에서는 기존 **103개 메시의 형상·색·부모·변환을 보존**했다. 여기에는 포탑 전체, 차체 장갑 본체 `WT_@root`, 궤도·바퀴와 단순화 그릴이 포함된다. 이후 좌우 측면 경사 89면만 108 → 132로 밝힌 국소 변경은 `SideSlopes/`와 `check_side_slopes.py`로 별도 검사한다. ERA와 이전에 제외한 상부 측면 패널은 추가하지 않았다.

상위 시험본의 고정 TAN Emission 팔레트를 재사용했다. 예를 들어 직접 접하는 차체 지붕 168 → 해치 192 → 해치 위 덮개/잠금부 216의 명도 차이로 경계를 구분한다. 전방 경사 위 정비 덮개는 168, 뒤 램프 위 출입문은 156, 그 위 손잡이는 180으로 주변 장착면과 구분했다. 떨어진 부품끼리 높이 순위를 만들지 않는다.
작은 손잡이·견인 고리는 연결 영역의 측면을 단색으로 표현한다. 스커트 손잡이는 상부와 측면 모두 168이다. 전조등 유리와 후미등 렌즈만 별도 고정 색상이다. 광원·AO·그림자·시점에 따라 변하는 셰이더를 추가하지 않았다.

## 검수 결과와 남은 차이

- 원본 좌표/면 일치, 복구 면의 양수 면적과 중복 없음, 대상 밖 103개 메시 보존을 확인했다.
- 후방 램프 잠금부는 `REAR_RAMP_HINGE`, 출입문은 `PERSONNEL_DOOR_HINGE`를 따라 움직인다. 기존 4개 동작과 TOW 모델의 5개 클립을 검수했다.
- 256px에서 해치·견인 고리·스커트 손잡이 실루엣을, 512px에서 가드·힌지·겹침과 색면을 확인했다. 상위 `VF_East/`와 `TOWDeploy/`의 256/512px를 갱신했다.
- 확대 차체 비교는 포탑을 숨긴 상태다. 중앙의 포탑 링 개구부는 이 비교에서 드러나는 기존 구조이며 최종 차량에는 포탑이 올라간다.
- 원본의 올리브색·마모·촘촘한 볼트와 텍스처 선은 복사하지 않는다. 정확한 M2A3 형식 전환이나 실측 기구학은 이번 범위에 포함하지 않았다. 실제 게임 내 검증은 미실시다.

## 파일과 재생성

- `hull_details.py`: 차량별 부품/면 선택·역할 채색. 상위 `build_trial.py`가 호출한다.
- `source_audit.json`: 원본 차체/해치/조명 영역과 수정 전 잔존 현황. 원본 SHA256 포함.
- `before_objects.json`: cbf17877의 오브젝트별 형상·색·부모 해시. 덮어쓰지 않는다.
- `validate_hull.py`, `validation.json`: 43개 복구 부품과 102개 완전 보존 메시·동작 검수. 차체 본체의 국소 색 변경과 형상 보존은 `check_side_slopes.py`에서 검사한다.
- `before_*.png`, `source_*.png`, `after_*.png`: 동일 카메라의 차체 비교. 원본 비교 렌더의 색은 형상 확인용 임시색이다.
- `before_after.png`: 정면/후면 차체 및 256px EAST 합성 비교. `256/`, `512/`는 차체 확대 검수용 세 시점이다.

상위 `build_trial.py` → `render_trial.py` → `validate_trial.py`, `check_corrections.py`, `FlatRolls/check_rolls.py`, `DetailRepair/validate_details.py`, `HullRepair/validate_hull.py` → `compare_trial.py` 순서다. 차체 비교는 Blender로 `HullRepair/render_hull.py`, Pillow/numpy Python으로 `HullRepair/package_comparison.py`를 실행한다. 이후 TOW의 빌드·검증·렌더·패키징을 갱신한다. 수정 전 감사 자료는 다시 캡처하지 않는다.
