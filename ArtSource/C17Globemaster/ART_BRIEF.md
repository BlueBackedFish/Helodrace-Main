# C-17 항공기 평면 텍스처 시험 기록

2026-10-25. 제공된 OBJ의 완전 상면 항공기 텍스처다. 후속 요청은 19×19타일의 큰 표시, 무전기·공작기계와 같은 절대 크기/화질 밀도, 12px 외곽선과 작은 디테일 추가다. 본판·아스널의 항공기 평면 스타일은 유지하며 지상 차량의 64도 투영·포탑별 외곽선을 적용하지 않는다.

## 입력과 형상

- 입력: `ext/c-17-globemaster-iii/source/C-17/C17.obj`. OBJ 헤더에는 Roblox Studio export라고 기록되어 있다. 다른 Dagor 차량과 같은 ext 아래에 있지만 해당 차량들과 같은 제작 원본이라고 가정하지 않는다.
- OBJ SHA256: `7bb6263fd9685db6a67328596292314f2e5ea94a90beceecb8b9c33987db7c7f`. 실제 절대 경로와 MTL 해시는 `vehicle.json`에 기록한다.
- 161개 그룹·486,906면을 모두 보존한다. 감량·장비 삭제·임의 실루엣 재구성 없음. 원본 UV를 유지하되 제공된 알베도/노멀/스페큘러를 최종 색에 사용하지 않는다.
- 앞은 원본 +Z, 위는 +Y다. 기수의 창과 전방 착륙 장치, 반대쪽 T자 꼬리의 위치 및 부품 식별표로 확인했다. 공통 도구의 직교 축 변환 후 상면 카메라를 180도 회전해 기수가 이미지 위를 향한다. 좌우 반전 합성을 사용하지 않는다.
- 길이/폭/높이, 생산형 C-17과의 일치 및 원본 단위는 별도 인증하지 않았다. 청사진은 제공되지 않았다. 실제 면에 사용되지 않은 OBJ 원점 정점은 카메라 프레이밍 범위에서 제외한다.

`analysis/aircraft_references.png/json`은 최초의 다섯 항공기 스타일 비교다. 그때의 1024px/10px 초안은 `review_history/01-initial-trial`에 보관한다. 현재 크기와 선폭은 아래의 절대 규격을 사용하며 항공기끼리 같은 화면 폭으로 맞춘 비율을 사용하지 않는다.

| 절대 크기 근거 | 실제 PNG | XML drawSize | 밀도 |
|---|---:|---:|---:|
| `HD_Radio` | 256×256 | 1.5×1.5 | 170.6667px/타일 |
| `HD_TreadleLathe` | 512×512 | 3×3 | 170.6667px/타일 |
| `HD_LineShaftTurretLathe` | 512×512 | 3×3 | 170.6667px/타일 |
| `HD_LineShaftMillingMachine` | 512×512 | 3×3 | 170.6667px/타일 |

`absolute_scale.py`는 실제 Def의 drawSize와 해당 PNG를 읽는다. 사용자 지정 12px는 이 밀도에서 약 0.0703타일이다. C-17은 19타일×170.6667을 반올림해 3243px로 출력한다. 19×19 그리기 영역 안에 작은 투명 여백과 원래 기체 비율을 유지한다. `scale.json`은 정수 반올림 오차, 근거 경로/해시와 캔버스 중앙 피벗을 포함한다.

## 채색과 합성

- 완전한 90도 상면 직교 카메라, 고정 RGB → Emission. 조명·AO·그림자·법선/높이 셰이딩·원본 사진 질감 없음.
- `vehicle.json`의 부품 역할과 `style.json`의 고정 RGB를 분리한다. 몸체·주익·조종면·꼬리·엔진·흡입구 립·유리·고무 등을 구분하고, 원본 곡면의 삼각형마다 밝기를 바꾸지 않는다.
- 기체 전체 알파에 한 번만 검은 외곽선을 생성한다. 개별 메시마다 검은 선을 쌓지 않는다. 최종 외곽선은 12px, 조종면/립/창의 내부 경계는 회색 4px다.
- 4096px로 다시 렌더하고 최종 12px를 마스터 배율에 환산한 원형 알파 확장을 넣은 뒤 3243px로 축소한다. 구형 1024px를 확대하거나 기체 크기에 비례해 12px보다 굵게 만들지 않는다.
- `surface_details.py`는 원본 좌표 위에 동체 점검구·패널 이음선·힌지/잠금부·환기 슬롯, 날개 패널/체결부, 엔진 덮개/흡입구 립, 꼬리 조종면과 작은 위치등을 고정색으로 채색한다. 동체/날개/엔진/꼬리의 실제 가림 마스크와 알파로 제한한다. 원본 셸이나 부품 위치를 이동하지 않는다. 세부 배치는 평면 아트용 근사이며 실차 정비 도면의 검증으로 간주하지 않는다.
- 모든 출력의 기준점은 캔버스 중앙이다. 개별 크기에서 trim/재중심 정렬을 하지 않는다. 이는 실측 무게중심이나 착륙/화물문 애니메이션 피벗을 확정했다는 뜻이 아니다.

## 검수와 한계

- `output/model_validation.json`: 모든 면·원본 좌표 변환 보존, 원본 UV 유지, 생략 0면, 소스 해시 유지, 무조명 상면 렌더.
- `output/texture_validation.json`: 3243px RGBA·여백·투명 RGB 0·해시·원본 렌더 불변과 디테일 범위.
- `output/delivery_validation.json`: 무전기/공작기계와 절대 밀도 일치, 19×19 캔버스, 원본 알파의 축소 결과 일치, 12px 외곽선의 좌우 표본, 구형 낮은 밀도 후보 제거.
- 실제 검수: `absolute_scale.png`의 타일 크기 비교, `detail_review.png`의 원래 해상도 부분도, `before_after_19tiles.png`와 세 배경. 네 엔진·후퇴 주익·기수 창·T자 꼬리를 유지했다.
- 국적 표식·기체 번호·원본 마모는 추가하지 않았다. drawSize는 19×19로 확정했고 게임 내 연결/비행/확대율 검증은 별도다.
- 항공기 정의/기능 연결, 실제 게임 표시·비행·착륙·화물문은 미실시다. 이번 범위는 모델에서 만든 시험 텍스처이며 기존 본판/아스널의 항공기를 교체하지 않는다.
