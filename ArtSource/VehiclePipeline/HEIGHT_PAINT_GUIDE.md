# 높이 채색 + 폴리곤 감소 + 세부 예외: 다른 차량에 빠르게 적용하기

M3A3 Bradley(`ArtSource/M3A3Bradley`, 2026-11-13)에서 사용자와 함께 정한 방식을 다음 차량에 다시 쓰기 위한 작업 지침이다. 규칙의 근거와 수치는 `../VEHICLE_ART_STYLE.md` §4, 공통 도구 사용법은 `README.md`에 있다. 이 문서는 **순서·설정·함정·질문 목록**만 다룬다.

> 이 방식은 사용자가 그 차량에 적용하라고 한 경우에만 켠다. 켜지 않은 차량은 기존 방향·겹침 규칙을 따른다.

## 1. 한눈에 보는 결정 사항

| 항목 | 결정 | 설정 위치 |
|---|---|---|
| 채색 기준 | 면 방향이 아니라 **평면 묶음의 중심 높이**. 높을수록 밝다 | `style.json` `height_paint` |
| 평면 묶음 | 이어진 면 중 첫 면과 12° 안쪽이면 같은 표면, 표면 하나 = 정확히 한 색 | `plane_angle` |
| 단계 | 레이어(차체/포탑·포신)별 7단계. 지붕 근처를 촘촘하게 나눠 지붕 위 해치·장비가 지붕보다 한 단계 밝음(시안 B) | `ladder`, `layers.<layer>.thresholds` |
| 벽 | 법선 Z < 0.25인 벽·하부만 한 단계 더 어둡게. 높이 3 cm 미만 띠는 제외 | `wall_steps` |
| 없앤 것 | 하이라이트 예외(accent), 매끈한 곡면 보간(smooth), 접촉 그래프(contacts), 부품 둘레 깊이 경계선 | 설정 스크립트에서 생성하지 않음, `boundary_lines.enabled: false` |
| 남긴 것 | 차체·포탑 바깥 검은 윤곽선(검수용), 비도색 재질 고정색(고무·궤도·금속·광학창·홈), 그릴 무늬 | |
| 폴리곤 | 전체는 평면 병합만, 곡면 부속만 collapse. 면 수보다 256px 결과 우선 | `style.json` `simplify`, 부품 `simplify` |

## 2. 작업 순서

각 단계 끝에 **이미지를 보여주고 묻는다**. 사용자는 숫자보다 그림을 보고 고른다.

1. **대상 확인.** 같은 차종 폴더가 여럿일 수 있다(M3A3: 새로 만든 `M3A3BradleyScratch` / 원본 기반 `M3A3Bradley`). 어느 모델인지 먼저 확인한다. 사용자가 "이전 모델"이라고 하면 원본 OBJ 기반 쪽이다.
2. **높이 분포 측정.**
   ```bash
   python ArtSource/VehiclePipeline/inspect_parts.py heights ArtSource/<Vehicle>/vehicle.json
   ```
   레이어마다 위를 향한 면적이 몰린 높이(지붕, 데크, 스커트 윗면, 포탑 지붕)를 찾는다.
3. **시안 두 개 렌더.** scratchpad에 `vehicle.json`·`style.json`을 복사하고 `height_paint`만 다르게 넣어 빌드한다. (A) 바닥~지붕 균등 구간, (B) 지붕 근처를 촘촘하게 나누고 지붕 위 부품을 한 단계 밝게. 현재 결과와 함께 1024 크롭 + 256px 실제 크기 비교판을 만든다. M3A3에서는 B가 선택됐다.
4. **밝기 조정.** 최상단 240은 너무 하얗게 뜨고 TAN이 약해졌다. 시작값은 아래 M3A3 값을 쓴다. 차체 지붕이 둘째 단계로 내려가 회색으로 보이면 그 레이어만 `ladder`를 한 단계 올린다. 지붕 근처의 살짝 낮은 조각(지붕 −5 cm)이나 앞 데크(지붕 −10~20 cm)가 따로 어두워지면 지붕 구간 경계를 내린다.
5. **폴리곤 감소.** 기본값 `{"weld": 1e-5, "collapse_ratio": 1, "min_faces": 200, "planar_angle": 8}`. 곡면 부속(바퀴·궤도·해치·전조등·포신·기관총·롤러·서스펜션·관측장비)에만 부품 `simplify: {"collapse_ratio": .3}`를 준다. M3A3는 렌더 면이 168,232에서 47,399로 줄었다.
6. **세부 예외.** 사용자가 부품 이름이나 번호로 요청하면 §4 도구로 위치와 shell을 찾아 이미지로 확인받고, §3 키로 설정한다.
7. **빌드 → 비교 → 커밋.** §5의 파일 잠금 우회를 쓴다. 쓴 값은 `VEHICLE_ART_STYLE.md` §4와 차량 `README.md`에 기록한다. 커밋 메시지에는 무엇을 왜 바꿨는지 적는다.

## 3. 설정 레퍼런스

### style.json

```json
"height_paint": {
  "ladder": [216, 196, 179, 160, 145, 128, 106],
  "plane_angle": 12,
  "wall_steps": 1,
  "layers": {
    "hull":   {"ladder": [236, 216, 196, 179, 160, 145, 128],
               "thresholds": [2.04, 1.78, 1.50, 1.20, 0.90, 0.65]},
    "turret": {"thresholds": [2.76, 2.66, 2.55, 2.42, 2.30, 2.18]},
    "barrel": {"thresholds": [2.76, 2.66, 2.55, 2.42, 2.30, 2.18]}
  }
},
"simplify": {"weld": 1e-5, "collapse_ratio": 1, "min_faces": 200, "planar_angle": 8},
"boundary_lines": {"enabled": false}
```

`thresholds`는 내림차순 높이(m)이고, 개수는 `ladder` 개수보다 하나 적다. 위 높이는 M3A3 값이므로 차량마다 2단계 측정으로 다시 정한다. 차체 지붕(약 2.0 m)이 `ladder[1]`에 들어가고, 그보다 높은 부품이 `ladder[0]`이 되게 잡는다.

### vehicle.json 부품 키 (높이 채색 모드)

| 키 | 의미 | M3A3 사용 예 |
|---|---|---|
| `height_steps` | 모든 표면 단계 이동. 음수는 밝게, 소수는 두 단계 사이 값 | 해치 6·전조등 보호대 −1, 포수 해치 −0.5, 손잡이 +2, 반달 홈 +1, 관측장비 원형 받침 +0.5 |
| `slope_steps` | 모따기·경사면(법선 Z 0.25~0.9)만 추가 이동 | 해치 경사면 +1 |
| `plane_angle` | 이 부품의 평면 묶음 각도 | 포방패·포구 덮개 45°(각진 원뿔이 두 색으로 잘리는 문제 방지) |
| `fixed` | 높이와 무관한 한 값(TAN 색조) | 힌지 145, 손잡이 받침 128, 측면 방열판 179 |
| `rgb` | 표시 sRGB 고정색(TAN이 아닌 색) | 관측장비 손잡이 FDE `[160,140,106]` |
| `inflate` | 법선 방향으로 m만큼 두껍게(1px 미만 부속) | 스커트 손잡이 0.01 |
| `simplify` | 기본 감소 설정을 덮음, `false`는 끔 | 곡면 부속 `{"collapse_ratio": .3}` |
| `role: "metal"` + `top` | 무채색 어두운 금속 | 힌지 축·연막탄 발사기 88, 주포 64, 동축 56 |
| `role: "recess"` + `top` | 거의 검정 | 후방 램프 케이블 25 |

부품 일부만 바꿀 때는 `configure_vehicle.py`에서 seed 면이 들어 있는 shell을 떼어 낸다(`take(group, [seed...], label, **settings)`). seed는 원본 OBJ 해시에 고정된 전역 면 번호다. 이 패턴은 M3A3 스크립트를 그대로 복사해 쓴다.

## 4. 부품 찾기 도구 — `inspect_parts.py`

| 명령 | 언제 |
|---|---|
| `components <profile> <group>` | 그룹 안 shell 목록(seed, 면 수, 크기, 평균 법선). 손잡이·힌지·축 후보 찾기 |
| `region <profile> <group> "x,y,z" "x,y,z"` | 상자 안 shell. 다른 메시에 섞여 있는 부품 찾기 |
| `zoom <profile> <view> out.png <part-id>...` | 빌드된 뷰에서 해당 부품을 빨간 테두리로 표시 |
| `at <profile> <view> "x0,y0,x1,y1"` | 1024px 화면의 영역이 어느 부품인지 확인 |
| `sheet <profile> <group> out.png` | 그룹의 shell을 색으로 나눠 앞/위에서 본 그림(전조등처럼 작은 조립품) |

크기로 읽는 법(M3A3 경험):
- **손잡이:** 10~25 cm 막대, 면 수 30~90.
- **힌지 마디:** 7~10 cm 원통.
- **힌지 축:** 30~45 cm 길이에 단면 약 5 cm인 닫힌 원통(평균 법선이 거의 0). 단면 두께가 1 cm 이하인 판은 축이 아니다.
- **연막탄 발사관:** 같은 크기 원통 4개가 한 쌍.

## 5. 함정과 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 큰 장갑판 외곽에 톱니 조각 | collapse decimate를 큰 판에 적용 | 큰 판은 평면 병합만, collapse는 곡면 부속에만 |
| 요청 부품이 엉뚱하게 칠해짐 | 원본 그룹 이름이 실제와 다름(`ex_decor_02/03`은 연막탄이 아니라 동축 탄통) | 이름을 믿지 말고 `zoom`·`at`으로 화면에서 확인 후 진행 |
| 부품을 그룹에서 못 찾음 | 다른 메시에 들어 있음(해치 3 힌지 축·연막탄 발사기는 포탑 본체 `bone_turret`) | `region`으로 주변 그룹을 함께 검색 |
| 좌우 대칭 부품 색이 다름 | shell 분할이 좌우가 다르고, 한쪽에만 보조등 같은 추가 부품이 있음 | 기준 쪽(사용자가 지정)을 분류하고 반대쪽은 면 중심을 좌우 반전해 최근접 면의 분류를 복사. 짝이 없는 면은 기준 안쪽 상자 안이면 안쪽으로 |
| 렌즈 색이 안 보임 | 앞을 향한 렌즈는 위에서 내려다본 뷰에서 0px, 앞을 향한 뷰에서도 256px에 약 2px | 등 전체를 고유색으로 칠하면 너무 튐(사용자 반려). TAN 유지 + 보호대 −1 단계, 안쪽 0, 렌즈는 광학창 192 |
| 경계선을 끄면 파괴 레이어가 없음 | 예전 `enabled:false`는 오버레이 생성까지 건너뜀 | 현재는 빈 선 마스크로 계속 진행(수정 완료) |
| 빌드가 `[Errno 22] Invalid argument`로 PNG 저장 실패 | 저장소 `output`의 PNG를 다른 프로세스가 잠깐 잡음 | scratchpad에 `vehicle.json`·`style.json`을 복사해 빌드 → `cp -rf <scratch>/output/. <vehicle>/output/` → report에 scratch 경로가 없는지 확인 |
| 해치가 지붕과 같은 색 | 중심 높이가 같은 구간 | 그 부품만 `height_steps: ±0.5` |
| 작은 원뿔·원통이 두 색으로 갈림 | collapse 뒤 면 사이 각도가 12°를 넘음 | 그 부품만 `plane_angle: 45` |

## 6. 사용자에게 물을 것 (체크리스트)

질문은 한 번에 2~4개로 묶는다. 위치를 묻는 질문은 **번호를 찍은 이미지**를 먼저 보낸다.

1. 대상 모델(폴더)과 레이어 범위(차체만인지, 포탑도 포함인지).
2. 높이 시안 A/B 중 선택, 최상단 밝기(216 기준을 권장).
3. 곡면 해치: 완전 평판 / 2~3면으로 꺾인 판(M3A3는 2~3면).
4. 예외 부품마다 색 방향: 밝게·어둡게·고정값·고유색(CB/FDE 등 hex)·두께 보강.
5. 이름이 모호한 부품("방열판", "홈", "램프의 선")은 후보 번호 이미지로 확인.
6. 경계선: 안쪽 깊이 경계선만 끌지, 바깥 윤곽선도 끌지(M3A3는 안쪽만).

## 7. 검수와 기록

- **비교:** 같은 크롭으로 이전/현재 1024 비교, 256px 실제 크기, 해당 부위를 3~4배 확대해서 본다. 앞을 향한 렌즈나 후방 램프처럼 위에서 안 보이는 부위는 `hull_north`·`hull_south` 같은 해당 방향 뷰로 확인한다.
- **테스트:** `python -m unittest discover -s ArtSource/VehiclePipeline/tests`
- **기록:** 차량 `README.md`에 바뀐 것과 렌더 면 수, `VEHICLE_ART_STYLE.md` §4에 그 차량 값을 남긴다. 게임 내 확인 여부는 따로 적는다.
