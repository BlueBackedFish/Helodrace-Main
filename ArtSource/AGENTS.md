# 차량 아트 작업 규칙

이 절은 Vehicle Framework 차량 모델·차량 텍스처 작업에만 적용한다. 가구 등 다른 아트에는 적용하지 않는다.

- 새 차량 제작과 기존 차량 수정 전에 `VEHICLE_ART_STYLE.md`를 읽고 적용한다.
- 새 OBJ+청사진 작업은 `VehiclePipeline/README.md`의 공통 도구와 작업 순서로 시작한다. 입력 수집·부품 식별표·설정 생성·초안 렌더를 자동화하고, 에이전트가 자료를 보고 차량별 JSON을 작성한다. 사용자가 부품마다 수동 선택하는 절차를 기본으로 삼지 않는다. 이름/재질 기반 제안과 임시 피벗을 검수 없이 확정하거나 기존 Bradley 결과를 새 빌더로 덮어쓰지 않는다.
- 기본 렌더는 고정 RGB/이미지 → Emission, 그림자·AO·조명·시점 의존 색 보정 없음이다. 넓은 곡면의 보간이 필요해도 고정 vertex 색으로 만든다. 이 공통 제작 도구의 팔레트는 시작 프리셋이며 RimThunder 실측값/승인 기준이라는 뜻은 아니다.
- 목표 아트 스타일·차량 외형·디테일 배치는 RimThunder를 기준으로 한다. Legion은 3D 모델 기반 렌더 방식을 참고한다. 한 면 한 색 제한은 취소했다.
- Legion의 별도 차량 디자인이나 생략 수준을 실제 Bradley의 형상 기준으로 사용하지 않는다. RimThunder에 가까운 식별력과 디테일을 구현한다. 직접 겹치거나 맞닿는 부품의 경계를 명도 차이로 표현한다(RimThunder식). 직접 겹치거나 맞닿는 부품은 바탕과 명도 사다리 한 단계(표시 명도 약 21–24) 이상 차이 나게 한다. 위 부품 상면은 바탕보다 밝아도 어두워도 된다. 장착 부품의 측벽·테두리는 바탕보다 어둡게 해서 경계를 만든다. 떨어진 부품끼리는 높이에 따른 차이를 강제하지 않는다. 넓은 해치 본판은 높이·곡률의 부드러운 명도 표현을 사용하고, 작은 힌지·관측장치의 원통 측면은 원주 전체 단색을 사용하며 끝면은 별색으로 구분할 수 있다. 일부 장비는 별도의 어두운 색을 사용한다.
- 사용자 제공 3D 파일은 비율·장비 배치의 근거, 청사진은 투영 검수와 디테일 선택의 근거로 사용한다. 두 자료의 차종/형식이 다르면 기록한다.
- 현재 Bradley 출력이나 기존 스크립트 수치를 승인된 스타일 표준으로 간주하지 않는다.
- 형상 변경이 별도로 요청되지 않으면 제공된 3D 형상을 보존하고 부품·면별 채색으로 가독성을 먼저 확보한다. 현재 Bradley는 2차 전 형상을 바탕으로 요청된 연결부·주포·해치 부속·원본 연막탄을 복구하고 평판 덮개를 유지한다.
- 새 차량 폴더에 `VEHICLE_ART_BRIEF_TEMPLATE.md`를 복사해 `ART_BRIEF.md`를 작성한다. 미확인 값은 추측으로 확정하지 않는다.
- 공통 스타일과 차량별 부품 매핑을 분리한다. 원본 오브젝트 이름을 공통 채색 알고리즘에 직접 박아 넣지 않는다.
- 원본 보존 → 부품·면별 명도 설계 → 분리 렌더 → 실제 출력 크기 비교 순으로 작업한다. 형상 재구성은 요청된 경우 별도 단계로 진행한다.
- 폴리곤 수 감소를 목표로 삼지 않는다. 장갑판에 일괄 collapse를 적용하거나 작은 부품을 크기만으로 삭제하지 않는다.
- 평면별 색은 부품 역할·방향·기울기를 함께 고려한다. 해치 전체를 일괄 암색 처리하지 않는다. 안쪽 홈/바닥은 의도적으로 어둡게 할 수 있지만, 삼각형 얼룩이 되지 않게 이어진 표면 단위로 처리한다.
- 사라진 부품을 복구할 때 해당 오브젝트만 보지 말고 상위 메시 안의 연결 받침과 장착대도 원본과 함께 대조한다.
- 높이/방향 때문에 어두워진 페인트는 채도도 낮춰 회색에 가깝게 한다. 의도적인 어두운 부품색·홈 강조와 원인을 구분한다.
- 직접 겹침 규칙은 최종 색에서 검증한다. 지붕 → 그 위 해치 → 그 해치에 장착된 장비처럼 직접 맞닿은 상면 쌍은 한 단계 이상 다르거나, 그 사이에 어두운 측벽·테두리가 256px에서 1px 이상 보여야 한다. 밝기 방향은 바탕의 사다리 위치와 RimThunder 대응 부품으로 정한다. 별개 해치와 별개 관측장비는 높이로 정렬하지 않는다. 보정 계수 검사만으로 통과시키지 않는다.
- 직접 겹친 주요 부품 사이의 명도 차이는 최소 간격을 확보하되 큰 높이 차이만으로 전역 대비를 계속 키우지 않는다. 넓은 본판과 작은 부속을 같은 곡면 규칙으로 묶지 않는다. 작은 원통(256px에서 폭 8px 미만: 힌지·롤러·작은 관측장치) 측면은 연결된 표면당 단색, 그 외 작은 곡면은 필요하면 두 색을 사용한다. 넓은 볼록 본판과 큰 곡면(주포·흙받이·큰 돔·바퀴 원판)은 RimThunder처럼 고정 꼭짓점 색의 매끈한 명도 보간을 쓴다(`VEHICLE_ART_STYLE.md` §4, 2026-11-06 사용자 결정).
- 같은 차량의 RimThunder 레퍼런스가 있으면 부품 대응을 확인하고 실제 겹침 관계를 지키면서 재질·명도 관계를 맞춘다. 해치 손잡이와 뒤쪽 힌지처럼 인접한 다른 부품을 혼동하지 않는다.
- 반복 채색은 문제 부위의 표면 유형을 먼저 정하고, 회차마다 그 유형에 필요한 변수만 바꾼다. 이전 결과·변경 이유·수정 범위를 기록하고 다른 부위의 승인된 표현은 유지한다.
- RimThunder 대조는 `RimThunderAudit/`의 차종 짝과 측정 스크립트를 사용한다. 원본 모델과 RimThunder 차종이 다르면(`ext/t34`는 Sherman Calliope) 비교에 쓰지 않는다. 평면은 정확히 한 RGB, 명도는 사다리 단계 재사용, 궤도 등 비도색 재질은 페인트와 분리한다(`VEHICLE_ART_STYLE.md` §4, §15).
- 작은 장착 부품(견인 고리·인양 고리·손잡이·렌즈 테두리)은 색상 규칙의 예외로 하이라이트를 줄 수 있다. 바탕보다 한 단계 이상 밝게, 접촉 그래프 밖에, 이유를 기록하고 면적은 전체 표면의 3% 이하로 둔다(`VEHICLE_ART_STYLE.md` §4). 적재물 단순화와 그릴 패널 맞춤은 §2·§3 절차를 따른다.
- 파괴 상태 레이어: 관측장비·전조등은 분리하고, 탄약고 블로아웃 패널은 승무원 공간과 격리된 분리 탄약고가 있는 차량(M1A2 등)에서만 분리한다(`VEHICLE_ART_STYLE.md` §6).
- 장착 부품 둘레에는 주변 면 색을 같은 비율로 어둡게 한 경계선(256px에서 1px, 덮임 비율로 안티앨리어싱, 흩어진 작은 조각·바늘구멍 정리)을 넣고, 포탑 기관총은 별도 무기 스프라이트로, 기존 자산이 있는 장비(CROWS)는 장착점만 기록하고, 높이 3 cm 미만 벽 띠는 윗면 색으로, 1px 미만 막대·난간·배선은 지운다(`VEHICLE_ART_STYLE.md` §3·§4). 선 넣기 전 레이어를 보존한다.
- 같은 차량 화면 크기로 레퍼런스와 256px/512px 결과를 비교한다. 캔버스 크기가 같다는 이유만으로 동일 스케일이라고 판단하지 않는다.
- 검수용 이미지에는 차체와 포탑을 각각 검은 윤곽선으로 처리한 뒤 원래 피벗으로 합성한다. 기본 두께는 256px에서 2px, 512px에서 4px다. `VehiclePipeline/outline_review.py`를 사용하고 원본 모델/무윤곽 렌더와 검수용 후처리를 구분해 보존한다. 합성 완료 이미지의 바깥 테두리만 두르는 것으로 대신하지 않는다.
- 원본 계층, 포탑·포신·문 피벗, 투명 배경, 그림자 없음, 일관된 투영을 유지한다.
- 작업 완료 시 모델 검증과 실제 크기 시각 검수 결과, 남은 차이 및 미실시한 게임 내 검증을 구분해 기록한다.

커밋과 브랜치는 상위 `AGENTS.md`를 따른다.
