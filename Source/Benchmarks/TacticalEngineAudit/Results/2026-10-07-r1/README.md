# R1 대조/격리 원본 — 2026-10-07

`New`는 아직 새 실행기가 없는 `vanilla-fallback`이다. 이 결과는 수집/격리 도구 검증이며 새 전술 AI의 2배 합격 결과가 아니다. [구현·검증 보고서](../../../../../Docs/전술/R1%20대조%20실행과%20격리%20검증%20결과.md)와 [실행기](../../README.md)를 함께 읽는다.

## 자료

- `measurements.json`: 실행별 audit와 메서드 총 경과/호출/평균/max/p95/p99/호출·비용/틱/Core 비율. 개별 CPU는 전체 틱에만 있으며 창 전체 CPU도 별도 저장한다.
- `raw-manifest.json`: 압축 전 원본의 SHA256와 바이트 수. gzip 압축을 풀어 재검증할 수 있다.
- `raw/verified`: 실제 완료 및 격리/수집을 확인한 fixture v5 결과. 엔진 비교 JSON에는 중앙값·반복 범위·진행이 있다.
- `raw/excluded`: 초기 실패와 예비 결과. 기존 파일/로그는 변경하지 않고 압축 복사했다.
- `tests`: 실제 게임 DLL 통합/프로파일러/CLI 검증과 빌드 로그. `pack-evidence.py`는 원본 압축·집계에 사용한 스크립트다.

검증 기록은 23회(반복 18/비계측 3/유휴 2), 제외·예비는 18회다. 원본 263개 파일의 압축 전 바이트 수/해시를 검증했다. 비계측 대조에는 `profiles` 디렉터리가 없고 실제 창 CPU는 audit에 있다.

메서드 inclusive 값은 중복되므로 합산하지 않는다. Core %는 10,000회 배치 비용에 대한 경과 시간 비율이며 CPU 점유율이 아니다. Map/컴포넌트 Update도 게임 틱 수로 정규화한다. 워커별 CPU는 직접 측정하지 않는다.

## 반복 비교 그룹

| 그룹 | 반복 | 요청/실제 인원 | 준비/수집 틱 | 측정 DLL SHA256 |

| HIGH 닫힌 외벽 공병 | 각 엔진 3회 | 13/13, 무전 13 | 600/1800 | `8678c209a3501b44adc3363ddf7dea7e232822553acc34881bb655c05dfbb32e` |
| LOW 열린 외벽 일반 이동 | 각 엔진 3회 | 12/12, 무전 0 | 180/1200 | `3b0b29ff28f5845bd4d1dc4b1c995215913605e029607b4b231c023155812dde` |

첫 DLL은 구현 커밋 `41ded3b8`의 측정본이다. 이후 audit에 비계측 창 CPU/측정 틱 진단을 추가한 두 번째 DLL로 LOW/비계측/유휴를 검증한다. 서로 다른 DLL이나 시나리오를 하나의 CPU 비교 그룹으로 합치지 않는다. 두 빌드 모두 New 실행기는 없다.

서로 다른 엔진은 전술 시작/종료 단계가 다를 수 있으나 동일 장비/지도/편제/수집 조건으로만 비교한다. HIGH 자격/채굴 20의 fixture 전용 보정도 세 엔진에 같다. LOW Legacy는 모두 진입 0명, HIGH Legacy는 진입 3/5/1명으로 완료 작업량이 다르다. 이들 값이 낮아도 정상 진행의 비용 개선이라 주장하지 않는다.

## 재분석

확인할 run 폴더를 새 디렉터리에 압축 해제해 원래의 `audit.json`/`profiles/capture-*.json` 관계를 유지한다. 같은 fixture v5 그룹만 현재 CLI로 읽는다.

```powershell
dotnet Source/Tools/AgentProfiler/bin/Debug/net10.0/AgentProfiler.dll engine-compare "$root/open-approach/vanilla" "$root/open-approach/new"
```

기능 완료·50/200/400명 부하·다중 맵·저장/로드는 R2~R7에서 별도 검증한다. 비계측 1회 대조는 도구가 동작을 막지 않는지/창 CPU 수집이 가능한지 보는 예비 확인이며 정확한 계측 오버헤드율 추정에는 사용하지 않는다.
