# R2 반복 CPU와 최소 진입 검증 원본

2026-10-08. 최종 DLL `0fc21ff73dadb2009947190503e38043b5c22406fa08da7dc80b0be10716ccc1`, fixture v9. [R2 보고서](../../../../../Docs/전술/R2%20최소%20돌파%20진입%20구현과%20검증.md)에 구현 범위와 제한을 정리했다.

## 최종 검증

- LOW 실제 60명/5분대 및 204명/17분대. 일반 접근/닫힌 외벽을 별도 Vanilla/New 각 3회씩 실행했다. 24회가 같은 DLL·지도·폰 지문·수집 대상·시드·준비 0틱/측정 6,000틱으로 대조됐고 네 그룹 모두 전체 틱 CPU 및 틱 밖을 포함한 메인 CPU ≤2배다.
- New 12회 모두 실제 개구부 통과와 전 분대 자리 도착을 완료했다. 연결 슬롯·고유 자리·실제 외벽/실내 배치·후미 통과도 검사했다.
- 같은 DLL에서 야외 명시 목표·일반 문·16칸 방·외부 장애물·진입 중 작업 중단·HIGH 공병 사망의 6개 실제 기능 사례가 통과했다. HIGH 생성 13명 중 공병 사망 후 12명 진입을 확인한다. 대규모 HIGH CPU 합격은 주장하지 않는다.
- 세 개 최종 시험 폴더의 **30회**는 `raw/verified`에 있다. 사전 **31회**는 `raw/excluded`에 보존한다. 총 61 audit, gzip 원본 429개, 압축 크기 약 1MB다. 기존 R1 기록은 변경하지 않았다.

## 자료

- `low-50-*comparison.json`, `low-200-*comparison.json`: CLI의 원본 대조 출력. CPU 중앙값/실행 범위·각 회차 진행·조건·Core 기준 호출 비용이 있다.
- `cpu-summary.json`: 네 그룹 CPU, New 호출 평균/빈도·p95/p99/최대, 전체 틱 경과 분포 요약. 메서드 값은 경과 시간이며 CPU와 합산하지 않는다. Core %는 고정 10,000회 배치 단위다. 분위수는 마지막 2,048회 호출의 실행별 중앙값이다.
- `functional-checks.json`: 실제 실행기의 최종 6개 사례 판정.
- `measurements.json`: 61회 원본과 메서드 통계. `verified`는 완료된 수집과 기능/격리 검사이며 모든 항목이 CPU 대조라는 의미는 아니다. 강제 사망 기능 사례는 인원 변화 때문에 CPU 대조에 넣지 않는다.
- `raw-manifest.json`: 압축하기 전 바이트 길이와 SHA-256. 원래 audit·capture·capabilities·status·launcher·Player.log·폰 명세·설정 JSON을 보관한다. Saves/Worlds는 포함하지 않는다.
- `tests/`, `verification.json`: 실제 바인딩/엔진 선택, 수집기/CPU 게이트 v9, 실제 capture CLI 검사 결과와 검증 요약. 테스트 stdout은 UTF-8로 변환했다.

모든 최종 Player.log에는 초기 탄약 텍스처 누락 5종이 동일하게 있다. 수집기 ready 이후 전술/런타임 예외·오류는 없었다. 로그 원본을 지우거나 누락 메시지를 숨기지 않았다.

## 제외 기록

`excluded`는 실패 기록만 의미하지 않는다. 이전 DLL/fixture의 성공, 생성 지문이 다른 대조, 불완전 창, 짧은 생성 확인도 포함한다.

- 초기 12/60명 v6 smoke는 사전 기능 확인이다. 첫 문 smoke는 이전 DLL에서 벽을 부쉈으므로 문 기능 증거가 아니다.
- v6/v7 좁은 방은 코너 밖 가짜 입구 또는 자리 부족으로 실패했다. v7b에서는 좁은 방/장애물을 통과했지만 중단 이후 외부 복귀 판정 문제를 확인했다.
- v7c 중단/HIGH 사망은 통과했다. 204명은 16/17분대만 새 임무를 마쳤고 마지막 분대가 바닐라로 반환됐으므로 실패다. 300초에서 잘린 capture도 CPU 대조에 넣지 않았다.
- v7 개구부 목록 재사용 후 204명 성공과 최종 v7 야외 이동은 다른 DLL의 사전 확인이다.
- v7 및 v8의 60명 반복은 생성 폰 지문이 달라 같은 조건 3:3 대조를 만들 수 없었다. v8 짧은 204명 생성 4회가 일치했어도 이후 확대 지문 차이가 확인돼 최종 합격에 쓰지 않았다. 실행기를 중단했더라도 이미 시작한 격리 게임은 원본을 남기고 자체 종료했다.

## 원본 확인과 대조 재현

CLI를 빌드한 뒤 다음을 실행한다. 게임을 시작하지 않고 gzip 원본의 길이/해시를 확인해 새로운 CreatorTemp 폴더에 풀고 네 CPU 대조를 다시 수행한다. 결과 비율이 저장된 JSON과 같은지도 확인한다. 현재 검증에서 429개 원본과 네 대조가 모두 일치했다.

```powershell
dotnet build Source/Tools/AgentProfiler/AgentProfiler.csproj --no-restore
python Source/Benchmarks/TacticalEngineAudit/Results/2026-10-08-r2/verify-evidence.py --output C:/Users/Public/Documents/ESTsoft/CreatorTemp/hd-r2-review-fresh
```

새 폴더를 지정해야 하며 기존 증거 폴더를 삭제/덮어쓰지 않는다. `pack-evidence.py`는 지정한 시험 폴더를 다시 압축하는 도구다. 최종 폴더 3개는 `--verified`, 사전 폴더는 `--excluded`로 전달한다. 실제 게임 재수집 절차는 [실행 안내](../../README.md)에 있다.
