# R4 접촉 기억·대응 대표 시험

LOW 12명, sapper-door, r4-contact-drill, fixture v18, 준비 0·측정 4,800틱. 해당 메서드와 기존 Core/전체 틱 기준만 수집했다. 실제 폰을 후방·다른 문칸·개구부 양쪽에 배치하고 실제 LOS/lean으로 관측한 뒤 숨긴다. 테스트가 기억에 직접 접촉을 삽입하지 않는다.

- `failed-01`: 다른 문을 목표 방의 일부라는 이유로 위협 분류에서 제외해 두 번째 상황에서 멈춘 기능 실패. 수집 완료와 기능 완료를 구분한다.
- `failed-02`: 첫 위협 대응 이후 다음 관측 조각에서 들어온 반대 방향을 반영하지 못한 기능 실패.
- `passed`: 현재 DLL에서 세 상황 대응·복귀, 숨은 위치 추적 없음, 대응 중 계획/확보 이력 유지, 미관측 문 열림으로 계획 교체 없음, 4,717틱에 세 방/12명 전원 완료. 안전 완료 전 진입 0. 캡처/감사/환경 통제/격리 정상, dropped/계측 예외 0.

각 폴더의 `summary.json`에 호출·평균/상위/최대 비용·틱당 호출·Core 비율·전체 CPU와 실제 이벤트를 기록한다. 원본 감사/런처/로그/캡처/capabilities는 gzip으로 보존하며 `raw-manifest.json`에 압축 해제 내용의 길이/SHA256과 원래 경로를 기록한다.

세 실행은 수정된 서로 다른 DLL이므로 동일 조건 3회 반복이나 개선율 비교로 사용하지 않는다. 적과 공격자는 피해를 막은 기능 fixture다. 실제 피해 교환/킬 성능의 증거가 아니며, 한 분대 결과로 대규모 CPU 2배 합격을 선언하지 않는다. [구현·검증 분석](../../../../../Docs/전술/R4%20접촉%20기억과%20대응.md)을 참조한다.
