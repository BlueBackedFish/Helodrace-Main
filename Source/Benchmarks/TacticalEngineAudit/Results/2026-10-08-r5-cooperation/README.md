# R5 연락·협력 진입 약식 검증

fixture v19, 준비 0틱, 실제 LOW 12인/High 13인 분대 두 개. 격리된 quicktest 프로세스와 저장 경로를 사용했다. 각 폴더의 `raw-manifest.json`은 원본 경로·gzip 해제 바이트 수·SHA256를 보존한다. `audit.json.gz`, `launcher.json.gz`, `Player.log.gz`, `capabilities.json.gz`, `capture-*.json.gz`를 실제 원본과 대조해 압축했다.

| 폴더 | 용도 | 완료/제한 |
|---|---|---|
| `low-coop` | 최초 LOW 24명/6,000틱 | 다른 외벽/담당 방·분리 후 보고 차단·실내 식별, 3,814틱 완료. 이전 DLL 참고 |
| `radio-loss-failed-01` | 첫 High 단절/승계 | 독립 임무는 완료했으나 합의 0회. 실패 원본이며 협력/CPU 합격에 사용하지 않음 |
| `radio-loss-recovery` | 600틱 연락 기회 수정 | High 생존 25명, 합의/담당 구역·메시지 폐기·승계, 3,763틱 완료. 적 보고 자극 추가 전 |
| `shared` | 첫 유일한 입구 시험 | LOW 24명 선두/후미 모두 같은 실제 개구부 통과, 2,434틱 완료. 이전 LOS 검사 |
| `radio-loss-report` | High 최종 대표 | 무전 파츠 인벤토리 제거/착용 복구, 대기 메시지 발신자 사망/승계, 수신 측 LOS 없는 실제 적 보고, 다른 입구/담당 구역, 3,790틱 완료 |
| `low-coop-current` | LOW 최종 대표 | 4,800틱 창, 4,651틱 전원 완료. 식별 5회와 해당 분대만의 임시 자리 정리, 다른 입구/실제 담당 방, 분리 중 보고 차단 |
| `shared-current` | 마지막 LOS 변경 확인 | 최종 DLL, 3,600틱 창, 2,435틱 전원 완료. 개구부 자체 LOS로 알려진 입구 재사용, 공유 입구 후속 진행 |

최종 DLL SHA256: `6d011e670d4945aa05c2ef4940f69ea8f0fc881e2198b443a658b7abd9e1a175`. LOW/High 최종 대표의 `2bfd1740…` 이후 변경은 `ReuseOpening`의 LOS 대상을 바깥 칸에서 실제 개구부로 강화한 것뿐이며, 해당 변경 경로를 `shared-current`에서 검증했다. 모든 성공 자료를 같은 DLL의 반복 CPU 대조로 합치지 않는다.

메서드 비용은 inclusive 경과 시간이며 실제 개별 CPU가 아니다. Core는 고정 10,000회 배치다. `Pump`에 `ProbePair/Deliver`가 포함되므로 합산하지 않는다. 전체 틱 CPU와 틱 밖 포함 메인 창 CPU는 별도로 보존했다. 분위수는 최근 최대 2,048호출이고 전체 창에는 완료 이후 일부 유휴 시간이 포함된다. 바닐라 대조와 대규모 반복은 이번에 수행하지 않았다.

대표 세 결과의 감사/캡처 완전성·격리·환경 통제·개구부 통과·실제 고유 자리·실제 확보 이력·폭발 안전을 확인했다. 계측 예외/누락은 0이며 Job 중단/실패는 회복한 이벤트로 별도 남긴다. 게임 기동의 기존 텍스처/장비 착용 경고를 전술 실행 예외와 혼동하지 않는다.
