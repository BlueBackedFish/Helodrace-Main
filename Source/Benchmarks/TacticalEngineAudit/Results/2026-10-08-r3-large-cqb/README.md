# R3 204명 다방 진행 검증

LOW 204명/17분대, 세 방, sapper-wall, fixture v17, 준비 0틱, 관련 메서드 소수와 전체 틱/메인 창 CPU 수집.

- `unfinished-10000`: 첫 관측 창은 정상 종료했지만 16/17분대 완료와 한 분대 Clear 상태로 끝났다. 기능 통과나 CPU 합격에 사용하지 않는다. 원래 false 결과를 수정하지 않았다.
- `new-15000`: 확보 구역·목표·조사·경계/재시도 진단을 추가한 빌드의 확장 관측. 17분대·204명 모두 10,274틱에 완료했으며 세 구역/목표 확보, 내부 고유 자리, 연결 스택, 엔진 격리/환경 통제를 확인했다. 안전 대기 전 진입 0건, capture/감사 complete=true, dropped/계측 메서드 예외 0.
- `reviewed-regressions.json`: 기존 성공 회귀 12개의 실제 원본 감사/캡처를 읽고 검사한 경로와 SHA. 역사적 DLL 자료이며 다른 빌드를 동일한 CPU 대조군으로 묶지 않는다.

각 하위 폴더의 summary와 raw-manifest는 실제 DLL·집계 값과 gzip을 해제한 원본의 SHA256/길이를 보존한다. 전술 본체의 동작을 변경하지 않고 검증기에서 방 개수와 진입 횟수의 동일시를 제거했다. 모든 대표 바닥 구역과 목표, 실제 중복 없는 진입 이력은 계속 요구한다. 폭발로 두 기존 방이 연결되면 이를 다시 나눠서 돌파할 필요가 없기 때문이다.

첫 창에서 남은 분대가 영구 정지했다고 확정하지 않는다. 확장 창은 실제 전원 완료를 보여 준다. 측정 창/DLL이 다른 두 New 실행의 수치를 개선율로 비교하지 않는다. 약식 결과를 정식 3회 반복 CPU 합격으로 표시하지 않으며, 정식 CPU 판정은 사용자 지침대로 R7 최종 통합 검증에 남긴다.
