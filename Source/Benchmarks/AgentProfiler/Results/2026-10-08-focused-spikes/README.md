# Schema 8 내부 진단 약식 검증

실제 게임에서 프리셋별 짧은 수집을 확인했다. 전체 임무 완료 또는 전후 CPU 개선률/바닐라 2배 게이트 시험이 아니다. 각 감사의 기능 완료 false는 그대로 보존했다.

| 자료 | 인원 | 준비/실제 측정 틱 | 등록 메서드 | 초기 기록 | dropped | 계측 예외 | 보존 틱 상세 잘림 |
|---|---:|---:|---:|---:|---:|---:|---:|
| needs | 60 | 120/180 | 70 | 320 | 0 | 0 | 0 |
| jobs-before | 24 | 0/180 | 102 | 479 | 252 | 0 | 0 |
| path-before | 24 | 0/180 | 101 | 608 | 0 | 0 | 47,218 |
| jobs | 24 | 0/180 | 71 | 360 | 0 | 0 | 0 |
| path | 24 | 0/180 | 77 | 464 | 0 | 0 | 0 |

`jobs-before`는 불완전 수집으로 비교에 사용하지 않는다. 자동 직접 호출 범위를 좁히고 제외 이유 카운터를 추가한 뒤 jobs/path를 다시 실행했다. 첫 경로 자료의 상세 잘림은 전체 메서드 집계의 누락과 다르다. 두 계측 집합을 CPU 개선률 비교로 합치지 않는다. needs 자료는 제외 카운터 추가 전의 동일 욕구 대상 구현이며, 최종 jobs/path는 현재 DLL 지문과 일치한다.

needs에서 기분 NeedInterval 최대 19.2225ms를 관측했다. 초기 8회 최대는 0.8900ms이므로 이후 호출에 발생했다. 이것은 JIT·GC·생각 계산·폰별 초기화의 원인 확정이 아니다. 자세한 기분 표본은 needs/summary.json에 있다.

game/CLI 빌드와 단위·실제 어셈블리 바인딩 검사를 통과했다. 정상 수집 3개에서 CLI 초기 호출/느린 틱/폰 조회, 같은 캡처 비교, 조건·스키마·대상·기준 불일치 거부 검사를 통과했다. 최종 jobs/path의 다른 스레드·중첩 깊이 제외 카운터는 모두 0이다.

각 폴더의 raw-manifest.json은 capture/audit/launcher/capabilities/status/Player.log gzip의 해제 길이·SHA256·원본 경로를 기록한다. derived-manifest.json은 CLI 진단 결과 gzip의 길이·SHA256이다. `spikes.json.gz`와 `initial.json.gz`는 조회 결과 예시이고 원본에서 다시 만들 수 있다. 종료한 게임의 저장이나 기존 플레이 세션은 재사용하지 않았다.
