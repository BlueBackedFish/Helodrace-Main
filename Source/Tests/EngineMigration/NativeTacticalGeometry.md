# Native tactical geometry checks

Build Main and the Main engine bridge, then run serially against actual RimWorld 1.7, Harmony 3 and mandatory Blancas:

```powershell
dotnet build Source/Helodrace/Helodrace.csproj -p:IntermediateOutputPath=obj/Migration17/ -v:minimal
dotnet build Source/Tests/EngineMigration/EngineMigration.csproj -v:minimal
Source/Tests/EngineMigration/Run-Migration.ps1 -Case native-tactical-geometry -RuntimeRoot .codex-staging/migration17/tactical-native17 -NoWindow
Source/Tests/EngineMigration/Wait-Migration.ps1 -RuntimeRoot .codex-staging/migration17/tactical-native17 -TimeoutSeconds 45
```

Use a fresh runtime. An observation timeout leaves the game running; wait on the same recorded PID/runtime until it exits instead of launching another game.

Frozen calculations come from 68ad3bf5. FrozenTacticalGeometry.cs contains the selected original focus/target/visual-cell/equipment-prefix, strike and coordinated geometry/state/gate methods. Unchanged utility dependencies explicitly use the current product TacticalAimUtility; their aim/training/visual results are controlled in this test. The pre-existing AngleMath.Interpolate expression is copied unchanged. Coordinated fixture construction is additional test code to initialize every frozen state field explicitly. FrozenTacticalHighSpeed.cs copies the original whole utility, excludes its external Harmony classes and imports the existing product job-driver types. Namespace/dependency qualification and trailing whitespace are adjusted; no duplicate product patches are registered and product visibility is not widened.

The actual 1.7 Vector3Utility.AngleFlat uses Quaternion.LookRotation(v).eulerAngles.y, with a zero-X/Z guard. RotatedBy uses a Y-axis AngleAxis quaternion. The native SpatialMath helpers use actual Waylith/BCL equivalents. Game position inputs cross through ToNative; equipment/GenDraw results cross through ToGame. Current ref equipment-draw and Projectile.Launch Harmony signatures retain the host game vector type explicitly. No simulation rule, tick ownership, RNG or save key changes.

Coverage:

- 84 private focus-direction cases, including the tiny-distance cutoff and nonzero y, 48 public target-angle pairs (Thing/cell/same-cell/invalid), five focus-cell cases and 160 visual-target-cell angles. The latter include 16 ordinary/wrapped angles and 144 derived half-cell rounding boundaries/adjacent floats across four quadrants. Resulting IntVec3 cells and validity branches must be exactly equal.
- 3,840 aiming equipment-prefix calls cover those angles, four previous angles, three offsets/heights and enabled/disabled visual overrides. Float offsets/angles are paired, and preserved height bits match exactly.
- 100 strike cases call actual BeginStrikeAnimation and TryGetVisual/AdjustEquipmentDraw with generated, spawned pawns and actual equipment ownership. Tiny/ordinary directions, aiming vs normal return angles and elapsed -1/0/1/6/7/8/12/23/24/25 cover interpolation, impact and animation expiry. State creation/removal, start tick, angles, thrust and draw geometry are compared. This does not execute melee damage/knockback/stun.
- 576 coordinated target-arc cases combine reference direction, range, near/at/outside 30-degree boundaries, CanHitTarget and line-of-sight results. Actual target Thing/map/position and equipment verb are used; controlled DrawPos values isolate geometry. Arc/range/LOS booleans must agree and at least one accepted arc must execute. 36 DrawActive calls compare valid/invalid formation submission gates and each fan endpoint/width/color. Partner-selection results are controlled, while the remaining IsFormationValid checks run against actual pawns/ownership.
- 108 slide profiles combine nine directions, three cell movement times and clear/walk-blocked/stand-blocked/LOS-blocked cases. Native and frozen utilities each run the actual HasClearSlidePath and AdvanceSlide bodies. Walkable/Standable/LOS and active/sliding gates are controlled; current map bounds and pawn-grid lookups remain real. Every sampled cell/order, advance result/position, direction angle, speed-curve result and state field is paired. Pawn position is restored to the same pre-step position before the frozen side; each controller retains its own progress. Travelled-distance bits must match. The movement-time getter is controlled to prevent the product's tick-rate hook reading one controller's newly advanced state for the other side.

Draw submissions are intercepted before rendering. DrawPos, aim/training/visuals, CanHitTarget, LOS, range and the stated grid/controller inputs are controlled. This is CPU geometry/state/rounding evidence, not GPU output, physical target input, natural training/access/LOS/pathfinding, slide job integration or attack/interception accuracy. Targeter ring color conversion compiles but full targeting flows are not executed here. Generated pawns/equipment and all fixture static state/Harmony prefixes are removed, and the tick counter restored at completion.

The initial engine run passed all seven checks with ordinary visual angles. The final run adds half-cell rounding boundaries/adjacent float angles without changing the product or the existing numerical/branch/state criteria. Numeric components use the existing relative 2e-5 comparison; actual maximum/nonzero differences are recorded separately. Branches, target cells, sampled cells/results, state identity/removal and specified scalar bits use exact comparisons.
