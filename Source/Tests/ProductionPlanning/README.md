# Production planning integration checks

Run `Source/Tests/ProductionPlanning/Start-Checks.ps1 -RuntimeRoot .codex-staging/ProductionPlanning/fresh-name`, then collect that host with `Source/Tests/Wait-Game17Host.ps1 -RuntimeRoot .codex-staging/ProductionPlanning/fresh-name -TimeoutSeconds 45`. The shared runner isolates the actual installed 1.7 game, required mods and test profile, and refuses to launch alongside another game. Retain failed runs and use fresh directories.

The fixture uses real steam/shaft power, four mechanical machines, a basic workbench and two planning desks. It resets research before checking lockout, then unlocks recipes for production. It checks disabled/no-desk behavior, manual target-count bill coverage, a constrained carbon-steel budget, duplicate suppression, actual work AI and unfinished ingredients. A stockpile is supplied for the native manual resource counter; the planner uses that bill's actual counter instead of assuming its stock settings. A native save/load must preserve the exact partial work and bill ownership. Removing/reinstalling the last desk pauses/resumes those same bills.

The worker fills all six stock targets. Electrical components consumed by electronic production are replenished. The initial manual shaft order is excluded from planner completion counters, then a second shaft deficit is automatically produced too. The fixture tests mechanical power loss, 10-piece batching, lower targets, delivered stock, the actual planning window and a second save/load with exactly 36 planner-made units recorded. Completed work is never inferred from item acquisition. The engine is refueled between production intervals: this is not a fuel-endurance experiment. Simulation is paused every update before explicit ticks.

Goals are now per item (`GoalFor`); the fixture targets the six basic components by name, so the same 36-unit counters apply.

Performance, coverage and flowchart mode: `Start-Checks.ps1 -RuntimeRoot ... -Perf [-Visible]`. It spawns about 4,000 item stacks and seven tables with bills, times 20 planner refreshes and 240 real window frames (Harmony stopwatch around `DoWindowContents`). It checks that the plan lists exactly the Helod resources and intermediates (including steel, pig iron, alumina, charcoal, aromatic base oil, general machine parts and press components, and no weapons, apparel, ammunition, food or money), that recipe-made items show their recipes, and that the two-product aromatic base oil recipe is plannable. It then targets every plannable item, expands the largest flowchart and times it, and checks unfold, expand-all and collapse-all. With `-Visible` it saves `flowchart-expanded.png` and `flowchart-electronic.png`. The perf map's machines are unpowered, so that refresh queues no bills; real bill creation is covered by the main run.

Final runs (2026-11-06): `.codex-staging/ProductionPlanning/flow-01`, 25 PASS and COMPLETE, only the pre-existing missing Workshop folder error. `perf-before-01` (old code): draw avg 5.27 ms, refresh avg 5.40 ms. `flow-perf-06` (flowchart): draw avg 0.38 ms, refresh avg 0.72 ms, 33-goal refresh avg 0.84 ms, 496-box flowchart draw avg 0.33 ms, 12 PASS and COMPLETE. Failed fixture runs are retained and are not completion evidence.
