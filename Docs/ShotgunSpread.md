# 산탄 시스템

## 발사와 탄군

한 발에 바닐라 사격 경로를 한 번만 실행한다. 사격 보고서·탄약 소비·발사 기록을 공유하며 첫 투사체의 발사 정보로 나머지 산탄을 생성한다. 무기의 추가 피해와 피해 종류 재정의도 복사한다. 단일 투사체 모드에서는 산탄 문맥을 만들지 않는다.

폰을 조준할 때는 바닐라의 성공/실패에 따른 칸 단위 빗나감을 사용하지 않고, 사격 보고서의 명중률로 연속적인 공통 조준 오차를 구한다. 이 때문에 근거리에서 낮은 사격 레벨의 탄군 전체가 옆 칸으로 빠지는 일이 줄어든다. 명중률 `a`는 `AimOnTargetChance_StandardTarget`을 0~1로 제한한 값으로, 사격 능력·무기 정확도·날씨·연막 등의 영향을 받는다. 대상 크기와 자세는 타원 판정에 따로 반영한다.

- 거리 `d`의 축별 조준 오차 표준편차: `0.025 + d × tan(0.15° + 1.5° × (1-a) × d/(d+8))`.
- 각 산탄의 확산각: `spreadAngle × 탄약 spreadMultiplier × (1 + 0.25 × (1-a))`.

근거리 보정은 거리에 따라 부드럽게 줄어든다. 명중률이 높으면 공통 조준 오차와 최대 25%의 조작 산포가 줄어들지만, 초크 없는 총열의 기본 산포는 유지한다. 명중 탄 수를 강제하거나 빗나간 탄을 다시 굴리지 않는다. 건물·지면 조준은 원래 칸 단위 빗나감을 유지한다. M79 산탄처럼 강제 빗나감이 사격 보고서 생성을 건너뛰는 경로에서도 보고서를 얻어 같은 조준 모델을 사용한다. 단일 유탄 모드는 바닐라 경로를 사용한다.

폰의 충돌 위치는 지도 위치와 경로의 이동 진행률로 계산한다. 피격 흔들림·기울기·프레임 보간은 명중에 영향을 주지 않는다. 이동 방향과 실제 경로 이동 비용, 산탄의 수평 탄속으로 도착 위치를 예측해 선행 조준하며 알려진 이동 목적지를 넘겨 조준하지 않는다. 발사 후 탄도는 고정되어 이후의 정지·방향 전환은 빗나감을 만들 수 있다.

산탄은 화면 안팎에서 매 틱 갱신한다. 출발점과 도착점의 표시 높이를 같게 두어 비행 시간을 수평 거리로 계산한다. 한 틱의 비행 구간이 표적의 몸을 지나는지 검사하되 벽·방어막 등 바닐라 비행 차단 처리를 먼저 실행한다. 같은 한 발의 산탄은 해당 틱의 대상 위치·자세·크기를 공유한다. 첫 탄의 피해 반응이 즉시 경로를 취소하거나 자세를 바꾸더라도 같은 틱에 도착하는 나머지 탄의 충돌 위치가 바뀌지 않는다. 다음 틱에는 실제 이동과 자세를 다시 반영하며 부위 피해와 방어구 판정은 산탄마다 계속 따로 처리한다.

근거리의 우연한 중간 충돌을 생략하는 바닐라 경로에서도 벽 같은 완전 차폐물은 검사한다. 열린 문은 통과하며, 다른 폰과 부분 엄폐물의 거리별 중간 충돌 확률은 유지한다.

산탄은 공통 조준 오차 주변에 독립적인 2차원 정규분포로 퍼진다. `spreadAngle`은 축별 각도 표준편차이며 단위는 도이다. 거리 `d`에서 기본 탄군의 약 90%를 포함하는 지름은 `4.292 × tan(spreadAngle) × d`이다. 이는 게임용 모델이며 지도 칸을 현실의 미터로 환산하지 않는다.

```xml
<li Class="Helodrace.VerbProperties_Shotgun">
  <verbClass>Helodrace.Verb_ShootShotgun</verbClass>
  <pelletCount>9</pelletCount>
  <spreadAngle>0.8</spreadAngle>
  <!-- 나머지 사격 설정 -->
</li>
```

투사체는 `Helodrace.Projectile_ShotgunPellet`을 사용하며 탄약별 설정을 추가할 수 있다.

```xml
<thingClass>Helodrace.Projectile_ShotgunPellet</thingClass>
<modExtensions>
  <li Class="Helodrace.ShotgunProjectileExtension">
    <spreadMultiplier>1</spreadMultiplier>
    <energyHalfDistance>40</energyHalfDistance>
    <internalPenetrationChance>0.35</internalPenetrationChance>
  </li>
</modExtensions>
```

| 무기·탄약 | 기본 확산각 | 탄약 확산 보정 | 에너지 반감 거리 |
|---|---:|---:|---:|
| M1887 | 1.0° | 1 | 40칸 |
| M1897 | 0.8° | 1 | 40칸 |
| M79·하부 발사기 M576 | 0.9° | 1.2 | 25칸 |

엄폐물 선택은 산탄별로 굴리며, 각 투사체는 게임의 비행·장애물·방어막 경로를 통과한다. 대상의 대략적인 체표는 타원으로 근사한다. 서 있는 대상의 반경은 `(0.32, 0.55) × BodySize^(1/3)`, 누운 대상은 `(0.55, 0.20) × BodySize^(1/3)`이다. 탄군의 가장자리만 걸치면 일부 산탄만 명중하며, 큰 대상은 같은 탄군에서 더 많은 탄을 받는다. 탄군을 벗어나거나 사라진 부위로 향한 산탄을 무조건 다른 부위로 다시 배정하지 않는다.

무기 정보 탭에는 **기본 산탄 확산각**과 **10칸 거리 탄군 지름**을 표시한다. 탄군 지름은 사수의 조준 오차·조작 산포와 탄약 보정을 제외한 기본값이다. 설명에는 근거리 조준 보정과 기본 무초크 산포를 안내한다.

## 종족 신체 자동 적용

`BodyPartRecord`의 `depth`, `coverageAbs`, `height`, 부모 관계를 사용한다. 인간의 부위 이름이나 특정 종족의 DefName 목록은 사용하지 않는다.

1. 피격 면적이 있는 외부 부위를 체표 후보로 등록한다.
2. 각 내부 부위의 잔여 면적을 가장 가까운 유효 외부 조상에게 한 번만 돌려준다. 장기를 추가하면서 체표 자체를 키우지 않았다면 외부 명중 면적도 증가하지 않는다.
3. 체표 면적을 정규화한다. 날개·꼬리·추가 팔다리도 정의된 면적에 따라 포함한다.
4. 최초 피해가 생기기 전에 발사·대상별 체표 중심을 정한다. 부위 간 연결 거리에는 면적과 높이 차이를 반영하며, 면적 없는 구조용 중간 노드는 건너뛴다.
5. 각 산탄의 실제 확산 크기에 따라 중심 주변 체표를 가중 선택한다. 손실된 부위와 손실된 조상 아래의 부위는 제외한다.

내부 부위가 없는 종족은 체표 손상만 처리한다. 사용할 수 있는 외부 부위가 없는 특이 신체는 기본 부위 선택·피해 처리로 돌아간다. 의수처럼 내부 구조가 교체된 부위 아래로 원래 장기 손상을 생성하지 않는다.

기본 신체 정의에는 정확한 3차원 위치와 부위별 입사각이 없으므로, 부위 간 근접성은 확률적 근사이다. 신체를 확장하는 종족 모드는 별도 목록 없이 적용되지만 투사체나 피해 처리 자체를 교체하는 전투 모드는 별도 연동이 필요할 수 있다.

## 장갑과 내부 피해

산탄별 남은 에너지는 `0.5^(비행 거리 / energyHalfDistance)`로 계산한다. 피해량은 에너지에 비례해 정수로 반올림하며 최소 1이다. 관통력은 에너지의 제곱근에 비례한다. 여러 산탄의 관통력을 합산하지 않는다.

부위 선택은 체표부터 시작하고 해당 부위의 바닐라·모듈 장갑 판정을 산탄별로 실행한다. 장갑에 완전히 막힌 탄은 내부 손상을 주지 않는다. 장갑에서 둔탁한 피해로 변환된 탄도 장기 관통을 생성하지 않는다.

관통 확률은 탄약의 `internalPenetrationChance × 남은 에너지 × 장갑 이후 피해 비율`이다. 후보는 해당 체표에 연결된 남아 있는 내부 부위로 한정한다. 더 깊은 장기로 가는 경로에 고형 부위가 있으면 각 중간 고형 부위마다 관통 확률에 0.65를 곱한다. 이름을 검사하지 않고 게임의 고형 부위 속성을 사용한다.

관통이 발생하면 장갑과 피격자 피해 배율을 적용한 피해의 60%를 체표에, 40%를 내부 경로에 배분한다. 내부 경로에 여러 부위가 있으면 내부 몫을 나누며 장갑·피해 배율은 재적용하지 않는다. 바닐라의 부위 파괴·영구 상처·즉사 방지 처리를 사용하고, 소형 동물에게 부모 부위 피해를 복제하는 전파는 산탄에서 생략한다. 체표가 파괴되어 내부 부위가 사라지면 남은 내부 피해를 다른 곳으로 전송하지 않는다.

## 상처와 저장

일반 `Hediff_Injury`를 유지하고 발사 식별자와 탄흔 수만 별도 게임 구성 요소에 보관한다. 같은 **한 발·실제 부위·상처 종류**의 미치료 상처만 합산한다. 이전 발사의 상처, 다른 부위, 다른 종류, 치료된 상처와 흉터는 구분한다. 중증도 상한을 넘는 합산으로 피해를 버리지 않는다.

상처 이름에 `산탄 5발`처럼 기여한 탄 수를 표시하며 중증도는 실제 합산 피해를 표시한다. 같은 한 알이 여러 피해 경로로 기여해도 해당 상처의 탄 수는 한 번만 증가한다. 게임의 상처 추가 루프가 여러 기존 상처를 확인하더라도 새 피해는 한 번만 합산한다.

영구 흉터나 손상된 장기 전용 이름으로 바뀐 상처에도 산탄 수를 한 번만 덧붙인다. 상처 합산 조건과 별개로 기존 탄흔 기록을 계속 표시한다.

비행 중에는 지도 구성 요소가 공통 조준점·조준 오차·체표 중심·산탄 참조를 저장하고, 투사체는 자신의 확산 방향을 저장한다. 상처의 발사 식별자와 탄 수는 게임 구성 요소에 저장하여 지도 밖으로 이동한 폰도 유지한다. 종료된 탄군과 사라진 상처 기록은 주기적으로 정리한다.

## 검증

```powershell
dotnet build Source/Tests/ShotgunSpread/ShotgunSpread.Tests.csproj
& Source/Tests/ShotgunSpread/bin/Debug/net48/ShotgunSpread.Tests.exe
```

설치된 RimWorld 1.6 DLL과 Harmony를 사용한다. 분포·거리·대상 크기, 추가 장기와 팔다리·구조용 노드, 발사당 한 번의 바닐라 호출과 9/20발 생성, 피해 종류·추가 피해 복사, 산탄별 장갑 판정과 내부 피해 총량, 발사별 상처 분리, 탄흔 수·저장 복원을 검증한다. 렌더링·게임 생성·장갑 수치 등의 게임 실행 경계는 독립 실행 테스트에서 대체한다.

`Run-InGameChecks.ps1`은 별도 게임 실행 폴더와 저장 폴더를 만들어 인간·Helod에 대한 실제 투사체 비행, 피해·상처 묶기·탄흔 표시와 정보 탭 항목을 검증한다. 바닐라 조준 실패를 활성화한 채 M1887·M1897의 사격 0/20레벨과 5/8/12/17칸 거리, M79 산탄의 강제 빗나감 경로도 검사한다. 분포 검사는 같은 대상에게 반복 피해를 주지 않도록 실제 발사 직후 탄도를 집계하고 투사체를 정리하며, 별도 한 발은 사격 0레벨·8칸에서 실제 비행과 피해까지 확인한다. `SHOTGUN_TESTS` 빌드의 검사 구성 요소만 실행하며, 배포 DLL에는 포함되지 않는다. 원본 게임 폴더·사용자 저장 파일은 수정하지 않는다.

## 실제 피격 수 감소 원인과 수정

2026-10-15 추가 조사에서 발사 직후 탄도 집계와 실제 피격 수 사이의 큰 차이를 재현했다. 위 분포 수치는 발사 시점의 표적 탄도이며 반복 실탄 피격 평균을 의미하지 않는다. 기존 단발 통합 검사만으로 이 문제를 충분히 검출하지 못했다.

이전 `HitsPawn`, `ImpactSomething`, `Impact`는 `Pawn.DrawPos`를 충돌·거리 계산에 사용했다. 이 좌표에는 `Pawn_DrawTracker`의 이동 보간 외에도 피격 흔들림, 조준 기울기와 작업용 시각 오프셋이 합쳐져 있다. 바닐라 `JitterHandler`는 총상마다 발사 방향으로 0.17칸의 시각 오프셋을 즉시 더한다. 두 발 뒤에는 약 0.34칸이다. 성인 인간의 전방 거리 허용치 약 0.32칸을 넘으므로 지도 위치가 그대로여도 다음 탄의 `HitsPawn`이 거짓이 되었다.

전체 비행·피해를 추적하는 `-ImpactAudit` 모드를 추가했다. 8개 조건에 각각 8회, 총 64회를 발사해 최초 표적 탄도, 실제 충돌, 피해 발생, 상처에 남은 탄 수, 부위 선택 실패를 따로 기록한다. 동일 무기·탄약·산포를 유지하고 렌더 좌표만 경로 진행률 기반 위치로 바꾼 비교 빌드도 각 조건 8회씩 검사했다. 사수는 사격 0레벨이며 표적의 의복을 제거한다. 폰 생성 조건은 실행마다 달라질 수 있다.
