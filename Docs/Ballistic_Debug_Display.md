# 피격 탄도 디버그 표시

개발자 모드를 켠 뒤 `모드 설정 → Helodrace → 탄도 디버그 (개발자 모드)`에서 설정한다. 두 표시 옵션은 기본적으로 꺼져 있으며 모드 설정에 저장된다. 개발자 모드를 끄면 남은 표시도 지운다.

- **피격 탄도 결과 표시**: 대상별 최근 피격의 관통·비관통·도탄·탄체 파쇄, 피격 구역, 법선 기준 착탄각을 표시한다. 운동탄에는 입사·잔여 운동에너지, 성형작약에는 입사·잔여 RHA 환산 관통 여력을 표시한다. 물리 장갑 판정을 하지 않은 피격은 별도 상태로 표시한다.
- **스폴·파편 경로 표시**: 차량 내부 추적기가 피해 계산에 사용한 대표 광선을 그대로 표시한다. 장갑 스폴, HESH 스캡, 내부 탄두 파편을 포함한다. 선 하나는 여러 파편을 대표하는 묶음이며 개별 파편의 그래픽은 아니다.
- **표시 유지 시간**: 1~20초, 기본 6초. Waylith 실시간을 쓰므로 일시정지 중에도 만료된다. 지도별 최근 32건, 피격별 최대 32개 광선으로 제한한다. 같은 대상의 결과 창은 가장 최근 피격 하나만 표시한다.

흰 선은 입사 방향이다. 관통·도탄 후 방향을 계산한 경우 유색 선으로 이어 표시한다. 차량 도탄처럼 잔여 비행 방향을 계산하지 않은 경우에는 출사선을 만들지 않는다.

파편 광선은 주황색(남은 파편이 계속 진행), 파란색(정지), 자홍색(승무원 명중)이다. 십자는 정지 지점과 각 광선의 첫 승무원 명중 지점을 표시한다. 3차원 경로를 지도에 투영하므로 높이 방향으로 퍼진 광선은 겹칠 수 있다. 장비에서 감속된 뒤의 속도 변화는 선 색에 반영하지 않으며, 결과 창의 파편 속도는 초기 속도다.

## 연결과 범위

Main의 `HumanoidBallisticImpact.Finish`와 Lobos의 `VehicleArmorDamagePatch.Postfix`·`VehicleBlastDamage.Deliver`에서 `BallisticsDebugDisplay.Record`를 호출한다. 차량은 내부 피해 전파가 끝난 뒤 결과를 복사한다. 탑승 중 지도에 직접 생성되지 않은 승무원 피격은 차량 표시로 묶는다.

제트·내부 기폭 뒤에 이어지는 같은 탄의 외부 폭발은 별도 결과 창으로 덮어쓰지 않는다. 스폴 경로만 켠 경우에는 파편 광선이 없는 피격을 표시 기록에 넣지 않는다.

`SpallTracer.Trace`의 선택적 `debugRays` 출력은 기존 대표 광선의 시작점·정지점·첫 승무원 명중점·파편 수·초기 속도를 복사한다. 표시를 위해 관통·피해 계산을 다시 하거나 난수를 추가로 소비하지 않는다. 디버그를 끄면 광선 목록을 생성하지 않는다. 표시 스냅샷은 저장 게임에 쓰지 않는다.

탄도 자료가 없는 바닐라 탄·일반 근접 피해의 판정을 새로 계측하지 않는다. 차량의 기존 VF 경로로 넘어간 경우에는 물리 장갑 판정 없음으로 표시한다.

## 검증

순수 코어 회귀에서 디버그 수집 전후 파편 명중 결과가 동일한지, 회전한 차량의 장비 정지점과 승무원 명중점이 실제 교차 위치인지 확인한다. 실제 게임 검사는 표시 끄기·실제 보병 피격 전달·번역·32건 상한·개발자 모드 제한·만료, 차량 피격과 스폴 광선 전달을 검사한다. 화면 표시의 기하와 UI 계약은 native 경계 목록에 기록한다.

2026-11-11 검증 결과:

- Main `BallisticsCore` 290,834개, Lobos `VehicleArmor.Tests` 50,283개 통과.
- 실제 1.7.5000 `.codex-staging/BallisticDebug20261111MainB`: 99 PASS, COMPLETE, 종료 코드 0. 외부 후속 폭발의 중복 억제와 스폴 전용 모드도 검사했다.
- 실제 1.7.5000 `.codex-staging/BallisticDebug20261111LobosB`: 452 PASS, COMPLETE, 종료 코드 0. 관통 사격 뒤 스냅샷 32건과 실제 대표 광선 192개를 확인했다. 기존 차량 Def/Workshop 오류 3종 외에 새 엔진 오류는 없었다.
- 제품 Main·Lobos 차량 Release 빌드 경고·오류 0. Lobos 검사 하네스의 기존 미사용 필드 경고 2건은 유지했다. 화면 외형의 수동 검수는 이 검사에 포함하지 않는다.

### 차량 피격 결과를 보병 알림이 덮어쓰던 문제 (2026-11-11)

`VehiclePawn`도 `Pawn`이므로 `Bullet.Impact`의 보병 패치가 차량 피격에 빈 인간형 착탄 범위를 만들었다. VF 차량 어댑터가 장갑과 내부 피해를 계산해 알림을 낸 뒤, 바깥 보병 패치의 finalizer가 물리 장갑층 0개인 `None` 결과와 감소하지 않은 탄 에너지를 같은 차량의 마지막 알림으로 추가했다. 결과 창은 대상별 마지막 알림만 그리므로 실제 계산 결과가 가려졌다.

설치된 1.7.5005에서 `.codex-staging/VehicleScopeRepro20261111`로 재현했다. M3A3 측면의 25 mm AP는 장갑 추적 `Overmatch`, 화면 스냅샷 `None`으로 달랐다. 한 발의 실제 추적에는 고경도강 12 mm와 알루미늄의 RHA 환산 8.04777 mm, 합계 20.0478 mm, De Marre 한계 538.512 m/s, 운동에너지 120,611 → 103,794 J가 기록됐다. 장갑 계산을 생략한 관통은 아니었다.

`HumanoidBallisticImpact.TryBegin`은 인간형 폰에만 범위를 만들도록 제한했다. 차량은 자체 어댑터가 알림을 소유하며, 차량 내부 승무원에 대한 명시적 `ApplyPhysicalHit` 경로는 유지한다. 회귀 검사는 실제 M3A3 25 mm 사격의 마지막 표시 결과와 차량 장갑 추적 결과가 일치하는지 확인한다.

수정 후 `.codex-staging/VehicleScopeMain20261111`은 100 PASS, `.codex-staging/VehicleScopeFixed20261111B`는 455 PASS와 COMPLETE·종료 코드 0이다. 같은 M3A3 사격이 장갑 추적 `Overmatch`, 표시 `Overmatch`로 일치했다. Main·Lobos 차량 Release 빌드 경고·오류 0. 차량 검사 마지막의 제트 점화 사례는 앞선 연소 비교로 손상된 대상을 재사용하지 않고 새 차량을 사용하도록 격리했다. 차량 검사 엔진 로그에는 기존 오류 3종만 남았다.
