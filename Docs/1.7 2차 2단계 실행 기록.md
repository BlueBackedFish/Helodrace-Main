# 1.7 2차 2단계 실행 기록

대상: [2차 수정 계획](헤로드%202차%201.7%20수정%20계획.md)의 T2-04·08·23·25·28·33·35. 엔진: RimWorld 1.7.4995 rev309 / Harmony 3.

2026-11-03: 2단계 7개 항목의 구현·빌드·정적/독립 회귀 검사·실게임 거래·귀환·공격·저장/불러오기 검증을 완료했다.

## 금융·통신 데이터

- 금융 대상은 기존 스탈레르 거래 대상인 민간 LOW·HIGH 두 세력으로 통일했다. 장부 조회·증감·소비, 거래/선물 적립, 통행 보장과 연체 처리, 회사 UI가 같은 분류를 따른다. 회사 서비스와 대출 제공자는 기존 LOW로 유지한다.
- 바닐라와 외부 종족 세력에는 금융 잔액을 쓰거나 금융 통행 보장을 적용할 수 없다. 일반 선물·거래의 외교 우호도는 유지한다.
- 전신 개통비는 250 STL, 서비스 보상은 12.5 금융 우호도다. 확인창·차감·보상은 같은 비용 상수를 사용한다.
- 무전기는 `HD_HelodTechnology_Build` 탭에서 강철 40·기초 전자 부품 4로 건설한다. `HelodWireless`의 선행 연구 `HelodHighElectronics`가 기본작업대의 전자 부품 생산을 이미 해금하므로 새 중간재나 연구를 추가하지 않았다. 청취·교신 오락은 유지한다.
- 무기 상단은 바닐라 리볼버·자동권총·볼트액션 소총·펌프 산탄총을 매입한다. 판매 재고는 늘리지 않으며, 군용 소총류는 이 목록에 포함하지 않는다. 기존 헤로드 무기 취급도 유지한다. 실제 결제 통화는 기존 바닐라 은화이며 스탈레르는 매입 5.25·매각 4.75 은화의 교환 상품이다.

## 석유 상단

- 수정 전 실제 20·260·1,000 포인트 생성에서 상인과 운반동물만 나오고 인간 호위가 없었다. 260 포인트는 상인 비용 45를 차감하면 215가 되며, 전투용 최대 폰 비용 곡선이 호위 상한을 약 61.51로 제한한다. 석유 상단의 정예 호위 130·대장 160은 모두 탈락했다.
- 최소 호위 예산은 상인 비용을 차감한 뒤의 예산으로 적용한다. 석유 상단에는 320을 확보해 160짜리 선택이 있어도 최소 두 호위를 만들 수 있게 했다.
- LOW 상단의 호위 선택에서만 현재 호위 풀의 최대 비용을 허용한다. 남은 총 포인트 검사와 대장 한 명 제한은 유지하며, 전투 그룹의 비용 곡선은 바꾸지 않는다.

## 일반 폰 치환 제거

- 일반 `PlayerColony` 시작 폰의 헤로드 강제 치환을 제거했다. 명시적인 `HD_HelodPlayerColony` 시작과 헤로드 제노타입을 요청한 시나리오는 유지한다.
- 노예·난민·우주 난민의 15% 치환, 일반 방랑자 사건·합류 퀘스트의 치환 패치와 세 확률 설정 필드를 제거했다. 구형 설정이나 호환 경로는 남기지 않았다.
- 헤로드 세력의 정상 생성·외형·성비·제노타입 정책과 명시적으로 활성화하는 감사용 폰 생성은 유지한다. 일반 게임에서 감사 생성 플래그가 꺼져 있는지 검사한다.
- 일반 인간 생성의 의류 후보에서도 기존 착용 권한을 검사한다. 헤로드 전용 의류를 초기 장비로 선택한 뒤 착용을 거절당하는 경고를 막고, 재료·필수 장비의 바닐라 조건은 유지한다.

## 착용 근접무기

- 실제 원본 패치에서 소총과 나이프를 착용한 헤로드의 두 나이프 Verb가 목록에는 한 번씩 있지만, 캐시 선택 가중치가 모두 0이었다. 기존 `AdjustedMeleeSelectionWeight`로 구한 피해량 제곱 기반 최고값을 1.7의 DPS 기반 `FinalSelectionWeight`에 넘겨 카테고리를 잘못 계산했다. 구조체 `VerbEntry`를 리플렉션으로 수정하려던 코드도 목록 원소에 반영되지 않았다.
- 1.7은 이미 착용한 `CompEquippable`의 근접 공격을 수집한다. 중복 수집·가중치 재구성·강제 최솟값을 제거하고 이 경로를 사용한다. 모드 컴포넌트는 실제 착용자를 caster로 제공하고 착용·해제·불러오기 시 연결만 관리한다.
- 새 Unity API 의존성은 추가하지 않았다. 게임의 시뮬레이션·Verb·Job·Scribe 계약을 사용하며 테스트 호스트 종료는 Waylith API로 수행한다.

## 검증 기록

- 수정 전 상단: `.codex-staging/Stage2/baseline-3/Evidence/checks.txt`.
- 원본 나이프의 실제 캐시 가중치 0 및 수정 상단: `.codex-staging/Stage2/baseline-4/Evidence/checks.txt`.
- 전신·금융·대출·연체 241개 검사, 통행 보장 30개 검사, 무전기 56개 검사 통과. 종족 정적 검사도 통과했으며, 기존 검증 fixture의 appendage 출력 인자를 현재 `System.Numerics.Vector3` 계약에 맞췄다.
- 최종 실제 게임 검사: `.codex-staging/Stage2/final-1/Evidence/checks.txt`. 460개 `PASS`, `COMPLETE`, `FAIL` 없음. `engine.log`의 실제 ERROR 레벨 행은 기존 미설치 WorkshopItem 3781143823 한 건뿐이다. 새 생산·거래·예약·Job·전투 예외와 의류 착용 거절 경고는 없다. 기존 의존성·번역·native 종료 할당 경고까지 모두 해소했다는 뜻은 아니다.
- 전신 개통 시 실제 맵의 돈이 정확히 250 줄고 금융 우호도가 12.5 늘었다. 재요청에는 추가 차감이 없었다. 일반 세력의 선물 우호도는 증가하되 금융 잔액은 생기지 않았고, LOW의 선물 적립과 실제 저장 후 잔액 보존을 확인했다.
- 20 포인트 직접 생성 10회에서 운반동물과 최소 두 호위를 확인했다. 실제 전신·적대 무전기·무작위 방문 경로에서는 상품을 실은 상단이 도착했고, 디젤을 각각 실제 구매했다. 도착 사건은 바닐라가 포인트를 다시 결정하므로 입력 20을 실제 호위 예산으로 보고하지 않는다. 무작위 방문 4회와 무기 상단을 포함한 모든 방문 상단은 강제 제거 없이 62,000틱 이내에 맵을 살아서 떠났다.
- 적대 무전기 상단은 `LordJob_FinancialCaravan`, 통행 보장 활성, 외교 우호도 -100을 동시에 유지했다. 거래 후에도 외교 적대가 유지됐다. 무기 상단에는 바닐라 비군용 총기 4종과 기존 헤로드 총기 매각 목록·양수 가격이 나타났고 실제 매각 뒤 기지 재고에서 빠졌다. 군용 돌격소총은 추가 매입 대상에 포함되지 않았다.
- 일반 시작·노예·난민 요청 300회와 실제 인간 생성, 명시적인 헤로드/시나리오 생성, 초기 의류 후보 제한, 감사 생성 비활성 상태를 확인했다.
- 소총을 든 헤로드의 나이프는 자동 선택 200회 중 161회 선택됐으며 다른 공격도 선택됐다. 실제 근접 공격은 벽에 피해 11과 쿨다운을 발생시켰다. 모든 후보 가중치가 1.7 DPS 분류와 일치했다. 해제·재착용·실제 저장/불러오기·교체·다른 착용자에게 양도한 뒤 중복/남은 공격이 없었다.
- 실제 저장 파일은 같은 실행의 `Profile/Saves/Stage2Roundtrip.rws`다. 제품 DLL에는 검사 GameComponent와 제거한 방랑자 치환/구형 가중치 설정이 없다. `launcher.json`에 실제 호스트와 DLL 해시가 있다. 종료 수집 시 핸들이 없어 종료 코드는 `null`이며 0으로 간주하지 않았다.
- 실행 절차와 fixture 범위: [Stage2 검사 설명](../Source/Tests/Stage2/README.md).
