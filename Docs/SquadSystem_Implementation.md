# 분대·지휘 체계 구현 현황

`SquadSystem.md`의 조직·편제·승계 MVP를 구현했다. 18장의 완편 스폰 규칙이 앞부분의 불완전 편제 예시보다 우선한다. 조직된 습격대에는 전술 계획과 기본적인 이동·투척·파워커터 진입 실행이 연결되어 있다. 외부 지원과 완전한 통신·CQB 행동은 별도 작업이다.

## 적용 범위

- `HD_HelodCivilLowFaction`의 습격용 Combat 생성에 적용한다. 민간인·상인·정착지 인원은 기존 생성 경로를 사용한다.
- `FactionOrganizationExtension`이 교리를 선택한다. 조직 트리와 슬롯을 먼저 만들고 각 슬롯의 무기별 대전기 PawnKind를 생성한다.
- `GeneratePawnKindsExample`도 같은 계획을 사용한다. 전술 실행 계층이 집결·투척·돌입 명령을 내린 뒤에는 기존 Lord가 전투를 이어 간다.
- 다른 세력은 동일한 확장과 Def를 추가해 사용할 수 있다. 현대식 화력조와 더 깊은 트리도 같은 자료 구조로 표현할 수 있다. 현재 활성 교리는 대전기 하나다.

## 기본 대전기 편제

| 편제 | 인원 | 비용 | 구성 |
| --- | ---: | ---: | --- |
| 순찰조 | 6 | 510 | 카빈 분대장, 소총 부분대장, HAR, 소총수 3 |
| 소총분대 | 12 | 1,000 | SMG 분대장, 카빈 부분대장, HAR, 소총수 9 |
| 기관총조 | 3 | 300 | M1919A6, 카빈 2 |
| 바주카조 | 2 | 235 | 바주카 사수, 별도 바주카 탄약수 |
| 저격조 | 2 | 190 | 저격수, 소총수 |
| 증강 소총소대 | 45 | 3,885 | 카빈 지휘부 2, 소총분대 3, 기관총조·바주카조·저격조 각 1 |

모든 생성 인원은 대전기 무기와 대전기 의류를 쓰는 기존 `HD_GW_*` PawnKind다. 지휘 직책 때문에 PawnKind나 무기를 바꾸지 않는다. 지원조는 소대 하위 편제로 생성하며, 기본 루트 후보는 소대·분대·순찰조다. 장비 운용 및 바주카 승무원 행동은 이번 조직 시스템에서 변경하지 않는다.

비용은 PawnKind의 `combatPower`를 합산한다. 이는 보통 장비 비용을 이미 포함하므로 자동으로 시장가를 더하지 않는다. 슬롯의 `equipmentPointCost`, `specialistPointCost`로 추가 비용을 설정할 수 있다. 모든 인원 제한은 슬롯에서 계산한 정원과 같아야 한다.

선택은 `selectionPriority`가 높은 편제, 같은 우선순위에서는 비용이 큰 편제부터 가능한 완편 단위를 반복해서 선택한다. 전역 최적 비용 탐색이 아니라 교리의 우선순위에 따른 선택이다. 허용 초과는 원래 전체 예산의 10%를 한 번 적용하며 편제마다 누적하지 않는다. 가장 작은 편제도 허용 범위 안에서 살 수 없으면 폰을 생성하지 않으며, 일반 생성으로 불완전 편제를 만들지 않는다.

예: 500pt는 6명/510pt, 1,300pt는 12명/1,000pt + 지원 300pt, 1,400pt는 18명/1,510pt로 계획한다. 문서의 520pt 분대는 예시이며 실제 기본값과 다르다.

## 역할·지휘권

- 전투 역할, 원래 지휘 역할, 지휘 자격, 대행 직책을 분리한다. 한 폰은 하위 조직의 원래 직책을 유지하면서 여러 상위 조직을 대행할 수 있다.
- 원래 지휘관이 사망·다운·정신이상·포로화·노예화·세력 변경 등으로 지휘할 수 없으면 손실 상태를 기록한다. 90틱 혼란 후 후임자가 승계하고, 300틱 동안 효율 70%를 거쳐 정상화한다.
- 명시적 승계 슬롯/직책 → 자격 있는 하위 지휘관 → 자격 있는 대원 → 숙련 대원 → 나머지 순으로 선정한다. 동률은 권한·역할 우선순위·서열·숙련·영구 폰 ID로 해결한다.
- 하위 지휘관의 승계 순서는 `ChildFormationSlot.successionPriority`로 정의한다. 원래 상급자가 돌아오면 지휘권을 반환한다. 후임도 손실되면 새 혼란 시간을 적용한다.
- 승계 후보는 해당 조직의 하위 트리 안에서만 찾는다. 상급 지휘권 손실로 하위 조직의 자체 지휘를 중지시키지 않는다.
- 지휘 상태는 15틱 간격으로 갱신한다. 지휘 효율·지연·상급망 가용성은 자료로만 제공하며 폰 행동에는 적용하지 않는다.

## 저장·API

GameComponent가 조직과 그룹을 Deep 저장하고, 폰·지휘관은 참조로 저장한다. 조직 ID, 그룹 ID, 부모 ID, 역할, 승계 순서, 지휘 상태, 회복 시각과 지원 잔액을 유지하며 로드 후 트리와 조회 사전을 복구한다. PawnOrganizationComponent는 폰의 소속 ID와 조회 인터페이스를 제공한다.

`OrganizationAPI`: `GetOrganization`, `GetGroup`, `GetCommander`, `GetEffectiveCommander`, `GetSubordinates`, `GetParentGroup`, `GetChildGroups`, `GetSupportPoints`.

`CombatOrganization`: `CanSpendSupportPoints`, `TrySpendSupportPoints`, `RefundSupportPoints`. 음수·NaN·무한대 금액을 거부하고 환불은 최초 잔여 예산을 넘지 않는다. 지원의 실제 소비자는 아직 구현하지 않았다.

## 검증과 게임 내 확인

```powershell
dotnet run --project Source/Tests/SquadSystem/SquadSystem.Tests.csproj -- .
powershell -File Source/Verify-SquadSystem.ps1 -PatchSmokeTest
dotnet build Source/Helodrace/Helodrace.csproj --no-restore -p:IntermediateOutputPath=obj/SquadSystem/
```

로직 테스트는 실제 생산 코드와 XML을 사용하며 게임 경계만 스텁으로 대체한다. 완편/비용/허용 범위, 가변 깊이, 명시·계층 승계, 반복 손실, 원래 지휘관 복귀, 역할 보존, 지원 포인트, Scribe 호출을 흉내 낸 저장·복원 경로를 검증한다. 이 테스트는 실제 게임의 Scribe 저장 파일이나 Unity 동작을 대신하지 않는다.

게임 개발자 메뉴의 `Helodrace/Organization`에서 편제 예산 미리보기, 1,400pt 조직 스폰, 선택 폰 조직 검사, 전체 조직 목록을 확인할 수 있다. 개발자 모드에서 소속 폰의 인스펙터와 `전투 조직` 버튼에도 소속·역할·지휘관·승계가 표시된다.

개발자 `Settings → View → 습격 조직 정보`를 켜면 조직에 소속된 폰 아래에 조직/그룹, 전투·지휘·대행 역할, 현재 지휘관과 지휘 상태가 세 줄로 표시된다. 기본값은 꺼짐이며 다른 디버그 View 설정처럼 세션 동안 유지한다. 안개에 가려진 폰과 다른 맵의 폰에는 표시하지 않는다.

게임 내 확인 절차:

1. 조직을 스폰하고 모든 인원의 대전기 장비와 각 그룹 정원을 확인한다. O
2. 분대장을 다운시켜 혼란 후 부분대장이 승계하고 무기·원래 역할을 유지하는지 확인한다. O
3. 부분대장도 다운시켜 다음 후보가 승계하는지 확인하고, 원래 분대장을 회복시켜 지휘권 반환을 확인한다. O
4. 승계 대기 또는 대행 상태에서 저장·로드하고 조직 ID, 역할, 지휘관, 회복 시각, 지원 잔액을 비교한다.
5. 소대 지휘부 손실 시 하위 분대의 지휘관이 유지되고 정해진 분대 순서로 상급 직책을 승계하는지 확인한다.

실제 게임 내 스폰 및 저장·로드 확인은 별도로 필요하다.
