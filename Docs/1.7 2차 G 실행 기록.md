# 1.7 2차 G 실행 기록

대상은 T2-05 전력·기계 부하와 T2-11 발전량 설정이다. 사용자 지시에 따라 T2-15 석탄과 T2-31 유전 공간·추출 효율은 제외한다.

## 기계 동력 단위 정리 — 완료

기계망은 W의 공급·요구량을 계산한다. 기존 `requireTorque`·`GridTorqueDemanded`·`TorqueFulfillmentRatio`를 `mechanicalPowerRequired`·`GridPowerDemanded`·`PowerFulfillmentRatio`로 바꾸고 미사용 `powerConsumed`를 제거했다. 별칭은 남기지 않았다. 정격 토크는 `T = P × 60 / (2π × RPM)`으로 별도 계산해 N·m와 해당 RPM을 표시한다. 예: 선반 250 W·250 RPM은 약 9.55 N·m다. 전기 W와 기계 W는 발전기·전동기의 변환 손실을 거쳐 연결하며 토크 수치를 W와 직접 더하지 않는다. 차원 계산 검사와 제품 빌드를 통과했다. 커밋 `0faac403`.

## T2-11 발전량 설정 — 완료

- 기본 목표는 300 W, 메뉴는 0·300·600·1200·1800·2400·3600·4800·6000·8000 W다. 0은 축 부하도 0으로 만든다. 목표는 현재 저장과 함께 유지된다.
- 정격 기계 입력 10000 W, 저부하 효율 60%, 정격 효율 80%다. 기존 계단식 효율을 연속식 `효율 = 0.6 + 0.2 × 입력/10000`으로 정리하고, 목표 전기 출력을 만족하는 기계 입력을 이차식으로 역산한다. 출력만 제한하고 축 부하를 고정하지 않는다. 과부하에서는 실제 배정받은 입력만 변환하며 정격과 목표 출력을 넘지 않는다.
- 동력원 스위치 변경을 즉시 기계망에 반영하고, 포장되거나 고장난 동력원은 공급원에서 제외한다. 주기 갱신은 경과 틱 기준으로 처리하며 망을 다시 구성했을 때 바로 갱신한다. 기관의 시간당 연료 소비량을 자동 조절하는 기능은 아니다.
- `Source/Tests/PowerBudgetMath`에서 W·RPM·N·m 관계, 출력 역산, 에너지 보존, 정격 상한과 잘못된 입력을 검사했다. `generator-valid-layout/Evidence/checks.txt`는 실제 열 개 출력·공유 축 부하·전력망의 램프 공급·메뉴 콜백·무부하·과부하·동력원 정지·실제 저장/불러오기와 출력 재개가 모두 `COMPLETE`, `FAIL` 없음이다.
- 검사 배치에서 발전기 아래 전선을 직접 생성하면 엔진의 정상 로드 규칙이 발전기를 포장한다. 인접 전선으로 고친 배치에서 저장 회귀를 통과했다. 이를 제품의 저장값 또는 망 등록 오류로 계산하지 않는다. 최종 수집 로그의 ERROR는 기존 미설치 WorkshopItem 한 건뿐이다.
- 게임 명령 아이콘 경계는 [native 경계 목록](1.7%20native%20경계%20목록.md)에 기록했다. 내부 수학에 Unity 타입·API를 추가하지 않았다.

## T2-05 전력·기계 부하 — 완료

- [전력 기준과 변경표](1.7%202차%20G%20전력%20기준.md)에 설비 36종, 동력 작업대 조합법 69행, 가동률과 4인/8인 일일 수지를 연결했다. 전기 생산 설비 12종을 시대별 부하로 정리하고 대기 입력 10%·실제 제작 100%를 적용했다.
- 소형 증기기관은 정격/최대 1500/1800 W로 조정했다. 히트펌프는 40 HU/s에서 200 W, 기본 목표 −5°C다. 대형·디젤기관의 출력과 모든 기관의 연료 소비율·용량은 유지했다. 시추기·펌프와 석탄 경로는 변경하지 않았다.
- 전기 작업대를 커스텀 `CompPowerTrader` 하위 타입으로 바꾸면 현재 엔진의 정확한 타입 판정에서 자동 연결 대상이 빠진다. 네이티브 컴포넌트를 유지하고 별도 제어 컴포넌트로 고쳤으며 12개 작업대의 연결 계약을 실제 Def 검사에 포함했다. 전원 재시동에 필요한 예상 소비량도 유지한다. 반응기 `Building_WorkTable_HeatPush.UsedThisTick`가 기본 작업 콜백을 호출하는 현재 엔진 계약을 확인했다.
- 최종 증거는 `.codex-staging/PowerStageG/final-full/Evidence/checks.txt`의 `COMPLETE`, `FAIL` 없음이다. 새 게임의 열 개 발전량·메뉴·공유 부하·과부하·정지·실제 저장/불러오기를 다시 통과한 뒤, 4인과 8인을 각각 정확히 60,000틱 운전했다. 모든 배치의 자동 제작과 정량 산출, 작업/대기 전환, 냉장·조명·통신·CNC 전력, 실제 운반 담당의 자동 보충을 통과했다.
- 4인은 축 피크 약 1291.93 W, 목재 약 50.00/일·보충 7회다. 8인은 축 피크 약 4153.24 W, 숯 약 119.93/일·보충 1회다. 초기 냉각 이후 냉장실 최고 온도는 약 −3.30°C였다. 두 기지 모두 정격 안에서 운전했으며 상세 에너지·가동률은 CSV에 보존했다.
- 검사 루프 밖의 자동 진행 틱이 연료 계측에 섞이지 않도록 프레임마다 일시정지를 유지하고 실제 게임 시계 차이도 검사했다. 앞선 실패 실행의 약 0.8% 초과 계측을 정상 연료 소비로 채택하지 않았다. 초기 냉각기의 과냉각도 기존 목표 온도를 −5°C로 조정해 해결했다.
- 제품·실게임 검사 빌드와 수학 검사, 레시피 배치 검사, XML 496개 파싱, 기존 1단계 생산 검사 빌드를 통과했다. 최종 수집 로그의 ERROR는 기존 미설치 WorkshopItem 한 건뿐이며 새로운 연결·제작·저장 예외는 없다. 격리된 Main·Blancas·Harmony 기준이며 다른 모드 구성의 전체 호환 검사는 아니다.

요청한 T2-05·T2-11은 완료했다. T2-15·T2-31은 미완료 상태로 남긴다.
