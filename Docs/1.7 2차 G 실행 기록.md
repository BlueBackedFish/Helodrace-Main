# 1.7 2차 G 실행 기록

대상은 T2-05 전력·기계 부하와 T2-11 발전량 설정이다. 사용자 지시에 따라 T2-15 석탄과 T2-31 유전 공간·추출 효율은 제외한다.

## 기계 동력 단위 정리 — 완료

기계망은 W의 공급·요구량을 계산한다. 기존 `requireTorque`·`GridTorqueDemanded`·`TorqueFulfillmentRatio`를 `mechanicalPowerRequired`·`GridPowerDemanded`·`PowerFulfillmentRatio`로 바꾸고 미사용 `powerConsumed`를 제거했다. 별칭은 남기지 않았다. 정격 토크는 `T = P × 60 / (2π × RPM)`으로 별도 계산해 N·m와 해당 RPM을 표시한다. 예: 선반 250 W·250 RPM은 약 9.55 N·m다. 전기 W와 기계 W는 발전기·전동기의 변환 손실을 거쳐 연결하며 토크 수치를 W와 직접 더하지 않는다. 차원 계산 검사와 제품 빌드를 통과했다. 커밋 `0faac403`.

## T2-11 발전량 설정 — 완료

- 기본 목표는 300 W, 메뉴는 0·300·600·1200·1800·2400·3600·4800·6000·8000 W다. 0은 축 부하도 0으로 만든다. 목표는 현재 저장과 함께 유지된다.
- 정격 기계 입력 10000 W, 저부하 효율 60%, 정격 효율 80%다. 기존 계단식 효율을 연속식 `효율 = 0.6 + 0.2 × 입력/10000`으로 정리하고, 목표 전기 출력을 만족하는 기계 입력을 이차식으로 역산한다. 출력만 제한하고 축 부하를 고정하지 않는다. 과부하에서는 실제 배정받은 입력만 변환하며 정격과 목표 출력을 넘지 않는다.
- 동력원 스위치 변경을 즉시 기계망에 반영하고, 포장되거나 고장난 동력원은 공급원에서 제외한다. 주기 갱신은 경과 틱 기준으로 처리하며 망을 다시 구성했을 때 바로 갱신한다. 기관의 시간당 연료 소비량을 자동 조절하는 기능은 아니다.
- `Source/Tests/PowerBudgetMath`에서 W·RPM·N·m 관계, 출력 역산, 에너지 보존, 정격 상한과 잘못된 입력을 검사했다. `generator-valid-layout/Evidence/checks.txt`는 실제 열 개 출력·공유 축 부하·전력망의 램프 공급·메뉴 콜백·무부하·과부하·동력원 정지·실제 저장/불러오기와 출력 재개가 모두 `COMPLETE`, `FAIL` 없음이다.
- 검사 배치에서 발전기 아래 전선을 직접 생성하면 엔진의 정상 로드 규칙이 발전기를 포장한다. 인접 전선으로 고친 배치에서 저장 회귀를 통과했다. 이를 제품의 저장값 또는 망 등록 오류로 계산하지 않는다. 최종 수집 로그의 ERROR는 기존 미설치 WorkshopItem 한 건뿐이다.
- 게임 명령 아이콘 경계는 [native 경계 목록](1.7%20native%20경계%20목록.md)에 기록했다. 내부 수학에 Unity 타입·API를 추가하지 않았다.

## T2-05 전력·기계 부하 — 진행 중

4인/8인 기지의 냉장·필수 생산 부하, 설비 대기 부하, 단위 제품 에너지 표와 실제 일일 수지를 검증한 뒤 완료 처리한다. 석탄과 유전 산출량·압력·점유 면적은 이번 수치 변경 대상에 넣지 않는다.
