# 텍스트·연구 내용 검수 규칙

## 검사 범위와 판정

한국어를 기준으로 문제를 판정하고, 확정한 수정 방향을 대응 영어 원문에도 적용한다. 아이템 외에 연구, 건물, 제작법, 시스템 안내도 살핀다. 검수 단계에서는 게임 정의나 번역을 수정하지 않는다. 원문, 문제 구간, 이유, 보존할 정보, 개선 방향, 출처와 사용자 검수 의견을 함께 기록한다.

`PawnKindDef`와 군용 태블릿은 제외한다. 인용문 때문에 길어진 설명은 길이 검사에서 제외한다. 기능 툴팁·계약서·상태 설명은 수치와 사용법이 필요한 자리이므로, 아이템 설명과 같은 잣대로 삭제 대상으로 삼지 않는다.

기존 상세 기준은 [DictionaryAndTextureRefining.md](DictionaryAndTextureRefining.md#작업-2-재작성-필요-텍스트-색출)를 따른다. 특정 단어가 있거나 문장이 매끄럽다는 이유로 AI 문체라고 단정하지 않는다. 자동 탐지는 후보 추출이며 최종 판정은 문맥을 대조한다.

## 텍스트

- 같은 의미 반복, 모델명만 바꾼 범용 문장, 낮은 정보 밀도, 광고성 수식과 불필요한 장단점 나열을 검사한다.
- 세계관 속 사물 설명에 게임 수치, 구현 방식, 편집기, 개발 상태, 상세 조작 순서가 끼어 있는지 확인한다. 필요한 조작 정보는 별도 도움말로 옮기는 방향을 기록한다.
- 기술 원리, 물건의 정체성, 실제 용도와 설정은 보존한다. 자연스러운 비교나 짧은 기술 설명을 일괄 삭제하지 않는다.
- 설명의 장비명·해금 목록을 실제 XML·코드와 대조한다. 오래된 목록, 없는 장비, 이름과 기능이 다른 설명은 문체와 별도의 내용 오류로 기록한다.
- 현실 고유명사는 실제 가상명 치환 근거가 있을 때만 지적한다. 일반 제식명·탄약 규격·기술명까지 자동 치환하지 않는다. 아이템과 제작법의 명칭도 교차 확인한다.

## 연구 이름

- 연구 64개 전체의 한국어·영어 이름과 기술 내용, 인접 계보의 제목을 함께 대조한다. 비교 대상 수는 연구 추가·삭제 때 갱신한다.
- 현재의 주된 제목 방식은 기술의 이미지·성과·역사적 의미를 짧게 표현하는 방식이다. 예: `병 속의 번개`, `공기에서 빵을`, `천분의 일 인치를 향하여`, `사격과 기동`.
- 후에 추가된 `시대/등급 + 장비 종류` 같은 분류명, 사전 표제어, 내부 작업용 제목이 이 제목군과 어긋나는지 검사한다.
- `시너지`처럼 홍보 문구로 읽히는 말, 번역투, 어색한 단계 표현, 의미가 불분명한 조어, 띄어쓰기도 별도로 확인한다.
- 기술명을 직접 쓴다는 이유만으로 오류로 판정하지 않는다. `기계공학 입문` 같은 계통 시작점이나 `수치제어` 같은 정확한 기술명은 역할을 고려해 유지 또는 검토로 구분한다. 모든 제목을 비유형으로 강제하지 않는다.
- 제목이 해금 대상이나 기술 범위를 잘못 암시하면 문체보다 의미 정확성을 우선한다. 개명 예시는 검수용 제안이며 자동 적용하지 않는다.

## 아이템·연구 배치

- 현실 기술의 발전 순서에 비해 이르거나 늦은 해금, 기본형보다 빠른 파생형, 기술적 인과가 약한 필수 선행 조건을 기록한다. 화면 좌표만으로 연대를 판정하지 않는다.
- 본체, 기본 프리셋, 부품, 탄약의 연구 조건을 대조한다. 공용 부품은 기본 프리셋에서 가장 먼저 사용하는 총기의 연구 시점을 기준으로 한다. 보유한 물건의 사용·전리품 획득과 생산 연구는 구분한다.
- 직접 연구뿐 아니라 제작법, 제작대, 재료·기반 물건, XML 상속, 부품 컴포넌트의 `requiredResearch`, 코드상 획득 경로를 추적한다. `Inherit="False"`와 `IsNull="True"`로 제거한 부모 제작법을 되살려 계산하지 않는다.
- 대체 제작법과 제작대는 각각 별도 경로다. 서로 다른 경로의 연구를 무조건 AND로 합치지 않는다. 바닐라·헤로드 OR 연결의 연쇄 완료도 고려한다.
- 바닐라 전기=진공관 이후, 기계 가공=수치제어 이후, 미소전자공학=실리콘 혁명 이후라는 현재 대응 기준을 적용한다. 연결 정의는 [LinkedResearch.md](LinkedResearch.md)를 참조한다.
- 개발 전용·효과용·투사체·터렛 내부 총기, 화폐, 원료, 거래·서비스 지급품은 직접 연구가 없다는 이유만으로 누락 처리하지 않는다. 획득 경로가 미확인인 경우 `확인 필요`로 남긴다.
- 실제 런타임에서 확인하지 않은 획득·생성 동작은 확정적으로 서술하지 않는다. XML 선언 불일치와 실제 우회 재현을 구분한다.
