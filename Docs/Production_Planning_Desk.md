# 생산 계획대

헤로드 기술 건설 메뉴에서 개척 정신 연구 후 50 소재로 건설한다. 기존 기초 작업대 그림에 색을 달리해 사용한다. 설치 후 **생산 계획** 명령으로 창을 연다. 계획대 자체는 전담 작업자나 전력이 필요하지 않다.

## 대상 품목

`HD_`로 시작하는 보관 가능한 모든 물품(`ProductionCatalog.IsHelodItem`)을 목록에 표시한다. 포탑 장착 총(떨어뜨리면 사라짐)과 보관 분류가 없는 일시적 물건(날아가는 클레이 피전, 조명탄 표적, 분류 없는 모듈 부품)은 제외한다. 2026-11-06 실제 1.7 게임 기준 199종을 표시한다.

| 구분 | 수 | 처리 |
|---|---|---|
| 자동 계획 가능 | 165 | 목표 재고 입력 칸 표시 |
| 수동 전용 | 1 (`HD_AromaticBaseOil`) | 제작법이 여러 산출물을 낸다. 트리만 표시 |
| 제작법 없음 | 33 | 채굴·수확·거래 등으로 얻는다. 목표 칸 대신 — 표시 |

자동 후보는 산출물이 하나이고 `Helodrace.ProductionPlanningExcluded` 확장이 없는 모든 제작법이다. 일반 부품으로 바꾸는 비상 조합법 3종과 그레이록 M1861→M1873 개조에는 이 확장을 붙여 자동 선택하지 않는다. 같은 제작법을 지원하는 후대 기계도 사용한다. 연구·설비·동력과 재료를 만족하는 작업대 중 대기 작업이 적고 작업 속도가 높은 곳을 고른다.

## 자동 생산

모든 계획대는 맵 하나의 목표를 공유한다. 현재 재고와 수동·자동 예정 생산을 뺀 부족량에 맞는 가장 큰 배치(예: 10·5·1개)를 등록한다. 모든 배치가 부족량보다 크면 가장 작은 배치를 등록한다. 품목마다 동시에 한 자동 배치만 유지한다. 수동 ‘재고까지 제작’의 남은 생산량은 해당 기본 작업의 제품 카운터와 설정을 따른다. 재고는 금지되지 않은 바닥 물품과 플레이어 폰의 인벤토리·운반품을 센다. 방문 상인의 인벤토리는 제외한다.

기존 작업의 재료 요구량을 먼저 예산에서 빼고, 여러 자동 작업이 같은 자재를 중복 배정받지 않게 한다. 고정 재료는 해당 물품을, 여러 물품을 허용하는 재료는 허용된 물품 중 재고가 가장 많은 한 종을 사용한다. 미완성품에 이미 들어간 첫 배치 재료는 다시 예산에서 빼지 않는다. 실제 재료 예약·제작·운반은 기본 게임 작업 AI가 수행한다.

목표 0은 해당 품목의 자동 생산을 끈다. 시작 전 자동 작업은 더 이상 필요 없거나, 더 작은 배치를 지금 등록할 수 있는데 목표를 넘기면 지운다. 작업자가 이미 시작한 배치는 미완성품을 보존하고 마칠 수 있으므로 그 경우 한 배치 분량의 초과 생산이 가능하다. 자동 생산을 끄거나 마지막 계획대를 철거하면 소유한 작업을 일시 중지한다. 다시 설치하거나 켜면 같은 작업을 이어간다. 수동 작업은 이 제어로 중지·삭제하지 않는다.

**현재 / 예정 / 누적**은 각각 소유 재고, 활성 기본 제작 작업의 예정 산출, 계획대가 등록한 작업의 실제 완료 수량이다. 수동 ‘재고까지 제작’의 기본 자원 카운터는 저장 구역에 들어간 물품을 세므로 해당 수동 작업에는 저장 구역도 필요하다. 수동 제작·거래로 들어온 물건을 누적 생산에 더하지 않는다. 진행 중인 작업·소유권·목표·완료 집계와 미완성품은 저장/로드로 유지한다. 목표와 누적이 모두 0인 품목은 저장하지 않는다.

## 창

왼쪽은 분류별로 접을 수 있는 품목 목록이다. 아이콘·이름·현재·예정·누적·목표를 표시하고, 검색과 ‘계획한 품목만 표시’로 거른다. 품목을 누르면 오른쪽에 생산 트리를 연다.

오른쪽 트리는 품목 → 대체 제작법 → 재료 → 하위 재료 순서로 원자재까지 내려간다. 각 행은 행 전체를 눌러 펼치거나 접고, 재료 행의 **열기**는 그 재료를 새 기준으로 연다. **모두 펼치기**·**모두 접기**를 제공한다.

- 수량은 선택한 품목 1개 기준이다. 제작법 행은 배치당 산출과 필요한 배치 수, 재료 행은 필요한 개수와 현재 재고를 표시한다.
- 제작법 행 둘째 줄에 작업대와 `LinkedFacilityRecipes.RequiredFacilitiesText`의 필요 설비를 표시한다. 자동 계획에서 제외한 제작법은 ‘수동 전용’으로 표시한다.
- 여러 물품을 허용하는 재료는 ‘다음 중 하나’ 행으로 묶고, 펼치면 허용 물품을 최대 12종까지 보여 준다. ‘모두 펼치기’는 이 묶음을 펼치지 않는다.
- 같은 가지의 위쪽에 이미 있는 품목은 ‘순환’으로 표시하고 다시 펼치지 않는다. 깊이는 16단계, 표시 행은 2,500행으로 제한한다.

## 성능

창을 열거나 사용할 때의 지연은 그리기마다 각 목표의 재고·예정 수량을 구하려고 맵의 모든 물건과 모든 작업을 다시 훑던 것이 원인이었다. 이 비용은 목표 수에 비례하므로 모든 헤로드 물품으로 확장하면 수십 배가 된다. 지금은 다음과 같이 나눈다.

- Def에서 나오는 품목·제작법·재료·작업대·설비 문자열은 `ProductionCatalog`가 처음 사용할 때 한 번 만든다.
- 맵 재고와 예정 수량은 `HaulableEver` 목록과 작업대 작업을 한 번 훑어 사전에 담는다. 60틱 또는 실시간 0.5초가 지나야(정지 중에는 2초) 다시 센다. 계획 갱신은 항상 새로 센다.
- 목록과 트리는 입력이 바뀔 때만 평탄화하고, 화면에 보이는 행만 그린다.
- 250틱 갱신은 목표나 자동 작업이 없으면 건너뛴다.

실제 1.7 게임 측정(`Start-Checks.ps1 -Perf`, 물품 약 4,000더미·작업대 7개):

| 창 그리기 평균 / p95 / 최대 | 5.27 / 9.74 / 29.36 ms | 0.39 / 0.47 / 11.73 ms (첫 프레임) |
| 계획 갱신 평균 / 최대 | 5.40 / 20.85 ms | 0.79 / 6.03 ms |
| 165개 목표 계획 갱신 평균 / 최대 | — | 2.10 / 10.02 ms |
| 1,513행 전체 펼친 트리 그리기 평균 / p95 | — | 0.71 / 0.91 ms |
| 창 첫 열기(카탈로그 생성 포함) | 0.67 ms | 19.10 ms (한 번만) |
