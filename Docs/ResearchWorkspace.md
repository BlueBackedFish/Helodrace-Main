# 헬로드 연구창

기본 연구창의 헬로드 탭 오른쪽에 전용 캔버스를 표시한다. 왼쪽의 바닐라 연구
설명·연구 시작 패널과 다른 연구 탭은 유지한다. 연구 데이터는 기존
`ResearchProjectDef`, 연구 비용·완료 상태는 게임의 `ResearchManager`를 사용한다.

## 기능과 조작

| 기능 | 동작 |
| --- | --- |
| 트리와 섹션 구분 | 기초, 기계·동력, 전기·통신, 화학·의약, 화기·포병, 방호·장비의 여섯 섹션을 두 갈래의 가로 플로우로 배치하고 배경색과 제목으로 구분한다. 섹션 제목으로 접고 펼치며, 상단 메뉴로 이동한다. |
| 섹션 내부 정렬 | 섹션 내부의 선행 관계 깊이에 따라 열을 정하고 분기는 겹치지 않는 행에 배치한다. 각 열의 빈 행은 압축하고 섹션별 행·열 간격을 통일한다. 노드 높이는 현재 게임 글꼴의 실제 제목 높이로 계산한다. 추가 모드의 미분류 노드는 기타·확장 연구에 표시한다. |
| 선 교차 | 선택 노드와 연결된 선 → 큐의 선 → 완료된 선 → 나머지 선 순으로 위에 표시한다. 같은 우선순위는 DefName 순서로 고정한다. 아래 선의 교차 구간은 끊고, 위 선은 밝기·채도를 높인다. 직각 경로는 모든 노드 본문과 섹션 제목을 피한다. 선은 배율을 반영한 픽셀 좌표의 사각형으로 그려 축소 시 회전 텍스처의 선 끝 돌출을 없앤다. |
| 연구 큐 | 노드의 +로 목표를 추가한다. 미완료 선행 연구는 중복 없이 자동으로 앞에 삽입한다. 목표 순서 변경·삭제·일시 정지·재개를 지원한다. 목표와 정지 상태는 저장된다. |
| 개방 파츠 | P 배지가 있는 연구를 선택하면 `CompProperties_ModularWeaponNode.requiredResearch`를 통해 개방되는 파츠를 별도 표시한다. 사용 가능, 선택 연구 완료 시 사용 가능, 다른 연구도 필요함을 구분한다. 파츠 버튼은 정보 카드를 연다. |
| OR 연구 | 관련 연결의 양쪽 연구를 클릭 가능한 GUI 카드로 표시하고 양방향 OR 연결선으로 잇는다. 복수 조건은 AND 그룹으로 묶는다. 바닐라·헬로드 구분, 선택·완료·함께 완료 예정 상태를 표시한다. 선택 연구를 완료했을 때 실제로 함께 완료될 연구를 선행 연구·연쇄 연결까지 포함해 미리 보여 준다. 예측은 실제 연구 상태를 변경하지 않는다. |

- 노드 클릭: 왼쪽의 기본 연구 상세 패널과 선택 상태를 동기화한다.
- 빈 공간에서 왼쪽 마우스 드래그 또는 가운데 마우스 드래그: 캔버스 이동. 노드·추가 버튼·섹션 제목의 클릭은 그대로 작동한다.
- 왼쪽 아래 전체 배치도 클릭: 해당 위치로 이동. 배치도에는 섹션 색, 선택 노드와 현재 보이는 영역을 표시한다. 스크롤바 이동도 가능하다.
- Ctrl + 휠 또는 상단 +/-: 확대·축소. 배율 버튼: 100% 복원.
- 검색어와 찾기 버튼: 해당 노드를 선택하고 그 위치로 이동한다.
- 다른 탭의 연구를 OR 목록·큐에서 선택하면 기본 연구창의 해당 탭으로 이동한다.

## 큐의 진행 규칙

큐에는 사용자가 선택한 목표만 저장한다. 표시되는 실행 순서는 목표에서 현재
미완료 선행 연구를 계산한 결과다. 여러 목표가 공유하는 선행 연구는 한 번만
포함하고, 목표를 삭제해도 다른 목표에 필요한 선행 연구는 유지한다.

현재 연구는 중간에 순서만 변경했다고 강제로 교체하지 않는다. 큐가 시작한
연구는 일시 정지하거나 더 이상 어떤 목표에도 필요하지 않게 되면 멈춘다.
사용자가 별도로 직접 선택한 연구는 종료될 때까지 유지한다. 연구대·기술 증거 등
게임의 `CanStartNow` 조건을 충족하지 못한 다음 항목은 대기하며 우회하지 않는다.
OR 완료로 끝난 목표와 선행 연구는 다음 갱신 때 제거된다.

순환 선행 관계를 가진 모드 연구는 추가를 거부한다. 저장된 큐에서 순환이
발견되면 큐만 일시 정지하고 경고를 기록한다.

## OR와 파츠 표시의 의미

OR는 [연구 연결 목록](LinkedResearch.md)의 양방향 완료 공유 기능이다. 일반
선행 연구 그래프에 양방향 화살표를 넣지 않는다. 각 측 내부는 모두 필요한 AND
그룹이며, 선택한 연구 하나만으로 그룹이 충족되지 않으면 반대쪽을 완료 예정으로
표시하지 않는다.

완료 예측은 바닐라 `FinishProject`가 완료하는 일반 선행 연구를 포함한다.
숨겨진 선행 연구는 큐의 진행 조건에는 포함하지만 완료 예측에서는 자동 완료로
취급하지 않는다. 파츠도 선택 연구 하나뿐 아니라 자신의 모든 연구 조건을
확인한다. 연구 이후의 재료·작업대·재고 조건까지 충족됐다는 뜻은 아니다.

## 호환성 경계

현재 자동 연결 대상은 정확히 바닐라 `MainTabWindow_Research`를 사용하는 기본
연구창이다. 창 전체를 교체하는 미지원 모드가 있으면 그 모드의 원래 연구 화면을
사용한다. 기존 연구 Def는 그대로 남으므로 해당 모드가 계속 표시할 수 있다.
이 경우 헬로드의 자동 큐 진행도 멈춰 다른 큐와 경쟁하지 않는다.

외부 창은 `ResearchWindowCompatibility.Register(IResearchWorkspaceHost)`로
어댑터를 등록하고, 자신의 그래프 표시 위치에서 `TryDraw(window, viewport)`를
호출할 수 있다. 어댑터는 다음 항목을 제공한다.

- 대응하는 `WindowType`, 현재 창에서 활성인지, 선택한 연구, 선택 변경 기능.
- 외부 모드가 연구 큐를 소유하는지 여부.
- `IResearchQueueBridge`: 목표·실행 순서·정지 상태와 추가·삭제·순서 변경·정지 조작.

렌더러는 외부 큐의 필드나 저장 형식을 직접 변경하지 않는다. 외부 어댑터가
자기 모드의 연구 예약 API로 전달해야 한다. 같은 ID의 어댑터를 등록하면 교체하며,
여러 ID가 같은 창에 대응하면 먼저 등록된 어댑터가 선택된다.

ResearchPowl·ResearchPal 등 창 교체 모드용 개별 어댑터는 아직 포함하지 않는다.
등록 경계와 기본 화면 대체 동작을 제공하는 단계이며, 이들 모드의 전용 UI 기능까지
검증한 것은 아니다.

## 정의

`Defs/Research/ResearchSections_Helod.xml`의 `HelodResearchSectionDef`로 섹션의
이름·순서·색·연구 소속과 `flowColumn`·`flowRow`로 섹션의 가로·세로 위치를 지정한다. 섹션은 연구 프로젝트가 아니며 비용이나
선행 조건을 만들지 않는다. 기본 64개 연구는 정확히 한 섹션씩 소속된다.

## 검증과 격리 실행

저장소 루트에서 실행한다.

```powershell
dotnet run --project Source/Tests/ResearchWorkspace/ResearchWorkspace.Tests.csproj
dotnet run --project Source/Tests/LinkedResearch/LinkedResearch.Tests.csproj
```

검증 결과: 연구창 단위·정의·호환 경계 검사 2,742개, 기존 연구 연결 검사
1,127개 통과. RimWorld 1.6 격리 실행에서 큐 목표 2개, 선택 연구의 파츠 74개,
OR 카드의 실제 렌더링과 한국어 표시를 확인했다. 65% 배율에서 64개 노드와 연결선 99개의 완전성·노드 회피를 검사하고, 실제 마우스의 왼쪽 드래그·전체 배치도 클릭·바닐라 OR 카드 선택을 검증했다. 큐·파츠·OR·축소 배치·이동 화면을 캡처했으며
해당 실행 로그에 UI 예외가 없었다. 다른 연구창 교체 모드에서의 렌더링은 미검증이다.

실제 게임 UI smoke fixture는 `Source/Tests/ResearchWorkspaceGame`에 있다.
전체 모드를 `.codex-staging/ResearchWorkspace`로 빌드한 뒤 fixture를 빌드하고
`Run-Smoke.ps1`을 실행한다. 게임의 원본 Data·런타임에는 읽기용 디렉터리 연결을
만들고, 실행 파일·빌드 DLL·프로필·스크린샷은 작업 폴더 내부에 둔다.
기존 RimWorld 프로세스가 실행 중이면 시작을 거부한다.

fixture는 격리 게임에서만 연구 진행을 초기화하고 큐·파츠·OR 페이지와 65% 배율의 플로우 배치를 차례로
렌더링해 `.codex-staging/ResearchWorkspaceGame/Screenshots`에 기록한 뒤 종료한다.
설치된 모드 폴더와 실제 저장 게임에는 배포하거나 저장하지 않는다.
각 실행은 별도 하위 폴더를 쓰며 `last-run.txt`로 마지막 실행 위치를 확인한다.
기본 제한 시간은 240초다. 그 안에 끝나지 않으면 해당 테스트 프로세스만 종료한다.
Unity가 숨김 창의 UI 렌더링을 생략하는 환경에서는 사용자가 창 표시를 허용한 뒤
`Run-Smoke.ps1 -Visible`로 실행한다.

`Run-Smoke.ps1 -Visible -Interactive`는 마지막 화면에서 실제 왼쪽 드래그,
전체 배치도 클릭, 바닐라 OR 카드 선택을 기다린다. 테스트용 Harmony 관찰자는
입력 이벤트나 게임 상태를 변경하지 않고 실제 조작의 이동·선택 결과를 확인한다.
세 조작을 모두 확인하면 경로 검사 결과와 함께 기록하고 자동 종료한다.
