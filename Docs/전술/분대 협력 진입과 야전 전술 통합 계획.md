# 분대 협력 진입과 야전 전술 통합 최종 계획

상태: 1단계 구현 및 사용자 플레이 확인 이후 2단계 노드 이동을 구현했다. 2단계 플레이에서 중간 정지·좁은 방의 과도한 노드·빈 도착 영역 정체가 확인되어 공통 지향점과 은엄폐 접근으로 수정 방향을 정리했다. 수정 실행 코드는 아직 적용하지 않았으며, 3단계 이후는 미착수다. 거리·지연·곡률의 조정값은 구현과 플레이 검증에서 확정한다.

## 1. 목적과 적용 범위

여러 분대가 하나의 진입점에 모이는 기존 조직 단위 실행을 분대별 실행으로 바꾼다. 분대는 서로 다른 접근 경로와 진입점을 사용하고, 전달받은 정보와 실제 합의에 따라 협력한다. 같은 이동 노드·관측·명령 체계를 CQB, 야전 교전, 수비와 High 화력조 운용에 사용한다.

최종 결과는 다음 행동을 지원해야 한다.

1. 분대 A와 B가 사전에 서로 다른 진입점과 담당 구역을 정하고 각자 접근·돌파·정리를 수행한다.
2. LOW는 접촉 없이 다른 분대의 새 관측이나 준비 완료를 알지 못하고, High는 유효한 무전 보고를 통해 협동을 조정한다.
3. 분대는 이동점 노드를 따라 목표로 이동하며, 먼 거리의 적 접근을 발견하면 진행을 보류하고 엄폐·호형 대형을 준비한다.
4. LOW는 기존 분대 안에서 임시 대응조를 편성하고, High는 기존 화력조의 엄호·기동을 운용한다.
5. 위협 대응과 통신 단절 이후에도 기존 목표와 완료한 진행을 유지하고 다음 유효 이동점에서 임무를 이어 간다.

이번 범위에 지형 굴착이나 새 전투호 장비는 포함하지 않는다. 호형은 활처럼 휘어진 사격 대형을 뜻한다. 기존에 제거한 킬존 감지·전략적 중요도 맵은 다시 도입하지 않는다. 직접 지정한 최종 목표도 기존 목표 공급 방식으로 사용할 수 있어야 한다.

## 3. 공통 원칙

- 상위 지휘는 임무·담당 구역·협력 합의를 관리한다. 개별 폰의 목적지는 해당 실행 단위가 발행한다.
- 하나의 폰에는 한 명령 주체만 있다. 분대와 화력조, 야전과 CQB가 동시에 이동 명령을 덮어쓰지 않는다.
- 일반 갱신은 계획을 바꾸는 사건이 아니다. 목표·현재 노드·진입점·배치는 유지하고 불가능해진 부분만 복구한다.
- 정적 구조는 습격 시작 버전으로 유지한다. 적, 열린 문, 새 구멍, 확보 상태는 관측 또는 유효 보고로만 전술 정보가 된다.
- 실제 이동·사격·예약·폭발 안전은 바닐라/기존 모드 검사를 거친다. 후보 점수나 지도상의 선만으로 통행/사격 가능을 확정하지 않는다.
- 긴급 회피는 대형 유지보다 우선한다. 이미 발사된 투척물이나 설치된 폭발물의 안전 진행은 모드 전환이나 지휘자 교체로 초기화하지 않는다.
- 협력 정보가 없으면 자체 임무와 마지막 합의를 따른다. 다른 단위의 숨은 상태를 읽어 협동을 연출하지 않는다.

## 4. 실행 단위와 데이터 소유권

### 4.1 단위 식별

실행 단위 키는 `OrganizationId + GroupId`를 기본으로 한다. Squad를 기본 독립 단위로 하고, 독립 운용되는 기관총조·바주카조·정찰조 등도 자기 단위를 가진다. 소대 직속 인원을 모든 분대에 중복 배정하지 않고 본부/지원 임무의 한 소유자에 배정한다.

조직 ID가 다른 아군 단위도 같은 연락·협의 규칙으로 협력할 수 있다. 같은 팩션이라는 이유만으로 기억을 합치지는 않는다. 기존 편제 생성·조직 소속·지원 포인트 예산은 유지하고, 실행을 분리했다고 각 분대가 동일한 지원 예산을 중복 사용하지 않게 한다.

High의 분대장과 하위 화력조는 하나의 분대 임무 아래 역할과 진행을 분리한다. 현재 현대 화력조 정의의 단위 수준이 `Team`이므로 문자열 `Fireteam`만으로 식별하지 않고 편제의 부모/자식 관계와 운용 역할을 확인한다. LOW의 임시 대응조는 새 `CombatGroup`을 생성하거나 원래 소속을 바꾸지 않는다.

### 4.2 권장 데이터 구분

아래 이름은 책임 구분을 위한 제안이며 실제 공개 API 이름은 구현 단계에서 정한다.

| 데이터 | 소유자 | 주요 내용 |
|---|---|---|
| 정적 구조 버전 | 맵 | 셀 구조·방·문/벽 위치·연결 특징, 객체 없는 워커 입력 |
| 임무 의도 | 조직/상위 지휘 | 최종 목표, 담당 구역, 지원 의도, 전달 가능한 명령 |
| 단위 실행 상태 | 분대/독립조 | 확정 계획 세대, 모드, 단계, 현재 노드, 실제 담당자 |
| 노드 경로 | 실행 단위 | 노드 순서, 연결 구역, 집결/엄호 목적, 통행 상태 |
| 지역 지식 | 실행 단위 | 직접 관측/보고된 접촉, 통로 변경, 방 진행·보안 우려 |
| 협력 합의 | 합의 참여 단위 | 목표·역할·진입점·구역·시작/중단 조건·시간 한도 |
| 통신 상태 | 단위별 송수신 | 연락 상대, 전달 대기, 보고 출처·수신·확인 응답 |
| 임시 임무 배정 | LOW 분대/High 화력조 | 대응/엄호/기동 인원, 자리, 합류 조건 |
| 물리적 사용 예약 | 이동/작업 실행 계층 | 목적지, 좁은 개구부 사용권, 해제 조건 |

물리 예약으로 충돌을 방지하는 것은 허용하되, 예약 실패가 보이지 않는 다른 분대의 적 기억이나 전술 진행을 알려주지는 않는다. 사전 합의 기록을 보유한 조정자는 그 합의의 배정만 알고, LOW의 현재 준비 상태는 실제 보고 없이 갱신하지 않는다.

## 5. 이동점 노드와 경로

### 5.1 노드 구성

노드는 ID, 정적 버전, 중심과 도착 영역, 수용 인원, 사용 목적, 연결 목록을 가진다. 진행·배치 예약은 정적 노드와 분리한다. 주요 목적은 경유, 집결, 엄호, 돌파 준비, 합류/후퇴이다.

CQB는 코너·복도 연결부·개구부 전후에, 야전은 엄폐물 묶음·노출 구간 전후에 배치한다. 통행 가능한 모든 칸이나 일정 간격 격자점을 명령 노드로 만들지는 않는다. 현재 지역에서 필요한 임시 노드를 생성할 수 있다.

각 연결에는 사용할 구역/통로, 연결 비용과 필요한 통과/돌파 조건을 둔다. 가까워 보이는 벽 너머 노드를 거리만으로 연결하지 않는다. 세부 셀 경로가 필요하면 연결 확인과 바닐라 실행에 일시적으로 사용하고, 그 셀 목록을 매 단계의 이동 명령으로 강제하지 않는다.

### 5.2 실제 이동

단위는 현재 연결과 다음 노드를 확정하고, 각 폰에게 도착 영역의 서로 다른 유효 목적지를 준다. 폰은 바닐라 길찾기로 장애물을 우회한다. 다른 방/입구로 크게 돌아가는 통로는 별도 연결 선택으로 처리한다.

접근 구역은 넓은 선호 영역과 실제 진입 제한을 구분한다. 비용 증가만으로 다른 개구부 사용을 확실히 막았다고 가정하지 않는다. 허용 방/통로와 선택한 개구부 조건은 현재 물리 맵에서 검증하며, 긴급 회피 경로는 일반 접근 제약에 갇히지 않게 한다. 외벽 직선 돌파 선호는 돌파점 선택에 적용하고 이동 선을 강제로 직선화하는 규칙과 분리한다.

도착 판정은 폰 전원이 정확한 한 칸에 서는 조건이 아니다. 연결된 도착 영역, 활동 인원, 필수 역할 준비를 사용한다. 지나간 경유점은 재방문시키지 않으며, 특정 연결 안에서 안전하게 다음 노드로 진행할 수 있을 때만 건너뛴다. 벽/개구부 통과와 필수 집결 노드는 임의로 생략하지 않는다.

늦은 인원은 같은 통로를 따라 합류한다. 분대 중심과의 직선거리 때문에 벽에 붙어 비비지 않는다. 좁은 구역에서 후미를 기다려야 하면 다음 넓은 집결점을 사용한다. 다운/사망 인원을 도착 대기에 포함하지 않는다. 교전·회피 후 복귀는 다음 유효 노드와 중단 전 진행을 사용한다.

## 6. 관측, 기억과 연락

### 6.1 공통 관측 기억

CQB와 야전은 같은 기억 형식을 쓰되 관측 반경과 대응 판단을 분리한다. 관측은 사격과 같은 몸 내밀기 LOS를 사용하고 연막 차폐를 유지한다. 사거리, 탄약, 무장 여부가 발견 자격을 제한하지 않는다. 실제 사격은 자기 무기의 현재 유효 판정을 거친다.

접촉은 마지막 위치·원 관측 시각·출처 단위/관측자·관측 방향·통과한 개구부·관측 무장·신뢰도를 보관한다. 적이 시야에서 사라지면 그 위치를 갱신하지 않는다. 연속 관측이 끊긴 구간의 이동 경로를 만들어내지 않는다. 문 칸 적은 인접 방/통로 관계로 처리한다.

문 열림·새 구멍·방 진행도 같은 정보 소유권을 따른다. 정적 지도에 문이 있다는 사실과 지금 열려 있다는 사실은 다르다. 미관측 개폐로 현재 진입점을 바꾸지 않는다. 실제 통행 실패는 지역 복구를 요구할 수 있지만 먼 문이 열린 이유를 알아내는 근거는 아니다.

### 6.2 LOW 접촉 기반 공유

분대 사이 공유는 가까운 거리에서 상호 확인 가능한 접촉과 짧은 보고를 거친다. 같은 조직, 같은 방, 같은 맵이라는 이유만으로 공유하지 않는다. 일반 병사가 받은 보고는 자기 분대의 연락 가능한 지휘/보고 경로로 전달한다. 분대 내부도 고립된 병사의 관측이 벽 너머 전원에게 즉시 퍼지지 않도록 가까운 구두/지휘 전달을 간단히 모델링한다.

협력 변경은 분대장 또는 대행 지휘자의 협의가 필요하다. 출발 전 합의는 이 연락 과정의 결과로 만들거나 습격 전 브리핑으로 주어진 명시적 계획으로 기록한다. 흩어져 진입하는 습격도 합의한 임무는 보유할 수 있지만, 전술 시작 순간 서로 떨어져 있다는 이유로 현장 정보가 새로 공유되지는 않는다.

### 6.3 High 무전 기반 공유

High의 보고·명령은 사용 가능한 송수신 장비, 가용 운용자, 호환 통신망을 통해 전달한다. 새 High 편제/장비 구성에는 필요한 무전 운용 조건을 명시한다. 팩션 이름이나 상위 지휘관 존재만으로 연결 성공을 간주하지 않는다.

무전은 짧은 전달·수신·확인 지연을 가지며, 운용자/장비 상실과 통신 불능에 대응한다. 무선 연결 자체에 시각 LOS를 요구하지 않는다. 기존 외부 지원 요청의 목표 관측 LOS는 전술 무전 연결 규칙과 별개이다. 단절된 단위는 마지막 수신 명령과 자체 관측으로 방어·합류한다.

### 6.4 보고 병합

보고는 원 보고 ID/수정 세대, 원 관측 시각, 수신 시각과 전달 경로를 구분한다. 중복·순환 전달을 막고 재전달로 정보 수명을 늘리지 않는다. 직접 관측한 최신 정보가 오래된 전달 정보보다 우선한다.

수신 보고를 `Visible` 접촉으로 만들지 않는다. 확인 안 된 옛 위치는 경계/재확인에 쓰고 실제 표적 판정을 대체하지 않는다. 방 번호는 정적 버전과 함께 기록하며 버전이 다르면 좌표를 기준으로 수신 지도에 대응시킨다. 클리어 보고는 누가 언제 어떤 범위를 확인했는지 포함하고 방에 적이 재등장할 가능성을 배제하지 않는다.

## 7. 분대 협력과 다중 진입

### 7.1 협력 합의 내용

협력은 전역 실시간 AI가 모든 분대를 조종하는 형태가 아니라, 참여 단위가 각각 보유하고 실행하는 합의로 표현한다. 합의에는 ID/세대, 참여자, 공통 목표, 담당 구역, 각 진입점과 접근 노드, 지원 역할, 투척/사격 제한 구역, 시작 방식, 준비 기한과 대기 한도, 중단·대체·합류 조건을 기록한다.

보고로 적 위치를 알게 된 것만으로 새 협력이 성립하지 않는다. LOW는 현장 접촉 또는 기존 브리핑 합의가 필요하고, High는 유효한 무전 명령/확인 응답으로 합의를 만들거나 바꾼다. 상급 지휘자 상실 시 자체 행동은 계속하고 기존 승계 규칙으로 새 합의/임무 변경 가능 여부를 판단한다.

합의 변경은 새 세대로 전달하고 각 참여자가 수신한 세대를 따로 유지한다. 미수신 단위가 새 계획을 자동 채택하지 않으며, 새 공통 시작 조건은 필요한 참여자의 수신 확인을 확보한 뒤 사용한다. 연락 실패와 서로 다른 계획 세대는 합의된 대기/중단/합류 규칙으로 처리한다.

### 7.2 진입점 배분

1. 정적 외벽/방 구조와 참여 단위가 가진 지역 지식에서 후보 개구부·돌파점을 찾는다.
2. 각 후보의 외부 접근, 실제 스택 공간, 작업자/관측자/투척자 동선, 안쪽 도착 공간과 연결성을 확인한다.
3. 각 단위의 장비·작업자·활동 인원으로 사용할 수 없는 후보를 제외한다. 같은 돌파 장비 한 개를 동시에 여러 진입점의 필수 수단으로 배정하지 않는다.
4. 유효 후보 안에서 다른 참여 분대의 진입점, 접근 연결, 집결 영역과 중복이 적은 배정을 우선한다. 좌표가 다르더라도 같은 좁은 통로로 합쳐지면 경로가 다양하다고 평가하지 않는다.
5. 배정 후에는 현재 계획을 유지한다. 다른 문 열림이나 작은 점수 변화 때문에 좌우 입구를 번갈아 선택하지 않는다.

경로 다양성은 안전·작업 가능성 이후의 우선도이다. 다양성을 확보하려고 접근 불가능한 벽 너머 스택이나 과도하게 긴 노출 이동을 선택하지 않는다. 합의된 분대 사이 배정을 비교하며 연락하지 않은 분대의 숨은 계획을 조회해 우회 경로를 만들어주지 않는다.

### 7.3 동기화의 LOW/High 차이

| 상황 | LOW | High |
|---|---|---|
| 출발 전 역할 분담 | 현장 협의 또는 명시적 사전 브리핑 | 현장 협의/무전 명령과 수신 확인 |
| 떨어진 분대의 준비 상태 | 직접 보고/관측 없이는 알 수 없음 | 수신한 준비 보고로만 갱신 |
| 진입 시작 | 합의한 시작 시각·시간차 또는 실제 관측 가능한 합의 신호 | 수신한 준비 상태와 시작 명령/확인 응답 |
| 한쪽 준비 지연 | 자기 대기 한도와 합의한 실패 규칙 적용 | 지연 보고를 받아 시작 시각/역할 조정 가능 |
| 현장 목표 변경 | 다시 연락 가능한 협의 필요 | 연결된 지휘망으로 새 명령 전달 |
| 통신/지휘 단절 | 자체 임무·마지막 합의·합류 규칙 | 마지막 수신 합의·자체 방어·재연결/합류 |

LOW의 동시 진입은 시각을 합의했다고 무조건 성공하는 기능이 아니다. 각 단위가 자기 준비를 완료한 경우에만 시작하고, 아직 준비되지 않았으면 대기/중단/합류 등 자기 합의의 규칙을 따른다. 다른 분대가 실패한 사실을 전역 플래그로 알아채지는 않는다.

### 7.4 같은 개구부를 공유할 때

진입점이 부족하면 진입조와 외부 엄호조를 나누거나 같은 입구를 시간차로 사용한다. 앞 단위가 통과할 공간과 뒤 단위의 대기 공간을 분리하고, 짧은 사용권/해제 규칙으로 양쪽에서 서로 밀고 들어가지 않게 한다. 사용권은 사망·취소·진행 정체에 해제되며 무기한 기다리지 않는다.

물리 충돌 방지와 협력 시작 보고를 구분한다. LOW가 사용권을 얻었다고 다른 분대의 실내 정리 완료를 안다고 처리하지 않는다. 양방향 좁은 통로는 먼저 진행한 단위의 통과를 마친 뒤 방향을 교대하고, 후퇴하는 아군이 나타나면 안전한 대기 노드로 양보한다.

### 7.5 내부 구역 분담과 방 확인

여러 분대가 같은 건물에 들어가면 합의한 방/복도 구역과 경계를 나눈다. 이미 다른 분대가 담당하기로 한 구역을 무조건 대신 클리어하지 않는다. 실제 상황 때문에 넘어가야 하면 관측/연락 또는 기존 대체 규칙으로 처리한다.

이미 열린 통로로 도달 가능한 방을 다시 파괴하는 목표로 만들지 않는다. 자기 단위가 확인한 방과 다른 단위가 보고한 방은 구분한다. 후방의 새 접촉은 해당 구역의 보안 우려를 다시 열고 필요한 감시·재확인을 수행하지만, 이미 확보한 물리 통로와 전체 최종 목표는 유지한다. 보고되지 않은 다른 분대의 방 클리어를 자기 완료로 복사하지 않는다.

## 8. CQB 진행과 협력 안전

분대별 기본 흐름은 노드 접근 → 연결된 벽 옆 스택업 → 돌파 → 개구부 관측 → 지원 판단/투척 → 효과 종료·복귀 대기 → 통과 → 방 확인 → 다음 담당 방이다.

기존 규칙을 유지한다.

- 목표 공급의 기본은 이름 있는 침대이며 지정 목표도 지원한다. 현재 방을 돌파 목표로 삼는 잘못된 계획은 방 확인/이동 의도로 복구한다.
- 스택업은 개구부 옆의 서로 연결된 실제 자리이다. 코너/벽 너머 자리를 같은 대형으로 묶지 않고, 도착 후 불필요한 배회를 막는다.
- 관측자는 개구부 옆에서 지정 출발 칸으로 짧게 본다. 적 하나를 관측하면 즉시 복귀하고 그 관측 지점을 우선 지원 대상으로 삼는다. 문 칸과 인접 대상 방도 기존 규칙으로 처리한다.
- 개구부 너머 야외는 안전 이동 연막, 실내는 수류탄 판단을 사용한다. 16칸 이하 작은 방은 기본적으로 절약하되 실제 적 관측은 기존 예외를 적용한다.
- 진입용 지원 투척은 개구부에서 최소 2칸 거리 규칙과 실제 탄종별 안전 검사를 유지한다. 투척자도 스택으로 복귀하고 폭발 전 진입하지 않는다.
- 통과 후 방 안 깊숙이 무조건 전진하지 않고 개구부 쪽 벽/엄폐를 사용한다. 통과 진행은 단방향으로 유지하고 문 안 왕복을 막는다.
- 공병 상실 시 기존 장비 회수와 작업자 승계를 적용한다. 유효한 돌파점은 작업자 교체만으로 다시 선택하지 않는다.

다중 진입에는 추가 규칙이 필요하다.

- 같은 방의 지원 투척·폭발과 다른 개구부의 진입은 한 합의 안에서 조정한다. 서로 다른 분대가 같은 방 양쪽에서 안전 확인 없이 수류탄을 던지지 않는다.
- 투척 가능한 시간/구역과 지원 담당을 먼저 배정하고, 동시 투척의 안전한 분리가 불가능하면 지원 하나와 시간차 진입을 선택한다.
- LOW는 이미 합의한 투척 종료 시각/조건과 자기 효과 대기를 사용한다. 예상과 달라졌는데 연락할 수 없으면 안전한 보류/지원 생략 규칙을 적용하며 원격 준비 완료를 읽지 않는다.
- High는 지원 실행/효과 종료 보고와 자기 안전 검사를 함께 사용한다. 무전 보고만으로 실제 탄종의 안전 대기를 생략하지 않는다.
- 알려진 아군 이동 구역으로 사격/투척하도록 배정하지 않는다. 실제 작업의 아군 안전 검사는 전술 정보 공유와 분리하여 적용한다. 안전 때문에 행동이 거절돼도 숨은 아군의 위치를 접촉 보고로 생성하지 않는다.

실내에서 새 아군 단위를 만나면 발견 → 짧은 식별 → 필요 시 보고/협의를 수행한다. 초기 식별 지연 검토값은 0.5~1초이고 이미 확인한 상대에 대한 반복 정지는 억제한다. 식별 중 돌입/투척을 보류할 수 있지만 폭발 회피는 허용한다. 식별 실패로 아군을 적 표적으로 삼는 기능은 만들지 않는다.

## 9. 야전 전용 실행

### 9.1 상태 흐름

노드 이동 → 조기 발견/접근축 평가 → 임무 이동 보류 → 대응 노드 배치 → 경계/교전 → 재평가 → 대응 인원 합류 → 다음 목표 노드로 복귀를 기본으로 한다. 필요하면 엄폐 이탈/계획 연막/후퇴로 분기한다. 기존 CQB 단계에 고정 시간 대기를 끼우는 방식으로 표현하지 않는다.

### 9.2 사거리 밖 조기 발견

야전 관측 반경은 CQB와 분리한다. 초기 검토값은 90칸이며 현재 70칸 관측과 약 36칸 반응 제한을 개선한다. 발견 거리 확대뿐 아니라 실제 준비 행동으로 이어지는 조건을 바꾼다. 무장하지 않은 적도 관측하며 무장/방향에 따라 대응 우선도를 구분한다.

연속 관측에서 이동 방향·접근 속도·분대 또는 예정 연결과의 거리 변화를 추정한다. 적의 숨은 job 목적지나 마음 상태의 목표를 읽어 미래 경로를 알아내지 않는다. 첫 발견은 진행을 보류할 수 있는 근거이고 이어지는 관측으로 접근·횡단·이탈을 구분한다. 정지한 장거리 사격 위협도 평가하지만 멀리 지나가는 적 하나 때문에 영구 정지하지 않는다.

### 9.3 대응 노드와 엄폐

현재 지역의 소수 후보에서 방향별 방호, 사격선, 인원 수용 공간, 이동 비용/노출과 후퇴·합류 경로를 평가한다. 엄폐 개수만으로 고르지 않는다. 안전하게 선점할 시간이 있으면 조금 앞선 엄폐 묶음을 사용할 수 있고, 이미 교전 중이면 가까운 엄폐·시야 차단·연막을 우선한다.

사거리 밖에서는 준비·경계를 하고 실제 유효 사격 조건에 들어오면 접근축에 화력을 집중한다. 엄호로 배정됐다는 이유만으로 사격 불가능한 화기가 이미 제압 중이라고 간주하지 않는다. 실제 사격/표적 선택은 바닐라 판정과 자기 단위 임무의 범위에서 수행한다.

### 9.4 LOW 임시 대응조와 호형 대형

기존 분대의 자동화기 담당자와 일부 소총수/보조 지휘자를 일시적으로 대응 임무에 배정한다. 실제 활동 인원·무장·부상 상태에 맞추고 작은 분대는 무리하게 분리하지 않는다. 원 조직 소속은 유지하며 종료 후 합류한다.

대응조는 활처럼 휘어진 완만한 호형 대형을 만든다. 양끝은 적 방향으로 조금 전진하고 중앙은 뒤에 두어, 좌·중앙·우측 사격선이 대형 전방 중앙의 예상 교전 구역에 겹치도록 유도한다. 아군이 서 있는 중앙점으로 사격시키거나 멀리 벌어진 포위 기동으로 확장하지 않는다.

접근축, 대형 폭/곡률과 집중 구역에서 이상적인 자리 후보를 만들고 실제 엄폐·LOS·연결·연락 거리·사격선 간섭에 맞춰 보정한다. 자동화기는 집중 구역을 안정적으로 사격할 수 있는 자리에 우선 배정한다. 완벽한 곡선을 강제해서 엄폐를 버리지 않는다. 좁은 지형은 폭/곡률을 줄이거나 연결된 엄폐 대형으로 대체한다.

나머지 인원은 보호된 대기/집결 노드에 머물고 실제 엄호가 가능한 뒤 짧은 안전 연결로 이동할 수 있다. 연락 범위를 벗어나면 사전 시작 조건·제한 시간·합류 지점을 따르며 원격 실시간 조정을 하지 않는다. 다른 분대의 엄호/우회 지원은 별도 접촉·보고·협의가 필요하다.

### 9.5 High 화력조 엄호·기동

기존 Alpha/Bravo 화력조에 엄호 노드와 기동 노드를 배정한다. 한 조의 자리·사격선·활동 화기 준비를 확인한 뒤 다른 조를 다음 노드로 이동시키고 필요할 때 교대한다. 무전으로 접촉·준비·역할 변경을 전달하고 분대장이 합의된 시작 조건을 확인한다.

화력조별 진행·접촉·담당자는 유지하며 단절 시 마지막 합의의 공간/시간 한도를 따른다. 무전이 다른 조의 관측 정보를 전달하는 것은 가능하지만 보고되지 않은 적이나 준비 상태를 자동으로 조회하지 않는다.

### 9.6 연막, 수비와 복귀

연막 목표는 투척자 위치보다 단위가 선택한 위험 이동 연결과 차폐 구간으로 정한다. 필요한 투척 출발 공간도 계획하고 뒤쪽 인원이 자기 도주 위치에서 엉뚱한 곳에 던지지 않게 한다. 형성된 연막을 따라 다음 노드로 진행하며 추가 차폐를 이어 갈 수 있다. HC 등 기존 안전 연막을 이동 차폐로 사용하고 WP를 통과 안전 연막으로 취급하지 않는다.

고정 수비도 같은 노드·접근축·엄폐/호형 배치를 사용하되 임무 구역과 추격 한계를 둔다. 지원 요청 같은 명시적 사건은 별도 대응 준비 계기가 될 수 있지만 고립된 분대가 다른 분대의 요청을 전달 없이 알아채지 않는다.

적이 사라지면 마지막 접근축을 잠시 경계하고 관측 이탈 또는 신뢰도 감소와 추가 위협 여부로 해제한다. 임시 대응 인원은 합류한 뒤 기존 목표의 다음 노드로 복귀한다. 마지막 적 위치까지 무제한 추격하지 않는다. 작은 방향 변화마다 대형과 노드를 회전/교체하지 않는다.

## 10. 사건 처리, 전환과 저장

| 사건 | 처리 |
|---|---|
| 사망/다운 | 해당 담당/예약 해제, 기존 지휘 승계·장비 회수, 영향 있는 임무만 재배정 |
| 실제 관측한 선택 진입점 차단 | 현재 지역에서 대체 연결/진입점 검토, 합의 변경은 연락 조건 적용 |
| 보이지 않는 다른 문 개폐 | 지역 지식과 현재 계획 유지 |
| 후방/측면 새 접촉 | 현재 확인 가능한 위협에 감시/엄폐/단계 중단, 원 목표와 열린 통로 유지 |
| 가까운 폭발 위험 | 즉시 회피, 이후 현재 단계/다음 노드에서 복귀 |
| 지휘자 상실 | 기존 승계 지연 적용, 하위 단위는 자체 방어와 마지막 임무 지속 |
| 무전/연락 단절 | 보고 전달 중단, 마지막 합의와 합류/중단 규칙 적용 |
| 늦은 합류/새 인원 | 안전한 합류 노드와 빈 역할 배정, 이미 진행 중인 통과 순서 초기화 금지 |
| CQB↔야전 | 명령 소유자를 하나로 유지, 접촉·목표·합의와 폭발 안전 대기 보존 |

정기 관측, 경미한 점수 변화와 잠깐의 충돌은 전체 재계획 사유가 아니다. 진행 정체는 실제 연결/작업 가능성과 해당 인원을 확인하고 재시도 간격과 지역 실패 원인을 기록한다. 합의 참여자 전체를 무조건 다시 집결시키지 않는다.

저장 대상은 단위 키, 임무·확정 계획/세대, 노드 진행, 담당/자리, 접촉 출처·시각·신뢰도, 관측 변경, 방 확인/보안 상태, 협력 합의, 전달 대기/마지막 수신 명령, 임시 대응 역할, 통과/지원 안전 진행이다. 정적 버전은 공유 저장하고 별도 객체/배열 복사를 늘리지 않는다.

불러오기 후 사망자·장비·예약·통신 조건을 다시 확인하고 실제 폰/투척물 참조와 단위 진행을 연결한다. 직접 관측 `Visible` 상태와 통신 연결은 재검증하며 로드 시각으로 정보 수명을 갱신하지 않는다. 복원이 끝나기 전 바닐라 습격 명령이 별도 이동을 시작하지 않게 한다. 이관에서 불필요해진 조직 전체 실행/공유 코드는 제거하며 이전 저장 형식/API 하위 호환 코드를 추가하지 않는다.

## 11. 성능과 개발자 표시

정적 노드/엄폐 후보·구조는 공유하고 관측 지식·선택 결과·진행만 단위별로 저장한다. 먼 적 관측은 거리/구역 필터 뒤 LOS를 검사하고 단위별 시점을 분산한다. 작은 지역의 제한된 후보에서 연결·엄폐·사격선 검사를 수행하고 실패 후보에는 재시도 간격을 둔다.

워커에는 객체 없는 불변 입력만 전달한다. 실제 맵·폰·Thing·LOS·예약과 작업 명령은 메인 스레드에서 처리한다. 기존 공통 처리 예산과 완료본 교체/취소 규칙을 유지하고 매 분대/단계마다 전체 맵 BFS나 비용 배열을 새로 만들지 않는다. 긴급 회피를 일반 캐시 준비 대기로 지연시키지 않는다.

개발자 표시/기록은 다음을 확인할 수 있어야 한다.

- 조직/분대/화력조 ID와 현재 명령 주체, 모드·단계·계획 세대.
- 이동 노드/연결/허용 구역·도착 영역, 진행 중/완료/합류 지점.
- 분대별 접근 경로·진입점·스택·담당 구역·물리 사용권과 공유 입구 대기.
- 직접 관측/보고 접촉, 원 관측·수신 시각과 신뢰도, 통로 지식·방 보안 상태.
- LOW 현장 접촉·협의와 High 무전 연결·보고 대기·수신 확인.
- 협력 합의의 시작/대기/중단 조건과 각 단위가 실제로 알고 있는 준비 상태.
- 야전 접근축·감지 반경·사격 범위, LOW 임시 대응조, High 엄호/기동 역할.
- 호형의 이상 자리·실제 엄폐 자리·전방 집중 구역, 연막 목표/출발 공간.
- 단계/명령 변경 이유, 경로 재요청·작업 교체·LOS/후보 수와 처리 시간.

전역 개발자 화면은 여러 단위의 실제 상태를 비교 표시할 수 있지만 그 집계가 AI의 정보 입력으로 되돌아가지 않게 한다.

## 12. 구현 순서와 단계별 완료 기준

1단계 구현·자동 검증 기록: [분대별 실행 상태 분리](1단계%20분대별%20실행%20상태%20분리.md). 플레이 검증 항목과 이후 단계의 경계를 함께 기록했다.

2단계 구현·자동 검증 기록: [이동 노드와 합류](2단계%20이동%20노드와%20합류.md). 1단계는 사용자 테스트에서 큰 문제가 없다는 결과를 받았으며, 2단계의 플레이 확인 항목은 별도로 기록했다.

2단계 플레이 후 수정 기준: [지향점과 은엄폐 접근](2단계%20수정%20방향%20-%20지향점과%20은엄폐%20접근.md). 개인별 중간 자리·정지 조건을 공통 지향점과 연속 통과로 교체하고, 고정기총/저격 대응을 위한 외곽·벽 접근의 기반으로 사용한다. 이전 2단계 구현 설명과 충돌하는 이동 기준은 이 수정 문서를 우선한다.

각 단계는 검증 후 `main`에서 별도 커밋한다. 아래 단계는 최종 구현 순서이며 문서 작성만으로 착수하지 않는다.

| 신규 통신/협력 데이터·정책 | 접촉/무전 전달, 합의와 사용권, LOW/High 차이 |
| 기존 전술 개발자 UI/오버레이와 테스트 프로젝트 | 단위별 정보/진행 표시, 순수 정책·바인딩·플레이 검증 |

신규 파일 이름은 실제 구현의 책임 분리에 맞춰 결정한다. 현재 소스의 한 조직 상태 조회를 남긴 채 새 분대 상태를 덧붙이는 우회 이중 실행 구조는 만들지 않는다.

## 13. 검증 시나리오와 조정값

| 시나리오 | 기대 결과 |
|---|---|
| 두 LOW 분대, 서로 다른 외벽 후보 | 사전 합의로 경로/진입점을 나누고 현장 준비 정보는 연락 없이 공유하지 않음 |
| 흩어져 진입하는 습격 | 각 단위가 자기 현재 위치에서 배정 노드로 접근하고 조직 전체 집결 대기로 멈추지 않음 |
| 두 진입 경로가 같은 좁은 통로로 합쳐짐 | 독립 경로로 과대 평가하지 않고 순서/대기 구역 또는 다른 유효 배정 선택 |
| 진입점 하나, 여러 분대 | 입구 사용권·시간차/엄호로 처리하고 무기한 대기·왕복·서로 밀기 없음 |
| LOW 한 분대만 준비 지연/지원 실패 | 다른 분대는 숨은 실패를 읽지 않고 자기 합의된 시작/안전 조건만 사용 |
| High 준비 완료 보고 뒤 무전 상실 | 마지막 수신 정보와 유효 합의로 행동하고 갱신되지 않은 상태를 현재 사실로 취급하지 않음 |
| 같은 방 양쪽에서 지원/진입 | 탄종별 대기와 구역/시간 조정, 미확인 상황의 위험한 추가 투척 보류 |
| 이미 열린 방/예기치 않은 관측 구멍 | 열린 통로를 사용하고 불필요한 재돌파·전체 목표 변경 없음 |
| 보이지 않는 반대편 문 반복 개폐 | 단위 지식과 현재 진입점 유지 |
| 문 칸 사격 적, 후방 재등장, 양쪽 복도 이탈 | 사격 LOS 관측·독립 기억·경계/재확인, 숨은 적 이동 추적 없음 |
| 먼 적이 사거리 밖에서 접근 | 목표 이동 보류와 엄폐 준비, 유효 사격 범위에 들어오면 교전 |
| 먼 적이 횡단하거나 이탈 | 필요 경계 후 해제하고 기존 다음 노드로 복귀 |
| 호형 대형과 좁은 지형 | 중앙 전방 사격선 중첩, 실제 엄폐/연결 유지, 폭/곡률 조정과 잦은 회전 억제 |
| High 엄호 화력조의 사거리/LOS 부족 | 엄호 준비로 거짓 판정하지 않고 다른 노드/차폐/대기 선택 |
| 후미의 연막 담당자, 투척자 사망 | 공통 목표/출발 공간 유지와 담당 교체, 무작위 개인 도주 투척 없음 |
| 새로운 아군과 실내 조우 | 짧은 식별/보고와 안전 보류, 식별 실패 공격·반복 정지 없음 |
| 수류탄 회피·공병/지휘자 사망·새 합류 | 해당 임무 복구, 열린 통로·완료 노드·폭발 대기와 원 소속 유지 |
| 여러 조직/맵과 CQB↔야전, 저장/로드 | 한 명령 주체, 버전/정보 출처/수명 보존, 캐시·예약 수명과 프레임 비용 확인 |

순수 검증은 노드 진행, 보고 병합/감쇠, 협력 시작·실패 규칙, 후보 배정·겹침, 호형 후보/보정 정책에 적용한다. 실제 게임 바인딩은 작업·LOS·예약·장비·저장 연결을 확인한다. 실제 맵에서 이동/충돌·투척·무전 단절·성능을 확인하기 전 플레이 완료라고 보고하지 않는다.

조정값은 별도 교리/설정 데이터로 둔다. 현재 기준/검토값은 CQB 접촉 24칸, 야전 초기 관측 90칸, 실내 식별 0.5~1초이다. LOW 연락 거리/보고 시간, High 전달/확인 시간과 연결 조건, 노드 간격/도착 반경, 대기/실패 한도, 호형 폭/곡률, 접근 판정/대형 변경 한계와 보고 신뢰도는 구현 단계에서 성능·플레이 검증으로 결정한다. 어느 조정값도 시야 밖 정보 공유나 무제한 대기의 예외를 만들지 않는다.
