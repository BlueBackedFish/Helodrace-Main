# LOW 벽 돌파 후 대인 수류탄 수정

2026-10-13. 사용자가 보고한 범위는 벽 돌파 후 실내 대인 수류탄이다. 코드에서 투척을 차단하는 세 조건을 확인하고 수정했다. 해당 플레이 장면을 Unity 게임에서 재현한 결과는 아니다.

## 투척 자리와 복귀

기존에는 안전한 스택업 자리에서만 투척 가능 여부를 검사했다. 벽 뒤의 대형 자리는 개구부를 향한 투척 LOS가 없을 수 있어, 장비가 있어도 투척자를 고르지 못하고 바로 진입했다.

현재 자리에서 가능하면 그대로 사용하고, 불가능하거나 위험하면 개구부 바깥의 양옆 한 칸을 검사한다. 빈 칸·다른 조직 예약·실제 폰 점유·투척 범위/LOS·아군 안전을 확인한 자리만 사용한다. 개구부나 안쪽 통로에 서서 던지는 위치는 추가하지 않았다.

준비 30틱 → 선택한 투척 자리로 이동 → 투척 18틱 → 원래 스택업 자리로 복귀한다. 투척 위치와 복귀 위치를 분리했다. 발사 직전 안전 재검사, 실제 프로젝트일/폭발·파편·복귀·정리 대기를 그대로 사용한다.

## 벽 파괴 후 방 병합과 충격 효과

벽이 사라지면 바닐라 Room이 접근 방과 목표 방을 합칠 수 있다. 기존 전체 방 아군 검사는 이때 벽 뒤 접근 대형까지 목표 방 아군으로 취급했다. 실제 실행 중인 개구부와 투척 목표가 확인된 경우, 합쳐진 Room의 접근 쪽은 전체 방 금지 대상에서 분리한다. 접근 쪽도 별도의 폭발·파편·산포·튕김 반경과 LOS 검사를 받는다. 개구부/문/안쪽 통로와 대상 쪽 아군, 다른 팀의 진입 예정지는 기존 보호를 유지한다.

MK II와 MK III에는 벽 너머로 약하게 전달되는 충격 효과가 있다. 기존에는 감쇠 계수가 조금이라도 있으면 벽 뒤 아군도 최대 위험 반경 전체에서 금지했다. 이제 실제 정의의 최대 충격 강도·환경 계수·벽 감쇠 계수로 기절/강도 피해 문턱에 도달하는지 판단한다. 해당 수류탄의 약한 벽 너머 억제 효과는 투척을 일괄 취소하지 않으며, 강한 효과와 유해 가스는 계속 보호한다. 무기 자체의 피해·반경·충격 효과 정의는 바꾸지 않았다.

## 계산과 진단

후보는 전역 계획 예산 안에서 한 번에 최대 4개의 목표점/투척자 조합을 확인한다. 진행 인덱스를 보존해 다음 틱에 이어 가며, 선호 순서 두 번을 모두 검사한 뒤 가능한 후보가 없으면 진입한다. 예산이 없다는 이유로 미완성 검사를 실패 처리하지 않는다.

Inspect의 `support skip`에 다음 이유를 표시한다: `Policy` 작은 방/수감자 등 교리, `NoTarget` 목표 없음/개구부에 너무 가까운 관측 지점, `NoGrenade` 사용 가능한 장비/담당 없음, `NoThrowPosition` 위치/거리/LOS 부족, `UnsafeFriendly` 아군 위험, `Formation` 대형 미완료, `Budget` 계산/명령 예산 대기, `Interrupted` 발사 전 작업 중단. 정상 선택 시 `None`으로 지운다.

16칸 이하 수류탄 절약·직접 관측한 적 예외, 수감자 보호, HIGH 교리와 외벽 HC 연막 사용은 유지한다.

## 검증

빌드 경고/오류 없음. 네 방향의 벽 뒤 자리에서 양옆 투척 자리 선택·반대쪽 빈 자리·기존 자리 유지·점유/개구부 배제, 병합된 접근 방과 안쪽/문 아군 구분, 실제 MK II/III XML의 벽 너머 강도 문턱·유해 가스, 4명 분산/같은 틱 중복 검사 차단/선호 검사 종료, 후보 진행·사유 저장과 기존 폭발/복귀/C4 안전 검사를 확인했다. 게임 내 재확인은 약식 목록 F52에서 진행한다. 실제 CPU 감소율은 측정하지 않았다.

## 투척 목표만 표시되고 진입하는 문제 후속 수정

사용자는 실제 발사는 없고 목표 표시만 나타난다고 확인했다. 기존 `Target`은 투척 가능성을 검사하기 전에 채워졌으며, 담당/LOS/아군 안전 검사에서 모든 후보가 실패해 `Enter`로 넘어가도 남았다. 개발자 노드는 이 제안 지점까지 실제 투척처럼 표시했다. 코드에서 확인한 이 경로는 실제 발사 후 폭발 대기를 생략하는 경로와 구분한다. 해당 플레이에서 어떤 검사 사유가 최종 거절했는지는 런타임 기록이 없어 확정하지 않았다.

또 기존 선택기는 사각 후보 하나를 선택한 뒤 다른 목표점으로 바꾸지 않았다. 그 사각에 투척 LOS가 없거나 아군에게 위험하면, 같은 국소 범위에 가능한 지점이 있어도 투척을 생략했다. 이제 기존 깊이 3~5칸·폭 0/±2칸의 최대 9개 후보를 한 번 보관하고, 사각 우선순위를 유지하면서 다른 후보도 검사한다. 관측된 적이 있으면 그 기억 지점 하나만 사용하며 개구부 2칸 거리 조건을 유지한다. 지도 전체 탐색이나 매틱 후보 재생성은 추가하지 않았다.

실제 작업 명령이 수락된 경우에만 `ThrowIssued`와 투척 노드를 확정한다. 표시되는 출발점도 선택된 투척 자리로 바뀐다. 준비 작업은 드라이버 초기화 여부 대신 진행 중인 투척 작업을 기준으로 보존한다. 발사된 수류탄은 폭발 대기로 처리해 복귀와 효과 정리를 기다린다. 발사 전 중단이나 모든 후보 실패로 진입할 때는 목표를 지우고 `support skip` 사유를 남긴다. 아군 위험 때문에 불가능한 투척을 강제로 실행하지 않는다.

관련 약식 코드 검증: 빌드 경고/오류 0, `--a2-safety`와 `--a5` 통과. 네 방향의 사각 우선/다른 목표 유지, 관측 목표 고정, 다중 목표의 4조합 분산과 완료 전 진입 차단, 제안/확정/중단/폭발 완료 표시, 드라이버 초기화 전 준비 유지, 후보 목록과 커서의 native Scribe 저장을 확인했다. 실제 게임 재확인은 F53으로 남긴다. 후보를 늘린 만큼 실패 시 총 검사 횟수는 증가할 수 있지만 한 번의 계획 예산과 틱당 4조합 상한은 유지한다.

## LOW 투척 판단과 적 발견 후 후퇴·투척 연결

후속 테스트에서도 LOW가 투척하지 않고, 관측/돌파 뒤 적과 교전하는 현상이 보고됐다. 코드에서 추가로 확인한 차단 경로를 수정했다. 해당 플레이 장면을 게임에서 재현해 최종 거절 사유를 수집한 결과는 아니다.

- 일반 접촉 대응은 `AdvanceOpeningAction`보다 먼저 실행된다. 관측 완료 뒤에도 가까운 적/다른 문 조건이 대응을 시작할 수 있고, 지속 관측이 교전 상태를 연장해 투척 단계에 도달하지 못했다. 돌파 중 일반 LOS 감지로 본 적도 개구부 투척 기록에 들어가지 않았다.
- 투척자의 임시 투척 자리를 폭발 때까지 계속 점유할 위치로 취급했다. 짧게 노출해 던지고 안전한 원래 자리로 돌아가는 계획도 본인 위험으로 거절될 수 있었다.
- 개구부/문에 가까운 관측 위치는 최소 2칸 조건에 걸리면 대상이 없는 것으로 끝났다. 파괴된 입구의 지붕만 사라져도 실내 적에 HC 연막만 고르려는 분류가 가능했다.

이제 돌파·관측·투척 준비 단계의 실제 LOS 관측이 목표 방향의 국소 범위(개구부 축 앞 0~14칸, 좌우 최대 14칸)에 있으면 첫 적 위치 한 개를 개구부 기록으로 보존한다. 그 이후 숨은 적의 현재 위치를 추적하지 않는다. 준비 중 발견하면 아직 확정하지 않은 맹목 투척 후보를 비우고 관측 위치부터 검사한다. 벽이 남으면 같은 돌파를 마치며, 개구부가 열리면 대형으로 복귀한 뒤 투척한다. 진행 중 C4는 안전 절차를 먼저 끝낸다.

해당 방향의 일반 접촉 교전·야전 화력점·근접 집중사격이 이 절차를 가로채지 않도록 했다. 기존 정면 교전 상태도 해제하고, 경계 작업의 해당 방향 사격과 진행 중 총기 버스트를 중단한다. 관측자는 다음 작업 틱에 관측을 끝내고 복귀한다. 반대편/후방 접촉과 실제 인접 피격 긴급 대응은 유지하며, 진입 이후의 교전은 억제하지 않는다. 공유 확보 보고도 새로 관측한 적을 무시하고 투척 단계를 건너뛰지 못한다.

문/통로의 가까운 적은 기억을 버리는 대신 그 위치 바로 뒤의 유효한 바닥으로 목표를 최소한 이동시켜 내부 개구부에서 2칸 이상을 확보한다. 작은 방이라도 적을 관측했으면 기존 예외대로 투척을 판단한다. 실제 관측 칸이 지붕 아래에 있으면 입구 지붕 소실만으로 야외 HC 교리로 바꾸지 않는다.

본인 안전 검사는 신관이 있는 `Projectile_ModernGrenade` 계열에서만 복귀 위치를 사용할 수 있다. 복귀 거리 최대 4번의 상하좌우 이동, 비어 있고 서 있을 수 있는 두 개의 짧은 직각 경로 중 하나, 폰의 실제 칸당 이동 시간과 최단 신관 시간 비교를 요구한다. 예상 이동에 2칸과 60틱 여유를 더해 신관보다 짧아야 한다. 긴/막힌/점유된 경로, 느린 부상자, 짧거나 알 수 없는 신관은 이 예외를 허용하지 않는다. 선택 시와 발사 직전에 다시 검사하며, 복귀 자리도 기존 방·문·폭발·파편·LOS 위험 검사를 받는다. 다른 아군은 현재 위치로 계속 검사한다.

Inspect에 `support issued`, `support checks grenade/LOS/unsafe`를 추가했다. 최종 실패 사유는 전체 검사 중 아군 위험/유효 투척 위치/장비 유무를 기준으로 남겨 마지막 인원의 장비 없음이 앞선 아군 위험을 덮어쓰지 않게 했다. 후보/검사량 저장, 전역 예산과 틱당 4조합 상한은 유지한다.

검증은 관련 빌드와 `--a2-safety`, `--a1-focus`, `--a5`로 한정한다. 일반 접촉·야전·집중사격의 실제 제어 메서드가 관측된 정면 적을 가로채지 않는지, 기존 정면 교전 해제와 후방/직접 피격 예외, 최소 거리 목표, 짧은 복귀/신관/막힌 경로, 실제 inventory/category 판별의 LOW MK II/MK III와 HC 선택, 상태 저장을 검사한다. 전체 Unity 폰의 생성·작업 실행은 약식 F54에서 사용자가 재확인한다. 성능 캠페인은 실행하지 않는다.
