# 최적화 전술 AI 검증 기준

2026-10-11 사용자 지침을 반영한다. 정기 성능 테스트·자동 프로파일링·Vanilla/New CPU 대조·반복 부하 행렬은 현재 계획에서 제외한다. 사용자가 직접 플레이하며 성능을 확인하고, 문제가 보고된 경우에만 그 부분을 조사한다. 검증은 역할을 나눈다. 메서드·실행 흐름 분석과 세이브 안정성처럼 복잡한 검증은 에이전트가 직접 담당하고, 플레이로 약식 확인할 기능은 목록으로 분리해 사용자가 테스트한다. 기존 R7은 사용자 판단으로 완료했고 이 규칙을 후속 계획에 적용한다.

## 검증 역할 분담

| 담당 | 범위 | 진행 방식 |
|---|---|---|
| 에이전트 | 빌드·관련 기존 검사, 메서드/실행 흐름 분석, 저장 데이터·작업 소유권·참조 복구 등 세이브 안정성 | 변경과 관련된 복잡한 항목을 직접 분석·검증하고 결과/한계를 기록 |
| 사용자 | 관측·대형·이동·돌파·투척·장비·편제 등 약식 기능 테스트 | 별도 목록의 장면과 기대 동작을 보고 플레이에서 확인 |
| 사용자 → 에이전트 | 성능 문제 | 사용자가 성능을 확인해 문제를 보고하면 에이전트가 해당 메서드/상황만 조사 |

## 변경 후 기본 확인

- 코드 변경에는 빌드와 변경 범위에 필요한 기존 검사만 실행한다. 문서 변경은 내용·링크·diff 확인으로 끝낸다.
- 게임에서 약식으로 확인할 수 있는 동작은 [별도 기능 목록](습격%20기능%20약식%20테스트%20목록.md)에 장면·기대 동작·미실행 상태로 기록한다. 목록의 완료를 기다리며 매 작업 구간을 멈추지 않는다.
- 약식 기능 목록은 사용자가 실행한다. 에이전트는 같은 플레이 테스트를 별도 게임 실행으로 반복하지 않고, 사용자 결과가 오면 해당 문제를 처리한다.
- 에이전트의 메서드 분석·세이브 안정성 검증은 변경이 영향을 주는 흐름과 상태에 한정한다. 전체 44개 기능 시험이나 모든 저장 상태의 반복 행렬을 기본 작업에 넣지 않는다.
- 완료 작업은 빌드와 변경에 필요한 에이전트 담당 검증 후 커밋하고, 사용자 기능 확인은 미실행 목록으로 남긴다. 사용자 테스트의 완료를 기다리며 다음 개발 구간을 보류하지 않는다. 복잡한 검증에서 확인된 실제 오류는 해당 변경에서 해결한다.

세이브 안정성은 사용자에게 넘기거나 검증에서 제외하는 항목이 아니다. 에이전트가 변경한 저장 데이터·참조·작업 소유권·복구 전이를 검토하고, 필요한 경우 영향을 받는 상태의 저장/로드를 직접 검증한다. 저장 상태를 바꾸지 않은 작은 수정마다 무관한 반복 로드 시험을 추가하지 않는다. 기존 도구를 재사용하고, 미검증 범위는 안정성 합격으로 표시하지 않는다.

## 사용자가 성능 문제를 보고했을 때

발생 상황·폰/분대 수·증상·가능하면 로그나 기존 측정값을 바탕으로 관련 메서드만 선택한다. 재현과 짧은 수집에 필요한 범위를 먼저 좁히고, 비용 원인을 해결하는 데 충분하면 수집을 종료한다. 대규모 반복 행렬은 자동으로 시작하지 않는다.

측정을 실제 수행하는 경우에는 기존 Core 레퍼런스 대비 메서드 경과 비용과 호출 수를 우선 기록한다. Core 비율과 OS CPU 비율은 구분하며 부모/자식 inclusive 시간을 합산하지 않는다. 직접 CPU 대조가 필요한 경우에만 해당 상황의 짧은 대조를 사용한다. 미측정 또는 단일 결과를 정식 반복 합격으로 표시하지 않는다.

## 유지할 설계 원칙과 과거 자료

CPU와 틱 지연을 낮추는 설계 우선순위, 제한된 후보·낮은 갱신 빈도·전역 작업 예산은 유지한다. 바닐라 대비 2배 이내는 설계 목표이며 의무 측정 게이트가 아니다.

기존 프로파일러·실행기·원본·비교 결과는 보존한다. 중단된 큐를 자동 재개하거나 남은 24그룹/96회 수집을 의무로 요구하지 않는다. 이 범위를 제외한 것은 측정 완료 또는 반복 합격을 의미하지 않는다.
