# 최적화 전술 AI 검증 기준

2026-10-11 사용자 지침을 반영한다. 정기 성능 테스트·자동 프로파일링·Vanilla/New CPU 대조·반복 부하 행렬은 현재 계획에서 제외한다. 사용자가 직접 플레이하며 성능을 확인하고, 문제가 보고된 경우에만 그 부분을 조사한다. 이 규칙은 후속 계획과 R7에 동일하게 적용한다.

## 변경 후 기본 확인

- 코드 변경에는 빌드와 변경 범위에 필요한 기존 검사만 실행한다. 문서 변경은 내용·링크·diff 확인으로 끝낸다.
- 실제 게임 확인이 필요한 경우에는 변경한 기능을 확인하는 작은 대표 사례만 짧게 수행한다. 기능 확인을 CPU 수집이나 전체 회귀 큐로 확대하지 않는다.
- 기능 확인에서 새로운 오류나 진행 불가가 발견된 경우에만 관련 확인을 추가한다. 전체 44개 기능 시험과 장시간 게임 실행을 기본 작업에 넣지 않는다.
- 완료 작업은 관련 확인 후 커밋하고, 아직 직접 확인하지 않은 범위를 분명히 기록한다. 성능 측정을 하지 않았다는 이유로 완료나 다음 단계 진행을 보류하지 않는다.

## 사용자가 성능 문제를 보고했을 때

발생 상황·폰/분대 수·증상·가능하면 로그나 기존 측정값을 바탕으로 관련 메서드만 선택한다. 재현과 짧은 수집에 필요한 범위를 먼저 좁히고, 비용 원인을 해결하는 데 충분하면 수집을 종료한다. 대규모 반복 행렬은 자동으로 시작하지 않는다.

측정을 실제 수행하는 경우에는 기존 Core 레퍼런스 대비 메서드 경과 비용과 호출 수를 우선 기록한다. Core 비율과 OS CPU 비율은 구분하며 부모/자식 inclusive 시간을 합산하지 않는다. 직접 CPU 대조가 필요한 경우에만 해당 상황의 짧은 대조를 사용한다. 미측정 또는 단일 결과를 정식 반복 합격으로 표시하지 않는다.

## 유지할 설계 원칙과 과거 자료

CPU와 틱 지연을 낮추는 설계 우선순위, 제한된 후보·낮은 갱신 빈도·전역 작업 예산은 유지한다. 바닐라 대비 2배 이내는 설계 목표이며 의무 측정 게이트가 아니다.

기존 프로파일러·실행기·원본·비교 결과는 보존한다. 중단된 큐를 자동 재개하거나 남은 24그룹/96회 수집을 의무로 요구하지 않는다. 이 범위를 제외한 것은 측정 완료 또는 반복 합격을 의미하지 않는다.
