# 야전 AI 최종 목표와 바닐라 기반 설계 — 2026-10-14

최초 작성은 설계이며, 2026-10-14에 W0~W2를 구현했다. 2026-10-15 W3 선제방어·방어적 명사수 태그와 W4 통신에 따른 엄호 교대도 구현했다. CQB의 동작 사이 정지/판단 지연 개선은 미룬다. 이후 야전 구현의 목표·성공 기준은 이 문서를 우선한다. 이전 모루와 망치 구현·검토 문서는 Git 이력에서 확인한다.

## W0~W2 구현 현황

- W0: 실제 방향 엄폐와 도착을 확인한 경우만 Fixed로 기록한다. fallback Wait·이동 실패는 Uncovered이며 고정 복귀 자리가 아니다. 첫 실패는90틱, 반복 실패는900틱 유예한다. controller의 직접 Job 발급을 제거하고 기존 safety-first JobTracker 어댑터 한 곳에서 작업을 공급한다. 유효 이동/조준은 유지하며 예산 거절 시 현재 작업을 지킨다.
- W1: 같은 조의 인접 밀집을 피하고 관측 적 방향의 앞뒤 겹침에 감점을 준다. 제한된 직접 엄폐 요청으로 바닐라 현재 자리 사격 shortcut을 우회한다. 우회조는 작은3~4인 규모를 유지하며, 연결된 바닥의 엄폐 footprint와 개인 간격을 사용한다. 유효 측면 사격을 확보하면360틱 같은 고정 타이머만으로 복귀하지 않는다. 엄폐/진행/지원이 없는 기동은 제한적으로 중단한다.
- W2: 실제 LOW 음성/HIGH 장착 무전 channel을 통해 준비 인원·대표 구역·기동 상태를 값으로 공유한다. 조정자는 전달된 보고로 다른 분대를 고르고 제안→수락→실행 확정 후에만 우회를 시작시킨다. 지휘 분대 자신이 사격하지 못해도 보고된 다른 지원 분대를 사용할 수 있다. 한 그룹에 새 합의 우회는1개이며 조정자는 상대의 살아 있는 roster를 직접 읽지 않는다. 합의된 분대는 가용 총기 인원 전체로 움직이며 일반 임시 조보다 넓은 엄폐 footprint를 사용한다.
- 다른 분대가 보고한 구역과 적 방향의 앞뒤 겹침을 새 엄폐/우회 후보에 반영한다. 연락 전에는 독립 운용하며 합류 전에 이미 시작한 기동은 안전하게 끝낼 수 있다. 명령은 epoch/번호/구역/방향/유효기한으로 검증하고 중복·변형·만료·잘못된 발신자에 의해 재출격하지 않는다. 실행 전 합의 임무는2400틱 유효하고 새 요청 간격은1800틱이다. 분대 해산 시 관련 명령/보고를 정리한다.
- 기본 우회 구역 폭/깊이는6/4, 합의된 분대 우회는12/8이다. 엄폐 후보 최대64개·연결 조사96칸/기회, 우회 후보24개·4개/기회, 최종 대표 도달성 확인 후 개인 Goto만 발행한다. LOW 공유 구역 후보도24개·4개/기회로 줄였고 구역 이동은1회로 제한했다. 배치가 항상 성공하거나 피탄을 막는 고정 간격이라는 뜻은 아니다.
- HIGH의 실제 교전/피격 상황에서는 정지한 플레이어 상대도 적극 기동할 수 있다. 먼 단순 관측으로 공격 접근을 멈추지 않는 기존 규칙은 유지한다. 방향 엄폐 유지·투척·의료·회피·C4·CQB 소유권은 기존 안전 제어를 따른다.

검증: 최종 빌드 경고/오류0. `--field-w2`의 보고 기반 배분·수락/확정·중복/변형/만료·native Scribe 임무/구역 복원 검사와 관련 기존 야전·협력·작업 예산 검사를 통과했다. W0/W1에서도 관련 폭발 회피·집중 사격·수류탄 검사를 통과했다. 전체 Unity 세이브 재생/게임 대형·경로 재현/CPU 실측은 수행하지 않았다. 실제 플레이 확인은 단일 약식 목록의 F75~F80·F84에 맡긴다.

아래의 원인 표는 개편 전 코드의 문제 경로이며, 목표·설계와 확정된 구현 현황을 함께 보존한다. 기존 홀짝/240틱 타임아웃 교대는 W4에서 제거했다. 구현 세부값은 현황을 우선하고 실제 게임 확인은 단일 약식 목록에서 관리한다.

## W3 구현 현황 — 2026-10-15

접근하는 적의 관측 이력이 있으면 사거리 밖에서도 먼저 엄폐를 준비한다. 먼 정지/횡단/이탈 관측만으로 공격 임무를 멈추지는 않는다. LOW 공유 탐색과 HIGH 조별 연결 엄폐 목록을 사용하며, HIGH의 빈 구역은 반경50 내 거친24후보를4개씩 확인하고 상위3개만 도달성 검사한다. 조별 이동은1회이고 fallback을 엄폐 성공으로 기록하지 않는다. 현재 방향의 실제 엄폐 기능 상실/열린 문은 개인 재선정을 요청한다.

명시적인 `aiModeTags/Defensive`를 M1D·M1903A4·M1918A2 HAR·M1919A6에만 붙였다. 모드는 즉시 선택하며 실제 연사/무기 재사용 대기 중에는 바꿀 수 없다. 전환 시 무기의 웜업을 취소한다. 정지120틱 준비가 끝난 뒤 특수 사격을 사용하고 준비 중에는 일반 사격도 하지 않는다. 이동은 모드 선택을 유지한 채 준비만 초기화하며 전환/준비 Job이나 이동속도 감소가 없다. 담당 해제는 AI 소유 모드만 정리하고 재사용 대기 중이면 만료 뒤 정리한다. 수동 전환은 소유권을 가져가며 태그 없는 HIGH 무기는 자동 전환하지 않는다. 관측 갱신 때 실제 장착 Verb의 사거리를 갱신한다.

검증: 명사수 모드 개편 후 빌드 경고/오류0, `--field-w4`의 접근/실제 장착 무기 즉시 전환·연사/재사용 대기 거절·웜업 취소·정지 준비·이동 재준비·사격 게이트41개 검사와 관련 기존 검사를 통과했다. 실제 게임 대형·전환·긴급 회피는 F85~F87에서 사용자 확인한다. Unity 전체 세이브/CPU 실측은 하지 않았다.

정지 준비는 `stationaryPreparationTicks`로 무기마다 지정하며 기본0틱이다. M1861·M1873·M1D·M1903A4·HAR·M1919A6에120틱을 적용한다. 준비 중에는 일반 사격도 대기하고 완료 후 기존 사격 웜업을 시작한다. 장착 무기의 기존 tick과 이동 시작/정지 사건으로 개인 시계만 갱신하며, 저장 시 모드·정지 시계·AI 소유/지연 해제 상태를 보존한다. 전체 Unity 세이브 재생과 실제 플레이는 별도이고 F93~F94에 남긴다.

## W4 구현 현황 — 2026-10-15

- 이동 구간마다 제안→수락→출발 전달→이동조 엄폐/엄호 준비 보고→후속 출발 전달→완료 보고로 진행한다. 처음 제안·수락만으로 움직이지 않는다. HIGH 단일 분대는 실제 화력조가 본대 엄호 아래 기동하고, 그 조가 실제 교차 사격을 확보하면 예비 화력조를 사용할 수 있다. 합의된 HIGH 전체 분대 기동에서는 화력조1과 나머지 실제 조를 묶어 교대한다. LOW 임시4인 조는 두 묶음이 지원 가능할 때 분리하고, 부족한3~4인 조는 본대 엄호 아래 함께 짧게 이동한다. 홀짝 순서·시간만으로 후속 인원을 보내지 않는다.
- 각 묶음의 살아 있는 연락 담당1명끼리 송신과 전달 모두 실제 channel을 검사한다. LOW는 doctrine 음성 거리·LOS·연막 차단, HIGH는 실제 장착 무전·네트워크·거리·신호 상태를 따른다. 태블릿은 사용하지 않는다. 담당자가 바뀌거나 channel이 달라지면 기존 pending 메시지는 무효다. 연락 단절 시 이미 출발한 인원은 구간을 마치고 엄폐를 유지하지만 새 역할/구간은 합의 전 시작하지 않는다.
- 분대 간 임무에 지원 분대 ID를 포함한다. 전달된 구역의 준비 보고로 다음 구간을 허가하며 상대 roster를 직접 읽지 않는다. 우회 분대가 엄호를 확보하면 기존 지원 분대를 다음 이동자로 선택할 수 있다. 조정 분대 자신이 움직이는 경우도 지원 분대의 수락→실행 확정 전달→확인 회신 후에만 출발한다. 완료 확인을 전달받기 전에는 다음 역할 교환을 발행하지 않는다. 준비된 역할 교환은 기존1800틱의 독립 출격 제한을 다시 기다리지 않는다.
- 준비는 실제 방향 엄폐＋자신이 소유한 Wait_Combat＋현재 사격 가능/최근 실제 발사 기록이다. 조준·쿨다운·연사 길이로180~1200틱의 발사 여유를 계산한다. 아직 교전하지 않은 접근 적에 대한 선제 엄폐도 준비로 인정한다. 실제 발사를 만들어 내거나 적의 제압 상태를 강제로 바꾸지는 않는다.
- 명사수 모드가 정지 준비 중인 인원은 엄호 준비 수에 넣지 않는다. 엄폐 판정은 바닐라 `CoverUtility.CalculateOverallBlockChance(cell, observedPosition, map)`를 사용한다. 가짜 표적 폰은 없다. 개인 준비/도착 엄폐를30틱 재사용하고 선택한 캐시 자리만 다시 확인한다. 이미 부서진 엄폐 후보는 공유 목록에서 제거한다. 주기적으로 전체 구역을 다시 만들지 않는다.
- 로컬 구간에는 pending 값 패킷1개만 두고 전역 통신 예산을 공유한다. 전달 지연은 doctrine 값(기본 음성40/무전20틱), 조사 간격15틱, 패킷/준비 보고 수명180틱이다. 분대 간 임무와 보고는 기존 전역64개 큐를 쓴다. 유효 엄폐의75%가 준비되면 후속을 허가하며 낙오 인원도 현재 허가 구간을 계속 마칠 수 있다. 지원/통신 없이 시간만 지났다는 이유로 후속을 보내지 않고 구간이1800틱 정체하면 기동을 중단·복귀한다. 짧은 신호 단절에 즉시 원점으로 돌아가지는 않는다.
- 구간·조 구성·보고·pending 채널/연락 담당/지연·임무 지원자·완료 확인·AI 모드 소유권을 저장한다. 개발자 `Inspect squad commands`에 leg/bound 단계, 분리 여부, pending channel과 준비 수를 표시한다.

검증: 빌드 경고/오류0. `--field-w4`의47개 교대/지연/단절/중복/낡은 보고/실제 actor 이동 허가/분대 역할 교환/native Scribe 검사와 관련 W2·W3·야전·협력·수류탄 회피·투척·전역 예산 검사를 통과했다. 과거 홀짝 이동 테스트를 현재 프로토콜/actor 허가 검사로 교체했다. 실제 게임 경로·배치 성공·전체 Unity 세이브 재생·CPU 감소 실측은 수행하지 않았다. 약식 확인은 F88~F92에 추가한다. CQB C단계는 이번 범위에서 구현하지 않았다.

## 최종 목표와 우선순위

| 우선순위 | 목표 | 플레이에서 보여야 하는 결과 |
|---|---|---|
| 1 | 일부 인원의 우회와 사격각 분리·밀집에 따른 추가 피탄 감소 | 여러 분대가 같은 전선/같은 구역에 몰리지 않는다. 본대가 교전하는 동안 일부 분대/조가 측면으로 이동하여 같은 적 구역에 다른 방향에서 화력을 집중한다. 우회가 불가능해도 적의 빗나간 탄이 주변의 다른 우리 폰에게 맞기 쉬운 밀집/앞뒤 겹침 배치를 줄인다 |
| 2 | 선제방어 | 사거리 밖에서 접근하는 적을 관측하면, 피격 전에 적 방향에 유효한 엄폐가 있는 구역을 확보한다. 방어적 태그의 총기는 배치 완료 후 명사수 모드를 미리 켠다 |
| 3 | 엄호와 이동의 교대 | HIGH의 화력조 및 통신 가능한 LOW 임시 조/분대가 한쪽은 사격을 유지하고 다른 쪽은 다음 구역으로 이동한 뒤 역할을 바꾼다 |

대형의 직선/호 모양이나 정확한 슬롯 도착은 목표가 아니다. **조별로 엄폐를 잡고, 적의 빗나간 탄이 주변 인원에게 다시 명중하기 쉬운 밀집을 줄이면서, 일부가 다른 사격각을 만드는 것**이 목표다. 화력 집중은 사수들을 한곳에 모으는 것이 아니라 떨어진 사격 구역에서 같은 적 구역을 타격하는 것이다. 호가 만들어져도 효과적인 사격각·엄폐·역할 분리가 없으면 성공으로 판정하지 않는다. 모루가 좋은 엄폐에서 계속 사격하는 것은 정상이며, 전체 인원이 같은 줄에 고정되어 다른 각도를 만들지 못하는 것이 문제다.

최적화 기준은 기존 바닐라 대비 전투 AI CPU 사용시간 2배 이하 목표를 유지한다. 정확한 전술 최적해보다 제한된 후보, 오래 유지하는 계획, 이벤트 갱신, 바닐라 실행 재사용을 우선한다. 이번 설계에서 성능 달성을 측정하거나 보장하지 않는다. 매 단계 성능 프로파일링은 필수 작업에 넣지 않으며 사용자가 성능 문제를 보고하면 관련 구간만 조사한다.

다음은 소스에서 확인한 경로다. 특정 게임 장면을 재현해 유일한 원인으로 확정한 것은 아니다.

| 현재 코드 | 문제 가능 경로 | 설계에서 바꿀 기준 |

## 바닐라에서 재사용할 부분

Lord/Duty는 집단 임무와 초점을 주고, 개인 ThinkTree/JobGiver가 Job을 고르며, Driver/Toil·PathFollower·Verb/Stance가 실행한다. 새 야전 계획은 **역할·구역·다음 목적지**를 결정하고, 그 안의 이동·사격 실행은 이 구조에 맡긴다. 기존 전술/CQB/의료/폭발 작업과 소유권을 분명히 나누는 야전 실행 어댑터가 필요하다.

| 기능 | 재사용 | 별도로 필요한 제한/판단 |
|---|---|---|
| 실제 사격 | Wait_Combat의 자동 표적·TryStartAttack·warmup/burst/cooldown | Wait 자체는 엄폐 이동 기능이 없다. 이를 엄폐 준비 성공으로 보지 않음 |

| 이동 | Goto + 개인 PathRequest/PathFollower | 목적지를 줄 뿐 전체 경로를 매 틱 강제하지 않음. 진행 중 작업은 유지 |
| 근접/급박한 공격 | 바닐라 meleeThreat·기존 집중 사격 대응 | 야전 복귀가 긴급 대응을 덮어쓰지 않음 |

현재 칸에서 쏠 수 있으면 바닐라 AIFightEnemy가 새 사격점 검색을 생략할 수 있다. 선제방어/엄폐 미확보 단계는 그 TryGiveJob 전체에 위임하지 않는다. 현재 보이는 유효 적에게 사거리가 닿으면 **직접 제한된 CastPositionRequest로 엄폐를 찾는다.** 아직 사거리 밖이거나 최근 위치 기억만 있으면 **셀 후보에 방향 CoverUtility를 적용하여 cover 배치만 먼저 수행**한다. CastPositionRequest.target은 Thing이므로 기억 좌표/가상 칸을 그대로 넣지 않고 가짜 Pawn도 만들지 않는다. 후보 칸을 LocalTargetInfo로, 관측 위치/방향의 대표 칸을 shooterLoc으로 사용해 엄폐 기여를 평가할 수 있다. 실제 공격은 바닐라가 현재 유효 적을 획득해야 하며 기억 위치에 가상 표적을 만들어 총을 쏘지 않는다.

## 1순위: 조별 협력 유지와 분산 배치·사격각 분리

**조 내부는 같은 임무와 연락 가능한 범위를 유지하되 개인 간 간격을 두고, 조/분대 간에는 다른 구역과 각도를 잡는다.** 서로 붙어서 촘촘히 서는 것이 응집의 뜻이 아니다. 모든 폰을 넓은 타원에 독립적으로 풀어 놓거나 한 줄/호의 개인 슬롯을 고정하는 방식도 쓰지 않는다. 화력 구역 중심은 지휘용 지향점이며 폰이 반드시 서야 하는 칸이 아니다.

### 빗나간 탄의 주변 인원 피탄을 줄이는 기준

사용자 교정: 여기서 줄일 피해는 **적이 우리 폰 하나를 겨눴지만 빗나간 탄이 옆/뒤의 다른 우리 폰에게 맞는 것**이다. 아군이 아군을 쏘는 오사 억제가1순위 목표가 아니다. 앞선 설계의 발사자 주변5칸을 근거로 한 촘촘한 조 배치 제안은 철회한다. 적 발사점의 근거리 중간 충돌 규칙을 우리 조 내부의 안전 간격으로 적용할 수 없다.

바닐라 Verb_LaunchProjectile의 wild miss/forced miss 등은 조건에 따라 NonTargetPawns hit flag를 포함한다. Projectile은 비행 경로의 중간 폰 또는 빗나간 도착 칸의 폰을 검사할 수 있으므로 원래 목표에게 명중하지 않은 사격이 다른 인원에게 피해를 줄 수 있다. 모든 빗나간 탄이 주변 반경 안의 폰을 자동으로 맞히는 규칙은 아니며, hit flag/탄도/착탄 칸/몸 크기/자세 등에 따라 달라진다. 따라서 밀집을 낮추는 것은 추가 피탄 기회를 줄이는 근사이며 안전을 보장하는 고정 간격은 없다. CE 등 다른 탄도 구현은 별도다.

배치 후보는 방향 엄폐를 우선하되, 가까운 우리 인원 수와 알려진 적 사격 방향에서 우리 인원들이 앞뒤로 겹치는 정도에 감점을 준다. 같은 엄폐를 공유하더라도 옆 칸에 몰아넣지 않고 가능한 간격을 둔다. 좋은 엄폐를 버리고 노출된 곳으로 산개시키지는 않는다. 한 구역의 안전한 수용 인원이 부족하면 일부를 다른 엄폐 구역으로 보내는 것을 우선한다. 아군 사선 방해/오사 검사는 부차적 안전 조건으로 유지하고 빗나간 적탄의 피탄 감소와 구분한다. 피해/명중률/hit flag를 바꾸거나 AI 폰에게 면역을 주지 않는다.

### 구역 선정과 역할

1. 공유된 관측에서 적의 대표 교전 구역·접근 방향을 정한다. 모든 적의 현재 위치를 읽지 않고 최근 관측/실제 발사에 사용한 확인된 위치를 사용한다.
2. 이미 사격 가능한 엄폐 조를 모루로 유지한다. 자동화기·긴 사거리 무기·부상자/의료 담당의 이동 부담도 반영한다. 더 좋은 후보가 생겼다는 이유로 모루 전원을 다시 이동시키지 않는다.
3. 한쪽 측면의 **연결된 엄폐 구역**을 소수 뽑아 모루와 다른 각도, 실제 조 무기의 사거리, 도달성, 간격을 둔 엄폐 수용 인원, 다른 우리 조와 같은 적탄 경로에 겹치는지 순으로 검사한다. 연결은 이동/구역 연결성이며 조원끼리 인접해서 서야 한다는 조건이 아니다. 한 무기의 최단 사거리만으로 조 전체를 탈락시키지 않고 필요한 주력 사수가 사격 가능한지 판단한다.
4. 우회측과 최종 구역을 잠그고 최대2~3개의 엄폐 지향점을 준다. 45~90도 각도를 우선하고 지형상 어렵다면 약20도 이상 대체각을 허용한다. 숫자는 구현 초안이며 실제 지형에 맞춰 조정한다. 180도 포위나 아군을 향한 교차 사격을 목표로 하지 않는다.
5. 일부 조만 이동한다. 본대 앞 사격 구역을 가로지르는 후보는 제외/감점하고 적 측면 쪽으로 돌며 접근한다. 낙오 하나 때문에 모든 조를 이전 칸으로 돌리지 않는다.
6. 측면 도착 후 실제 사격 가능한 인원과 발사 피드백으로 교차 사격을 확인한다. 해당 조는 새 모루/지원이 될 수 있다. 우회 완료 뒤 반드시 원점 복귀하는 타이머를 두지 않는다. 교전 종료·전진·상실/위험·임무 변경으로만 재편한다.

우회가 불가능하면 소수의 다른 엄폐 구역으로 사격각을 조금 나누거나, 현재 엄폐 안에서 간격을 확보해 적 사격 방향의 앞뒤 겹침/주변 밀집을 줄인다. 안전한 자리도 없으면 우회를 생략하고 바닐라 교전을 유지한다. 대체를 찾을 때마다 좌우를 바꾸는 반복 계획은 하지 않는다.

| 규모 | 기본 역할 배분 |
|---|---|
| LOW 12인 단일 분대 | 본대 모루＋3~4인 임시 우회조. 본대 자동화기가 하나뿐이면 남긴다. HAR 동행은 본대 지원 화기가 남을 때 우선 |
| LOW 6인 정찰분대/큰 손실 | 본대 지원과 기동조 양쪽이 유효해야 분리. 안 되면 우회 없이 작은 구역의 일반 교전. 분리 자체를 강제하지 않음 |
| HIGH 13인 분대 | 기존 4인 화력조3개를 모루/우회/지원·예비로 활용. 분대장은 임무를 연결하고 새 인원을 생성하지 않음 |
| 여러 분대 | 연락으로 합의한 그룹 안에서 일부 분대만 우회, 나머지는 모루/지원. 한 그룹에 우회 임무는 초기 최대1개. 우회 분대 내부의 추가 분할은 필요할 때만 |

조 내부 배치는 고정된3~4칸 밀집 영역으로 제한하지 않는다. 조원 사이 약2~4칸 간격을 후보 선호의 초안으로 두되 엄폐·연락 거리·지형을 우선하며, 매 틱 이 간격으로 강제 복귀시키지 않는다. 이는 피탄이 사라지는 임계값이 아니다. 좁은 엄폐에서 간격이 나오지 않으면 두 연결 가능한 엄폐 구역으로 나누거나 한 구역의 인원을 줄인다. 같은 칸 중복은 배치 예약에서 제외한다. 엄폐/연락 때문에 일시적으로 좁혀지는 상황과 상시 밀집 배치를 구분한다.

밀집/적 사격 방향의 겹침은 모든 pawn 쌍/매 탄환 검사로 풀지 않는다. 그룹의 엄폐 구역과 이동 중 구역을 값 형태로 공유하고, 관측한 적 구역→우리 후보 구역 선분을 폭이 있는 띠로 근사해 다른 우리 조와 앞뒤로 겹치는지 검사한다. 최종 개인 후보 몇 개에만 작은 주변의 우리 인원 수·가까운 점유와 방향 엄폐를 확인한다. 아군의 주력 사격점→적 구역 사선 방해는 별도의 부차 검사다. 다른 임무 아군은 최종 구역의 제한된 주변 검사로 확인한다. 방향이 조금 달라질 때마다 이동하지 않고 확정 뒤에는 지속 위험/방해·주요 적 방향 변화 때만 재검토한다.

## 2순위: 사격 전에 엄폐를 확보하는 방어

기존120칸 관측은 유지하되 넓은 감지와 전원 정지 조건을 분리한다. 관측한 적이 접근하고 있거나 수비 임무/지원 준비/실제 피격이면 선제방어를 검토한다. 먼 정지 적을 한 번 봤다는 이유로 공격 목표를 포기하고 무한 대기하지 않는다. 공격 임무에서 무리한 선제 배치는 진행 경로 근처의 엄폐 접근으로 처리한다.

이 설계에서는 LOW/HIGH와 AI/플레이어 상대 모두 실제 교전의 사격각 분리·엄폐 준비 목표를 갖는다. 기존 HIGH의 **플레이어55칸 접근만으로 적극 기동을 허용**하던 규칙은 독립 정책으로 정리한다. 실제 교전 중 우회는 상대 세력과 무관하게 허용하고, 사격 전 먼 관측에 의한 전원 방어 전환은 접근/임무/피격 근거를 요구한다. 기존55칸 제한을 모든 야전 교전의 일괄 진입 조건으로 유지하지 않는 것이 새 설계 제안이다.

### 엄폐 구역과 개인 위치를 분리

- 분대/조 공유 구역을 먼저 고른다. 현재 구역의 방향 엄폐가 부족하면 기존처럼 주변 최대50칸의 소수 구역 후보를 분산 검사한다. 반경50 모든 타일에 LOS/CanReach를 돌리는 방식은 사용하지 않는다.
- cheap 검사로 방향 엄폐·서 있을 칸·연결성·간격을 둔 수용 인원·목표 방향 이동량·관측 적 방향의 앞뒤 겹침/우리 인원 밀집을 평가한다. 아군 사선 방해는 부차 검사다. 상위2~3개에만 대표 인원의 도달성을 확인한다. 모드 Danger.Some을 적 사격 위험의 대체값으로 쓰지 않는다.
- 선택한 구역에 접근한 개인은 작은 반경의 CastPositionFinder/방향 CoverUtility로 실제 엄폐를 찾는다. 사거리 밖 적의 예상 접근 방향에서는 cover 배치만 먼저 가능하다. 사격 불가가 곧 엄폐 불가인 것은 아니다.
- 구역의 모든 인원이 동시에 도착해야 다음 단계로 넘어가는 전체 barrier는 두지 않는다. 도착한 사람은 엄폐 확인·모드 준비/사격을 시작하고 후속은 진행한다.
- **엄폐 성공**은 도착＋적 방향에 유효한 cover＋walkable/예약 충돌 없음이다. fallback Wait나 실패 Goto는 성공이 아니다. 처음부터 엄폐가 없는 사람을 Fixed로 영구 잠그지 않는다.
- 최초 탐색 실패는 같은 요청 반복 대신 작은 대체 후보를1회 검사하고, 다수가 실패하면 공유 구역을1회 옮긴다. 그래도 없으면 Uncovered로 제한된 바닐라 교전/공격 진행을 유지하고 재검토는 중요 이벤트 또는 긴 backoff 후만 한다.

기존 LOW 모루의25×12 활동 타원은 대략적인 분대 임무 범위로 사용할 수 있지만 개인 엄폐 슬롯/복귀 강제 범위가 아니다. 조 구역·이전 엄호 구역·다음 이동 구역을 우선하고, 고정 반경 때문에 유효 우회 후보를 모두 거부하지 않게 한다. 기존 FieldCombatFloor의 타원 경계와 우회 가능 범위는 한 곳에서 판정하도록 설계를 정리한다.

### 유지와 재선정

배치 성공 후에는 위치를 유지하고 바닐라 사격을 사용한다. 임시 LOS 소실·표적의 작은 이동·전략 검토 주기만으로 새 위치를 찾지 않는다. 재선정은 사용 중 엄폐 파괴/열린 문 등 cover 기능 상실, 현재 칸 불통, 임무/대표 사격 방향의 큰 변경, 장기간 유효 사격 불가, 폭발·급박한 근접 위험 같은 명시 이유에 제한한다. 파괴 시 해당 폰만, 구역 자체가 쓸모없어졌으면 해당 조만 움직인다.

모드 준비·수류탄·치료·회피 뒤 복귀는 기존 엄폐가 유효할 때만 한다. 불통 자리에 반복 복귀시키지 않는다. 진입/CQB가 소유한 Job은 야전이 덮어쓰지 않는다.

### 방어적 명사수 태그

명사수 모드는 `TacticalPrecisionFire`의 신체 부위 조준이 아니라 **CompSharpshooterWeapon의 altMode**를 뜻한다. 총기 comp 속성의 `aiModeTags/Defensive`로 자동 선택 대상을 지정한다. spawn용 weaponTags와 분리하고 기본은 태그 없음으로 둔다. 태그를 붙인 무기만 NPC 야전 AI가 자동 전환한다. Def 로딩에서 flag로 해석해 매 틱 문자열을 조회하지 않는다.

| 시점 | 처리 |
|---|---|
| 엄폐 배치/고정 엄호 완료, 아직 교전 전 | 현재 장착 무기·CanUseSharpshooterMode·AltVerb/모드 지원을 확인. Defensive이며 OFF면 즉시 ON 선택. `stationaryPreparationTicks` 동안 정지 준비 후 사격 |
| 이미 ON | 전환 작업을 추가하지 않음. 기존 상태를 유지 |
| 이동조 출발/계획된 재배치 | 모드 선택을 유지하며 준비만 초기화. 준비는 이동을 막지 않으며 다른 조의 엄호는 유지 |
| 급박한 회피/도주/근접 위협 | 긴급 Job 우선. 준비는 Job/이동 잠금을 가지지 않으며 이동 시작 시 무기 웜업/정지 준비 초기화. 이동속도 감소 없음 |
| 무기 교체/담당 해제/교전 종료 | AI 소유 모드만 정리. 활성 재사용 대기는 유지하고 끝난 뒤 정리. 플레이어 강제 모드/Job을 덮어쓰지 않음 |

UI 토글과 AI 원하는 상태 요청은 같은 즉시 전환 경로를 사용한다. 이미 그 상태면 유지하며 현재 장착 무기·능력·실제 연사/재사용 대기를 검사한다. 성공한 전환은 기존 무기 웜업을 취소한다. 준비는 별도의 개인 정지 시계이며 전원 동시 완료를 기다리지 않는다. 이동/탈착은 준비를 초기화하며, 준비 완료 전에는 어떤 기존 사격 명령도 그 무기로 사격할 수 없다. 모드 전환 후 실제 EffectiveRange/이동 속도를 사용하고 계획에서 오래된 사거리를 계속 쓰지 않는다.

Defensive 태그는 M1919A6·M1918A2 HAR·M1D·M1903A4에 적용했다. 빠른 조준/짧은 사거리/더블탭 모드까지 전부 Defensive로 취급하지 않는다. 이동속도 감소는 모두 제거했다. 별도 정지 준비는 M1861·M1873까지 포함한6종에120틱을 적용하며 나머지 모드는 기본0틱이다. M16 계열 등 HIGH 무기도 실제 alt-mode 이익을 확인하고 명시 태그가 있는 것만 적용한다. 태그가 없어도 엄폐/일반 사격은 정상 동작해야 한다.

## 3순위: 통신에 의해 합의한 엄호·이동 교대

처음에는 HIGH 화력조끼리 또는 통신 그룹의 분대끼리 교대한다. LOW 단일 분대의 임시3~4인 조는 인원/지원이 충분할 때 작은2개 묶음으로 교대하고, 불충분하면 본대 엄호 아래 함께 짧게 이동한다. 같은 분대라는 이유만으로 멀리 떨어진 LOW 조에 무전처럼 명령을 전달하지 않는다.

**A 엄호 → B 다음 엄폐로 이동 → B 엄폐 확보·엄호 가능 보고 → A 이동**을 반복한다. 기본은 대체 엄호자가 확보된 뒤 전환하는 방식이며 이동 도중 계속 쏘는 새 기능을 만들지 않는다. 고정 시간이 차면 무조건 교대하거나, 이동조가 중간에 적을 보았다고 조 전체가 영구 정지하는 규칙을 쓰지 않는다.

엄호 준비는 주력 사수의 현재 사격 가능/최근 실제 사격·유효 cover로 판정한다. 느린 단발총이300틱 발사 기록을 놓쳤다는 이유만으로 엄호 실패라고 하지 않고, 현재 Verb의 조준/연사/쿨다운을 포함한 여유를 둔다. 사격 전 준비 단계에서는 알려진 접근 방향에 사격 가능한 엄폐를 확보한 상태를 준비로 인정하며 실제 발사를 요구하지 않는다. 실제 제압 효과나 적 AI 강제 정지는 추가하지 않는다.

도착은 다수의 유효 엄폐 확보로 판단한다. 낙오/다운 하나 때문에 영원히 대기하지 않으며 bounded timeout 때 지원 가능한 인원으로 재편하거나 이번 전진을 중단한다. 타임아웃은 지원이 사라진 상황에서 다음 조를 무조건 보내는 허가가 아니다. 불리하면 엄호를 유지하고 기동을 중지한다.

### LOW와 HIGH의 정보 전달

- HIGH는 실제 무전 파츠/네트워크/거리와 흑점 폭발·재밍의 신호 조건을 따른다. 태블릿은 사용하지 않는다.
- LOW는 조/분대 연락 인원의 음성 거리·LOS·차단 조건을 만족해야 역할 제안/수락/출발·엄호 준비 보고가 전달된다. 기존 doctrine의 voiceContactRange를 사용하고 멀리 있는 실제 pawn 상태를 조정자가 직접 읽지 않는다.
- 분대 간에는 기존 communications 큐를 재사용하되, 단순 그룹 회원정보만이 아니라 임무 ID/버전·모루/우회/지원 역할·구역·시행 시점·유효 기한을 값으로 보낸다. 수신/수락 없이 타 분대가 곧바로 기동하지 않는다.
- LOW 임시 조 내부에도 같은 음성 가능 조건을 적용한다. 새 전원 쌍 통신망을 만들지 않고 각 묶음 연락 담당1명만 확인한다. 보고를 못 받으면 다음 엄호 교대를 추측하지 않는다.
- 연락이 끊기면 이미 합의한 한 이동 구간은 끝내 현재 엄폐를 잡을 수 있다. 새 구간/새 역할 교대는 정지하고 제한된 재접촉을 기다린다. 짧은 신호 단절 때문에 전체가 원점으로 돌아가지 않는다.
- 같은 조 안의 즉각적인 개인 사격/회피는 통신 ACK를 기다리지 않는다. 조정자 다운은 새 임무에만 선출/재합의가 필요하며 현재 유효 엄호를 취소하지 않는다.

## 실행 구조와 비용 제한

현재의 넓은 전술 시스템을 야전 때문에 다시 전부 교체하지 않는다. 야전 내부는 다음 세 책임으로 정리한다. 이름/필드는 설계 초안이며 아직 구현된 클래스가 아니다.

| 책임 | 가진 상태 | 실행 원칙 |
|---|---|---|
| FieldEngagementPlan | 관측 교전 구역·임무 ID/버전·합의된 역할·조 구역·다음 지향점 | 분대/연락 그룹 단위. 새 관측마다 전원 위치 재계산하지 않음 |
| FieldTeamOrder | 모루/우회/지원·이동/엄호·연락 담당·준비 수·마감/실패 이유 | 화력조/임시 조 단위. 준비 수와 이벤트로 진행, 독립적 바닐라 실행 유지 |
| FieldActorState | Unplaced/Seeking/Moving/Ready/Uncovered/Suspended·엄폐 참조·AI 모드 요청·현재 Job 소유권 | 폰 단위. 성공과 fallback 구분, Job 진행을 단계별 전원 barrier로 만들지 않음 |

상태 관계는 **관측 → 역할/구역 선정 → 개인 엄폐 확보**, 이후 준비된 조는 바로 **엄호 또는 우회/전진**이다. 먼저 끝난 조가 나머지 조를 기다리며 장시간 빈 Wait를 반복하지 않는다. 계획 큐 대기 중에는 유효한 현재 사격/이동을 그대로 유지한다. 아직 전투 Job이 없는 사람만 제한된 대기를 사용한다.

기존 FieldResponse/Formation/FireGroup/Post/Maneuver/FieldNativeJob의 중복 상태와 고정 fallback 경로는 이 책임에 맞춰 줄인다. 같은 폰에게 map controller와 JobTracker override가 서로 다른 다음 Job을 만드는 경쟁을 없애야 한다. **최종 Job 공급자는 하나의 야전 어댑터**로 통일하고, controller는 역할/요청을 바꾸며 다른 곳에서 같은 Job을 재발행하지 않는다. 지속 Job의 finish/도착/엄폐 상실 이벤트가 다음 작업 요청을 깨운다. 실제 근접/사격·안전 작업은 기존 실행을 우선한다.

### 계산 예산 초안

- 새 구역/우회 후보는 그룹당 최대24개, 처리당4개. 실제 엄폐 슬롯은 조별 소수 후보를 공유하며 폰마다 반경50 검색을 반복하지 않는다.
- cheap 방향 엄폐/기하/점유를 먼저 보고 상위2~3개만 CanReach/상세 LOS를 검사한다. 후보마다 FindPathNow를 쓰지 않는다. 최종 Goto만 바닐라 비동기 경로 요청을 사용한다.
- 무거운 역할/구역 재검토는90~180틱 분산 또는 중요 이벤트. 개인 엄폐물 유효성은 기존90~119틱 정도의 분산 확인/파괴 알림으로 처리한다. 사격은 바닐라 주기를 유지한다.
- 계획 진행은 fixed phase sleep을 누적하지 않는다. 필요한 보고/도착이 생기면 다음 예산 슬롯에서 처리한다. 슬롯을 기다리는 동안 기존 Job을 재시작하지 않는다.
- 초기 엄폐 탐색은 작은 반경부터1회, 제한된 대체1회, 공유 구역 이동1회로 끝낸다. 실패 원인/다음 재검토 틱을 저장해 매30틱 같은 탐색을 반복하지 않는다.
- 역할·조원·구역 인덱스는 이벤트에서 갱신하고 틱 순환에서 반복 FindIndex/OrderBy/임시 List 생성을 줄인다. 그룹 수/메시지 큐/계획 요청은 기존 상한을 유지한다.
- 관측 적 방향의 우리 조 겹침 평가는 조 구역 수에 비례하는 근사로, 개인 밀집은 최종 후보 주변의 소수 점유 검사로 제한한다. 아군 사선 검사는 부차적으로 수행한다. 전 폰의 사거리·LOS를 전 폰 쌍에 대해 계산하는 전역 위험 맵을 추가하지 않는다.
- 우선 메인 스레드에서 이 제한으로 구현한다. 이 규모의 후보24개를 위한 별도 worker/스냅샷 비용은 근거 없이 추가하지 않는다. 추후 실측에서 순수 기하 계산이 병목인 경우에만 값 배열 worker를 검토한다.

중단/죽음/해산 때 조 임무·목적지 claim·요청/모드 소유권을 함께 해제한다. 저장할 값은 역할/임무 버전·조원 ID·선택 구역·진행/마감·엄폐/무기 참조이고 runtime Job/PathRequest/임시 후보 버퍼는 그대로 직렬화하지 않는다. 로드 후 실제 상태를 검증하여 현재 엄폐·진행 가능한 Job을 살리고 무효 요청만 정리한다. 이전 야전 상태 형식의 하위 호환은 저장소 규칙상 유지할 필요가 없다. CQB 저장 형식/행동은 이번 변경 대상이 아니다.

## 구현 순서와 완료 기준

우선순위1이 최상위 목표다. 엄폐 성공/실행 소유권 분리는 그 목표의 기반이므로 별도 소규모 변경으로 먼저 끝낸다. 아래는 다음 구현 계획이며 현재 요청은 여기까지다.

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| W0 — 구현 완료 | fallback 고정 제거·성공/실패 구분·단일 야전 Job 공급 경로 | 엄폐 없는 Wait/실패 Goto를 Ready로 잠그지 않는다. 유효 Job은 예산 대기 중 지속 |
| W1 — 구현 완료 | 1순위: LOW 단일 분대/ HIGH 조의 연락 가능한 분산·다른 사격각 우회 | 본대 엄호와 일부 기동이 분리되고 측면 도착 뒤 실제 사격. 엄폐 안에서도 주변 밀집을 줄임. 자리 없음은 bounded 생략 |
| W2 — 구현 완료 | 1순위 확장: 다분대 역할 합의·우회 임무 배분·적탄 방향 겹침 억제 | 다른 분대가 합의한 우회를 수행. 전원이 같은 측면/같은 앞뒤 전선에 몰리지 않음 |
| W3 | 2순위: 접근 관측 기반 선제 엄폐 준비·방어적 태그 | 사격 전 준비 가능. 태그 총기만 미리 ON, 이동/긴급 회피/무기 변경은 안전하게 정리 |
| W4 | 3순위: 엄호·이동 교대와 LOW 음성 조건 | HIGH 조/LOW 연락 가능한 임시 조·분대에서 실제 엄호 교대. 연락 없으면 새 교대 금지 |

W1~W2의 최초 이동은 본대 엄호 아래 한 조가 함께 짧게 움직여도 된다. 복잡한 묶음 교대를1순위 완료의 필수로 두지 않는다. W4에서 교대를 완성한다. W3의 명사수 정지 준비는 전체 인원이 기다리는 새 단계나 개인의 지연 Job으로 추가하지 않는다. 구조상 분리 가능한 완료 변경마다 검증 후 `main`에 구체적인 목적의 커밋을 남긴다.

### 향후 사용자 약식 기능 확인

W0~W2 항목은 단일 [약식 테스트 목록](습격%20기능%20약식%20테스트%20목록.md)에 반영했다. W3/W4 장면도 F85~F92에 추가했다. 코드 검사 통과를 게임 확인으로 표시하지 않고 기존 완료 항목을 전부 다시 실행하지 않는다.

| 장면 | 확인할 결과 |
|---|---|
| LOW12 단일 분대, 적 정면과 측면 엄폐 있음 | 본대 모루＋일부 우회, 조의 연락/임무 유지와 개인 간격, 실제 다른 사격각 |
| HIGH13 단일 분대 | 기존 화력조 유지, 분대장 역할 연결, 한 조만 우회·나머지 지원 |
| LOW/HIGH 여러 분대 | 연락 후 일부 분대만 우회. 연락 전 독립 운용. 적의 사격 방향에서 같은 구역/앞뒤에 인원이 밀집하지 않음 |
| 근처 엄폐 없음,50칸 안에 좋은 구역 있음/전부 없음 | 좋은 구역으로 제한적 이동/없으면 bounded fallback. 탐색·Wait 고정 반복 없음 |
| 사거리 밖 적 접근/먼 정지 적 | 접근에는 피격 전 엄폐 준비, 정지 먼 관측에는 원래 공격 임무 지속 |
| Defensive 무기·태그 없음·모드 이미 ON·무기 변경 | 명시 태그만 준비, 토글 왕복 없음, 준비가 다른 조를 대기시키지 않음 |
| 모드 ON 이동·수류탄 회피·엄폐 파괴 | 이동 불능/긴급 작업 지연 없음, 해당 사용자만 재배치 |
| LOW 음성 범위 안/밖, HIGH 무전/신호 차단 | 엄호 교대의 전달 조건 일치, 단절 시 현재 구간 완료 후 새 교대 정지 |
| 한 명 늦음/다운·적 잠깐 숨음·교전 종료 | 낙오 때문에 전원 역행하지 않음, 짧은 기억 소실로 우회 취소하지 않음, 종료 후 임무 복귀 |

에이전트는 관련 메서드/실행 소유권·전환/모드·저장 상태의 필요한 분석을 맡는다. 사용자에게 맡긴 약식 기능 확인을 대신 전부 자동 재생하거나 단계마다 심층 성능 검사를 붙이지 않는다.
