# 정착지와 자연 생성 구조물 구분 방안

2026-10-11. 사용자 F16 집중 사격 테스트는 정상 작동 확인을 받았다. 같은 테스트에서 정착지 밖 자연 생성 구조물도 돌파하는 현상을 보고했다. 이 문서는 코드와 바닐라 생성/소유권 구조를 확인한 **제안이며 미구현**이다. 실제 문제 장면을 재현하거나 해결한 기록은 아니다.

## 현재 후보에 유적이 들어갈 수 있는 이유

- `TacticalCommands.Goal`은 명시 목표 또는 플레이어 소유의 이름 있는 주인 침대를 사용한다. 자연 생성 구조물이 최종 목표로 직접 선택되는 문제라고 단정할 수 없다.
- `TacticalLocalPlanner.Find`는 분대장→목표의 직선에서 처음 발견한 벽·문·벽 틈을 기준으로 후보를 만든다. 벽면 형태·자리·돌파 수단을 검사하지만 구조물의 소유 세력을 검사하지 않는다. 목표 앞에 유적이 있으면 그 유적부터 스택업/돌파할 수 있다.
- `BeginRoomClear`와 `PlanRoomFrontier`는 지붕 있는 바닥과 벽·문 연결을 기준으로 다음 방을 탐색한다. 앞서 들어간 곳이 정착지 소속인지, 단순 통과 장애물인지 구분하지 않아 그 구조물의 다른 방까지 소탕 대상으로 이어질 수 있다.
- `ReuseOpening`과 `PendingGoal`에도 같은 분류가 필요하다. 최초 후보 생성만 수정하면 이미 기록한 개구부나 방 후보로 다시 돌아갈 수 있다.

근거: [목표·재사용](../../Source/Helodrace/Tactics/TacticalCommands.cs), [최초 후보](../../Source/Helodrace/Tactics/TacticalLocalPlan.cs), [방 탐색·후속 돌파](../../Source/Helodrace/Tactics/TacticalRoomClearing.cs).

## 생성 출처보다 현재 사용 여부를 구분

바닐라 `GenStep_ScatterRuinsSimple`은 `ThingDefOf.Wall`로 지형 적합성을 확인하고 유적 스케치를 세력 없이 생성한다. 일반 벽 DefName이나 재질만으로 유적을 제외할 수 없다. 반대로 `GenStep_AncientComplex`는 `Faction.OfAncients`를 사용하므로 `Faction == null`만 검사해도 모든 자연 생성 구조물이 제외되는 것은 아니다.

`Designator_Claim.DesignateThing`은 `SetFaction(Faction.OfPlayer)`를 수행한다. 따라서 유적을 점유한 후에는 소유권도 달라진다. 필요한 기준은 “원래 자연 생성되었는가”보다 “현재 임무 대상 세력이 사용하는 구조물인가”다. 일반적인 무주인 외부 유적은 제외하고 정착민이 개조해 사용하는 유적은 포함한다.

추천하는 근거 순서는 다음과 같다.

1. **명시 목표와 최초 침대 목표가 속한 구역:** 임무 대상으로 인정한다. 명시 좌표는 그 주변 모든 건물을 허가하는 범위가 아니라 해당 목표 구역을 지정한다.
2. **임무 대상 세력 소유의 벽·문:** 정착지 경계의 강한 근거로 인정한다. 일반 정착지 습격의 대상 세력은 플레이어이며, AI 대 AI에서는 별도의 명시 임무 대상 세력을 사용한다. 단순히 습격자에게 적대적인 모든 세력을 대상으로 삼지 않는다.
3. **무주인 벽 내부의 대상 세력 침대·실사용 설비:** 실제 관측했거나 이미 목표로 알려진 근거가 해당 국소 구조에 속하면 점유한 구조물로 인정한다. 근처에 램프·다른 건물 한 개가 있다는 이유만으로 이웃 유적을 포함하지 않는다.
4. **대상 구역과 이어진 무주인 벽·문:** 공유 벽·연속 벽면 또는 같은 제한된 국소 내부 구역에 속하는 경우만 포함한다. 단순 거리나 맵 전체의 통행 가능 연결로 확장하지 않는다.
5. **근거 없는 무주인/다른 세력 구조:** 별도 소탕 대상에서 제외한다. 시야 안에서 실제 위협을 확인한 경우에만 해당 접촉에 대응한다.

홈 영역은 사용자가 임의로 넓히거나 지울 수 있고 AI 대 AI에 공통으로 적용되지 않으므로 필수 조건으로 쓰지 않는다. 지붕, 인공 벽, 방 크기, 침대와의 거리 역시 단독 판정 기준으로 쓰지 않는다. 숨은 내부 설비나 적을 새로 전역 검색하여 정착지 근거를 만들지 않는다. 기존 침대 목표 외의 근거는 관측/임무 입력 범위에서 얻는다.

## 소탕 대상·이동 장애물·위협 대응을 분리

| 분류 | 행동 | 다른 방 소탕으로 확장 |
|---|---|---|
| 임무 대상 구조물 | 기존 스택업·관측·돌파·진입 절차 사용 | 알려진 대상 구역만 허용 |
| 외부 무주인 유적 | 목표 방향 탐색에서 넘기고 유효한 정착지 경계를 찾음. 주변 통행 가능 경로로 우선 이동 | 금지 |
| 목표 접근을 실제로 막는 비대상 장애물 | 제한된 우회 후보 실패 후에만 통과 목적의 장애물 돌파 검토 | 금지. 통과 후 원래 목표로 계속 이동 |
| 실제 관측한 적이 있는 비대상 구조물 | 기존 접촉 대응으로 관측한 적/입구만 처리 | 자동 전체 소탕 금지. 위협 해소 후 원래 임무 복귀 |
| 분류가 아직 끝나지 않은 후보 | 예산 내 분류를 이어가며 판단 보류 | 금지. 분류 대기를 임무 종료로 처리하지 않음 |

직선에 벽이 있다는 사실은 반드시 파괴해야 한다는 근거가 아니다. 비대상 구조는 먼저 넘어가서 다음 정착지 경계를 탐색하고, 그 경계 바깥 목적지로 일반 이동할 수 있으면 유적을 돌아간다. 기존 최종 도달성 검사 상한을 유지한다. 그 목적지에 도달할 수 없다면 제한된 좌/우 접근 목적지만 검토하고 실패를 기록한다. 이 제한된 실패만으로 유적 돌파가 절대 필요하다고 단정하지는 않으며, 통과 돌파는 별도의 보수적인 마지막 수단으로 취급한다.

큰 유적·복잡한 지형에서 유효한 대상 경계나 우회가 탐색 상한 밖이면 다음 예산 구간에서 재탐색한다. 분류 제외 직후 `Direct`로 잘못 전환하거나 임무를 해제해 바닐라 이동/공격에 넘기면 기존 열린 입구 선호 문제가 재발할 수 있다. 이 실패 경로까지 함께 교정한다. 외벽, 통과 지점, 명시 목표 구역을 따로 지정한 임무는 그 지정 범위를 우선한다.

## CPU 비용을 제한하는 구현 방향

별도 전역 방 캐시나 매 틱 맵 컴포넌트는 만들지 않는다. 후보 생성/후속 방 선택 시 같은 분대 단위 분류 함수를 사용하고 결과는 임무 동안 재사용한다.

- 소유 세력의 단순 비교를 먼저 수행한다. 소유 벽/문과 명시 목표는 복잡한 탐색을 생략한다.
- 애매한 무주인 구조만 기존 국소 탐색의 벽/바닥 정보를 재사용하여 제한된 연결 여부를 확인한다. 탐색 셀 수와 후보 수에 상한을 두고 기존 계획 예산으로 여러 틱에 나눈다.
- 분류 값은 `대상 / 비대상 / 미판정`, 근거, 목표 세력, 대표 좌표, 용도(`소탕 / 통과 / 접촉 대응`)로 둔다. 전체 RimWorld Room ID를 안정적인 구조물 ID로 사용하지 않는다.
- 실제로 검사한 벽/입구 좌표의 결과를 재사용한다. 가까운 모든 건물에 넓은 원형/사각형 허가 범위를 씌우지 않는다.
- 기존 재계획 시 후보의 벽·문 소유권과 알려진 근거만 재검사한다. 새 접촉, 관련 벽/문 파괴·소유권 변경, 목표 변경 시 해당 국소 항목만 갱신하고 전체 캐시를 새로 만들지 않는다. 실제 이벤트 연결이 없는 변경은 다음 후보 재검사까지 늦게 반영해도 된다.
- 분대 간 새 전역 정보를 자동 공유하지 않는다. 근거/입구를 전달할 필요가 생기면 기존 LOW 접촉·High 무전 조건을 지킨다.

원시 소유권 비교는 작지만 연결 판단에는 추가 비용이 있다. 성능 이득을 측정한 제안은 아니며, 폰별 반복 검사와 전체 맵 재탐색을 피하는 것이 설계 조건이다. 초기 구현은 소유 벽/명시 목표의 빠른 분류와 비대상 유적을 넘기는 경로부터 하고, 점유 유적의 국소 연결 예외를 같은 판정 안에 넣는다. 소탕 공유 정보와 방 상태를 새 전역 지도 형태로 합치지 않는다.

## 적용 순서와 확인

후속 A2의 다음 건물 선택에 앞서 **A2.0 목표 구조물 구분**으로 넣는 것을 추천한다. 최초 접근에도 적용하므로 A2.1 중정→다음 건물 기능을 기다려서만 고치지 않는다.

1. 공통 분류와 명시 임무 대상 세력/용도를 정한다. AI 대 AI가 대상 세력 없이 모든 적대 구조를 돌파하지 않도록 한다.
2. 최초 직선 후보·개구부 재사용·후속 방 후보·대기 목표 선택에 공통으로 적용한다. 비대상 후보는 작업/임대/목적지로 확정하기 전에 제외한다.
3. 통과만 한 유적은 물리 개구부 이력만 유지하고 정착지 소탕 후보를 파생하지 않는다. 소탕 종료와 접근 실패를 구분한다.
4. 사용자 약식 확인은 [F17](습격%20기능%20약식%20테스트%20목록.md)에 분리한다. 정기 성능 수집이나 전체 기능 재시험을 추가하지 않는다.

남는 한계: 점유하지 않은 빈 유적을 정착지 외곽 엄폐물로 쓰는 경우와 탐색 범위가 매우 큰 무주인 연결 구조는 근거가 부족하면 제외될 수 있다. 처음에는 이런 보수적 누락을 허용하고, 실제 관측한 위협과 명시 목표 예외로 필요한 대응만 수행하는 편이 현재 CPU 우선 방침에 맞다.
