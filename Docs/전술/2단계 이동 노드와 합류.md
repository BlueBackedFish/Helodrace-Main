# 2단계 이동 노드와 합류

2026-10-04. 통합 계획의 2단계를 구현했다. 1단계는 사용자 플레이 테스트에서 큰 문제가 없다는 결과를 받았다. 기존 1단계 문서의 사용자 체크 표시는 수정하지 않았다.

## 변경한 동작

기존 접근 노드는 화면 표시용이었고, 각 폰은 처음부터 자기 최종 스택 위치로 이동했다. 이동 비용 맵은 상세 경로 주변을 선호하게 만들어 길에서 벗어났을 때 복귀하려는 힘이 생겼다.

이제 확정된 접근 통로를 연결 검증에 사용하고, 실제 명령은 다음 이동 노드의 도착 영역을 대상으로 발행한다. 작은 장애물 우회는 바닐라 길찾기가 수행한다. 세부 경로의 각 칸을 이동 명령으로 강제하지 않으며 경로 밖에 100의 추가 비용을 주던 처리를 제거했다.

- 노드는 중심, ID, 정적 버전, 목적, 다음 연결, 원 통로의 구간, 도착 영역과 수용 규모를 가진다.
- 목적은 경유, 문/방 경계 통과, 집결, 돌파 준비, 건물 엄폐 구간 진입이다.
- 문과 방 경계를 필수 경유점으로 남기고, 벽·대각선 모서리를 통과하는 연결을 만들지 않는다.
- 야외에서는 정적 캐시에 있는 건물 인접 구간의 시작/노출 전환을 남긴다. 나무·바위까지 포함하는 야전 엄폐 평가와 사격 대형은 이후 야전 단계의 작업이다.
- 긴 통로는 최대 16개의 상세 경로 칸 범위에서 다음 연결을 압축한다. 단순한 지그재그는 직선 통행이 실제 가능하면 묶는다. 전체 맵에 일정 격자를 생성하지 않는다.
- 도착 영역은 중심 반경 3칸, 문 통과 노드는 반경 2칸의 작은 연결 영역이다. 다른 문을 통과하거나 벽/코너 너머로 퍼지지 않는다. 문 통과 후 대기는 문 타일 바로 너머에서 수행한다.
- 각 폰은 서로 다른 유효 목적지를 보유한다. 평상시에는 목적지를 유지하고, 막힌 경우 제한된 재시도 간격으로 해당 노드 영역만 다시 검사한다. 영역 갱신은 노드별 최대 60틱에 한 번이며, 목적지 실패 재시도는 120틱이다.

위 조정값은 `DoctrineDef`의 `movementNodeSpan`, `movementArrivalRadius`, `movementPortalRadius`, `movementArrivalRefreshTicks`, `movementDestinationRetryTicks`로 지정할 수 있다. 영역 반경은 1~6, 연결 압축 범위는 1~64로 제한하여 국소 처리의 범위를 유지한다. 확정된 노드에는 당시의 영역·재시도 설정을 저장한다.

## 진행과 후미

분대 현재 노드와 폰별 완료 노드를 분리한다. 일반 경유점은 활동 인원의 약 2/3가 도착하고 지휘/필수 인원이 준비되면 선두가 진행한다. 좁은 통로는 수용 규모에 맞춰 먼저 통과한 인원을 내보내고, 후미 대기는 최종 집결·돌파 준비 구역에서 한다. 좁은 문 안에 분대 전원을 채워야 다음 명령을 내리는 교착을 만들지 않는다.

후미는 자기 미완료 노드를 순서대로 따라간다. 선두를 후미 쪽으로 돌려보내거나 분대 중심과의 직선거리로 끌어당기지 않는다. 출발점은 흩어진 폰을 억지로 모으는 필수 집결점이 아니다. 마지막 도착 영역을 지난 인원은 자기 최종 스택 자리로 이동하여 뒤따르는 인원의 공간을 비운다. 최종 접근 완료는 모든 활동 인원의 완료 기록으로 판정하며 정확한 한 칸에 동시에 서 있을 필요는 없다.

회피·연막·교전 보류 중에도 완료 노드와 목적지를 유지한다. 보류 시간은 접근 정체 시간으로 계산하지 않는다. 같은 계획에서 사상자/지휘 변경이 발생하면 진행을 보존하며, 다운·사망 인원은 도착 대기에 포함하지 않는다. 실제 정체가 1,200틱 지속되면 현재 위치와 기존 목표로 접근을 복구한다. 방 진행·기억·최종 목표를 버리거나 최초 출발점으로 되돌리는 복구는 사용하지 않는다.

## 통행 제약과 안전

선호 비용과 물리적인 연결 사용을 구분한다. 접근 비용 맵은 계획에 포함되지 않은 문을 피하도록 하며, 실제 `Pawn_PathFollower.TryEnterNextPathCell`에서도 해당 폰의 현재 연결에 허용된 문/방인지 검사한다. 선택하지 않은 문이나 다른 방의 새 구멍으로 우회하려는 정상 접근 작업은 중단하고 재시도한다. 회피 때문에 경로 밖 방에 있는 폰은 원 통로로 나올 수 있다.

검사는 전술 AI 소유의 정상 접근 이동에만 적용한다. 긴급 회피, 플레이어 명령, 투척/관측/장비 작업을 같은 제한으로 막지 않는다. 기존 외벽 접근·투척 안전·선택 개구부 돌입의 별도 제약은 유지한다. 열린 문/구멍이 있다고 해서 숨은 문 변경으로 노드·진입점 전체를 주기적으로 다시 선정하지 않는다.

## 저장과 개발자 표시

노드 중심/연결/목적/버전/도착 영역/허용 문·방, 분대 현재 노드, 폰별 완료 번호·목적지·재시도 시각을 저장한다. 오래된 표시 전용 `ApproachNodes`와 경로 비용 루트 자료구조는 제거했다. 상세 접근 통로는 연결과 연막 계획을 위한 참고 자료로 유지한다.

기존 전술 노드 보기에서 현재 노드와 도착 영역, 완료한 노드를 구분한다. 전술 보고서에는 연결·수용 규모·정적 버전과 폰별 진행을 표시한다. 기록에는 노드 목적지 변경, 허용되지 않은 통과, 정체 복구 이유가 나온다.

## 검증과 플레이 확인

자동 검증은 노드 압축, 벽/대각선 연결 거부, 필수 통과 지점 유지, 후미 순서, 회피 후 진행 유지, 일반/좁은 통로/최종 집결의 도착 조건, 선택 문 사용과 경로 밖 방에서의 복귀를 확인한다. 실제 게임 DLL로 새 이동 훅의 메서드·주입 필드와 기존 CQB 훅을 검사했다. 비용 맵은 선 복귀 비용 제거와 선택 문 제약을 검증한다.

게임에서 다음을 확인해야 한다. 아직 이 단계의 플레이 완료로 판정하지 않았다.

1. 구불구불한 복도: 선두가 후미 쪽으로 되돌아가지 않고 후미가 순서대로 합류하는지.
2. 한 칸 폭 문/코너: 문 안에서 인원을 모으느라 교착하지 않는지.
3. 외벽 접근: 다른 열린 문으로 들어가지 않고 확정 돌파점의 스택 자리로 접근하는지.
4. 야외 장애물: 작은 우회 후 경로 선으로 직선 복귀하지 않는지.
5. 수류탄 회피/연막/교전: 이전 완료 노드와 폭발 안전을 보존하고 접근을 재개하는지.
6. 다운/사망/늦은 합류: 활동 인원 대기와 목적지가 적절히 갱신되는지.
7. 접근 중 저장·불러오기: 분대/폰별 노드 진행과 목적지가 유지되는지.
8. 개발자 표시와 프레임 비용: 목적지/노드가 주기적으로 흔들리지 않고 작은 영역만 재검사하는지.

3단계 통신, 협력 합의, 다중 진입 배정, 야전 조기 대응·호형 대형·High 화력조 엄호/기동은 이번 변경에 포함하지 않았다.
