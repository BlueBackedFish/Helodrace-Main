# R2 최소 돌파·진입 구현과 검증

2026-10-07. 구현·검증 진행 중. 최신 작업 지침에 따라 `main`에서 진행한다. 이전 실험 브랜치의 R0/R1 기록은 fast-forward로 보존했다.

## 구현 범위

새 엔진은 [분대 명령 서비스](../../Source/Helodrace/Tactics/TacticalCommands.cs), [국소 계획](../../Source/Helodrace/Tactics/TacticalLocalPlan.cs), [지속 작업](../../Source/Helodrace/Tactics/TacticalJobs.cs)으로 구성된다. 기존 조직·편제·장비 정의와 해머/문 고장 효과를 사용하며, 구형 실행·통신·캐시·이동 후크는 설치하지 않는다.

- 전역 스케줄러가 모든 맵에서 한 틱당 최대 2개 분대를 판단한다. 최대 4개 due 항목을 확인하고, 처리 경과 시간이 1.5ms를 넘으면 다음 판단을 다음 틱으로 넘긴다. 하나의 판단 내부를 선점하는 제한은 아니다.
- 습격 Lord 생성 시 멤버와 작업 소유권을 등록한다. 300틱마다 누락/로드 상태를 확인한다. 분대 평상시 판단은 120틱, 돌파·진입은 30틱, 입구 사용 대기는 240틱, 완료 상태는 600틱 간격이다. 완료·실패·사상자 이벤트는 due 시점만 앞당긴다.
- 목표 방향으로 최대 256칸을 확인하고, 벽/문 경계 후보는 최대 8개, 최종 도달 가능성 검사는 최대 2개로 제한한다. 적합한 일반 문을 우선하고, 외벽 앞의 고립된 장애물은 외벽으로 해석하지 않는다.
- 스택은 같은 벽면에서 이어지는 고유 자리다. 기본은 한쪽 대형이며 짧은 벽에서는 입구 바로 뒤를 비워 두고 그 뒤쪽에서 양쪽을 연결한다. 코너 너머로 연장하지 않는다. 대형과 진입 후 자리는 계획 생성 때만 정한다.
- 각 폰은 하나의 지속 Job을 가진다. 집결 후 정지·방향 보기, 해머 돌파, 외부 칸→실제 개구부→첫 실내 칸→가까운 벽 자리의 진입 순서다. 후미도 동일한 진입 Job을 사용한다.
- 개구부를 지난 이력은 작업 중단 후에도 유지한다. 실내까지 통과한 폰은 재시도할 때 바깥 집결 칸으로 되돌아가지 않는다. 일반 이동에는 통과 노드나 매 셀 경로 교정이 없다.
- 물리적 자리와 입구 사용권을 분대끼리 공유해 중복 정지를 막는다. 전술 정보 공유/다중 진입 협력은 R5 범위다. 임무 완료 후 바닐라 전투에 제어를 반환한다.

이 단계는 한 겹 외벽/일반 문과 한 방 진입이다. 관측·수류탄·연막·폭발 장비·떨어진 공병 장비 회수·다방 정리·동적 교전은 R3 이후다. 착용한 해머가 남아 있으면 다른 운용자로 교체하며, 아무 운용자도 없으면 바닐라에 반환해 분대 전체의 영구 정지를 피한다. 저장/로드의 전체 실행 복원과 다중 맵 부하 검증은 R7에 남아 있다.

## 실행 방법

시작 인수 `-hdTacticalEngine=new`를 사용한다. 엔진 선택은 실행 중 바꾸지 않는다. 기본 선택은 비교용 Legacy로 유지한다.

개발자 도구 `Helodrace/New tactical AI`에서 명시 목표 칸을 지정하거나 분대 명령 상태를 확인할 수 있다. 명시 목표가 없으면 이름 있는 소유자의 침대를 기본 목표로 쓴다. 명시 목표를 사용하면 AI 대 AI 임무에도 사용할 수 있다.

## 검증 방법과 현재 결과

[독립 시험 실행기](../../Source/Benchmarks/TacticalEngineAudit/Run-R2Functional.ps1)는 문, 16칸 실내, 외벽 앞 장애물, 실내 통과 후 작업 중단, High 공병 사망, 200명 요청을 실제 게임에서 실행한다. 구형 컴포넌트/후크가 0개이고 New 컴포넌트가 정확히 2개인지 확인한다. 진입 완료뿐 아니라 실제 개구부 통과·후미 통과·연결 대형을 기록한다. 문 시험은 실제 고장을, 중단 시험은 바깥으로 돌아가지 않았는지 추가 확인한다.

초기 시험에서 LOW 12명 외벽 진입, 12명 일반 문 고장 후 진입, 50명 요청으로 생성한 LOW 60명/5개 분대의 진입이 완료됐다. 60명 시험은 60명 모두 선택한 개구부를 통과했고 5개 분대 모두 실내 자리에 도착했다. 이는 초기 구현의 기능 확인이며 최종 빌드 반복 대조 결과가 아니다.

성능 합격은 같은 최종 DLL·지도·장비·편제·시드·수집 대상·틱 구간의 Vanilla/New를 각 3회 비교한다. 실제 전체 틱 CPU와 틱 밖을 포함한 메인 스레드 구간 CPU 모두 2배 이하여야 한다. 새 실행기의 모든 분대 진입 완료가 확인되지 않으면 저렴해도 합격하지 않는다. 메서드 경과 시간은 Core 기준 배치 대비 비율과 함께 기록하며, 메서드별 실제 CPU 점유율이라고 해석하지 않는다.

현재 R2 최종 합격은 아직 선언하지 않는다. 최종 반복 결과와 증거 경로는 검증 완료 후 이 문서에 추가한다.
