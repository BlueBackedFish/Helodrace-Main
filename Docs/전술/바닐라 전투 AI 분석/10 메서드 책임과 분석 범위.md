# 10. 메서드 책임·상태 소유권·분석 범위

기준은 설치된 RimWorld 1.6.4871 rev590이다. 이 장은 앞 장에서 본 메서드를 호출 지점과 책임으로 다시 묶는다. 숫자는 소스의 기본값 또는 해당 정의의 값이며 실제 모드 플레이의 호출 횟수/CPU 측정값이 아니다.

## 코드에서 읽을 수 있는 CPU 비용의 의미

**실제 병목 순위와 ms는 측정하지 않았다.** 다음은 호출을 과하게 추가했을 때 생기는 비용 경로에 대한 정적 해석이다.

- 매 폰·매 틱 트리를 강제로 조회하면 바닐라의 Job 유지·hash interval·만료·continuation이 줄여 주는 일을 다시 늘린다. Lord가 공통 Duty를 준다는 사실이 개인 판단 비용을 없애지는 않는다.
- CastPositionFinder를 자주 부르면 후보별 LOS/Verb 사선·CanReach·예약·cover 계산이 반복된다. 현재 칸 단축 분기를 유지하는 것은 이동 품질뿐 아니라 비용에도 영향을 준다.
- FindPathNow는 worker 사용 여부와 별개로 메인 스레드에서 완료를 기다리고 즉시 계산한다. 일반 비동기 PathRequest와 같은 것으로 집계하면 동기 대기 비용을 놓칠 수 있다.
- StartJob 반복은 예약/Driver/Toil/stance/큐 정리까지 반복한다. 단순 목표 변경의 비용으로 보면 안 된다.
- Reachability의 working guard, CastPositionFinder/AttackTargetFinder의 공유 임시 상태 때문에 기존 함수를 그대로 병렬 호출하는 것은 안전한 순수 계산 이전이 아니다. Native snapshot 경로와 mutable 객체 판단을 구분해야 한다.
- 1.6은 이미 grid/data의 틱 캐시·부분 갱신·worker batches를 사용한다. 비슷한 전체 맵 캐시를 모드에 추가한다고 자동으로 메인 틱이 줄지는 않는다.

이는 이후 성능 검토의 조사 지점을 정하는 근거이며 최적화 구현이나 성능 보장으로 제시하지 않는다.

## 분석 범위와 검증

어셈블리 전체를 추출해 호출자/override/상수/타입을 검색하고 주요 전투 본문을 ThinkTree·Duty XML과 대조했다. 공통 판단/실행, 기본 습격·방어/이동, 공병·브리처·포위·도주, 플레이어 명령/회피, 동물·메카·정신 상태·DLC 특수 전투와 능력, 포탑·사냥·입장 그룹을 다뤘다.

9,217개 C# 파일은 추출 범위이고, 1,027개 후보 파일/3,399개 서명과 1,505개 XML 노드는 검색 색인이다. **그 수를 개별 본문 분석 완료 수로 제시하지 않는다.** 비전투 음식/작업/관계/스토리, 모든 quest/transport 생성 코드, 무기·능력별 피해 효과와 렌더링은 이 행동 구조 분석의 범위 밖이다.

[근거 검증 기록](근거%20검증%20기록.json)은 버전/해시·파일 수·링크 목적지/줄 범위와 장 목록을 확인한 기록이다. 링크 검사는 파일 위치 검증이며 의미가 맞다는 자동 증명은 아니다. 본문의 동작 조건은 실제 메서드와 정의를 읽어 대조했다. 실행 중 Harmony/XML 패치 결과나 특정 세이브의 current Job/Lord 상태는 이번 정적 분석으로 확정하지 않았다. 게임 코드는 변경하지 않았다.
