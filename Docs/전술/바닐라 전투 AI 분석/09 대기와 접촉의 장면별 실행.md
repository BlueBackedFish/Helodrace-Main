# 09. 대기·이동 중 접촉: 장면별 실행

앞 장의 공통 파이프라인을 실제 상황에 대입한다. 같은 “대기” 텍스트라도 LordToil·Duty·Job·stance가 다르면 반응도 다르다.

## 대기 중 적이 나타났을 때

| 대기 상태 | 적 확인 주체 | 누가 이동/사격하는가 | 집단 변화 |
|---|---|---|---|
| drafted Wait_Combat | 개인 Wait Driver의 자동 공격 검사 | 현재 자리에서 가능한 적을 쏜다. 이 Driver는 엄폐 Goto를 만들지 않음 | 일반적으로 Lord 집단 배치 변경 없음 |
| NPC Wait_Combat | 개인 자동 공격 + Job 만료 시 main 판단 | 즉시 현재 자리 사격; 만료/종료/override에서 JobGiver가 새 사격점 선택 가능 | 별도 trigger가 없으면 개인별 |
| 일반 Wait/Wait_Wander | Wait Driver 근접 반응 + 상위 main/constant | 같은 원거리 자동 사격 분기 없음. 종료/constant 반응에 따라 fight Job 선택 | Duty/graph에 달림 |
| Defend Duty의 대기/배회 | 각 폰 AIDefendPoint | 적 획득 후 자기 엄폐/사격점 또는 현재 자리 대기 | 공통 방어점·반경을 공유하며 개인 위치는 별도 |
| Build Duty의 작업/대기 | Duty 우선순위·피해/만료 반응 | 해당 폰이 제한된 반경의 적 대응. 다른 폰은 자기 Build/Defend 유지 가능 | Siege graph의 별도 피격 확률/손실 trigger면 Assault |
| Sapper/Breaching/Escort 대기 | 해당 Duty의 가까운/최근 피해 전투 분기 | 공병·브리처·호위가 서로 다른 반경/목적을 사용 | 공병 상실/재배정/공통 target은 Lord 경로 |
| 비징집 플레이어 작업/대기 | ConfigurableHostilityResponse | 설정 Attack/Flee/Ignore에 따라 개인 반응. 강제 작업은 예외 | 분대 공통 전략 아님 |
| dormant/특수 NPC | active 상태·Comp·특수 Lord/트리 | 종족과 사건별 활성화 경로 | Wake/AcquiredTarget/Memo가 graph에 있으면 집단 전환 |

전투 중 busy stance는 Wait Driver의 새로운 공격 검사를 생략한다. 원거리 공격 자체가 시작되면 관측/표적 탐색과 warmup/shot의 순서도 다르다. 화면 밖 interval 묶음은 검사 반응 시각에 영향을 줄 수 있다. 근거는 [01](01%20틱과%20판단과%20작업%20소유권.md)·[02](02%20표적과%20엄폐와%20대기%20사격.md)·[04](04%20사격선과%20공격%20실행.md)다.

## 이동 중 적이 나타났을 때

Goto Toil은 목적지로 이동하는 명령이며 스스로 매 틱 원거리 표적을 고르는 전투 Driver가 아니다. 일반 pather에도 “적이 보이면 엄폐를 찾고 전원을 멈추기” 분기는 없다. 개인이 멈추는 경로는 현재 Job의 override/종료, constant reaction, 상위 전투 Duty, 근접/경로 blocker 반응, Lord가 EndAllJobs를 실행하는 경우다.

예를 들어 전투 JobGiver가 만든450~550틱 Goto가 적을 볼 수 있는 칸을 지나더라도 그 Goto 자체가 즉시 중간 칸에서 사격할 것을 보장하지 않는다. 다음 판단/종료·피해/근접 이벤트의 개입이 있어야 전투 작업으로 바뀐다. 도착하면 다시 트리를 통해 Wait_Combat/새 Goto 등으로 바뀔 수 있다. 강제 player Goto와 NPC 전투 Goto는 source/expiry/playerForced가 다르다.

FollowClose도 기본적으로 따라가는 실행이다. Escort Duty가 다음 판단에서 defend를 먼저 선택할 때 전투한다. “모든 호위가 선두의 같은 경로를 따라가면서 알아서 이동 사격”이 아니다. 독립 CompTurretGun 같은 예외는 [08](08%20도달성과%20경로%20비용과%20포탑.md)에 구분했다.

## 공통 전투 반응에 없는 것

이 분석에서 확인한 일반 Assault/Defend/Sapper/Breaching/Travel/Wait에는 모드와 같은 room-clear 기록, 적의 마지막 room/door 기억 그래프, 관측 뒤 수류탄 판단·폭발 대기, 스택업 슬롯·진입 순서, 자동 화력조 분할·망치/모루 역할·분대 접촉 통신이 없다. 바닐라가 공유하는 것은 **현재 집단 상태/Duty와 특정 돌파 target/grid**, 개인의 enemyTarget/last attacked/engage 시각, 맵의 캐시/예약이다. 단순히 바라보는 방향을 지정하거나 Goto 목표를 주는 것만으로 위 전술 기능이 자동 생성되지 않는다.

반대로 vanilla에는 버려서는 안 될 기존 실행 규칙이 많다. 현재 칸 사격, target 변경/continuation, warmup·burst·cooldown, 상대적 cover·lean LOS, door/manual open·blocking bash, reachability/path 요청·도착 알림·예약 해제는 각 계층이 나눠 맡는다. 전술 모드가 어느 계층을 소유하는지 불명확하면 이 규칙들이 서로 다른 작업을 다시 시작하거나 이동을 멈추게 할 수 있다. 이는 코드 구조에서 도출한 해석이며 특정 모드 오류를 재현한 진단 결과는 아니다.
