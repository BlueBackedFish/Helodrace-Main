# R4 접촉 기억과 동적 대응

상태: 구현·관련 로컬 검사·대표 실제 게임 약식 검증 완료. 기존 R3 안전 조건과 방 확보 이력은 유지한다. 정식 반복 CPU 판정은 R7 범위다.

## 작업 방식

- 구현 전에 아래 대표 시험의 발생 조건과 성공 조건을 확정한다. 시험이 발생하지 않으면 합격으로 처리하지 않는다.
- 변경 단위는 접촉 기억·제한 관측, 대응·복귀, 실제 게임 통합 검증으로 나눈다. 의미 있는 검증 완료 단위마다 main에 커밋한다.
- 기존 프로파일러를 그대로 사용한다. 해당 메서드와 전체 틱 CPU/Core 기준만 수집한다.
- 한 LOW 분대의 대표 실제 게임 시험에서 후방, 문, 양방향 접촉과 소실을 순차 확인한다. 실패한 동작이나 변경 영향만 재검증한다.
- 전체 회귀·대규모 반복 CPU 비교는 R7에 둔다. 이번 약식 측정은 정식 2배 CPU 합격을 대신하지 않는다.

## 구현 계약

- 분대당 최대 8개 접촉에 적 ID, 마지막으로 실제 본 좌표·시점, 당시 문/인접 구역 좌표만 저장한다. 기억은 Pawn 참조를 보관하지 않는다.
- 관측자 한 명과 폰 후보 최대 16개를 회전 검사한다. 전체 맵/분대에 공유되는 관측 예산을 사용한다. 바닐라 사격의 표적·출발 lean 칸과 LOS를 사용하며 무기 사거리로 관측을 제한하지 않는다.
- 후방·근거리·서로 반대 방향 위협이면 현재 진입 계획을 보존하고 국소 엄폐/경계로 전환한다. 접촉이 사라지면 마지막 목격 방향을 잠시 경계한 뒤 원래 임무를 재개한다. 숨은 폰을 추적하거나 확보 이력을 삭제하지 않는다.
- 접촉 위치가 바뀌어도 대응 중 계속 위치를 재배정하지 않는다. 제한된 주기로 변경을 허용한다. 폰마다 긴 경로·엄폐 검색을 하지 않는다.
- 발사된 수류탄과 설치/기폭된 C4의 안전 처리는 우선한다. 대응 때문에 안전 기록을 지우거나 조기 진입하지 않는다.
- 다른 분대에는 기억을 공유하지 않는다. LOW 접촉·High 무전 공유는 R5 범위다. 야전 화력조 교리는 R6 범위다.

## 대표 검증

| 항목 | 발생 조건 | 성공 증거 |
|---|---|---|
| 기억과 만료 | 실제 본 적이 LOS 밖으로 이동 | 저장 좌표가 새 숨은 위치를 따라가지 않음; 지정 기간 후 만료 |
| 후방 공격 | 첫 방 확보 후 후방에서 적 출현 | 후방 접촉 분류·대응 발행, 기존 계획/확보 이력 유지, 소실 후 복귀 |
| 문 접촉·후퇴 | 다른 실제 열린 문칸에서 적 출현 후 숨음 | 사격 lean/LOS로 기억, 문 옆 구역 좌표 기록, 소실 후 숨은 위치 갱신 없음 |
| 복도 양방향 | 앞뒤 적 동시 출현 후 둘 다 숨음 | 두 접촉 기억, 양방향 경계, 제한 대기 후 임무 복귀 |
| 미관측 문 변경 | 시야 밖 문의 상태 변경 | 그 이벤트만으로 계획/진입점 변경 없음 |
| 진행·안전 | 위 이벤트가 끝난 후 | 전원 원래 임무 완료, 안전 완료 전 진입 0, 예외/수집 누락 0 |
| 비용 | 같은 시험의 관련 메서드 수집 | 호출·평균/상위/최대 비용·Core 대비 비용, 전체 틱 CPU와 p95/p99/max 기록 |

순수 정책/제한량 검사는 로컬 테스트로 보완한다. 실제 게임 시험에서 확인하지 못한 항목은 별도로 표시한다.

## 구현 결과

- `TacticalContactMemory`: 분대별 최대 8개, 신선도 240틱·보존 1,800틱. 실제 관측 때만 좌표를 갱신하며 Pawn 참조를 저장하지 않는다. 방 확보 이력과 분리한다.
- `ScanContacts`: 기본 45틱 간격, 전방·후방·중간 관측자 교대, 최대 16개 폰 후보·최대 2개 목격. 기존 전 맵 공통 관측 예산 1회/틱과 시간 회계를 사용한다. 다른 분대와 공유하지 않는다.
- `TacticalContactSight`: 바닐라 표적/출발 lean 칸과 LOS, 관측 반경 28칸. 버퍼를 재사용한다. 개구부 관측의 첫 접촉도 같은 기억에 기록한다.
- `RespondToContacts`: 후방·근거리·다른 문·양방향 접촉에 대해 현재 계획을 유지한 채 대응한다. 다음 관측 조각에서 두 번째 방향이 발견돼도 반영한다. 실제로 다시 본 좌표에 한해 90틱 간격으로 경계 방향을 갱신한다.
- `FindContactPost`: 현재 위치 2칸 이내의 연결된 바닥 후보 최대 25개, 한 지휘 갱신에 최대 2명 배정. 중복 자리·다른 분대 자리·개구부 병목·문 너머·이미 통과한 면의 반대편을 제외하고 엄폐/비노출을 우선한다. 별도 장거리 경로 검색은 하지 않는다.
- `HD_NewTacticalContactGuard`: 제한된 주기로 마지막 목격 칸을 확인하고, 그 칸에서 실제로 보이며 무기로 사격 가능한 적에게만 사격을 시도한다. 새로운 숨은 위치를 적 ID로 조회하지 않는다. 일반 자동 공격 검색은 차단한다.
- 마지막 관련 목격 뒤 240틱이 지나면 기존 임무로 돌아간다. 진입 중단은 통과 이력을 보존한다. Clear 중단은 기존 자리 복귀 후 조사/후속 진입을 재개한다. 미발사 관측/투척은 재시작할 수 있지만 발사된 수류탄·C4 안전 절차는 중단하지 않는다.
- 후속 진입점 우선순위는 조사 때 기록한 문/벽/개구부 종류와 실제 접촉 정보로 정한다. 미관측 문의 현재 Open 상태를 점수로 읽지 않는다. 선택한 진입점의 실제 통과 가능 여부는 실행 직전에 확인한다.
- 기존 개발자 `Inspect squad commands`에서 마지막 목격 좌표·경과 틱·문 인접 구역·대응 방향을 확인할 수 있다.

## 검증 결과

`dotnet build Source/Helodrace/Helodrace.csproj --no-restore -v:q` 경고/오류 0.
`dotnet run --project Source/Tests/RaidTacticalBindings/RaidTacticalBindings.Tests.csproj --no-restore -- --r4`에서 기억 제한/만료·분대 분리·방 확보 이력 보존, 전역 작업 예산, 지원 안전 정책, 국소 방 조사/미관측 문 우선순위 고정 검사를 통과했다.

실제 게임은 LOW 12명, `sapper-door`, `r4-contact-drill`, fixture v18, 준비 0·측정 4,800틱, 관련 메서드 6개 추가 선택으로 실행했다. [원본과 요약](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-08-r4-contact-drill/README.md)을 보존했다.

- 최종 DLL SHA256: `212761f9821029a62a6dab20e59ce424fe7a4bd1cd34931faa8b9d826b46ff14`.
- 후방 목격 1, 다른 실제 문칸 목격 1, 앞뒤 양방향 대응 1, 소실 후 복귀 3. 36개 경계 작업을 실제 발행했다.
- 숨긴 적의 좌표로 기억을 갱신하지 않음, 대응 중 진입점/확보 이력 유지, 미관측 문 열림으로 계획 교체 없음.
- 4,717틱에 12명 전원 완료. 세 구역/목표 확보·실제 고유 자리 도착·통과 이력 확인. 지원 투척/복귀 각각 3, 안전 완료 전 진입 0.
- 감사/캡처 complete, 격리/환경 통제 true, 비시험 폰·dropped·계측 예외 0. 작업 실패/중단 18건은 회복해 완료했다. 오류와 동일시하거나 0건으로 보고하지 않는다.
- 게임 기동 로그에는 기존 탄약 텍스처 누락 5건이 남아 있다. 전술 실행 Exception은 기록되지 않았으며 이 단계에서 관계없는 텍스처 정의는 수정하지 않았다.
- 첫 실패는 같은 목표 방에 연결된 다른 문을 위협 분류에서 제외한 조건 때문이었다. 두 번째 실패는 서로 다른 관측 조각에서 들어온 양방향 접촉을 이미 시작된 대응에 추가하지 못한 조건 때문이었다. 실패 원본을 보존하고 동일 대표 시험만 수정 후 재검증했다. 세 실행은 다른 DLL이므로 반복 CPU 대조가 아니다.

## 약식 비용

메서드 값은 계측된 **경과 시간**이다. OS CPU는 전체 틱/창에만 측정한다. Core 기준은 10,000회 고정 배치 중앙값 0.2958ms이며, 아래 Core 비율은 CPU 점유율이 아니다. p95/p99는 프로파일러의 최근 호출 표본이다.

| 메서드 | 호출 | 합계 ms | 평균 µs | p99 / 최대 ms | Core 배치 대비 틱당 |
|---|---:|---:|---:|---:|---:|
| ScanContacts | 386 | 5.3265 | 13.80 | 0.1061 / 2.0946 | 0.3751% |
| RespondToContacts | 386 | 5.1545 | 13.35 | 0.1693 / 1.0289 | 0.3630% |
| FindContactPost | 36 | 1.3263 | 36.84 | 0.6786 / 0.6786 | 0.0934% |
| TacticalContactSight.CanSee | 209 | 1.5492 | 7.41 | 0.0180 / 1.3540 | 0.1091% |
| RestoreContactPosts | 334 | 0.0865 | 0.259 | 0.0006 / 0.0009 | 0.0061% |
| TickGuard | 9,127 | 8.2257 | 0.901 | 0.0083 / 3.3441 | 0.5793% |

실제 관측은 103회, 후보 검사 1,442회다. Scan/Respond/Restore/TickGuard의 중복 없는 측정 합계는 18.7932ms, 약 **0.00392ms/틱**, Core 배치 대비 약 1.324%/틱이다. CanSee와 FindContactPost는 상위 호출에 포함되므로 더하지 않는다. 이 값은 전술 이동/바닐라 경로까지 포함한 전체 전술 AI 비용이 아니다.

전체 틱 OS CPU 0.4102ms/틱, 틱 밖을 포함한 창 메인 CPU 5.6836ms/틱. 전체 틱 경과 p95/p99/max는 1.6822/2.4682/63.5863ms. 새 지휘 스케줄러 전체는 88.453ms(0.01843ms/틱), 최대 18.8595ms여서 **틱 스파이크가 제거됐다는 결론은 내리지 않는다**.

한 분대의 대표 기능 시험으로 관측/대응 비용과 완료를 확인했다. 동일 조건 바닐라 반복 대조·다중 맵·대규모 인원 곡선·실제 피해 교환·모든 안전 절차와 위협의 조합은 이번에 재실행하지 않았으며 R7 통합 판정에 남긴다. LOW/High 정보 전달은 R5, 야전·수비·화력조 교리는 R6다.
