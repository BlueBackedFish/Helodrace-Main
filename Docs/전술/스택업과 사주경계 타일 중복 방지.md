# 스택업과 사주경계 타일 중복 방지

## 원인

대형 계획은 각 폰에게 서로 다른 `Position`을 지정했지만 실행의 `AtStagingPosition`은 `SafeStackCells` 또는 `SafeSupportCells` 중 어느 칸에 서 있어도 도착으로 처리했다. 따라서 다른 폰의 자리나 이동 중 겹친 칸에서 그대로 대기할 수 있었다. 진입 인원이 작은 방의 수용 인원 제한으로 경계 인원으로 바뀔 때도 실제 현재 위치를 안전 경계 구역에 추가하고 바로 대기시켰다.

## 변경

- 스택업·사주경계의 도착 조건은 자기 지정 칸에 도착했고 그 칸에 다른 폰이 없는 경우다. 안전 구역은 자리 후보 목록으로 사용한다.
- 다른 분대의 계획상 자리와 외부 인원의 현재 위치도 최초 대형 배치에서 제외한다.
- 실행 중 자리가 막히거나 중복 지정되면 같은 역할의 기존 안전 후보 안에서 빈 칸을 찾는다. 벽면 연결성·수류탄 안전 조건을 통과한 후보를 사용하며, 새 자리는 다른 폰의 계획상 자리, 실제 점유, 이동 목적지 예약, 도달 가능 여부를 확인한다.
- 같은 자리를 요구한 경우 폰 ID로 소유자를 고정한다. 충돌이 없는 자리는 유지하며, 잠시 지나가는 폰은 영구 점유로 취급하지 않는다.
- 재배치의 경로 검사는 최대 32회다. 자리를 찾지 못하면 120틱 뒤 재시도하고 겹친 상태를 대형 완료로 처리하지 않는다. 빈 자리가 없는 경우 위험한 칸을 임의로 추가하지 않는다.
- 일반 집결의 자리 보정은 기존 자리 반경 4칸 안의 같은 방·직접 시야가 연결되는 빈 칸으로 제한한다.
- 좁은 방에서 예비 경계로 바뀐 인원도 자기 자리로 이동한 후 대기한다.

이 규칙은 최종 대기 자리의 중복을 막는다. 개구부 통과 중 공유하는 이동 칸은 그대로 유지한다. 특수 상황에서 대기 타일 중복을 허용하는 기능은 이번에 추가하지 않는다.

## 검증

자리 소유·재배치 회귀 검사 10개와 실제 게임 `ThingGrid`를 이용한 도착 판정 검사 15개를 추가했다. 인접 안전 칸, 실제 중복 점유, 점유 해소, 스택업·경계·화력 지원·일반 집결, 부족한 자리, 제한된 경로 검사 횟수를 검사한다. 전체 빌드(경고·오류 0), 전술 계획·바인딩·기하·분대 테스트 및 XML 검증을 통과했다. 게임 내에서는 다수 분대가 같은 벽면에 집결할 때와 좁은 방에서 예비 경계로 전환할 때 추가 확인이 필요하다.
