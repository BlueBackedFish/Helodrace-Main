# R1 대조 실행과 격리 검증 결과

2026-10-07. R1 완료. 구현 커밋 `41ded3b8`·비계측 CPU 추가 `daee55eb`, 브랜치 `experiment/tactical-ai-rewrite`. LOW/HIGH 반복 18회, 비계측 3회, 유휴 2회로 총 23회 검증했다. R2는 미착수다.

## 구현된 범위

같은 코드/장비에서 시작 인자 `-hdTacticalEngine=vanilla|legacy|new`로 엔진을 고정한다. 기본값은 Legacy다. Vanilla/New는 구형 컴포넌트의 Tick 조기 반환을 넘어 11개 Map/GameComponent를 실제 실행 목록에서 제거하고, 25개 구형 Harmony 패치 클래스를 설치하지 않는다. 생성·편제·조직 등록·장비 효과는 공통이다. New에는 아직 새 전술 실행기가 없어 바닐라 Lord를 사용하는 `vanilla-fallback`이며 `newEngineImplemented=false`다.

Map PreTick/PostTick/Update, Map/GameComponent 전체 Tick/Update 호출기, Helodrace 컴포넌트의 구체적 콜백을 기본 등록했다. 이전 Raid 이름 필터에서 빠졌던 지도 분석·조직 유지도 포함한다. 내부 메서드는 실행 인자로 선택하며 기본 추가 대상은 StartJob/PathFinder.CreateRequest다. 기본 수집은 51개 메서드다.

전체 틱의 실제 스레드 CPU에 더해 측정 창 전체 메인 CPU와 프로세스 CPU를 기록한다. 종료 후 격리 확인과 JSON 직렬화는 창 밖에서 실행한다. 짧은 메서드의 개별 실제 CPU 귀속은 수집하지 않는다. 메서드 값은 경과 시간/호출/분포/Core 배치 비율이며 부모와 자식을 합산하지 않는다.

## 동일 조건과 fixture 수정

실제 조직 생성기로 LOW 12인 소총 분대와 HIGH 13인/3화력조 분대를 만든다. 지도·시드·폰 수·기술·나이·장비·무장 모듈·방탄복 파츠·질환 해시를 비교한다. HIGH 13명 전원이 정상 무전 파츠를 가진다. 요청 50명 예비 시험은 LOW 60명으로 완편 올림됐으며 최종 소규모 그룹과 섞지 않는다.

일반 AssaultColony의 열린 외벽 경로와 sapper Lord의 닫힌 외벽 경로를 별도로 실행한다. 식민자는 이름 있는 침대에 배정하고 정지·비무장·피해 면역으로 고정한다. 이 시험은 엔진 격리/수집/진행 확인이며 교전·방 클리어 완료 시험이 아니다.

초기 HIGH fixture에서 바닐라 돌파가 없었다. 바닐라 `SappersUtility.IsGoodBackupSapper`는 폰카인드의 `canBeSapper` 및 채굴 능력/기술을 요구하는데 HIGH 기본 폰카인드는 자격이 없었다. fixture v5는 채굴 가능한 첫 폰의 채굴을 20으로 고정하고 해당 kind의 자격을 격리 프로세스에서만 켠다. 모든 엔진에 같은 수정을 적용하고 실제 게임 편제 XML은 바꾸지 않는다. HIGH의 자격 수는 2명으로 일치했다.

장비 XML exporter는 출력 문서의 DefName에 UTC 현재 시각을 붙인다. 그 값까지 해시한 초기 HIGH 기록은 같은 실제 장비라도 해시가 달랐다. v5는 문서용 root DefName만 제거하고 실제 장비/파츠/위치/설정은 유지한다. 원본 폰 manifest도 저장한다. 장비가 달라지면 해시도 달라지는 통합 검증을 통과했다.

## HIGH 닫힌 외벽 — 엔진별 3회

RimWorld 1.6.4871, 동일 Core/DLC/Harmony/Helodrace, 800×600, 요청 배속 3, 준비 600틱/수집 1800틱, seed `hd-r1-20261007`이다. DLL SHA256은 `8678c209a3501b44adc3363ddf7dea7e232822553acc34881bb655c05dfbb32e`다. LOW와 같은 데이터 그룹으로 합치지 않는다.

| 항목 | Vanilla | New 바닐라 대체 |
|---|---:|---:|
| 전체 틱 실제 CPU 중앙값, ms/틱 | 0.89410 | 0.91146 |
| 창 전체 메인 CPU 중앙값, ms/틱 | 11.75347 | 11.29340 |
| 누적 진입 인원 / 13명, 각 회차 | 11 / 11 / 13 | 13 / 13 / 13 |
| 구형 컴포넌트 / 설치 후크 | 0 / 0 | 0 / 0 |
| 수집된 구형 메서드 호출 | 전부 0 | 전부 0 |

New/Vanilla는 틱 CPU 1.0194배, 창 전체 메인 CPU 0.9609배다. **바닐라 대체 동작을 비교한 수치이며 새 전술 AI의 2배 합격이 아니다.** 비교 결과의 `newAiFixedWindowCpuGatePassed`는 false다.

Legacy는 실제 구형 컴포넌트 11개/후크 30개(클래스 25개, Prefix/Postfix 중복 포함)를 유지한다. 세 번의 진입 인원은 3/5/1명이고 목표 6칸 이내 접근은 0명이다. 따라서 Legacy의 고정 창 비용을 동등한 완료 작업량의 성능으로 해석하지 않는다. 사용자의 기존 5~6배 관측도 이 작은 fixture로 확정/반박하지 않는다.

## LOW 열린 외벽 — 엔진별 3회

준비 180틱/수집 1200틱, 실제 LOW 12명/소총 분대 1개/무전 0명, 나머지 실행 조건은 같다. DLL은 비계측 창 CPU 진단을 추가한 `3b0b29ff28f5845bd4d1dc4b1c995215913605e029607b4b231c023155812dde`다. HIGH 그룹과 합치지 않는다.

|---|---:|---:|
| 전체 틱 실제 CPU 중앙값, ms/틱 | 1.14583 | 0.95052 |
| 창 전체 메인 CPU 중앙값, ms/틱 | 8.26823 | 8.02083 |

New/Vanilla는 틱 CPU 0.8295배, 창 메인 CPU 0.9701배다. 두 모드 모두 바닐라 동작인데도 진입·사격·프레임 수와 CPU가 달라질 수 있음을 보여 준다. 단일 비율을 엔진 최적화 효과라고 부르지 않고 범위/진행을 보존한다. Legacy는 세 번 모두 이동 12명/진입 0명으로, 낮은 CPU는 성능 개선의 증거가 아니다.

## 비계측 대조

최종 LOW 빌드에서 같은 12명/180틱 준비/1200틱 창으로 각 엔진 1회씩 메서드 프로파일러를 끄고 실행했다. 창 시작/끝에서만 OS CPU를 읽어 audit에 저장하며 profiler 디렉터리/패치를 생성하지 않는다. Core 기준 배치와 개별 Tick 계측도 없다. 모든 엔진이 실제 1200틱/12명 이동을 기록했고 Vanilla/New의 구형 컴포넌트·후크는 0개다. 진입은 Vanilla 6명, Legacy 0명, New 3명이다.

동작/진행과 CPU 창 수집을 확인하는 시험이다. 계측 켠 3회의 중앙값과 끈 1회를 빼서 오버헤드율을 확정하지 않는다. 진입·사격·프레임 수가 달라질 수 있어 정확한 오버헤드는 앞으로 반복 대조로 확인한다. NoProfile에서는 메서드 CPU나 Core %를 만들지 않는다.

| 비계측 LOW 12명, 1회 | 창 메인 CPU ms/틱 | 프로세스 CPU ms/틱 |
|---|---:|---:|
| Vanilla | 8.00781 | 13.95833 |
| Legacy | 4.79167 | 8.30729 |
| New 바닐라 대체 | 6.83594 | 12.20052 |

0명/준비 0/수집 180틱의 Vanilla/New 비계측 대조도 정상 종료했다. 두 모드 모두 구형 컴포넌트/후크 0개·조직 0개·무전 0명이며 메인 창 CPU는 각각 984.375/921.875ms였다. 초기화·렌더링·바닐라 유지 작업이 포함된 짧은 창이다. 전술 잔존 부하율이나 유휴 CPU 0을 증명하는 수치로 해석하지 않는다.

## 검증과 남은 경계

- 게임/CLI 빌드: 경고·오류 0. 실제 게임 DLL 대상 통합 테스트와 profiler 테스트 통과.
- 엔진 파서/기본값/설치 정책, 실제 FillComponents 대상, shared 조직 유지, 패치 탐색 누락, 장비 해시 검증 통과.
- 중첩/예외/중복 finalizer/stop drain/외부 스레드 거부, CPU·JSON·Core 기준·호출 분포 검증 통과.
- 엔진 비교는 서로 다른 시작 단계를 허용하면서 DLL/지도/장비/인원/수집 대상/기준 불일치, missing CPU/틱, dropped, 격리 실패, 이동 부족, 무자격 공병 등 15가지 잘못된 입력을 거부했다. 바닐라 대체 및 정지한 새 엔진의 합격 오표시도 차단했다.
- 실제 구형 제거·후크 비설치·콜백 0회, 공통 조직 콜백 유지, 완편/무전/장비 일치를 raw audit/capture로 교차 확인했다.
- 23회 완료 기록 및 압축 원본 263개 파일의 압축 전 바이트/SHA256를 모두 검증했다. 초기/예비 18회는 최종 비교에서 제외하고 사유와 함께 보존했다. 테스트 게임 프로세스는 전부 자체 종료했다.
- 50/200/400명 부하, 새 지속 작업·스택·해머 돌파·후미 합류, 안전 투척·동적 교전·저장/로드·다중 맵은 이번 R1의 완료 주장에 포함하지 않는다. 각각 R2~R7의 구현/검증 대상이다.
