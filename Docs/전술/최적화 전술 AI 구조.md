# 최적화 전술 AI 구조

2026-10-08. 전체 구조의 설계 기준이다. R2 최소 지휘·지속 작업·돌파·진입은 구현했으며 [R2 기록](R2%20최소%20돌파%20진입%20구현과%20검증.md)에서 실제 범위와 검증 상태를 확인한다. 관측·지원·연락·야전 부분은 후속 단계 설계다. 구현 순서는 [로드맵](최적화%20전술%20AI%20로드맵.md), 성능 판정은 [검증 기준](최적화%20전술%20AI%20검증%20기준.md)을 따른다.

## 지휘는 적게, 실행은 오래

새 AI는 분대가 다음 행동을 드물게 정하고 폰에게 지속 작업을 발행한다. 바닐라의 이동·사격·엄폐·위험 회피를 기반으로 쓰며, 개구부 통과·정지 스택·돌파·관측·지원 안전처럼 필요한 부분만 좁은 전용 작업으로 보완한다. 모든 바닐라 전투 판단을 전술 시스템이 다시 계산하지 않는다.

```text
조직 생성/목표 입력 ──→ 분대 임무 상태
                           ↓ 기한 또는 사건
                    예산이 제한된 지휘 큐
                           ↓ 변경된 작업만
               폰 작업: Goto / 경계 / 돌파 / 투척 / 진입
                           ↓ 완료·실패·중단
                     짧은 결과 → 지휘 큐

국소 관측 → 마지막 위치 기억 → 필요한 경우 연락 → 지휘 큐
```

### 상태의 책임

| 소유자 | 보관하는 값 | 보관하지 않는 값 |
|---|---|---|
| 맵 실행 서비스 | 활성 분대, 다음 기한 큐, 소수 개구부 사용권, 필요할 때 갱신하는 후보 목록 | 전역 위협/중요도 맵, 전체 방 토폴로지, 모든 분대의 최신 적 지식 |
| 분대 | 임무/최종 목표, 현재 단계, 접근 방향/개구부, 고정 슬롯, 제한 접촉 기억, 확보 구역/개구부 이력 | 매 폰 전체 경로, 전체 맵 격자, 다른 분대의 미전달 정보 |
| 폰 작업 | 주체 ID/개정, 목표, 필수 통과 지점, 완료 조건, 실패/재시도 기한 | 매 틱 조직 트리 조회, 전체 계획 재검증 |
| 보고 | 원 관측 시각/위치/출처, 수신자, 전달 기한, 간단한 확인 | 살아 있는 숨은 적의 계속 갱신되는 위치 |

맵 서비스가 물리 충돌을 막기 위해 아군 위치/입구 사용권을 다루는 것과 분대가 그 아군의 접촉·클리어 상태를 아는 것은 구분한다. 공유 후보 인덱스도 LOS 검사의 입력일 뿐 관측 성공이나 분대 지식이 아니다.

## 이동과 진입

- 일반 접근은 공통 지향점과 넓은 도착 범위를 준다. 폰의 세부 경로와 한 칸 옆 이탈을 교정하지 않는다. 매 이동 셀 후크와 맵 크기 비용 마스크는 새 기본 구조에서 제외한다.
- 열린 통로로 긴 우회를 만드는 목표는 발행하지 않는다. 외부 접근점과 선택한 벽/문을 먼저 처리한 뒤 내부 목표를 준다.
- 확보된 개구부는 선택적인 접근 지향점과 다르게 **필수 통과**로 표현한다. `Goto`의 최종점만 줘서 자동으로 해당 구멍을 이용한다고 가정하지 않는다.
- 전용 통과 작업이 외부 출발 자리 → 입구 → 안쪽 비움 자리까지 이어 간다. 중간에는 정지 대기하지 않고 완료 뒤에 실내 경계/사격을 시작한다. 후미 Security도 이 작업을 사용한다.
- 바닐라가 다른 입구로 돌아가는 경우 첫 검증에서 잡아낸다. 해결은 개구부 주변의 작은 이동 구간에 한정하며 전역 경로 감시로 확대하지 않는다.
- 문턱과 첫 안쪽 칸은 스택/경계/양보 자리로 쓰지 않는다. 좁은 입구는 소수 통과 허가와 고유 대기 자리로 조정하되 매 틱 전체 인원을 정렬하지 않는다.
- 늦은 폰은 현재 진입 구간 또는 앞쪽 합류점을 받는다. 완료된 외부 접근을 다시 시작하지 않는다. 장기 실패는 원래 임무를 보존한 채 제한 재시도·지역 대체·바닐라 복귀 중 하나를 선택한다.

## 국소 계획과 대형

외벽/문 후보는 목표 방향의 짧은 탐색과 인접 구조만 사용한다. 후보별 작업 공간, 연속 벽 방향, 외부 스택 연결, 안쪽 통과 자리를 확인한다. 먼 열린 입구·최적 사격 각도 전체 탐색은 하지 않는다. 해머는 사용 가능한 일반 문을 선호하고 보호 문은 기존 장비 제한을 따른다.

스택은 같은 쪽 벽을 따라 연결되는 작은 템플릿을 사용한다. 슬롯 간 연결과 겹침을 한 번 검증하고 유지한다. 부적합한 바위/코너 후보는 버리며, 방이 작으면 입장 인원을 줄인다. 도착한 폰은 정지·경계하고 사격/위험 회피로 실제 자리를 잃었을 때만 일부 슬롯을 복구한다. 전체 분대를 계속 새 위치로 보내지 않는다.

방/구역은 현재 개구부 주변에서만 확인한다. 작은 방 여부는 최대 17칸까지의 제한 탐색으로 16칸 이하/초과를 구분하는 안부터 시험한다. 정확한 대형 방 면적·전체 맵 방 번호는 기본 요구가 아니다. 넓은 방·긴 복도는 국소 구역으로 나눠 진행하되 완료 구역을 다시 돌파하지 않도록 이미 확보한 개구부 좌표와 진입 방향을 기록한다.

전술 계획은 정기적인 맵 변화로 교체하지 않는다. 현재 작업의 실제 대상 파괴·경로 실패·관측 변경 때 해당 부분만 바꾼다. 단순한 벽/문/지붕 읽기와 최종 `CanReach`/LOS/예약 확인은 메인에서 소수 후보에만 적용한다. 후보 실패를 계기로 무제한 탐색을 실행하지 않는다.

## 스케줄과 계산 상한

다음 값은 성능 측정 전 초기 조정안이다. 교리의 확정 상수나 응답시간 보장은 아니다.

| 작업 | 초기 제안 | 상한/재사용 |
|---|---|---|
| 일반 지휘 | 분대당 60~180틱 | 기한을 분산하고 한 틱 처리 분대를 제한 |
| 조용한 대기/경계 | 300~600틱 | 보고·작업 결과·사상자 사건으로 조기 깨우기 |
| 활동 CQB 관측 | 60~120틱 | 관측자 1~2명, 적 후보 8개, 한 차례 LOS 최대 16회 |
| 야전 관측 | 60~180틱 | 먼 거리도 검사하되 같은 후보를 모든 폰에서 반복하지 않음 |
| 위치/돌파 후보 | 변경 때 | 한 차례 최대 8개, 최종 도달 검사 최대 2개 |
| 기억/보고 | 분대당 제한 목록 | 접촉 8개·대기 보고 16개부터 시작, 같은 보고 병합 |
| 연락 후보 | 보고 발생 때 | 대표 연락자·인접 분대 소수, 전체 O(n²) 연락망 금지 |
| 작업 복구 | 실패 사건 + 저빈도 확인 | 동일 실패 음성 결과 180~600틱 유지, 반복 발행 제한 |

고정 개수 예산과 경과 시간의 보조 한도를 함께 사용한다. 한 작업 내부도 후보 루프를 잘게 나눠 단일 호출이 한도를 넘는 것을 줄인다. 시간 한도는 실제 CPU 예산과 같지 않으며 [검증 기준](최적화%20전술%20AI%20검증%20기준.md)의 전체 측정을 대신하지 않는다.

사건은 상태 변경을 표시하고 큐에 하나의 깨우기를 넣는다. 한 틱에 많은 사상자/보고가 발생해도 큐 중복과 즉시 전체 재계산을 만들지 않는다. 폭발 안전/작업 적용의 짧은 검사는 해당 Job이 처리하고, 위험 이후 새 전술 계획은 지휘 큐에서 처리한다. 미처리 작업의 나이를 기록해 조용한 분대가 영구적으로 굶지 않게 한다. 여러 맵도 같은 총 예산을 나눠 쓴다.

주기 스캔은 누락 이벤트 보정용이다. 활성 분대와 해당 작업의 제한된 멤버만 확인한다. 습격 종료·맵 제거·Lord 이탈 시 작업, 기한 큐, 입구 사용권, 보고를 해제한다. 비활성 맵에서는 전술 격자/이동 영역 갱신이 남지 않아야 한다.

## 연락과 협력

분대 내부의 세밀한 병사→중계자 그래프는 대표 관측자/지휘자 사이의 지연된 보고로 근사한다. 실제 관측과 분대가 전달받은 정보는 분리한다. LOW 분대끼리는 연락 가능한 대표자의 접촉으로 최신 보고를 전송하고, 멀어지면 사전에 정한 합의만 계속 실행한다.

High는 정상 장착 무전 파츠와 가용 운용자 여부를 보고 전송/적용 시 검증한다. 장비 상태는 이벤트와 저빈도 보정으로 재사용한다. ACK·중단·승계는 작은 메시지이며 전체 장비 열거/망 그래프를 주기적으로 재작성하지 않는다.

협력은 제한된 참여 분대의 입구·역할·구역·시작 조건을 확정한 합의로 표현한다. 연락 없이 알 수 없는 준비 완료는 기다리는 전역 조건으로 사용하지 않는다. 분대 조우의 식별 지연은 작업을 잠시 보류하는 방식이며 피아식별 실패·프래깅은 만들지 않는다.

## 워커와 비동기 큐

R2 기본 구조는 워커 없이 시작한다. 작은 거리 계산·보고·상태 조회를 매번 워커에 보내지 않는다. 기존 워커 사용 경험 자체가 새 엔진의 병렬화 필요성을 입증하지는 않는다.

측정 후 여전히 큰 순수 계산이 남으면 다음 구조를 검토한다.

1. 메인에서 필요한 국소 셀 플래그·좌표·개정·후보 ID만 평평한 배열/값으로 수집한다. `Map`·`Pawn`·`Thing`·`Room`·Job/예약 객체를 넘기지 않는다.
2. 워커는 후보 점수·근사 시야/접근축·작은 구역 연결 등 순수 계산만 한다. 바닐라 LOS/길찾기/예약을 그대로 워커에서 호출하지 않는다.
3. 제한된 비동기 큐에서 분대별 요청을 병합하고 오래된 미시작 요청을 버린다. 개정 변화마다 작업을 계속 취소·재생성하지 않는다.
4. 메인에서 완료 결과만 제한 개수 적용한다. 작은 위치 오차·오래된 결과는 허용하고, 작업 주체·대상 존재·폭발 안전 등 필요한 조건만 재검증한다.
5. 결과가 늦으면 이전 결과/싼 대체 동작을 사용한다. 메인 틱에서 `Wait`, `Result`, 동기 완료를 요구하지 않는다. 버퍼는 워커가 읽는 동안 재사용하지 않는다.

도입 여부는 **스냅샷 + 큐 관리 + 적용 비용을 포함한 메인 시간 절감**으로 판단한다. 워커 CPU가 증가해도 메인 틱이 줄면 유효하지만, 총 프로세스 CPU·코어 포화·결과 대기 지연을 함께 보고한다. 큰 순수 계산이 이미 사라졌다면 병렬화는 생략한다.

## 이전 체계와의 교체 경계

| 기존 영역 | 처리 방향 |
|---|---|
| 조직/생성/편제/장비/가스 효과 | 유지. 새 AI가 기존 실행 제어를 경유하지 않고 사용하도록 어댑터 최소화 |
| 프로파일러/격리 실행 도구 | 유지. 선택 엔진과 새 완료 지표만 확장 |
| 전술 계획·실행·개인 명령 서비스 | 새 분대 상태/작업으로 교체 |
| 전체 정적 맵·국소 정기 격자·이동 마스크 | 기본 구조에서 제거. 국소 값 읽기와 오래 재사용하는 작은 결과로 대체 |
| 매 셀 이동/일반 작업/자동 사격 전술 후크 | 제거 또는 전용 Job으로 국한. 장비/플레이어 기술의 별도 후크는 구분 |
| 관측·기억·통신·협력 | 관측 입력과 작은 보고 체계로 새로 구성 |
| 돌파/관측/투척 Job | 장비 효과는 재사용 가능. 이전 계획/명령 상태 의존을 그대로 가져오지 않음 |
| 개발자 표시 | 새 임무·지향점·슬롯·기억·큐 지연 중심. 표시를 끈 상태에는 계산하지 않음 |

자료를 적게 보관하는 목적은 메모리 누수 대응보다 반복 계산 제거다. 기록이 비어 있어서 싸거나, 폰이 정지해서 싸게 측정되는 구조는 합격으로 보지 않는다.
