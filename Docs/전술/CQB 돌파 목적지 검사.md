# CQB 돌파 목적지 검사 — 2026-10-13

외부인들2의 `(159, 0, 122)`부터 `(162, 0, 122)`까지는 폭 4칸 구조물의 남쪽 끝벽이다. 남쪽 `z=121`은 지붕 없는 야외이며, 북쪽 `z=123`의 `x=160,161`이 지붕 있는 복도 바닥이다. 양 모서리는 북쪽으로 벽이 계속된다.

기존 `TryWallNormal`은 코너의 두 벽 길이가 같으면 목표까지의 이동에서 더 큰 축을 선택했다. 이 끝벽을 동서 방향으로 통과하면 4칸 건물 폭 전체가 `TryDepth`의 최대 4겹 벽으로 계산된다. `ClassifyStructure`는 대상 세력 소유 벽이면 벽의 방향을 보지 않고 돌파 대상으로 통과시켰다. 실제 두께를 가로지르는 방향과 벽의 길이 방향을 구분하지 못한 것이 원인이다.

최초 수정 `8400eae0`은 지붕 있는 목적지를 필수 조건으로 넣어 지붕 없는 외곽 담장·마당으로의 정상 돌파도 막는 잘못된 제한을 만들었다. 이 지붕 제한과 전방 지붕 검색은 제거했다. 야외→야외 여부 자체는 돌파 금지 조건이 아니다.

수정한 판정은 다음과 같다.

- 새 돌파 지점은 소유권 단축 판정 전에 벽의 두께/방향을 확인한다. 이중벽 이상은 남아 있는 각 벽층이 이동 방향의 옆으로 이어져 있어야 한다. 진짜 두꺼운 벽은 각 층이 옆으로 이어지지만, 문제 끝벽을 동서로 훑으면 중간 벽칸에는 옆으로 이어지는 벽이 없어 제외된다. 1겹 벽에는 이 추가 제한을 넣지 않으며, 파괴돼 없어진 층도 제외 근거로 사용하지 않는다.
- 지붕 없는 외곽 담장과 야외 마당으로 향하는 1~4겹 외벽의 정상 가로지르기는 허용한다. 대상 세력·목표·접근 가능성·실제 바닥·이미 확보한 구역·도구·자리 배정 등의 기존 조건은 유지한다. 지붕을 잃은 입구도 지붕이 없다는 이유만으로 거절하지 않는다.
- 첫 벽의 방향을 정할 때도 위 검사를 사용한다. 코너가 벽의 길이 방향으로 걸리면 같은 벽면의 바로 인접한 두 벽칸까지만 확인하고, 실제 두께를 가로지를 수 있는 벽칸을 후보 탐색 시작점으로 사용한다. 다른 벽 축도 목표 쪽으로 향할 때만 시도한다. 각 후보와 여러 틱에 걸쳐 준비한 계획의 공개 시점에도 벽 방향을 검사한다. 기존 확보 통로·열린 출구 재사용은 유지한다.

검증은 지붕 없는 1~4겹 외벽·코너·파괴된 층·원본 세이브 좌표를 포함한 32개 검사와 기존 벽면/개구부·야외 반복 방지 20개·열린 출구 재사용·계획 미리 준비 12개·진입 교전 18개·전역 예산 검사로 진행했다. 실제 좌표의 끝벽을 동서로 길게 훑는 후보는 제외되고, `x=160,161`에서 북쪽 복도로 가거나 남쪽 야외로 벽을 수직 통과하는 방향은 유지된다. 실제 선택은 목표/접근 방향과 기존 방 소탕·출구 규칙에 따른다. `(162, 0, 122)` 코너에서는 유효 인접 벽면 `(162, 0, 123)`을 사용할 수 있다.

앞선 지붕 조건 버전은 외부인들2 복사본의 LOW 12명·2,200틱 실행에서 `(162, 0, 123)`을 선택했으며 [해당 버전의 짧은 실행 결과](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-13-cqb-end-wall.json)를 보관한다. 이 기록은 현재 지붕 제한을 제거한 DLL의 실행 결과가 아니다. 이번 수정은 위의 관련 회귀 검사로 검증했고 별도 게임 재생·메서드 프로파일링·장시간 검증은 하지 않았다.

개발자 화면 약식 확인은 [테스트 목록 F64](습격%20기능%20약식%20테스트%20목록.md)에서 진행한다. 검사는 최대 4개 벽층과 층마다 옆 두 칸뿐이며, 전체 방/맵 탐색이나 캐시는 추가하지 않는다. 이미 심하게 파괴된 짧은 벽 조각에서는 방향 판단이 근사값이므로 F64에서 함께 확인한다.
