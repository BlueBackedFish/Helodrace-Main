# CQB 돌파 목적지 검사 — 2026-10-13

외부인들2의 `(159, 0, 122)`부터 `(162, 0, 122)`까지는 폭 4칸 구조물의 남쪽 끝벽이다. 남쪽 `z=121`은 지붕 없는 야외이며, 북쪽 `z=123`의 `x=160,161`이 지붕 있는 복도 바닥이다. 양 모서리는 북쪽으로 벽이 계속된다.

기존 `TryWallNormal`은 코너의 두 벽 길이가 같으면 목표까지의 이동에서 더 큰 축을 선택했다. 이 끝벽을 동서 방향으로 통과하면 4칸 건물 폭 전체가 `TryDepth`의 최대 4겹 벽으로 계산되고, 반대쪽 야외가 진입 칸이 된다. `ClassifyStructure`는 대상 세력 소유 벽이면 목적지 구조를 보지 않고 바로 돌파 대상으로 통과시켰다. “목표 건물에 속한 벽”과 “건물 안으로 진입하는 방향”을 혼동한 것이 원인이다.

수정한 판정은 다음과 같다.

- 아직 확보되지 않은 새 돌파 지점은 소유권 단축 판정 전에 목적지 쪽 바닥을 확인한다. 실제 벽 두께 뒤에서 진행 방향으로 최대 3칸만 확인하며, 바닥이 끊기거나 그 범위에 지붕 있는 실내가 없으면 제외한다. 벽 옆이나 뒤쪽의 지붕을 빌려오지 않는다. 입구 지붕만 폭발로 사라진 경우에는 바로 앞 실내를 근거로 사용할 수 있다. 전체 방/맵 탐색이나 캐시는 추가하지 않는다.
- 첫 벽의 방향을 정할 때도 위 검사를 사용한다. 코너 자체가 건물 폭 또는 긴 측벽에 걸리면 같은 벽면의 바로 인접한 두 벽칸까지만 확인한다. 그곳이 진짜 실내로 연결되면 유효 인접 벽칸을 후보 탐색 시작점으로 사용한다. 선호 축 전체가 야외로만 이어지면 목표 쪽의 다른 벽 축을 시도한다. 실제 각 후보는 다시 목적지 검사를 통과해야 한다.
- 초기 접근의 후보 생성, 새 건물 외벽 조사, 대상 건물 분류에 같은 기준을 적용했다. 여러 틱에 걸쳐 준비한 계획도 공개 시점에 새 목적지를 재검사한다. 다른 분대가 이미 확보했다고 보고한 열린 통로와, 확보한 방에서 알려진 다음 목표로 나가는 기존 열린 출구는 각자의 통과 규칙을 유지한다.

검증은 원본 세이브를 읽기만 하는 22개 검사와 기존 벽면/개구부·야외 반복 방지 20개·열린 출구 재사용·계획 미리 준비 12개·진입 교전 18개·전역 예산 검사로 진행했다. 실제 좌표의 끝벽을 동서로 가로지르는 후보와 남쪽 야외 후보는 모두 제외되고, `x=160,161`에서 북쪽 복도로 향하는 후보는 유지된다. `(162, 0, 122)` 코너를 서쪽으로 접근할 경우 유효 인접 벽면 `(162, 0, 123)`을 사용할 수 있다.

원본을 보존한 외부인들2 복사본에서 LOW 12명을 `(170, 0, 114)` 주변에 생성해 2,200틱씩 짧게 실행했다. 목적지 검사 추가본과 최종 인접 벽면 시작점 보완본 모두 실내로 연결되는 `(162, 0, 123)`을 선택했다. 최종 실행의 CQB 예외·작업 실패·보고된 끝벽 좌표 선택은 0회였다. 종료 시점에는 해머 돌파가 진행 중이므로 진입 완료를 검증한 결과는 아니다. [최종 짧은 실행 결과](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-13-cqb-end-wall.json)에 요약을 보관했다. 메서드 프로파일링·장시간 검증은 실행하지 않았다.

개발자 화면 약식 확인은 [테스트 목록 F64](습격%20기능%20약식%20테스트%20목록.md)에 추가한다. 이 판정은 지붕과 짧은 전방 바닥에 기반한 근사이며, 건물 전체의 완벽한 내외부 구분을 수행하지 않는다.
