# 공통 확보 기록 구현

2026-10-12 사용자 지시에 따라 확보 구역·확인된 개구부 정보는 대화/무전 보고에서 분리했다. LOW·HIGH를 포함한 같은 맵의 전술 분대는 하나의 공통 기록을 참조한다. 주변 개구부와 돌파 흔적을 통한 추정을 단순화한 규칙이며 별도의 흔적 관측 AI를 추가한 것은 아니다.

## 현재 동작

- 실제 확인한 열린 개구부는 열린 통로 기록으로 바로 등록한다. 개구부가 생겼다는 것만으로 너머 방을 확보 처리하지 않는다.
- 진입 후 완료된 국소 방 조사 결과의 확보 칸을 공통 기록에 등록한다. 분대별 사본·전달 대기·연락 범위·무전기·동일 목표점 조건 없이 다른 분대의 다음 판단에서 조회한다. 맵이 다르면 기록은 분리된다.
- 공통 확보 칸으로 판단하면 같은 방을 다른 벽에서 반복 돌파하는 계획을 억제한다. 벽 파괴로 연결된 공간에 대한 국소 연결 확인도 공통 확보 기록을 사용한다. 실제 문/벽·통로·예약/진입 자리 유효성 검사는 유지한다.
- 이미 선택한 스택업/돌파/관측/투척 준비 대상도 다시 확인한다. 확보된 방의 사용 가능한 통로라면 준비 작업을 멈추고 통과하며, 다른 벽을 부수려던 계획이면 기존 작업을 반환하고 재계획한다. C4 실행과 이미 투척된 수류탄은 이 처리로 취소하지 않는다.
- 확보된 열린 통로는 계획 생성부터 `Enter`로 바로 시작한다. 전체 스택업 공간·집결 완료·관측/투척·협력 시작 대기를 요구하지 않으며, 이동도 바깥 접근 칸과 추가 진입 경유점을 건너뛴다. 선택한 개구부→안쪽 칸→개인 목적지는 실제로 통과해 후방 경계 인원이 다른 출입구로 돌아가는 것을 막는다. 이 통과 중에는 피아식별에 따른 집결 정지도 생략한다.
- 진입 목적지는 기존 최대 289칸의 연결된 국소 탐색으로 고른다. 입구 축 안쪽의 실제 이동 가능한 공간을 사용하고 다른 분대가 예약한 자리는 제외한다. 작은 방의 잉여 인원은 입구를 비운 접근 쪽 개인 경계 자리로 이동하지만 전체 인원을 모은 뒤 들어가는 스택업 단계는 없다. 확보 통로는 돌파용 독점 예약을 잡지 않고 개인 목적지만 예약한다.
- 폭발로 개구부 앞 지붕이 사라져 해당 칸이 확보 조사에서 누락되어도, 같은 방향의 개구부에 실제 방 확보 칸이 기록돼 있으면 확보 통로로 인정한다. 열린 구멍만 기록된 경우·관측된 적 때문에 재확인 상태인 경우는 이 규칙으로 확보 처리하지 않는다. 통과 중 문이 닫히거나 새 장애물이 생기면 재계획하고, 통과용 목적지를 돌파 대형으로 재사용하지 않는다. 이미 확보된 열린 통로를 사용할 수 있으면 공병 장비 회수부터 기다리지 않는다.
- 분대의 직접 진입·통과·실제 확보 칸은 별도로 유지한다. 공통 정보를 안다고 이미 방 안에 들어간 것으로 처리하거나 원격 확보 정보를 치료용 안전 자리로 복사하지 않는다.
- 새 적을 실제 관측하면 해당 구역의 공통 확보 판정을 재확인 상태로 바꾼다. 개구부 이력은 유지한다. 오래된 적 보고가 더 최근의 실제 재확보를 무효화하지 않도록 관측 시각을 비교한다. 적 ID/위치/무장 기억과 공동 작전 협의는 기존 LOW 접촉·HIGH 무전 조건을 유지한다.

## 비용과 저장

공통 기록은 기존 맵 컴포넌트에 값 상태만 저장하며 새 틱 컴포넌트나 전체 지도 재계산은 없다. 기존 확보 통신 메시지·전송 함수·수신 함수·ACK·분대별 확보 보고 사본은 제거했다.

한 기록의 확보 칸은 최대 16개, 후속 구조 후보는 최대 2개, 맵 전체 기록은 최대 256개로 제한한다. 확보 칸·개구부·재확인 대상은 인덱스로 조회한다. 동일한 재확인 상태에서 반복되는 적 관측은 최신 시각만 갱신하고 구조 변경 번호를 계속 올리지 않는다. 후속 구조 후보는 각 분대의 기존 판단에서 최대 2개 기록씩 반영하고 매 프레임 전체 분대로 복사하지 않는다. 오래된 기록은 한도에서 제거되므로 매우 큰 지역의 전역·영구 확보 기억을 보장하지 않는다.

공통 기록은 맵에 한 번만 저장한다. 각 분대는 반영 진행 번호만 저장하며 로드 후 같은 맵 객체를 참조한다. 목표 변경으로 기록을 지우지 않는다. 마지막 전술 실행 분대가 해제되거나 맵이 제거될 때 공통 기록도 비워 이후 별개 습격에 과거 확보 판정을 넘기지 않는다. 로드 시 유효한 전술 분대가 하나도 복구되지 않으면 남은 기록을 제거한다.

개발자 `Inspect squad commands`의 `secured own/shared`는 자기 분대의 직접 확보 칸 수 / 공통 기록 수이고 `recheck`는 공통 재확인 기록 수다.

## 검증

빌드 경고/오류 0. `--shared-secured`에서 공통 객체 참조, LOW/HIGH·목표·연락 독립, 다른 맵 격리, 적 기억 비공유, 중복/낡은 재확인·부분 갱신·반영 상한·기록 제거·맵 정리·바닐라 Scribe 공통 기록 저장/읽기를 확인했다. `--a2-walls`의 기존 방 조사·개구부·이중벽·C4·투척 안전·전역 예산 검사도 통과했다. 전체 Unity 세이브 로드나 정기 성능 수집은 하지 않았다.

직접 통과 수정은 `--cleared-transit`으로 검사한다. 개구부 앞 칸 누락·짧아진 이중벽 통로·구멍만 열린 경우·적 재진입 무효화, 13인 대형이 서지 못하는 좁은 접근로, 작은 방 잉여 인원, 목적지 중복/예약·벽 너머 배치 방지, 중단된 진입의 스택업 복귀 방지를 포함한다. 기존 공통 확보·목표 진행·C4/투척 안전·전역 예산 검사도 함께 실행한다.

사용자가 확인할 간단한 장면은 [단일 약식 목록](습격%20기능%20약식%20테스트%20목록.md)의 F04·F18에 둔다.
