# R3 CQB 구현과 검증

요구별 최종 근거와 단계 경계는 [R3 완료 검토](R3%20완료%20검토.md)에 정리했다.

2026-10-08. **R3 구현과 단계별 약식 검증을 완료했다. 정식 반복 CPU 게이트는 R7 최종 통합 검증에 남긴다.** main에서 [로드맵](최적화%20전술%20AI%20로드맵.md)의 CQB 행동을 새 지속 작업 체계에 연결한다. 기존 전역 맵 캐시와 Legacy 실행은 재도입하지 않는다.

## 비용과 안전 구조

Stack → Breach → Observe → Support → BlastWait → Enter → Clear 순서다. Clear에서 인접 구역 진입을 이어가거나 Returning으로 전환한다. 기존 전역 Job/경로/계획 예산을 유지하며, 개구부당 작은 OpeningAction만 둔다. 관측 위치 하나와 ID를 고정하고 지원 준비 중 해당 적의 미래 위치를 조회하지 않는다.

관측은 한 폰이 15틱 간격으로 최대 16명 후보를 순회하고 전역으로 틱당 한 번만 수행한다. native 피격 가능 칸과 LOS로 식별하며, 고유 대형 슬롯 옆에서 lean한다. 관측 불가/중단은 제한 유예 후 미확인 상태로 처리한다. 작은 방 여부는 문과 현재 개구부를 경계로 바닥을 탐색하고 17칸에서 중단한다. 야외 여부는 진입칸 지붕으로 근사한다.

지원은 관측한 위치를 우선하고 없으면 국소 후보 9개 중 관측자에게 안 보이는 칸을 우선한다. 개구부에서 2칸 미만인 적에게는 폭발물을 던지지 않는다. 폭발 지원 전 필요하면 같은 벽면의 제한된 연결 대형을 한 번 만들고, 모두 도착한 뒤 투척한다. 각 슬롯은 목표 LOS에서 벗어나야 한다. 안전한 자리/장비/throw LOS/실제 아군 안전 조건을 만족하지 못하면 강행하지 않는다. Smoke 선택에는 불필요한 폭발 대형 재계산을 하지 않는다.

투척은 기존 InventoryGrenadeUtility의 효과와 산포를 쓰고 실제 생성 Projectile을 받는다. 준비와 복귀 사이 바닐라 다음 행동 검색을 끼우지 않는다. 발사체 소멸만으로 진입하지 않고, 같은 instigator/projectile의 Explosion 종료와 복귀 후 30틱 안정화를 확인한다. 목표 변경이나 임무 해제로 이미 발사한 지원의 안전 상태를 지우지 않는다.

관측 적이 진입 자리를 차지한 경우 대체 자리를 고른다. 수류탄 때문에 다른 외벽에 구멍이 나도 바깥으로 자리가 새지 않도록 기존 계획에서 이미 탐색했던 안쪽 최대 81칸 발자국에만 제한한다. 전체 방/맵 캐시가 아니며 추가 전역 탐색이나 주기 갱신이 없다.

## 약식 검증

일반 방 LOW 12명, 준비 0틱/수집 3000틱에서 전원 진입 완료. 관측 1회·투척 1회·투척자 복귀 1회·폭발 대기 판단 29회·안전 완료 전 개구부 통과 0회다. 작업 실패/중단 6회는 회복 후 완료했으며 종류를 기록하는 필드를 추가했다. 예외 6개를 의미하지 않는다.

16칸 방에서 시야에 없는 적을 둔 사례는 전원 완료, 관측 1회·접촉 0회·투척 0회·실패 0회다. 시야 밖 적으로 절약 규칙을 해제하지 않았다.

보이는 적 예외 검증은 별도 contact 사례로 진행했다. 처음에는 감사 이벤트가 실행되지 않았고, 다음에는 관측 적과 자리 충돌로 1명이 반복 재시도했으며, 대체 자리 수정 뒤에는 폭발로 생긴 외부 구멍에 자리가 선택되는 문제가 발견됐다. 해당 실패 원본도 보존하며 최종 수정 결과와 혼합하지 않는다.

단위 검증은 16/17칸 경계, 무한 야외 탐색 상한, 접촉 예외, 최소 투척 거리, 발사체·폭발·복귀·안정화 조건과 전역 관측 예산을 확인한다. 새 5개 표현/사격 훅은 실제 게임 메서드/필드 바인딩을 통과했다. New 실행의 Legacy 컴포넌트/후크는 0개, New 컴포넌트는 2개·후크는 6개다.

다방 CQB CPU 2배 게이트는 아직 판정하지 않았다. 관련 메서드와 Core 기준을 짧게 수집하며, 이번 초기 기능 결과를 전체 R3 완료나 정식 CPU 합격으로 표시하지 않는다.

## 장비 승계와 절단기 연결

New 분대 등록 때 착용 해머와 주무장 절단기 참조를 보관한다. 조직에서 사망자가 빠져도 원본 장비를 시체/다운 폰/바닥에서 찾는다. 건강한 운용자에게서 장비를 빼앗지 않으며 착용 가능 여부·바이오코딩·조작 능력·거리 32칸·예약·접근을 확인한다. 실제 회수 작업은 전역 Job/경로 예산을 공유하고, 회수 후 다음 돌파 명령까지 보유 작업에서 대기한다. 다른 인원은 원래 연결 스택을 유지한다.

회수 경로 검사는 전역 계획 예산으로 한 번만 수행한다. 실패 후보를 재시도할 때 다른 후보로 순환하고 180틱 간격을 유지한다. 유효 회수 작업이 없어도 대기만 영구 지속하지 않고 기존 1200틱 진행 제한으로 해제한다. 계획 전 공병을 잃은 경우에도 회수를 먼저 시도한다.

절단기는 기존 native 장비 작업의 속도·음향·렌더·효과·구조물 파괴를 재사용하며, New 완료 통지와 이동 예산을 연결했다. 일반 문에는 유효한 착용 해머를 우선하고 해머가 못 여는 문이나 절단기만 있는 경우 절단기를 사용한다. 작업 중인 절단기를 HP 변화가 없다는 이유만으로 중단하지 않는다.

12명/준비 0/수집 3000틱의 장비별 약식 시험을 각각 한 번 사용했다. `recovery`는 해머 하나만 남긴 뒤 해당 공병을 돌파 작업 중 죽인다. 회수 시작/완료 1/1, 생존 11명 모두 개구부 통과 및 내부 자리 도착, 분대 완료다. `cutter-recovery`는 모든 해머를 제거하고 절단기 하나를 주며 해당 작업의 운용자를 죽인다. 회수 1/1, 절단기 작업 발행 2회, 구조물 파괴 완료 1회, 생존 11명 전원 진입이다. 이 사례의 사망은 작업 발행 뒤이며 실제 절단 효과 진행 중 사망을 별도로 보증하지 않는다.

## C4 설치·기폭과 안전 대기

New 설치/기폭 작업은 기존 C4 설치 속도, 실제 C4·점화기 소모, M81 즉시 기폭과 M60 지연 신관 효과를 재사용한다. 설치 전 한 번만 최대 128칸의 연결 퇴피 후보를 만들고, 분대가 폭발 반경과 방향성 파편 반경 밖으로 이동한 뒤 기폭한다. 운용자는 실제 케이블/신관 거리 안에 있어야 한다. 기폭 직전 실제 아군 위치를 확인하고, 실제 신관·발사 파편·폭발이 끝난 뒤 30틱 안정화를 기다린다. 이미 기폭한 상태는 운용자 사망·목표 변경·명령 해제로 삭제하지 않는다.

설치 전 공병 사망 때는 C4와 점화기를 같은 후임에게 회수한다. 바닥 물품을 DeSpawn한 뒤 인벤토리로 옮기며, 회수 완료 후 대기 작업을 계속 회수 중으로 오인하지 않는다. 설치 뒤 아직 기폭 전인 운용자가 사망하면 거리·조작 조건을 만족하는 후임에게 장치 제어를 넘긴다. 목표 변경은 확보한 물리 개구부를 지우지 않으며, 안전 대기 종료 후 기존 개구부를 검증하여 재사용한다.

12명/준비 0/수집 3600틱 약식 사례를 사용했다. 설치 작업 발행 뒤 공병을 죽인 M81 사례는 재료 회수 2회·설치 1회·기폭 1회, 생존 11명 전원 진입이다. 실제 설치 이후 기폭 전에 공병을 죽인 M60 사례는 제어 승계 1회·기폭 1회·대기 판단 45회, 생존 11명 전원 진입이다. M60 기폭 대기 중 목표를 변경하고 운용자를 죽인 최종 사례도 기존 개구부로 11명이 진입했다. 세 사례 모두 기능 완료·물리 계획·격리 검사 통과, 안전 완료 전 진입 0회다. 마지막 수정은 목표 변경 사례로 다시 검증했으며 앞선 두 사례의 DLL SHA는 원본 그대로 보존한다.

회수 첫 시험의 맵 물품 직접 전송 오류, 두 번째 시험의 완료 대기 오인, 목표 변경 첫 시험의 확보 개구부 소실은 실패 원본으로 남긴다. 실패 결과를 완료 또는 개선율 계산에 사용하지 않는다. 설치/기폭 작업의 실제 게임 API·범위·안전 대기 단위 검증과 빌드는 통과했다.

## 분대별 확보 이력과 연속 방 진입

한 방 진입 뒤 바로 Returning으로 끝내던 흐름을 Enter → Clear → 다음 Stack/Observe로 연결했다. 이름 있는 침대가 있는 구역을 우선하고, 해당 구역 확보 후 아직 들어가지 않은 인접 구역을 처리한다. 확보한 바닥과 개구부/진입 계획 이력은 분대별로 보관하며 다른 LOW 분대의 확보 상태를 가져오지 않는다. 이 이력은 진입과 구조 탐색 기록이며 모든 적의 사망을 확인한 기록은 아니다. 동적 교전·재침입 판단은 R4, 저장/로드 연결은 R7 범위다.

진입 직후 한 번만 지붕 있는 연결 공간을 조사한다. 전역 Plan 예산을 공유하며 탐색과 이력 복사 모두 한 번에 128칸씩 수행한다. 각 셀의 물리 분류를 해당 조사 동안만 재사용하고, 열린/닫힌 문은 모두 구역 경계로 취급한다. 좁은 복도는 벽 틈으로 분할하지 않으며, 양쪽 벽 지지가 남은 짧은 빈 개구부는 인접 구역의 통로로 보관한다. 최대 양쪽 3칸까지 지지 벽을 찾는 근사다. 더 넓게 벽이 없어지면 한 연결 구역으로 합쳐질 수 있다.

후속 스택은 그 분대의 확보한 바닥 안에서만 만들고, 진입 자리는 아직 확보하지 않은 쪽의 작은 연결 발자국 안에 둔다. 후보는 한 판단에서 최대 두 개, native 도달 검사는 각 후보에 한 번이다. 선택은 진입 완료 때 정하며 숨은 문 상태의 주기 갱신으로 교체하지 않는다. 후보가 막혀 목표/남은 구역을 확보하지 못하면 성공 Complete로 표시하지 않는다. 아주 작은 인접 구역에 분대 전체 자리가 없는 경우 등은 아직 추가 회귀와 개선이 필요하다.

문 안쪽 첫 칸과 그 다음 중앙 칸을 대형 자리에서 빼고 통로로 확보했다. 진입자는 해당 통로를 빠져나온 뒤 벽 가까운 고유 자리로 이동한다. 각 이동 구간 사이에 별도의 대기 대형을 만들지 않으며 기존 전역 경로 시작 예산을 유지한다. 해당 공간이 없는 경우 통로를 강제로 만들지 않는다.

약식 유효 지도 시험은 LOW 12명, 준비 0/수집 4800틱이다. 외벽 (100,103), 내부 문 (114,108), 내부 문 (126,119)를 차례로 통과하고 3485틱에 전원 완료했다. 세 구역의 대표 바닥과 이름 있는 침대 구역 확보, 중복 없는 세 개구부 이력, 연결 스택·고유 실내 자리·실제 물리 계획·엔진 격리 검사를 통과했다. 진입 12명, 안전 완료 전 통과 0회, 시험 외 폰 0명, capture complete=true/dropped=0/메서드 예외 0이다. 작업 실패/중단 12회는 회복됐으며 메서드 예외 수와 다르다.

처음에는 문 앞 정지와 짧은 수집 창을 구분하지 못했다. 통로 수정 뒤 같은 빌드의 창을 늘려 실제 세 방 진입 완료를 확인했지만, 서 있을 수 없는 침대 칸이 목표 확보에서 누락됐다. 방 소속에는 Walkable을 쓰고 대형 자리에는 Standable을 유지하여 수정했다. 후속 시험은 침대의 두 번째 칸이 칸막이 벽을 초기 배치에서 덮어썼다는 추가 문제를 발견했다. 기존 방 합침을 수류탄/메카노이드 때문이라고만 본 추정은 세 방 검증의 근거로 사용하지 않는다. 최종 fixture는 침대를 칸막이에서 떨어뜨리고 칸막이가 온전한지 생성 단계에서 검사한다.

## 현재 구역 목표와 예상 밖 개구부 회귀

Direct 목적지의 자리 선택을 주변 Standable 칸 나열에서 연결 공간 탐색으로 바꿨다. 반경 8칸·최대 289칸만 조사하고, 문·벽·지붕 경계를 넘어 자리를 채우지 않는다. 침대처럼 이동 가능한 가구는 연결 공간에 포함하되 실제 서 있을 수 있는 칸만 자리로 사용한다. 자리 수가 부족하면 다른 방의 빈 칸으로 채우지 않는다. 현재 구역 진입 완료 후 Clear에서 목표 확보와 인접 구역 정리를 계속한다. Direct 시작에는 스택이 필요 없다는 사실을 대형 이력에 반영하여 이후 실제 스택의 연결 검사를 유지한다.

후속 경계 후보는 이미 열린 구멍/문을 닫힌 문보다 우선한다. 한 번 정한 순서를 주기적으로 교체하지 않으며 구역 진입 완료 때만 정한다. fixture v13은 두 번째 구역 관측 중 다른 칸막이의 벽 한 칸을 제거하는 unexpected-hole 사례와, 목표 구역 안에서 시작하고 같은 구역의 이름 있는 침대를 명시 목표로 지정하는 inside-goal 사례를 추가했다.

LOW 12명/준비 0 약식 실제 실행을 사용했다. 예상 밖 구멍은 외벽 (100,103) → 내부 문 (114,108) → 새 구멍 (120,119)을 통해 세 구역을 확보하고 3275틱에 전원 완료했다(수집 4800틱). 현재 구역 목표는 Direct 확보 뒤 내부 문 (114,108), (126,119)로 이어져 2431틱에 전원 완료했다(최종 수집 3000틱). 두 사례 모두 실제 구조·연결 대형·고유 자리·세 구역/목표 이력·엔진 격리 검사를 통과했다. 안전 완료 전 진입 0회, 비시험 폰 0명, capture complete=true/dropped=0/메서드 예외 0이다.
