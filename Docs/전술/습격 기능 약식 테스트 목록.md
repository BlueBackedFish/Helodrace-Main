# 습격 기능 약식 테스트 목록

2026-10-11. [추가 계획](습격%20설계%20추가%20계획%20검토.md)의 게임 내 기능 확인을 개발 작업과 분리한 목록이다. 목록을 작성하는 것은 시험을 실행했다는 뜻이 아니다. A1 코드는 구현·관련 에이전트 검증을 완료했다. F01~F02는 사용자가 확인했으며 의견은 해당 행에 보존한다. 화력점 배치 수정 후 F02는 재확인 대기이며 이후 단계 항목은 후속 변경을 위한 초안이다.

## 진행 방식

이 목록의 확인 담당자는 사용자다. 메서드 분석과 세이브 안정성 검증은 별도의 에이전트 담당 작업이며 이 기능 목록에 넘기지 않는다.

- 에이전트는 빌드와 변경에 필요한 메서드 분석·세이브 안정성 등 복잡한 검증을 직접 수행한다. 게임에서 쉽게 확인할 동작은 이 목록에 기록해 사용자에게 넘기고 다음 작업으로 진행한다.
- 사용자가 플레이하면서 해당 항목을 확인한다. 에이전트는 매 구간마다 같은 약식 기능을 다시 게임 실행으로 시험하거나 전체 목록을 순회하지 않는다.
- 테스트는 결과가 눈에 보이는 최소 규모로 한다. 기본은 한 분대이며, 연락/협력 확인에만 두 분대 또는 필요한 화력조를 사용한다. 한 장면으로 여러 항목을 확인할 수 있으면 묶는다.
- 메서드/실행 흐름 분석과 저장/로드 안정성 검증은 에이전트가 담당한다. 정기 CPU 수집·성능 비교는 계획에서 제외한 상태를 유지하며, 사용자의 성능 문제 보고가 있을 때 관련 부분만 에이전트가 조사한다.
- 결과는 `통과 / 문제 / 미실행`과 짧은 증상으로 남긴다. 미실행 항목은 다음 개발 구간의 진행을 막지 않는다. 보고된 문제와 직접 확인한 진행 불가는 해당 수정 범위에서 처리한다.
- 새로운 기능마다 새 테스트 도구를 만들지 않는다. 기존 게임 UI·개발자 표시·이미 있는 짧은 검사로 확인하고, 확인 수단이 없는 항목은 사용자 테스트에 필요한 관찰 지점을 적는다.

## 결과 기록

확인한 행에 상태를 갱신하고 아래 형식으로 짧게 남긴다. 대량 원본 묶음·세이브 반복·메서드 수집 보고서는 요구하지 않는다.

`날짜 / 변경 또는 커밋 / F번호 / 사용자 확인 결과 / 통과 또는 문제 / 실제 관찰·필요한 오류 로그`

관찰하지 못한 동작은 미실행으로 유지한다. 문제 보고가 오면 관련 행만 재현·수정·재확인한다.

2026-10-11 / F01~F02 / 사용자 확인 완료. 호를 고정된 전선이 아닌 여러 화력점의 배치로 정정. 구현 후 F02에서는 중앙 후퇴·측면 인원 이동·구역 내 불규칙 배치·같은 교전 지점을 향한 사격·대기 중 반복 왕복 없음만 확인한다.

2026-10-11 / 추가 계획 F16 / 사용자 테스트에서 방어막 근접 폰 대응 부족 보고. A1.4에 우선 집중 사격→일반 원거리 교전 제어 반환 계획 추가. 구현이나 게임 시험을 수행한 기록은 아님.

2026-10-11 / 추가 계획 F02·F05 / 사용자 보고: 호 형성에서 방향만 공유하여 임시 화력조가 산개하고 화력 구역이 만들어지지 않음. A3.1에 조별 집결 구역·안정된 조 구성·합류 상태·구역 도착 기준·지연 인원 대기 한도 계획 추가. 기존 F02 확인 기록은 유지하며 새 보완의 구현·시험 완료로 간주하지 않음.

2026-10-11 / A1.4 구현 F16 / 별도 근접 위협 관측/보고·분대 공통 표적·현재 자리 사격·일반 AI 반환·원본 작업 소유권과 값 저장/복원 구현. 관련 에이전트 검사 통과. 구현 완료 기록 당시 사용자 게임 확인은 미실행이었고 이후 확인 결과는 아래에 기록함. A3.1 집결 보완은 여전히 계획 상태.

2026-10-11 / A1.4 F16 / 사용자 정상 작동 확인 / 통과. 테스트 중 정착지 밖 자연 생성 구조물도 돌파하는 별도 문제 보고. 목표 구조물 구분 방안을 검토하며 F16 통과를 취소하지 않음.

2026-10-11 / A2.0 F17 / 정착지 밖 자연 생성 구조물 돌파 문제를 코드와 바닐라 소유권/생성 방식으로 검토. 대상 세력·점유 근거·통과/접촉 대응 분리 계획 추가. 코드 변경과 게임 시험은 수행하지 않음.
