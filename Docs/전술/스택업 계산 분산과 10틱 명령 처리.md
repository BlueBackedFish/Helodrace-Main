# 스택업 계산 분산과 10틱 명령 처리

2026-10-12. 습격 시작의 불필요한 대기와 위치 계산의 한 틱 집중을 줄였다. 준비·스택업·진입 판단은 10틱 간격, 일반 이동 명령은 분대당 최대 2명씩 10틱 간격으로 처리한다. 계산이 진행 중이면 전역 계획 허가를 받아 다음 틱에 작은 계산 구간을 이어간다.

## 개인 자리의 배정 방식

- 스택업 공간은 연결된 양쪽 날개를 구한 뒤 양쪽을 번갈아 채운다. 만들어진 `Stack[i]`는 분대의 인원 인덱스에 대응한다.
- 진입 공간은 분대 인원수만큼 연결된 국소 공간을 먼저 구하고, 개구부 축에서 먼 자리→같은 축 거리에서 개구부와 먼 자리 순으로 정렬한다.
- 진입 인원은 공병 우선, 일반 인원, HAR/기관총, 저격/바주카/탄약수, 의무요원 순으로 정렬하며 같은 역할 안에서는 접근 자리와 개구부의 거리를 사용한다. 분대장은 정렬된 명령 순서의 중간에 넣는다. 이 순서와 실내 자리 순서를 하나씩 대응시킨다. 경로 자체는 바닐라가 계산한다.
- 작은 방의 잉여 인원은 남은 고유 접근 자리 중 가까운 엄폐 자리와 양옆 경계를 번갈아 배정한다. 다른 인원과 자리를 겹치거나 입구에 최종 대기하지 않는다.

배정 규칙은 유지하면서 LINQ 정렬/변환을 작은 리스트 정렬과 직접 순회로 바꿨다. 개인 실내 자리 배정, 잔류 경계 후보 검사, 경계 배정은 각 계산 구간에서 최대 2명/2자리씩 처리한다. 결과가 완성되기 전에는 실제 명령 계획에 게시하지 않는다.

## 시작 대기와 명령 처리

다른 분대가 있다는 이유만으로 협력 상대를 기다리던 최대 600틱의 시작 대기를 제거했다. 실제로 시작한 협의·피아식별·확정된 작전 시작 조건은 유지한다. 기본 공동 작전 시각은 제안 후 900틱에서 300틱으로 줄였지만, LOW 음성 보고/무전 전달과 시작 메시지의 90틱 여유는 유지해 상대보다 먼저 돌파하지 않도록 했다.

조직 발견 재시도는 300틱에서 10틱으로 줄였다. 일반 스택업/돌파 판단의 120틱, 진입 판단의 30틱, 관측 준비의 15틱 간격을 10틱으로 줄였다. 스택업 이동과 진입 명령은 최대 2명씩 10틱 간격으로 발행한다. 강제 작업과 유도 담당자는 일반 이동 배치가 다른 인원을 막지 않도록 건너뛴다. 완료된 임무의 유휴 간격, 실패 재시도 완충, 적 교전 소강 판정, 수류탄/C4 효과 안전 대기 조건은 유지한다.

전역 작업 2회·반환 1회·경로 4회·계획 계산 1회와 1.5ms 사후 예산도 유지한다. 따라서 여러 분대는 같은 틱에 모두 경로/계산을 시작하지 않으며, 예산을 얻지 못한 계산은 후속 틱으로 넘긴다.

## 위치 계산을 나누는 구조

`TacticalPlanSearch.Step`은 메인 스레드에서 이어지는 계산 한 구간만 실행한다. 외벽 방향 탐색은 최대 32칸씩, 후보 형상 검사는 한 후보씩 처리한다. 형상/거리로 먼저 순위를 정한 뒤 선택 후보의 스택업 공간, 진입 공간, 도달 가능성을 서로 다른 구간에서 계산한다. 첫 후보가 성공하면 나머지 후보의 대형은 계산하지 않는다. 후보 최대 8개와 네이티브 최종 도달 검사 최대 2회는 그대로다.

`TacticalPlanPreparation`은 탐색→개인 배정→최종 유효성 확인을 이어간다. 다른 분대가 그동안 잡은 예약, 실제 보행 가능성·개구부·장비와 확보 판정을 게시 직전에 다시 확인한다. 목표, 인원 구성/순서, 원래 계획, 실행 단계, 새로 확정된 협력 작전이 바뀌면 미완성 작업을 버린다. 예약은 완성된 계획에만 잡는다. 후속 실내 방과 확보되지 않은 보고된 개구부도 스택업/진입 공간을 별도 구간에서 만든다.

이 상태는 실제 `Map/Pawn`을 워커에서 읽는 비동기 작업이 아니다. 실행 도중의 iterator/델리게이트는 저장하지 않는다. 로드 후 저장된 단계와 같은 방 후보에서 미완성 준비만 다시 시작한다. 실제 Job·통과/진입·확보 이력은 유지한다. 목표 변경·반환·맵 제거 시 준비 상태를 정리한다.

개별 플러드필 한 번과 예외적인 가구 제거 시뮬레이션 내부까지 선점하는 구조는 아니다. 큰 최초 호출과 바닐라 폰/경로 스파이크가 완전히 사라진다고 보장하지 않는다.

## 약식 검증과 측정

빌드 경고/오류 0. `--cadence`, `--stack`, `--cleared-transit`의 배정·연결 대형·작은 방·협의/피아식별·중단된 준비·목표 변경·공통 확보·폭발 안전·예산 검사를 확인했다. 전체 장시간 CPU 대조와 게임 전체 저장/로드 반복 검사는 하지 않았다.

같은 단일 방·LOW 12명·1800틱에서 중간 구현과 개인 배정 분산 구현을 좁혀 수집했다. 두 번 모두 12명 실제 진입, 정상 계획, capture complete=true/dropped=0/메서드 예외 0이었다. 분산 구현의 흐름은 다음과 같다.

| 계산 | 호출/틱 | 경과 시간 |
| --- | --- | ---: |
| 스택업 공간 | 1회, 틱 13 | 3.272ms |
| 진입 공간 | 1회, 틱 14 | 1.562ms |
| 역할 순서 | 1회, 틱 16 | 2.720ms |
| 개인 자리 배정 | 틱 17~23에 7회 | 합계 0.034ms, 최대 0.019ms |

기존 단일 방 시험의 스택업/진입 공간 각각 7회 일괄 계산은 각각 1회로 줄었다. Core 10,000회 배치 중앙값은 0.2788ms이며 개인 자리 배정 평균은 기준의 1.742%다. 전술 판단 최대는 18.412ms로, 초기 판단의 큰 지연은 남아 있다. 전체 창의 판단 합계는 76.975ms/200호출이었다. 기존 시험의 74.120~75.420ms/101~102호출과 계측 대상·실행 흐름이 달라 정식 개선율이나 전체 CPU 합격 수치로 계산하지 않는다.

측정 이후 새 협의와 준비 상태 일치 검사, 보고된 열린 통로의 계산 분산을 더 적용했다. 최종 DLL은 프로파일러 없이 2400틱 동안 첫 방 455칸 확보→내부 문 `(114,108)` 계획→다음 방 12명 전원 진입/자리 도착을 확인했다. 연결 대형·실제 계획 검사 통과, 작업 실패/안전 대기 전 진입 0이다. 피해를 받지 않는 시험 목표와 계속 교전하므로 전체 임무 완료 시험은 아니다.

연속 방 검사의 기존 도구는 빈 중앙 통로를 사이에 둔 양쪽 대형과 경계 자리 재배정을 이전 규칙으로 검사했다. 실행 규칙과 맞게 날개 연결 검사·경계 후보 포함 검사를 사용하도록 수정했으며, 이전 false 원본도 보존했다.
