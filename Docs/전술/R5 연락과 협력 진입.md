# R5 연락과 협력 진입

상태: 구현·관련 로컬 검사·대표 실제 게임 약식 검증 완료. main에서 검증 완료 단위마다 커밋한다. R6 야전/수비와 R7 전체 반복 CPU 판정은 이번 범위가 아니다.

새 엔진은 `-hdTacticalEngine=new`로 선택한다. 기본 엔진 전환과 구형 제거는 R7 범위로 유지한다.

## 구현 계약

- 기존 조직과 착용 무전 파츠 판별만 재사용한다. 구형 통신 프레임/분대 간 폰 그래프/맵 캐시를 새 실행에 연결하지 않는다.
- 대표 연락자 중심으로 전 맵 공통 작업 예산을 사용한다. 한 번에 한 분대 쌍을 조사하고 메시지 큐는 최대 64개, 처리량은 최대 2건/틱으로 제한한다. 전체 분대 쌍을 한 틱에 재구축하지 않는다.
- LOW는 가까운 실제 LOS/연막 없는 접촉에서만 새 보고·협력 메시지를 교환한다. 접촉에서 확정한 역할·예정 시각은 분리 후에도 따르지만 새 준비/실패/적 상태를 원격으로 읽지 않는다.
- High 무전은 정상 착용 방탄복의 실제 설치 무전 파츠, 가능한 운용자, 호환 네트워크·사거리 조건을 송수신 시점에 확인한다. 인벤토리/지면 장비와 태블릿은 인정하지 않는다. 운용자 사망·다운·파츠 제거 시 진행 중 메시지는 무효로 하고 대체 운용자를 제한된 탐색으로 선택한다.
- 목격 보고는 원래 관측 시각·좌표의 값 복사다. 수신 시각으로 신선도를 부풀리거나 더 최신인 자체 관측을 덮어쓰지 않는다. 다른 분대의 확보 칸 전체를 실제 진입 이력으로 복사하지 않는다.
- 협력은 제안→수락→확정, 준비 보고, 시작, 완료/중단으로 표현한다. 분대별 합의 상태는 별개이며 상대 준비 상태는 받은 메시지로만 갱신한다.
- 다른 외벽 입구와 담당 구역을 우선 배분한다. 현재는 두 분대의 합의 단위로 구성하며 여러 쌍을 병행할 수 있다. 해당 구역의 실제 진입/확보가 필요하다. 공동 최종 목표와 맡은 구역의 완료를 구분한다.
- 같은 입구밖에 없으면 기존 물리 사용권과 대기 자리를 사용해 차례로 진행한다. 상대가 사용권 때문에 준비하지 못해도 서로 기다리며 멈추지 않도록 사전 예정 시각·시간 제한·독립 진행 복구를 둔다.
- 실내에서 다른 아군 분대와 실제 조우하면 짧은 식별 지연을 둔다. 오인 사격/프래깅은 만들지 않는다. 이미 발사한 수류탄·C4 안전 절차를 식별/통신 대기 때문에 중단하지 않는다.

## 검증 범위

### 현재 구현 상태

대표 연락자·전역 최대 64개 메시지 큐·틱당 최대 2개 연락 작업, 분리된 합의 상태, 실제 착용 무전 파츠 재검사, 원래 목격 시각을 유지하는 보고를 구현했다. 합의한 방향에 따라 외벽 후보를 나누고 담당 구역을 우선 정리한다. 공유 입구는 제한된 재시도 후 중앙 후보로 복구하며, 연락이 끊겨도 사전 예정 시각으로 독립 진행한다. 실내 조우 시 45틱 식별 대기를 두되 발사된 폭발물 안전 처리는 우선한다.

현재 빌드는 경고/오류 0개이며 `--r5` 관련 검사에서 합의·중복/지연 메시지·보고 신선도·역행 방지·방탄복의 물리 무전 파츠·메시지 큐/스냅샷 29개와 전역 작업 예산·접촉 기억 검사가 통과했다. 아래 실제 게임 결과로 협력 진입·공유 입구·무전 단절/승계와 관련 비용을 확인했다.

초기 연락 기회와 협상 유예는 각각 최대 600틱이다. 한 분대만 있으면 초기 연락 대기는 없다. 합의한 시각은 최초 제안 뒤 900틱, 임무 시한은 6,000틱이며, 준비 보고를 실제 받은 경우 시작 메시지로 앞당길 수 있다. 연락이 끊긴 LOW는 상대 준비 상태를 읽지 않고 사전 시각과 자기 준비 상태로 진행한다. 시한 또는 명시 목표 변경/실패에는 합의를 중단하고 독립 임무로 복구한다.

입구 합의는 전체 맵 검색 대신 공통 접근축의 좌우 영역으로 표현한다. 각 분대는 그 영역에서 국소 검증한 실제 벽/문을 선택하고 선택 좌표를 상태 보고에 담는다. 담당 구역은 공동 목표의 좌우 12칸을 지향점으로 삼고 자기 분대가 실제 확보한 바닥에 포함될 때 완료한다. 해당 지점이 부적합하면 기존 목표/인접 방 정리로 복구한다. 두 차례 실패한 외벽 후보는 중앙 후보로 복구하며 공유 입구의 물리 사용권은 유지한다. 서로의 확보 칸을 복사하지 않는다.

알려진 개구부 재사용도 자기 진입 이력, 실제 받은 보고 또는 28칸 이내 개구부 자체의 LOS가 필요하다. 물리 사용권이 그 개구부를 원격으로 알려 주지는 않는다. 개발자 `Inspect squad commands`에서 합의 단계·마지막 연락 채널·연락자·상대·담당 지향점·자기/보고된 준비 상태·보고 경과 틱을 볼 수 있다.

먼저 관련 정책·프로토콜·보고 신선도·작업 제한과 기존 실제 무전 파츠 판별을 로컬 검사한다. 실제 게임은 필요한 대표 사례만 각 1회 실행하고 실패/수정 영향만 재검증한다.

| 사례 | 발생 조건 | 성공 조건 |
|---|---|---|
| LOW 다중 진입 | 접촉 가능한 2개 완전한 분대, 실제 분리된 외벽 진입·방 배분 | 합의 3단계, 서로 다른 입구/담당 구역의 실제 진입·확보, 분리 후 새 보고 없음, 실내 재접촉/식별 지연, 전체 임무 진행 |
| LOW 공유 입구 | 유일한 통과 가능 개구부, 다른 돌파 수단 없음 | 합의/대기 후 두 분대의 선두·후미가 같은 개구부를 실제 통과, 후속 분대 영구 정지 없음 |
| High 연락 단절·승계 | 음성 범위 밖의 2개 13인 분대, 실제 방탄복 무전 파츠 제거/재설치 및 운용자 사망 | 무전 없이 보고/확정 없음, 착용 무전 복구 후 교환, 사망 발신자의 진행 중 메시지 무효·대체 운용자 사용·임무 진행 |
| 순수 정책 | 오래된/중복/미확정/취소 메시지와 최대 큐 부하 | 신선도/역행 방지, 미확정 협력 금지, 시한 후 독립 복구, 전역 메시지 처리량 제한 |

현재 프로파일러로 연락 조사·송수신·협력 게이트·관련 계획 함수와 Core/전체 틱만 수집한다. 메서드 경과 시간과 OS CPU를 구분하고 상위/하위 비용을 중복 합산하지 않는다. 약식 결과를 정식 N/V 2배 합격으로 표시하지 않는다. 대규모 반복·저장/로드·다중 맵 전체 검증은 R7에 남긴다.

디스크 공간이 부족해 로컬 테스트는 기존 게임 DLL을 직접 해석하도록 실행 진입점을 분리하고 Unity 참조 복사를 제외했다. 같은 관련 검사 실행이 통과했으며 불필요한 게임 런타임 사본 생성을 줄인다.

High 보고 시험은 적을 (99,80)에 놓고 발신 분대만 실제 사격 lean/LOS로 볼 수 있게 했다. 수신 분대의 모든 생존 폰에 대해 해당 LOS가 없음을 검사한 동안, 825틱 목격 정보가 886틱에 무전으로 도착했다. 수신 시각으로 목격을 갱신하거나 숨은 위치를 조회하지 않았다.

대표 세 결과 모두 감사/캡처 complete, 환경 통제·엔진 격리 true, 비시험 폰·계측 누락·계측 예외·안전 대기 전 진입 0이다. LOW/High/공유 입구의 Job 실패·중단은 각각 23/1/7회이며 회복해 완료했다. 메서드 예외와 동일시하지 않는다. 지원 투척/복귀는 각각 4/4, 2/2, 1/1이며 High는 실제 C4 설치/기폭 1/1도 완료했다. 식별과 C4 안전이 동시에 발생하는 모든 조합을 시험한 것은 아니다.

초기 High 실패는 사망 운용자를 교체하는 동안 상대 분대의 240틱 연락 기회가 끝나 협력 제안을 놓친 경우였다. 두 분대는 독립 임무를 완료했지만 합의 0회였으므로 실패 원본으로 남겼다. 초기 연락 기회를 600틱으로 조정한 뒤 같은 사례에서 합의/담당 구역 완료를 확인했다. LOW 식별 해제의 임시 자리 정리는 전체 맵 claim 순회 대신 해당 분대의 자리만 처리하도록 줄였다.

최종 DLL SHA256은 `6d011e670d4945aa05c2ef4940f69ea8f0fc881e2198b443a658b7abd9e1a175`이다. LOW/High 대표 결과의 DLL은 `2bfd1740…`이며 마지막 변경은 `ReuseOpening`의 LOS 대상을 바깥 칸에서 개구부 자체로 강화한 것뿐이다. 이 변경 경로는 최종 DLL의 공유 입구 시험으로 검증했다. 실제 다른 입구로 계획한 LOW/High 결과를 새로운 동일 빌드 반복 대조로 취급하지 않는다.

## 약식 비용과 제한

메서드 값은 inclusive **경과 시간**이고 실제 개별 CPU가 아니다. Core 기준은 고정 10,000회 `GenRadial.NumCellsInRadius` 배치 중앙값이며 CPU 점유율이 아니다. 아래 합계는 서로 중첩되지 않는 `Pump + AdvanceCoordination + CooperationReady`만 더한다. `ProbePair/Deliver`는 Pump 안에 포함되어 별도 합산하지 않는다. 전용 Job·바닐라 경로 비용 전체를 포함하는 값도 아니다.

|---|---|---:|---:|---:|---:|

| LOW 공유 입구 | 3,600 / 7.9048 / 1.7341 | 0.003868 | 1.3165% | 0.5339 | 4.1927 |

원본 summary/capture에 관련 메서드 호출·평균·p95/p99·최대·Core 비율을 보존했다. 분위수는 최근 최대 2,048호출이며 전체 창에는 완료 뒤 짧은 유휴 구간도 포함된다. 서로 다른 규모/빌드/창의 숫자로 개선율이나 성능 곡선을 만들지 않는다.

모든 맵이 하나의 서비스/예산을 공유한다. 메시지 최대 64개, 한 틱 최대 2개 연락 작업, 전달 검사 최대 4개, 분대 쌍 조사 최대 8틱에 1개, 연락자 대체 후보 최대 2명이다. 분대별 연락 그래프·모든 폰 쌍 검사·지도 전체 통신 갱신을 만들지 않았다. 이 상한은 반복 작업량을 제한하지만 이미 시작한 동기 호출을 선점하지는 않는다.

전체 틱 최대 경과 시간은 LOW/High/공유 입구 각각 73.8660/60.0486/41.7507ms이며 새 지휘 Tick 최대도 약 12.55~13.08ms다. 스파이크 제거 또는 전체 AI CPU ≤2배의 정식 합격은 선언하지 않는다. R7에 동일 조건 반복 N/V, 다중 맵·대규모 비용 곡선·저장/로드·종료 정리·많은 합의 쌍의 공정성·예외 조합을 남긴다. R6 야전/수비는 착수하지 않았다.
