# 전술 AI 작업·명령·이동 통합 구현 결과

작업: 2026-10-06. [구조 개편 검토](전술%20AI%20구조%20개편%20검토.md)의 D 단계다. C의 분산 실행과 공유 정적 구조·관측/통신 조건을 유지하면서, 명령 해석과 통행 조건의 중복을 줄인다. 역할별 책임 이전 단위로 main에 커밋한다.

## 1. 작업 의도와 실행 명령 분리

`RaidPawnCommand`는 해당 폰의 명령 소유자, 원래 목표, 이동/사격/대기 의도와 변경 세대를 가진다. `RaidPawnOrder`는 이를 현재 상황에서 실행 가능한 위치와 Job으로 해석한다. 접근·Security·돌파·공격·반응·개구부 대기를 구분한다. 범용 작업 그래프를 매 틱 탐색하지 않는다.

이전에는 접촉 경계와 외벽 진입 보정이 요청을 Move에서 Hold로 바꾸며 실질 명령을 덮어썼다. 새 구조는 원래 요청을 별도로 저장해 일시적인 대기 후 같은 목표로 복귀할 수 있다. Job 선정과 분대 조정기가 서로 다른 목적지를 직접 갱신하던 `ContinueExteriorIngress`를 제거하고 하나의 Resolve 경로를 사용한다.

일반 해석은 30틱 간격으로 제한한다. 작업의 의도가 변하거나 중간 진입 목적지에 도착했을 때는 즉시 해석한다. 동일한 명령을 반복 발행해 세대를 계속 갱신하지 않는다. 경계·진입 대기가 해제되면 원래 의도로 복귀한다. 실제 위험 대응과 공병/관측/투척 Job 보호는 유지한다.

폰별 정기 검토는 미완료 Move인데 해당 목적지의 Goto가 없으면 재검토 요청을 남긴다. 기존에는 소유한 Wait Job과 동일한 명령의 조합에서 `RefreshPending`이 꺼진 뒤 정기 검토가 아무 것도 하지 않을 수 있었다. 현재 경로, 도착한 폰, 의도적인 Hold, 재시도 제한 중인 폰은 새 Job을 반복 발행하지 않는다.

원래 의도와 소유자는 Scribe로 저장한다. 이전 저장 형식의 호환 처리는 두지 않는다. 연결 상태의 실제 사용은 다음 책임 이전에서 붙인다.

검증: 빌드 경고·오류 0개, 기존 바인딩 전체와 신규 의도/보류/이동 복구 검증 7개 통과. 실게임 Security 회귀 5개는 각 11명이며 예외 없이 완료됐다. 단계별 틱과 DLL 해시는 최종 측정 자료에 버전별로 보존한다.

## 2. 공통 통행 입력과 경로 세대

`TacticalMovementPermission`은 공유 비용 배열 생성과 실제 이동 칸 검사가 함께 사용하는 불변 통행 조건이다. 방·선택한 문/개구부·개인 실내 연결·지원 금지 방·반응/사격 활동 범위를 한 곳에서 해석한다. 실제 PathRequest가 선택한 조건을 폰 명령에 연결한다. 이동 중 매 칸마다 분대 단계와 개인 노드·내부 연결을 다시 조회하던 경로를 제거했다. 개구부의 실제 점유/예약은 여전히 칸 진입 시 검사한다.

조건은 관리 메모리의 값 객체이며 Native 배열 해제 후에도 안전하게 참조할 수 있다. 요청/읽기 완료에 따른 기존 Native 수명 규칙은 변경하지 않는다. 조건의 해석을 위해 매 칸 HashSet을 만들지 않고 공유 입력마다 한 번 구성한다. 무제한 조건의 0 비용 배열은 계산을 생략한다.

현재 경로의 명령 세대를 기록한다. 목적지가 같더라도 연결이 바뀌었으면 기존 Goto를 그대로 이어 쓰지 않고 새 요청으로 인계한다. 변하지 않은 명령은 경로를 반복 시작하지 않는다. 개인 연결은 작업 의도가 보관하므로 다른 인원의 단계 변경만으로 그 조건이 사라지지 않는다. 저장 시 제한된 실내 연결 칸도 함께 기록한다.

빌드 경고·오류 0개, 지도/이동/캐시/워커 검증 962개 통과, 실제 클래스 바인딩과 의도/관리 통행 조건 검증 10개 통과. 실게임 진입 시험 5개 통과(321 / 419 / 361 / 204 / 415틱, 각 11명). 실제 경로 조건 연결도 각 이동 인원에게 확인했다. 후미 한 명만 합류하는 4번은 1명, 나머지는 11명씩이다. 예외 로그는 없었다.

## 3. 후미의 독립 합류

접촉 경계 해제는 해당 폰의 마지막 합류 작업만 만든다. `ApproachComplete`, 공통 `CurrentNode`, 이미 도착한 선두의 진행을 다시 열지 않는다. 늦은 폰은 기존 배치 위치를 원래 목표로 유지하고, 별도로 캡처한 알려진 실내 연결로 움직인다. 다음 단계로 넘어갔어도 해당 연결의 수명은 명령이 가진다.

실내 합류는 자기 단위의 통로 지식과 해당 폰에게 도착한 기존 Passage 보고에서 연결을 만든다. 다른 분대의 숨은 통로를 가져오거나 전역 CanReach로 옛 외부 입구를 선택하지 않는다. 연결이 없으면 UnknownJoin으로 현재 공간에서 보류하고 90틱 뒤에 다시 탐색한다. 유효한 연결은 재사용한다. 전술 정보를 공유하는 접촉/무전 조건은 변경하지 않았다.

기존 Security 검증을 새 책임에 맞게 수정하고 실제 게임 시험에서도 선두의 완료 상태를 매 프레임 검사했다. 회귀 5개 통과(415 / 380 / 402 / 235 / 397틱), 실제 경로 조건 연결 확인, 예외 로그 없음. 완료한 선두와 늦은 한 명이 있는 4번에서 분대 접근 상태를 다시 여는 동작이 없었다.

## 4. 통로 입장과 정지 자리

돌파 작업 공간의 기존 사용권과 개구부 통행의 입장 순서를 별도로 관리한다. 공병·관측·투척·실제 효과 대기는 기존 작업 사용권/안전 조건을 유지한다. 후속 인원의 확정된 기존 연결은 다음 방 작업으로 교체하지 않는다. 실제 입구 점유와 입장 순서는 전술 지식을 전달하지 않는 물리 통행 정보다.

통로 가까이에서 실제 이동 가능한 인원만 FIFO에 등록한다. 반복 요청은 순서를 바꾸지 않는다. 실제 통과로 입구가 비면 다음 인원을 허용하며, 사상자·취소·90틱 이상 요청 없는 작업은 제거한다. 현재 입구를 통과 중인 인원은 밖으로 되돌리지 않는다. 대기 자리는 개구부 근처의 고유한 외부 칸을 우선하며 개구부/안쪽 첫 칸을 정지 목표로 사용하지 않는다. 병목에서의 짧은 순차 대기는 허용한다.

내부 임시 목적지와 외부 양보 자리는 지속적인 폰↔칸 인덱스가 가진다. 매 폰의 명령 해석마다 모든 분대의 진입 목적지를 다시 열거하던 코드를 제거했다. 일반 정리는 60틱 목록 검토에 묶고, 실제 통과/취소 때는 해당 폰만 해제한다. 사용권과 인덱스는 로드 시 기존 확정 진입 상태로 복구하는 파생 자료다.

이미 사용한 개구부와 첫 내부 통행 칸은 이후 정지 배치 후보에서 제외한다. 공간이 한 칸뿐인 방은 한 인원의 기존 수용 제한을 유지한다. 진입 목표가 나중에 다른 폰/예약에 막히면 그 인원의 미완료 목적지만 다시 선정한다. 이미 완료한 다른 인원의 통과를 초기화하지 않는다.

기존 연결을 재사용하는 진입도 실제 선택한 개구부를 사용하도록 비용 조건을 제한한다. 다음 방의 관측·지원·효과 대기 중인 목표 방은 후미 진입 경로에서도 제외한다. 이미 진행 중인 경로에는 같은 단위의 현재 지원 안전 경계를 확인한다. 긴급 회피와 보호 작업을 일반 이동으로 덮어쓰지 않는다.

개발자 전술 보고는 작업 소유자/세대, 원래 의도, 실제 실행 위치와 경로 세대를 표시한다. 감사 출력은 통로 대기 수와 최대 24명의 이동 요청 상세, 마지막으로 거부된 이동 칸과 현재 목적지의 허용 여부를 추가한다. 상세 목록은 이미 이동을 시작했다가 막힌 작업도 포함하므로 미출발 요약과 집계 범위가 다를 수 있다. 작은 방/양방향 후퇴/지속 교전 전체를 검증한 것으로 취급하지 않는다.

## 5. 실제 이동 칸의 반복 조회 축소

이동 칸 검사는 이미 발행한 전술 Job에 연결된 명령과 조직 그룹 ID를 확인한다. 전체 분대/참여자/통제 상태 검증은 기존 정기 검토와 Job 선택에서 수행한다. 같은 칸 진입 검사에서 조직 전체 조회를 다시 수행하지 않는다. 실제 지원 안전 경계와 입구 점유 검사는 유지한다.

칸 이동 후 외벽 진입 관측도 현재 경로에 미완료 진입 기록이 있는 폰에만 수행한다. 모든 일반 폰의 이동마다 조직과 분대 진입 목록을 열거하던 호출을 제거하고 캡처한 진입 기록을 사용한다. 사망·다운·드래프트·정신 상태·그룹 변경 인원은 이 경로를 사용하지 않는다.

숨겨서 실행하는 감사 게임은 맵 생성 전에 바닐라 `Root.Update`의 `Prefs.Apply`가 백그라운드 설정을 다시 끄는 경우가 있었다. 명시적인 감사 인자가 있을 때만 초기 설정의 `Prefs.RunInBackground`를 켠다. 일반 플레이 설정은 변경하지 않는다. 맵 생성 전에 멈춘 두 실행은 측정 자료가 없으며 정상 완료한 실행으로 집계하지 않는다.

## 계속 검증할 항목

일반 폴링 30/60/90틱과 C의 실행 예산에 따른 지연은 남는다. 모든 역할의 전술 단계 조정기를 범용 작업 그래프로 바꾸지 않았다. 변경 범위는 폰 명령 소유권, 개인 합류 수명, 경로 통행 조건과 통로 점유다. 여러 맵·High 실제 편제·서로 다른 진입점의 지속 교전·양방향 후퇴·진행 중 실제 저장/로드는 E의 통합 확인 범위다. C에서 발견한 장기 대기의 해결 여부와 성능은 아래 최종 실게임 측정으로 판단한다.
