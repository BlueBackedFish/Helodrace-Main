# 전술 AI 작업·명령·이동 통합 구현 결과

작업: 2026-10-06. [구조 개편 검토](전술%20AI%20구조%20개편%20검토.md)의 D 단계다. C의 분산 실행과 공유 정적 구조·관측/통신 조건을 유지하면서, 명령 해석과 통행 조건의 중복을 줄인다. 역할별 책임 이전 단위로 main에 커밋한다.

## 1. 작업 의도와 실행 명령 분리

`RaidPawnCommand`는 해당 폰의 명령 소유자, 원래 목표, 이동/사격/대기 의도와 변경 세대를 가진다. `RaidPawnOrder`는 이를 현재 상황에서 실행 가능한 위치와 Job으로 해석한다. 접근·Security·돌파·공격·반응·개구부 대기를 구분한다. 범용 작업 그래프를 매 틱 탐색하지 않는다.

이전에는 접촉 경계와 외벽 진입 보정이 요청을 Move에서 Hold로 바꾸며 실질 명령을 덮어썼다. 새 구조는 원래 요청을 별도로 저장해 일시적인 대기 후 같은 목표로 복귀할 수 있다. Job 선정과 분대 조정기가 서로 다른 목적지를 직접 갱신하던 `ContinueExteriorIngress`를 제거하고 하나의 Resolve 경로를 사용한다.

일반 해석은 30틱 간격으로 제한한다. 작업의 의도가 변하거나 중간 진입 목적지에 도착했을 때는 즉시 해석한다. 동일한 명령을 반복 발행해 세대를 계속 갱신하지 않는다. 경계·진입 대기가 해제되면 원래 의도로 복귀한다. 실제 위험 대응과 공병/관측/투척 Job 보호는 유지한다.

폰별 정기 검토는 미완료 Move인데 해당 목적지의 Goto가 없으면 재검토 요청을 남긴다. 기존에는 소유한 Wait Job과 동일한 명령의 조합에서 `RefreshPending`이 꺼진 뒤 정기 검토가 아무 것도 하지 않을 수 있었다. 현재 경로, 도착한 폰, 의도적인 Hold, 재시도 제한 중인 폰은 새 Job을 반복 발행하지 않는다.

원래 의도와 소유자는 Scribe로 저장한다. 이전 저장 형식의 호환 처리는 두지 않는다. 연결 상태의 실제 사용은 다음 책임 이전에서 붙인다.

검증: 빌드 경고·오류 0개, 기존 바인딩 전체와 신규 의도/보류/이동 복구 검증 7개 통과. 실게임 Security 회귀 5개는 각 11명이며 예외 없이 완료됐다. 단계별 틱과 DLL 해시는 최종 측정 자료에 버전별로 보존한다.

## 계속 검증할 항목
