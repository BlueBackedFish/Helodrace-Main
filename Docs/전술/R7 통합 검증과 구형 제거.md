## 종료 정리 첫 단위

기존에는 `Released` 명령이 맵의 분대 사전과 소유 상태에 남고, 마지막 분대 종료 후 알려진 개구부도 남을 수 있었다. 이제 종료 반환을 마친 명령을 맵/전역 큐에서 제거하고 해당 송수신 메시지와 상호 연락 참조도 정리한다. 마지막 분대가 없어지면 자리/사용권/개구부와 자동 목표 캐시를 비운다. 맵 제거도 전역 큐에서 제거한다. 다른 Lord로 이동한 폰을 원래 명령의 활성 인원으로 취급하지 않는다.

실제 LOW 12명/3,600틱 `r7-cleanup`: 1,659틱 전원 진입 과제 완료 → 실제 `Pawn.ExitMap`/WorldPawns 경로 → 1,663틱 명령·소유·자리·사용권·개구부·메시지 모두 0. 조직 표시 정보도 제거됐고 이후 240틱 이상 판단/연락 검사 증가 없이 유지됐다. `newFunctionalComplete=false`는 종료 감사 시 명령 자체를 제거했기 때문이며 이 플래그를 성공으로 덮어쓰지 않는다. 이 사례는 별도의 완료 시각과 `r7CleanupComplete`/실제 0 상태로 판정한다. 이것만으로 R7 전체 완료를 선언하지 않는다.

[종료 시험 원본](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-09-r7/cleanup/audit.json). 전투/저장 복구 및 최종 엔진에서 같은 상태가 유지되는지 추가 확인한다.

## 전투 상태 저장 복구 첫 단위

명령·선택 개구부·고유 자리/사용권·확보 구역·최근 관측·연락 및 세부 실행 상태를 명시적인 Scribe 값/참조로 저장한다. 현재 Job은 폰의 바닐라 JobTracker가 한 번만 저장하며, 명령에는 Job ID만 남겨 로드된 동일 Job에 연결한다. 발사된 실제 투척물과 설치된 실제 C4 참조는 별도로 연결한다. 전체 캐시 맵은 생성하지 않는다. 저장 중이던 미완료 국소 방 탐색은 이미 확보한 이력과 현재 계획을 보존한 채 제한된 탐색 예산에서 다시 시작한다. 이 재탐색은 의도적으로 허용한 최신성/반응 지연이다.

`r7-save-load`, LOW 12명: 실제 발사체가 살아 있는 폭발 대기, 첫 방 확보 후 다음 문 스택, 적을 본 지원 준비, 실제 CQB 경계 교전의 네 시점에 게임 저장/불러오기를 실행했다. 네 번 모두 동일 native Job ID·선택 개구부·확보 이력·최근 관측·경계 대응 상태를 유지했다. 실제 발사체도 복구됐다. 적을 물리적으로 시야 밖으로 옮긴 뒤 기억에 의한 대기를 마치고 임무에 복귀해 3,933틱에 3개 방/12명 진입 과제를 모두 완료했다. 안전 위반 진입 0, 격리/인원 조건 통과. 빌드 경고/오류 0, 관련 R6/R4/전역 예산 검사 통과. [원본](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-09-r7/reload-cqb/audit.json).

이것은 기능 시험이다. 로드 후 수집 창을 다시 시작하며 저장/로드/JIT 비용이 섞이므로 이 실행의 CPU 수치로 정식 성능 합격을 주장하지 않는다. 이 첫 CQB 단위 이후 C4·야전·의료·미전달 메시지 복구를 각각 확인했다(아래 기록). 다중 맵과 최종 부하 행렬은 아직 남아 있다.

첫 실패는 시험 도구의 참조형 시작 위치 사전에 Scribe 작업 목록을 전달하지 않아 로드 후 진행 수집에서 예외가 난 것이다. 작업 목록을 명시해 수정했다. 두 번째 실행은 세 상태 복구에 성공했지만 보호된 적이 계속 보여 교전 대기를 유지해 방 정리를 끝내지 못했다. 최종 시험은 이 교전 자체도 저장/로드한 후 실제 적 소실과 원래 임무 복귀를 확인한다. 이전 실패/미완료 원문은 `reload-attempt-01`, `reload-attempt-02`에 보존한다.

## C4 물리 상태와 폭발 안전 복구

실제 시험에서 저장 시 벽은 살아 있었지만 첫 로드 후 `TargetWall.Spawned=False`, `Destroyed=True`, 개구부 `Walkable=True`로 바뀌었다. 원인은 C4가 `Item`인 상태로 벽 칸에 설치되는 정의였다. 설치된 게임의 `Map.FinalizeLoading`은 비건물을 먼저 생성하고 `GenSpawn.SpawnBuildingAsPossible`은 그 칸의 아이템을 벽이 지울 경우 벽을 생성하지 않고 환불한다. 이후 AI는 기폭 전에 열린 개구부로 해석했다.

설치된 C4를 `Ethereal`로 정의해 벽과 함께 로드되도록 고쳤다. 실제 게임의 Spawn 판정과 현재 XML을 사용하는 독립 회귀 검사에서 기존 Item/벽 충돌을 재현하고 새 정의는 양방향으로 서로 제거하지 않음을 확인했다. 별도 호환용 저장 처리는 추가하지 않았다.

폭발 후 본체는 사라지므로 본체 컴포넌트 참조만 복구하면 안전 대기에서 null 참조가 생긴다. 명령의 폭발 주체와 살아 있는 파편 참조를 본체와 별개로 저장한다. 로드 이후 실제 도화선·파편·해당 개구부의 폭발이 끝나고 안정 시간이 지날 때까지 대기한다. 저장 외에는 새 파편 수집이나 지도 검색을 추가하지 않는다.

최종 `r7-charge-load`, LOW 12명, fixture 27: 설치 완료 후 철수 전, 도화선 진행, 본체 파괴 후 살아 있는 파편 18개가 있는 세 시점의 실제 저장/로드를 통과했다. 벽/개구부 물리 상태·카운트다운·Job·파편 ID가 일치했고, 기폭 1회/안전 대기 45회 이후 2,164틱에 전원 한 방 진입 과제를 완료했다. 조기 진입 0, 격리/인원 조건 통과, 전술 예외 없음. [원본](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-09-r7/reload-charge/audit.json). 배포 빌드 오류/경고 0, 관련 R4/전역 예산 및 새 Spawn 회귀 검사 통과.

기능 시험은 `-batchmode -nographics`로 실행할 수 있게 했다. 계측 또는 R7 이외 사례와는 함께 사용할 수 없으며 이 결과로 CPU 합격을 주장하지 않는다. 원문에 남은 아틀라스/셰이더 오류는 그래픽 없는 게임 초기화 경로이며 전술 실행 예외와 구분했다. 정식 CPU 비교는 기존 그래픽 실행 조건을 유지한다.

`charge-attempt-01`~`03`은 벽 소실 원인 확인 실패를 보존한다. `charge-attempt-04`는 세 C4 복구 상태와 살아 있는 파편 18개 유지에 성공했으나 세 방 시험에 소모성 기폭기 하나만 제공돼 마지막 방 완료를 입증하지 못했다. 최종 단위는 기존 한 방 C4 fixture로 기폭·진입까지 확인하며, 다방 정리는 앞의 CQB 시험과 별도 최종 행렬에서 확인한다. 여러 방을 폭약만으로 돌파하는 최종 회귀는 필요한 실제 기폭기/폭약 수량을 제공해야 한다. 이 제한을 R7 전체 완료로 대체하지 않는다.

## 치료·야전 실행 중 복구

같은 마지막 DLL에서 `r6-care-drill -Reload`, LOW 12명: 매딕가방 지혈 진행 중 및 혈장 수혈 진행 중 각각 저장/로드했다. 환자/시술자/같은 native Job ID·현재 Toil 단계·남은 Toil 틱을 그대로 유지했다. 네 상처의 부위별 지혈 표시, 실제 혈장 효과와 혈액 손실 감소, 바닐라 상처 치료 없이 적용, 환자 회복/원래 다음 방 진행을 확인했다. 6,334틱에 세 방 전원 완료. [원본](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-09-r7/reload-care/audit.json).

`r6-smoke-drill -Reload`, High 13명: 실제 연막 발사체가 살아 있는 시점과 실제 화력조 기동 중 각각 저장/로드했다. 대형 자리·접근축·기동조·연막 목표/투척물·native Job/Toil 단계와 남은 시간을 유지했다. 계획 위치에 두 차례 연막을 사용하고 두 기동 구간을 진행했다. 적의 접근 방향 관측 후 적을 물리적으로 숨긴 뒤 원래 CQB 개구부로 복귀해 3,215틱에 전원 완료. [원본](../../Source/Benchmarks/TacticalEngineAudit/Results/2026-10-09-r7/reload-field/audit.json).

두 사례 모두 `r7Reloads=2`, Job/확보 이력/개구부/관측/해당 세부 상태/Toil 복구 성공, `newFunctionalComplete=true`, 격리 및 인원 조건 통과다. 이들은 Headless 기능 시험이며 CPU 게이트 자료가 아니다. 스크립트에는 기능 drill에만 `-Reload`를 허용하고 물리적 fixture 진행 정보도 함께 저장하도록 했다. 미전달 연락 메시지, 다중 맵 및 최종 반복/규모 행렬과 구형 제거는 여전히 남아 있다.


## 미전달 메시지·협력 합의 복구와 실제 무전기 손실 수정

실제 네트워크가 생성한 제안(Offer)과 합의 후 상태 보고(Status)를 전달 전 저장한다. 시험 코드가 메시지/합의를 삽입하거나 정상 런타임보다 일찍 송수신 연결을 복구하지 않는다. 로드 직후 대기열 순서·송수신 분대/폰/맵·전달 시각·채널·내용과 두 분대의 합의/식별/확보 이력/Job 작업 단계·남은 시간을 비교한다. 첫 정상 게임 틱의 연결 복구 후 실제 메시지 전달과 협력 완료도 확인한다. LOW 분리/재접촉을 만드는 시험 도구의 보조 상태도 저장한다.

## 미전달 협력 제안 중 상대 철수

기존 종료 정리는 상대가 서로를 참조한 경우만 연결을 해제했다. 전달 전 제안은 송신자만 수신 분대를 참조하므로 수신 분대 철수 시 송신자의 참조·합의가 시간 초과까지 남을 수 있었다. 이제 명령 종료에서 남은 분대 목록을 한 번 검사해 들어오는 참조와 해당 상대의 합의를 중단하고 다음 판단을 깨운다. 해당 명령을 양 끝점으로 가진 메시지만 전역 최대 64개 큐에서 제거하고, 다른 메시지/분대는 보존한다. 이 검사는 명령당 한 번이며 폰별/매틱 통신 검사에 전체 검색을 추가하지 않는다. 수비↔공격 전환에서도 기존 협력 합의를 취소하고 가능한 실제 연락 채널로만 중단을 전송한다.

## 실제 박격포·CAS 지원 요청과 임무 복귀

기존 요청 API는 구형 실행기에만 통지했다. 두 `QueueStrike` API에서 신규 분대 명령에도 요청자와 요청 당시 지정 좌표를 전달한다. 이벤트는 이 값과 최소 600틱 대기 시각만 기록하고 판단 큐를 깨운다. 적 위치/작업을 조회하거나 즉시 분대 대형을 계산하지 않는다. 요청한 분대에만 기존 전역 예산의 국소 엄폐/활 모양 대응을 사용한다. 실제 지원이 진행 중이면 최소 대기 이후에도 유지하며, 지원 대기 중 새 전진 기동/연막 접근 구간을 시작하지 않는다. 진행 중이던 기동은 후속 자리 갱신을 중단한다. 이미 발사한 CQB 폭발물/설치된 C4의 안전 컨트롤러가 우선이며 이를 지원 이벤트로 지우지 않는다. 실제 `HD_CASStationaryGuidance` Job은 일반 전술 Job 발행 함수에서 보호한다.
