# Security 이동 원인 조사와 조직별 가장자리 진입

2026-10-05. 요청 범위는 Security 이동 원인 조사와 테스트용 `EdgeWalkInGroups` 조정이다. 이번 변경은 이동 동작 자체를 수정하지 않고 진입 그룹과 관측 정보를 수정했다. 기존 2·3단계 결과 문서의 사용자 편집은 유지했다.

## 코드에서 확인한 제약 불일치

1. **개인 도착과 분대 접근 완료가 다르다.** `FollowNodes`는 개인이 마지막 이동 노드를 지나면 곧바로 자기 스택업/경계 위치로 이동시킨다. `AllowsNodeStep`도 해당 개인의 노드 통과 제약을 해제한다. 반면 `RaidMovementAreas.Select`의 `nodeApproach`는 개인 진행을 보지 않고 분대의 `ApproachComplete`만 본다. 마지막 노드를 지난 Security가 경계 위치로 이동할 때도 다른 인원이 늦으면 공통 접근 경로에 없는 문에 최대 비용이 계속 부여된다. 일반 도달 가능 검사에서는 갈 수 있는 위치인데 실제 경로 비용은 긴 우회를 선호할 수 있다.
2. **경로 비용과 통과 허가의 범위가 다르다.** 접근 비용 맵은 전체 `ApproachPath`에 포함된 문을 허용하지만 `AllowsNodeStep`은 개인이 다음에 통과할 한 연결의 `AllowedPortals`/`AllowedRooms`만 허용한다. 바닐라 경로 탐색이 전체 경로의 다른 문 또는 연결을 택하면 실제 이동 직전에 거부되어 `StopDead`와 작업 실패가 발생한다. 재시도 대기가 붙어 문/개구부 앞에서 멈춘 것처럼 보일 수 있다. 모든 폰에 적용되지만 공통 진입 경로 밖의 경계 위치로 가는 Security에서 더 노출될 수 있다.
3. **외벽 합류는 먼저 첫 방의 빈 대기 칸을 요구한다.** `RedirectExteriorIngress`는 최종 경계 목표가 다음 방에 있어도 지정 개구부 → 첫 방의 별도 clearance → 원 목표 순으로 보낸다. clearance는 첫 방/국소 범위/진입 깊이 조건에 묶여 있고 다른 폰 점유·목적지 예약·동료 clearance와 겹칠 수 없다. 기존 진입조가 첫 방을 채우면 통로는 열려 있어도 후보가 없어서 `Invalid`가 반환된다. 주문 설정은 이때 현재 위치에 `Hold`를 주므로 입구에 이미 도달한 후행 Security가 그 자리에 멈출 수 있다.
4. **clearance가 이동 중 바뀐다.** 같은 함수는 기존 목적지에 다른 폰이 들어서거나 예약하면 실제 도착 전에도 새 clearance를 고른다. 첫 방이 혼잡하면 목표가 반복 교체되어 왕복/비비기로 이어질 가능성이 있다. 기존 `ObservePosition` 단독 검사는 통과 래치를 검증하지만, 혼잡 시 clearance 검색/명령 교체 전체를 재현한 검사는 아니다.

위 내용은 소스의 조건과 호출 순서로 확인했다. 특정 플레이 장면의 경로, 당시 맵과 개별 주문 기록을 재생한 결과는 아니다. 현재 `Player.log`에는 전술 이동 추적이 없고, 해당 추적은 개발자 창의 메모리에 기록되는 방식이므로 로그의 일반 오류만으로 어느 조건이 그 장면을 일으켰는지 확정하지 않는다.

## 다음 이동 수정의 우선순위

- 마지막 노드를 지난 개인은 접근용 문 비용에서 분리하고, 목적지까지의 연결 허가와 경로 비용이 같은 범위를 사용하도록 통일한다.
- 첫 방에서 반드시 정지할 별도 칸과 실제 통과를 구분한다. 후행 경계 인원에게 정지 칸이 없더라도 현재 목표까지 연결된 통로가 있으면 입구를 비우며 진행할 수 있게 한다. 방의 물리적 수용량을 초과해 같은 칸에 경계 대형을 세우는 방식으로 해결하지 않는다.
- 정상 이동 중 clearance는 안정적으로 유지하고 실제 막힘에만 교체한다. 대기해야 하는 경우에도 개구부와 안쪽 첫 칸을 점유하지 않는 대기를 따로 다룬다.
- 외부의 원래 진입로로 우회하는 것을 무조건 풀지 않고, 이미 확보한 지정 개구부를 통한 합류 규칙은 유지한다.

## 이번에 추가한 확인 정보

기존 전술 개발자 창의 `Staging and security assignments`에 다음을 추가했다.

- `approach unitDone/memberDone`: 분대 접근 완료와 개인 마지막 노드 통과 여부.
- 경계 슬롯과 현재 위치, 기존 실제 명령 목적지/작업/재시도 시각.
- 미완료 외벽 합류의 `active/entered/opening/clearance/requested/room`.

이동 추적의 `Node connection rejects crossing`, `move deferred`, `Exterior join via`와 함께 보면 접근 비용 단계, 문 통과 거부, clearance 부재/교체를 구분할 수 있다.

## EdgeWalkInGroups 조정

`PawnsArrivalModeWorker_EdgeWalkInGroups.Arrive`에서 조직이 있는 습격 인원은 기존 무작위 인원 혼합 대신 `RaidTacticalUnit` 단위로 묶는다. LOW 분대끼리는 별도 그룹이며, 소대 본부와 독립 지원조도 자기 단위로 유지한다. High는 분대장 + 3개 화력조, 13명 전체가 한 그룹이고 화력조 단독으로 분리하지 않는다. 그룹 ID에는 조직 ID도 포함하므로 다른 조직의 같은 이름 분대가 섞이지 않는다.

각 그룹의 가장자리 중심은 바닐라 `FindNewMapEdgeGroupCenter`를 순차 호출해 기존 그룹과 떨어진 후보를 고르는 방식을 사용한다. 생성 셀은 기존처럼 중심 8칸 이내에서 바닐라가 선택하고, `parms.pawnGroups`도 실제 그룹에 맞게 기록한다. 유효한 가장자리 후보가 부족하면 서로 가까워질 수 있으며 거리를 강제로 보장하지 않는다. 한 분대만 생성된 습격은 테스트를 위해 임의로 쪼개지 않는다.

조직 없는 습격은 바닐라 Arrive를 그대로 사용한다. 조직 인원과 비조직 인원이 섞인 경우 비조직 인원은 별도로 바닐라 무작위 그룹 분할을 사용한다. 일반 EdgeWalkIn, 수송낙하/드롭포드 진입은 바꾸지 않는다.

## 검증

게임 API 바인딩, LOW 본부/분대 분리, High 13인·자식 화력조 유지, 입력 순서, 서로 다른 조직의 동일 그룹 이름, 비조직 혼합/전체 바닐라 폴백, 빈 입력과 원본 인원 유지 검사를 추가했다. 실제 가장자리 셀 선택/스폰과 이동 문제 재현은 게임에서 별도로 확인해야 한다.
