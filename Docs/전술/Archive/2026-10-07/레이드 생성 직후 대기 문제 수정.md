# 레이드 생성 직후 대기 문제 수정

## 원인과 변경

실제 조직 생성 명령과 바닐라 레이드 사건을 실행해서 확인했다. 조직 등록과 Lord 생성은 정상이다. 맵 가장자리에서 생성된 LOW 분대가 먼 돌파 지점까지의 경로를 계산할 때 4096회 탐색 제한을 반복해서 소진했다. 이때 전술 실행 상태가 만들어지지 않은 채 계획 대기용 Hold 명령만 유지됐다. 수정 전 3600틱 표본에서도 전원 `Wait_Combat`이고 계획 실패 사유가 `Breach search allowance exhausted`였다. 가까운 위치에서 생성한 레이드는 진행됐다.

야외 경로는 노출된 칸의 실제 이동 비용이 기본 100에 35를 더한 값인데, 목표까지의 추정 비용은 칸당 100이었다. 먼 목표에서는 목표 주변으로 좁혀지기 전에 넓은 지역을 탐색해서 제한에 걸렸다. 야외에서 시작한 경로는 목표 방향을 우선하는 가중치 150으로 검색한다. 실내 시작 경로는 기존 100을 유지한다. 실제 비용의 벽 인접 엄폐·관측한 적의 노출 비용, 이동 가능 칸과 함정 회피 조건은 유지한다. **최소 비용 경로의 보장은 포기하지만, 탐색 제한 4096회와 프레임별 계획 예산은 늘리지 않는다.**

바닐라 사건의 최소 포인트도 조직 편제와 맞췄다. 조직이 있는 팩션의 Combat 레이드에는 가장 저렴한 유효한 완전 편제 비용을 교리의 허용 초과율로 나눈 값을 사용한다. 바닐라 사건의 포인트 보정 이후 실제 편제를 생성할 수 있다. HIGH의 병사 한 명 비용만으로 최소 포인트를 잡아 13인 분대를 생성하지 못하는 경우를 방지한다. 다른 팩션과 비전투 그룹은 바닐라 기준을 유지한다.

## 검증

빌드 경고·오류 0개. 실제 클래스 바인딩 검증 전체 통과. 기존 실내 재개 경로 검증과 새 210×210 야외 경로 검증을 합쳐 8개, 완전 편제 최소 포인트 검증 6개가 통과했다. 새 야외 경로 검증은 수정 전 DLL에서 실패하고 수정 후 통과했다. 지도·이동·캐시 검증 1171개 및 기존 전술 계획 검증 전체도 통과했다.

실제 게임 DLL SHA-256: `249DE0DFA9DFA0060D539F956EBD4C8ADD557F447A7A8AC91C105B421936A9A7`. 저장소와 설치된 모드의 해시가 일치한다.

| 실제 생성 경로 | 인원 | 실제 전술 Job으로 이동한 인원 | 계획 시작 분대 | 결과 |
| --- | ---: | ---: | ---: | --- |
| Spawn Great War organization (1400pt) | 18 | 18 | 2/2 | 통과 |
| LOW RaidEnemy / ImmediateAttackSappers / EdgeWalkIn | 12 | 12 | 1/1 | 통과 |
| LOW RaidEnemy / ImmediateAttackSappers / EdgeWalkInGroups | 12 | 12 | 1/1 | 통과 |
| HIGH RaidEnemy / ImmediateAttack / EdgeWalkInGroups | 13 | 13 | 1/1 | 통과 |

각 경로를 3600틱 관찰했다. 모든 생성 인원의 실제 위치 변화, 분대별 성공한 실행 계획, 분대별 전술 Job을 수행하면서 발생한 실제 이동, Lord 유지 여부를 검사했다. HIGH는 정확히 13명이 생성되는지도 검사했다. 조직 생성 명령의 결과 창은 실제 사용자가 확인 후 닫는 것처럼 시험에서 닫는다. 각 경로를 시작하기 전에 벽·문·이름 있는 침대 시험 구조를 복구한다. 분대와 Lord를 시험 코드에서 직접 만들어 우회하는 기존 성능 시험과 구분한다.

조직 생성 명령은 돌파·개구부 관측·진입 대기까지, LOW EdgeWalkIn은 방 확보까지 진행했다. 다른 경로 역시 성공한 계획과 전술 이동이 확인됐다. 이것은 레이드 생성 후 이동·습격 시작을 검증한 것이며 모든 방의 최종 정리, 모든 맵의 정체 해소나 성능 개선율의 검증은 아니다. 수정 후 실행 Exception과 `Resolved path returned no nodes`는 각각 0행이다.

초기 시험의 HIGH는 사용할 수 없는 Sappers 전략을 강제로 넣어서 바닐라가 포인트를 크게 올린 잘못된 조건이었다. 최종 시험은 실제 사용 가능한 ImmediateAttack을 사용했다. 초기 결과를 HIGH 수정 전후 비교로 사용하지 않는다. 초기 시험의 첫 실행은 결과 팝업으로 강제 일시정지되어 측정이 중단됐고, 이 실행도 정상 회귀 결과에서 제외한다.
