# 전술 AI 기능과 8단계 목표 현황

정리일: 2026-10-07. 생산 코드 기준: `45cefe5d`와 그 이전 구현. 통합 계획, 후속 수정 문서, 현재 소스를 대조했다. 문서에 있는 옛 주기·예산은 이후 성능 개편으로 달라진 경우 현재 소스를 우선했다.

현재 구조는 **분대별 CQB 실행·이동·관측·통신에 기존 야전/수비 반응을 연결한 상태**다. 여러 분대의 협력 합의와 진입점 배분, 독립된 야전 실행 체계, LOW 호형 대형과 High 화력조 기동은 이후 목표다.

통합 계획의 **1~8단계**와 CPU 최적화의 **1~4순위**, 성능 구조 개편의 **A~D 단계**는 서로 다른 작업 구분이다. 통신 최적화 3순위와 위치 탐색 최적화 4순위를 완료했다고 협력 합의 4단계를 완료한 것은 아니다.

## 1. 최종 목표

| 영역 | 지향하는 최종 행동 |
|---|---|
| 조직 운용 | 분대/독립 지원조가 자기 임무와 진행을 갖고 상위 지휘·승계를 유지 |
| 이동 | 듬성듬성한 지향점과 필요한 연결을 이용해 접근하고, 실제 이동은 바닐라 길찾기에 맡김 |
| CQB | 외벽/문 돌파, 벽 옆 스택, 짧은 내부 관측, 적절한 지원, 안전 진입, 방별 정리 |
| 전술 정보 | 실제 관측과 마지막 기억을 사용하고, 시야 밖 적의 현재 위치·먼 문 개폐를 자동 추적하지 않음 |
| 협력 | 분대끼리 연락/브리핑으로 역할·진입점·담당 구역·시작/실패 조건을 합의 |
| LOW | 접촉 기반 정보 전달, 분대 내 임시 대응조, 전방 중앙에 화력을 모으는 활 모양 호형 대형 |
| High | 장착 무전기를 통한 보고/명령/확인, 기존 3개 화력조의 엄호·기동·교대 |
| 야전·수비 | 사거리 밖 접근을 일찍 발견해 엄폐를 준비하고, 위협 해제 후 원 임무로 복귀 |
| 성능 | 전술 정확도보다 메인 CPU·틱 지연을 우선. 오래된 결과·근사·낮은 갱신 빈도를 허용 |

호형은 전투호를 파는 기능이 아니다. 전역 킬존 감지와 전략적 중요도 맵은 다시 추가하지 않는다. 문·벽·방 연결 같은 단순 구조와 판단 시점의 적 관측을 기반으로 한다.

## 2. 통합 8단계의 현재 상태

| 단계 | 계획 | 현재 구현과 남은 범위 |
|---|---|---|
| 1. 실행 단위 분리 | 분대별 계획·진행·정보·명령 소유권 | **구현됨.** LOW 분대·독립 지원조·소대 본부를 분리. High 화력조 소속은 보존하되 분대 계획 하나를 사용. 사용자 확인 기록도 있음 |
| 2. 노드 이동·합류 | 지향점, 연결, 진행 보존, 후미 합류 | **구현 및 후속 개편됨.** 중간 노드 정지 제거, 공통 지향점, 외벽 개구부 합류, Security 개인 연결, 입구 FIFO·고유 대기 자리. 간헐적 정체는 남음 |
| 3. 관측·통신 | 개인/분대 기억, LOW 구두 연락, High 무전, 보고 병합 | **구현됨.** 일부 플레이 확인과 자동 검증 기록 있음. 전달/ACK·단절·저장 구조 및 CPU 최적화 적용. 전체 통신 시나리오 검증 완료와는 구분 |
| 4. 협력 합의 | 브리핑/현장 합의, 역할·시작·중단·대기, 지휘 승계 | **미착수.** 보고 전달과 기존 지휘 승계는 있으나 참여 분대가 공유하는 협력 합의와 준비/시작 명령 체계는 없음 |
| 5. 다중 진입 | 다른 접근로·입구·담당 구역, 지원 안전, 아군 조우 | **전체 단계 미착수.** 공유 입구 사용권·순서·대기 공간은 선행 구현. 합의에 따른 다양한 입구/구역 배분, 분대 간 투척 일정, 실내 식별 지연은 없음 |
| 6. 야전 기본 | 조기 감지·접근축·대응 노드·교전·해제·복귀 | **새 체계 미착수.** 기존 넓은 관측·지원 수비·저격 대응·엄폐 이동·연막은 있음. 연속 관측 기반 접근/횡단/이탈 분류와 독립 야전 상태 흐름은 남음 |
| 7. 교리별 운용 | LOW 임시 대응조/호형, High 화력조 엄호·기동, 계획 연막 | **전체 단계 미착수.** High 편제/무전과 공통 계획 연막은 선행 구현. 임시 대응조, 호형 배치, 실제 엄호 준비에 따른 화력조 교대는 없음 |
| 8. 통합 검증·정리 | 다중 맵·조직·저장/로드·성능·구형 코드 정리 | **최종 단계 미착수.** 단계별 자동 검사·네이티브 이동 시험·대규모 수집·프로파일러는 이미 있음. 4~7단계를 포함한 통합 완료 검증은 남음 |

## 3. 현재 실행 단위와 생성 기반

- 실행 키는 조직 ID와 그룹 ID다. 분대마다 계획, 실행 단계, 적 기억, 통로 지식, 방 진행과 개인 명령을 가진다. 한 폰에 여러 분대가 동시에 명령하지 않도록 소유자를 확인한다.
- LOW 소총분대는 독립 실행하고 기관총·바주카·저격 지원조 및 소대 본부도 별도 단위가 된다. 지휘 승계·사상자 처리에서 원 조직과 단위 키를 유지한다.
- High는 분대장 1명과 4인 화력조 3개로 된 **13인 분대가 최소 생성 단위**다. 43인 소대도 있고, 예산 부족으로 화력조만 떼어 독립 생성하지 않는다. 화력조별 소속과 보직은 있지만 독립 엄호·기동 AI는 아직 없다.
- High는 공통 폰카인드에 보직과 슬롯 장비를 적용한다. M16A4, 조장의 M203A2, 자동소총수의 M249, 군복·방어구, 수류탄·연막·명시 돌파 장비를 지급한다. 유탄발사기 장비 지급과 전술 AI가 상황별로 유탄 사격을 선택하는 기능은 별개다.
- LOW 대전기 폰카인드는 소총수·카빈·HAR·SMG·저격수·M1919A6·바주카·별도 바주카 탄약수로 나뉜다. 대전기 무장/군복과 시대별 수류탄을 사용한다.
- 공통 군인 정의는 18~35세, 기본 사격 8~12, 노화성 부상 생성 금지다. 이 정의만으로 모든 종류의 만성질환이 후처리에서 완전히 제거된다고 단정하지 않는다.
- `EdgeWalkInGroups`에서는 조직 단위로 가장자리 진입을 나눠 현장 분리 시험을 할 수 있다. 서로 다른 돌파점의 협력 배분과는 별개다.

## 4. 목표·지도·계획

자동 최종 목표의 기본은 이름 있는 소유자가 배정된 침대다. 현재 자동 침대 선택은 **플레이어 팩션 침대/소유자**를 검사한다. 지정 목표 입력 경로도 있지만, AI 대 AI 전반의 자동 목표 공급을 완성했다고 보지는 않는다. 관측 적·진행 지점 등의 대체 목표도 사용한다.

최초 외벽은 열린 먼 입구까지 돌아가기보다 목표 방향의 벽/문을 돌파하는 후보를 선호한다. 단순 외벽 형상과 실제 작업·스택 공간을 확인한다. 바위·막힌 자리·코너 너머 배치 때문에 대형이 성립하지 않는 후보를 걸러낸다. 이 규칙은 전체 맵의 사격 킬존을 확실하게 알아내는 기능이 아니다.

지도는 다음 층으로 구분한다.

| 자료 | 내용과 수명 |
|---|---|
| 맵 정적 구조 버전 | 셀 플래그, 방/구조 ID, 벽·문·코너·복도·연결 영역, 방 면적 등. 여러 틱의 값 수집과 워커 계산으로 완료본 생성 |
| 습격 시작 구조 | 조직들이 공유 버전을 참조하고 습격 시작 당시 방 번호를 유지. 벽 파괴 때 원래 방과 진행 기록을 재번호화하지 않음 |
| 물리 지역 캐시 | 16×16 청크의 실제 건물·보행 상태, 공간별 폰 조회, LOS 재사용. 건물·문·지형 이벤트와 주기 확인으로 갱신 |
| 국소 CQB 지도 | 필요한 약 33×33 구역의 통로·문·새 구멍·방 연결. 원 구조와 단위가 관측/보고받은 변경을 결합 |
| 방 진행/보안 기록 | 단위별 클리어 이력, 최근 침입과 재확인 필요 상태. 정적 배열과 분리하고 저장 |

현재 물리적으로 길이 막혔는지 확인하는 자료와 AI가 전술적으로 알고 있는 통로 정보는 구분한다. 미관측 문 개폐로 확정 진입점을 계속 교체하지 않는다. 정기 갱신만으로 계획을 초기화하지 않고 불가능해진 부분을 복구한다.

현재 방이 목표이면 방 내부 정리로 전환하고, 새 내부 장애물이 실제 연결을 끊었을 때만 장애물 제거를 계획한다. 이미 통행 가능한 길·직접 만든 구멍은 재사용한다. 최종 목표 방 이후에는 인접 미정리 방을 이어서 처리하고, 이미 확보한 방을 불필요하게 다시 돌파하지 않도록 한다.

## 5. 이동·개구부 통과

분대의 공통 지향점과 필요한 방/문 연결을 확정하고 바닐라 `Goto`·길찾기가 움직인다. 중간 노드마다 전원이 정확한 칸에 서서 기다리는 조건을 제거했다. 선두의 연결된 도착으로 다음 지향점을 이어 주며, 작은 방은 불필요한 코너 노드를 압축한다.

일반 지향점은 후미가 연결된 앞쪽 지점으로 합류할 수 있지만 필수 문·개구부 통과는 생략하지 않는다. 약간 옆이나 앞으로 이동했다고 즉시 원래 선으로 복귀시키지 않는다. 큰 이탈이 지속될 때만 연결 가능한 앞쪽 합류점으로 보정한다. 벽 인접과 이미 관측한 적에게 덜 노출되는 접근을 선호한다.

외부 Security 인원은 이미 만든 개구부를 통해 뒤따라 들어간다. 실내에서 경계하다 늦어진 인원은 자기 단위와 개인의 알려진 연결로 합류하고, 선두가 완료한 접근을 다시 열지 않는다. 원래 목표와 임시 대기/양보 목적지를 분리해 보류 해제 후 임무를 복원한다.

공병 작업 공간 사용권과 개구부 통행 순서는 별도다. 같은 돌파점의 후속 분대에는 연결된 외부 대기 공간을 주고 앞 단위가 자리를 해제하면 깨운다. 좁은 통로는 가까운 이동 가능 인원의 FIFO로 통과하고, 입구와 첫 안쪽 칸을 일반 정지 자리로 사용하지 않는다. 스택·경계·대기 자리의 중복 점유를 방지하며 막힌 미완료 자리만 재선정한다.

이는 물리 충돌을 줄이는 기능이다. 사용권을 얻었다고 다른 분대의 숨은 접촉이나 방 정리 상태를 아는 것은 아니다. 두 분대가 같은 최적 입구를 선택하는 상황 자체는 아직 발생할 수 있다.

## 6. CQB 돌파와 지원

기본 흐름:

**접근 → 벽 옆 스택 → 돌파 → 옆에서 내부 관측 → 지원 판단/투척 → 효과·복귀 대기 → 개구부 통과 → 방 정리/확보 → 다음 방**

| 행동 | 현재 기능 |
|---|---|
| 스택업 | 현재 공간에서 서로 연결된 벽 옆 자리를 사용. 코너/벽 너머 대형과 타일 중복을 피하고 도착하면 정지·경계. 위험 회피가 우선 |
| 돌파 | 슬레지 해머·절단기·C4 등 사용. 열린 연결은 재사용. C4 후퇴/폭파 대기와 진행 중 지원 안전 상태를 보존 |
| 해머 | 무기가 아닌 장착 장비. 일반 적대 문을 우선 돌파하고 보호 문은 제외. 문은 고장 상태에서 상시 열리고 바닐라 수리로 복구. 벽에는 반복 피해 |
| 작업자 상실 | 다운·사망·이탈 알림으로 해당 분대 재평가. 해머를 지면/사상자 장비에서 회수하고 새 인원이 이어 사용. 해머 내구도·유품 영향 제거 |
| 내부 관측 | 개구부 정면을 피한 옆 자리에서 몸을 기울여 최대 90틱 관측. 적 하나를 발견하면 즉시 복귀하고 그 위치 하나만 지원 판단에 사용 |
| 문칸 적 | 목표 방에 직접 인접한 문 경계도 관측. 대각선·문 연쇄로 먼 방을 관측했다고 처리하지 않음 |
| 지원 종류 | 개구부 너머 야외는 안전 연막, 실내는 수류탄. 16칸 이하 실내는 절약하되 실제 적 관측은 크기 제한 예외 |
| 투척 목표 | 관측 적 우선, 적을 못 봤으면 보이지 않는 내부 후보. 개구부에서 최소 2칸. 실제 LOS·사거리·산포/파편·아군 안전 검사 |
| AI 준비 | 준비 30틱, 수류탄을 든 채 위치 이동, 도착 후 18틱 투척. 준비 중 총 사격·총 표시를 막고 위험/작업 중단 시 해제 |
| 진입 안전 | 실제 발사체·폭발/효과와 관측자/투척자 복귀를 기다림. 0.3초 투척은 신관/폭발 대기를 줄이는 기능이 아님 |
| 실내 자리 | 엄폐와 개구부 쪽 벽을 활용하고 입구 통행 칸을 비움. 좁은 공간은 수용 인원을 제한하고 나머지는 외부 경계 |

보이는 적의 최신 위치 변경, 마지막 칸이 비었음, 오래된 관측은 준비 중 투척을 취소할 수 있다. 관측한 표적이 불가능해졌다고 다른 적이나 임의 빈 구역으로 자동 대체하지 않는다.

## 7. 적 기억·CQB 동적 대응·통신

적 접촉은 적 ID, 관측 당시 위치/방/시각/관측자, 관측 무장·사거리, 실제 확인한 방향·개구부를 보관한다. 시야가 끊기면 적의 현재 이동을 계속 따라가지 않는다. 일반 병사의 관측은 개인 기억에 먼저 들어가며 지휘자와 명시적인 활성 개구부 관측자 입력을 제외하면 보고 경로를 거친다.

CQB 관측은 24칸, 야외 기본은 90칸으로 분리한다. 발견은 자기 총의 사거리나 적의 무장 여부에 제한되지 않는다. 사격과 비슷한 몸 내밀기 LOS 및 연막 차폐를 사용하며 문 위 적을 검사한다. 성능 개편 후 일반 스캔은 60틱, 조용한 공유 입구 대기는 180틱이며 한 번에 적 후보 16·관측자 2·LOS 예산 최대 32로 제한한다.

후방 침입·다른 문 접촉·복도 앞뒤 접촉에는 기존 계획을 보존한 채 경계 담당을 배정하고 필요하면 작업/추가 진입을 보류한다. 적이 사라져도 마지막 문/방을 잠시 경계하고 해당 구역을 재확인한다. 실제 발사한 수류탄·설치 C4의 안전 상태는 지우지 않는다.

**클리어 이력과 현재 안전 상태는 별개다.** 적이 다시 나타나도 이전 돌파 이력은 유지하고 해당 방을 재확인 필요로 바꾼다. 알려진 열린 확보 경로로 재확인하며 불필요한 재돌파/지원 투척을 생략한다.

| 통신 | 현재 조건 |
|---|---|
| LOW | 기본 8칸, 직접 시야와 연막 조건을 만족하는 구두 연락. 한 연결 기본 40틱, 병사→중계→지휘자 전달. 떨어진 분대의 새 정보는 접촉 없이 공유하지 않음 |
| High | 착용 방탄복에 실제 장착한 정상 무전 파츠, 가용 운용자·호환망·거리 필요. 기본 300칸, 보고 20틱+ACK 20틱. 연결 자체에 시각 LOS를 요구하지 않음 |
| 무전 단절 | 다운·사망·장비 제거·고장/장애 등을 전달 시 검증. 유효한 구두 연락은 대체 경로가 될 수 있음. 태블릿을 전술 무전기로 사용하지 않음 |
| 보고 병합 | 원 관측 시각·출처·전달 경로를 유지. 최신 직접 관측 우선, 순환/중복 전달로 수명 연장 금지. 보고 접촉은 현재 `Visible` 표적이 아님 |
| 방/통로 보고 | 버전이 다르면 좌표로 대응. 보고만으로 수신 분대의 자기 클리어 완료 이력을 생성하거나 현재 진입점을 자동 교체하지 않음 |

보고·기억·확정 진행은 저장하고 로드 후 직접 가시 상태와 연결 조건을 재검증한다. 저장 구조와 개별 로딩 검사 구현은 전체 전투 상황의 저장/로드 검증 완료를 의미하지 않는다.

## 8. 현재 야전·수비 반응과 이후 목표의 차이

현재도 야전 관련 기능은 있다. 지원 요청이 수락되거나 가까운 관측 적이 접근/교전 조건을 만족하면 스택 작업을 보류하고 주변 엄폐 수비를 준비한다. 더 긴 사거리의 적에게 노출되면 사격축에서 멀어지는 자리·시야 차단·엄폐를 찾는다. 폭발 위험은 대형보다 먼저 회피한다.

연막은 투척자의 개인 도주 위치가 아니라 분대 밀집 핵심, 선택한 이동 구간과 차폐 목표/투척 출발점을 기준으로 계획한다. 연막을 따라 이동하면서 추가 차폐를 이어 갈 수 있다. HC는 별도 가스이며 HC/WP 명중 계수는 각각 0.25/0.35다. WP는 사격 차폐에 포함되지만 안전한 이동 연막으로 고르지 않는다.

조직에 등록된 비플레이어 폰의 바닐라 `Defend`/`DefendBase`에는 기존 수비 실행이 연결돼 있다. 배치 주변 엄폐·사격과 제한된 대응 활동 후 복귀를 사용한다. 모든 NPC/플레이어의 수비 명령에 적용되는 범용 AI는 아니다.

6~7단계에서는 이를 별도의 야전 진행으로 정리해야 한다. 사거리 밖 **관측 확대는 구현됐지만**, 그 거리에서 적의 접근축·속도·횡단/이탈을 분류하고 대응 노드를 선점하는 전체 행동은 아직 없다. 현재 접근 반응에는 약 36칸 기준과 적의 `enemyTarget`/`Goto` 목적지를 참고하는 부분도 남아 있다. 최종 목표는 연속 관측만으로 접근을 추정하고 위협 해제 후 다음 임무 지향점으로 복귀하는 것이다.

LOW 임시 대응조와 활 모양 호형, High 3개 화력조의 실제 엄호 준비 확인→기동→교대, 동일 체계를 쓰는 새 고정 수비는 이후 구현 대상이다. 현재 엄폐 반응과 연막을 그 전체 기능의 완료로 세지 않는다.

## 9. 성능·비동기·개발자 도구

CPU 감소를 위해 구조 수집·계획 생성·실행을 여러 틱/프레임에 분산한다. 정적 구조와 이동 비용의 순수 값 계산은 제한된 워커 풀을 사용한다. 기본 동시 작업은 2개이고 정적 구조 계산은 하나로 제한해 이동 작업 자리를 확보한다. `Map`·`Pawn`·`Thing` 접근, LOS·예약·Job 적용은 메인 스레드에서 한다.

공유 이동 비용 배열은 같은 실제 허용 조건이면 재사용하고 바닐라 경로 작업의 읽기 종료 이후에만 회수한다. 계획은 분할 작업 큐, 실행은 단위별 다음 기한과 사건 깨우기, 개인 명령은 지속 의도와 파생 실행 위치로 관리한다. 매 틱 전체 분대를 다시 판단하지 않는다.

최근 CPU 최적화 1~4순위는 다음과 같다.

| 순위 | 적용 기능 |
|---|---|
| 1 | 폰 명령 조회/통제 결과 캐시, 반복 소유권 확인과 경계 방향 갱신 축소 |
| 2 | 대기 180틱·일반 실행 30틱·진입/활성 반응 10틱 등 상태별 예약. 관측·현재 적 검증·폰 인덱스·LOS 결과 재사용, 보고/지원/사용권 해제/사상자로 깨우기 |
| 3 | 통신 프레임 최대 2분대/틱, 그래프 300틱·장비 목록 600틱 재사용. 전달 직전 현재 연락/장비 조건 확인 |
| 4 | 대응 위치 후보 최대 25개, 최종 경로 검사 최대 2회. 계획/위협 방향별 물리 점수를 120틱 공유. 전체 BFS/정렬/무제한 대체 탐색 제거 |

관측·반응이 늦거나 오래된 상태를 쓰고 좋은 후보를 놓칠 수 있다. 정확성을 희생한 적용 결과이며 전체 틱 CPU가 모든 시험에서 감소한 것은 아니다. 짧은 메서드의 경과 시간과 실제 메인 스레드 CPU도 구분한다.

개발자 도구는 다음을 볼 수 있다.

- 폰 아래 조직/분대·역할·전술 정보와 명령 주체.
- 습격 시작 정적 방 레이아웃, 단위별 클리어 이력·위협/재확인 상태.
- 접근 지향점·연결·선택 개구부·스택·Security·실제 지시 위치·연막 계획.
- 직접 접촉과 전달 보고, 출처·나이·문 경계 담당.
- 지휘 연락/무전 인원, 전달 대기·ACK·장애·보고 경로.
- 이동 차단 이유·미시작 지연·실제 Goto·경로 세대·사용권/입장 대기.
- 계획/실행/관측 등 CPU 표본과 서비스 예산, 캐시/워커 상태.

에이전트용 메서드 프로파일러와 CLI는 호출 수·총/평균/최대·p95/p99·틱당 비용, 호출 중첩을 기록한다. Core 레퍼런스 배치 대비 비율로 비교하며 완료·예외·사상자·시작 단계·지도 조건을 검토한다. 네이티브 게임 감사에서 이동 7단계와 대규모 분대 시험을 수행할 수 있다. 전역 개발자 표시가 다른 분대의 AI 정보 입력이 되지는 않는다.

## 10. 현재 남은 핵심 문제와 다음 작업

1. **협력 자체:** 통신은 있으나 합의·준비/시작·실패 규칙이 없다. 다음 통합 단계는 4단계다.
2. **다양한 진입:** 독립 계획과 공유 입구 순서는 있으나 다른 진입점·경로·구역을 협력 배분하지 않는다. 분대 간 지원 시간/구역과 아군 조우 식별도 5단계에 남는다.
3. **야전 완성:** 기존 반응을 독립 야전 상태·관측 기반 접근 평가·호형/화력조 교대 운용으로 확장해야 한다.
4. **이동 안정성:** 최신 기능 감사는 재시험 7단계 통과지만 최초 Security 1단계 실패가 있었다. 한 폰의 Job·명령·배정 소실과 남은 경계 상태의 원인은 미확정이다. 통과 기록만으로 모든 정체 해결을 선언하지 않는다.
5. **성능:** 상위 메서드 비용은 줄었으나 전체 틱 CPU 개선은 조건에 따라 불명확하거나 악화됐다. 실제 적 수·교전·다중 투척·완전 방 정리·큰 분대의 연속 상황을 더 검증해야 한다.
6. **목표/적용 범위:** 플레이어 침대 자동 목표의 편향, AI 대 AI의 최종 목표 유지, 범용 수비 적용은 현재 구현을 별도 확인해야 한다.
7. **최종 통합:** 다중 조직/맵, 지휘·장비 상실, CQB↔야전 복귀와 진행 중 저장/로드 전체 시나리오는 8단계에서 확인한다.
