# 1순위: 반복 전술 명령 조회 최적화 결과

2026-10-07. `MapComponent_RaidTacticalOrders.For`의 반복 소유권·제어 검증을 줄였다. 기존 습격 계획/통신 최적화는 다음 순위로 남아 있다.

## 적용한 변경

- 명령 발행/로드 시 Pawn과 명령을 `ConditionalWeakTable`로 직접 연결했다. 명령 없는 Pawn은 지도 컴포넌트 조회 없이 즉시 null을 반환한다. 약한 키를 사용해 정적 인덱스가 종료된 게임의 Pawn을 영구 보유하지 않도록 했다.
- 이미 검증한 분대·제어 가능 결과를 명령에 보관한다. 반복 조회에서는 spawn/지도/사망/다운/draft/정신 상태와 조직 구조 revision을 확인한다. 같은 분대 멤버 LINQ 열거, 소유권·assignment·Lord/제어 검사와 컴포넌트 조회를 매번 수행하지 않는다.
- 기존 30틱 due review에서는 실제 조직·실행 상태를 다시 검증한다. review가 밀린 경우에도 actor별 60~89틱 fallback으로 다시 확인한다. 부정 결과도 다음 검증까지 재사용한다.
- 명령 발행 시 유효 결과를 즉시 갱신한다. 조직 Detach/Bind/Clear, despawn, 명령 Forget, 지도 제거에서 해당 바인딩을 해제한다. 로드 시 바인딩을 복원하고 이전 runtime verdict는 폐기한다. 다른 지도로 옮겨진 Pawn의 새 바인딩을 이전 지도 cleanup이 삭제하지 않도록 했다.
- Wait 사주경계 방향 보정을 Pawn별로 분산한 30틱 간격으로 낮췄다. 매 틱 For와 FaceCell을 호출하던 비용을 줄였다. 실제 사격 이후 경계 방향 복원에는 최대 30틱 지연을 허용한다.

캐시·bounded stale 상태를 사용하는 최적화다. 이벤트로 직접 해제되지 않은 실행 제어 변화는 다음 due review/fallback에서 반영될 수 있다. 사망·다운·draft·정신 상태·지도 불일치는 조회 즉시 거른다.

## 간단 성능 검증

기존 설치 DLL을 별도로 보관하고 변경 전후 각각 LOW 400명→0명 격리 quicktest를 실행했다. 시드 `hd-perf-20261007`, fixture 2, 준비 600틱/측정 900틱, 속도 3, 같은 초기 지도 해시와 시작 단계 `Assemble:37`이다. 추가 메서드는 **For 한 개만** 선택했고 기본 coarse의 컴포넌트/전체 틱 맥락은 유지했다. 이전 350개 메서드의 광범위 수집을 반복하지 않았다. CLI compare의 sameTargets=true를 확인했다.

100%는 Core `Verse.GenRadial.NumCellsInRadius(float)` 10,000회 배치 한 번이다. 아래 For 시간은 **Stopwatch 경과 시간**이며, 짧은 메서드 실제 CPU로 부르지 않는다. p95/p99는 마지막 2048회 완료 호출의 분포다.

| LOW 400명 For | 변경 전 | 변경 후 |
|---|---:|---:|
| 호출 수 / 900틱 | 454,680 | 80,078 |
| 호출/tick | 505.20 | 88.98 |
| 평균 µs/회 | 8.589 | 0.459 |
| 누적 경과 ms | 3,905.068 | 36.756 |
| 경과 ms/tick | 4.339 | 0.04084 |
| **Core%/tick** | **1,564.15%** | **14.92%** |
| p95 / p99 ms | 0.0113 / 0.0191 | 0.0008 / 0.0011 |
| 최대 ms | 15.4143 | 0.0282 |

**호출 수 82.4% 감소, 호출당 평균 94.7% 감소, Core 대비 틱당 비용 99.05% 감소**를 관측했다. For만 보면 약 4.30ms/tick 경과 비용이 줄었다. 최대값 감소는 JIT/GC/선점 영향을 포함할 수 있어 정규화한 누적 비용과 호출량을 우선 판단한다.

전체 틱은 참고로 경과 25.232→14.052ms/tick, Core 9,095.78→5,134.24%/tick, 실제 GetThreadTimes CPU 24.965→14.149ms/tick이었다. 종료 단계는 변경 전 `Support:1,Assemble:36`, 변경 후 `ObserveOpening:1,Assemble:36`으로 달랐다. 단일 전후 실행이며 환경 부하·전술 진행·계측 자체의 비용이 포함된다. **전체 틱 감소 전부를 이번 패치 효과로 귀속하거나 제품 전체의 반복 검증된 개선율로 주장하지 않는다.**

양쪽 감사는 complete로 끝났다. 400명 전원 생존, 이동 기록 399→398명, 미시작 이동 명령 0건, 성공 계획 37개를 확인했다. capture는 모두 complete=true, dropped=0, 계측 메서드 예외=0이다. 이동 발생과 최소 실행 진행을 확인한 것으로, 전체 CQB 클리어·대형 정확도를 보증하는 시험은 아니다.
