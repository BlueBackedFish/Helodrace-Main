# 전술 AI 실행 갱신 분산 구현 결과

작업: 2026-10-06. [구조 개편 검토](%EC%A0%84%EC%88%A0%20AI%20%EA%B5%AC%EC%A1%B0%20%EA%B0%9C%ED%8E%B8%20%EA%B2%80%ED%86%A0.md)의 C 실행 비용 축소를 진행했다. 기존에는 맵의 모든 조직을 10틱마다 열거하고, 30틱마다 모든 분대의 실행을 함께 갱신했다. 폰 명령 검토도 30틱에 한꺼번에 돌았다.

## 실행 대기열

`GameComponent_RaidExecutionScheduler`가 모든 맵의 분대 작업을 하나의 기한 대기열에서 처리한다. 다음 처리 시각이 빠른 작업부터 처리하며 같은 시각은 접수 순서를 유지한다. 반복 실행은 뒤의 다음 기한으로 이동하므로 오래 기다린 분대와 다른 맵을 앞질러 계속 실행하지 않는다. 기한 교체·취소는 기존 항목을 직접 제거하며 낡은 항목을 쌓지 않는다.

게임 틱당 일반 처리 시작 허용 시간은 2ms, 최대 분대 처리 수는 8개다. 단일 관측·지역 탐색·바닐라 Job 호출을 중간에 끊는 상한은 아니다. 실제 최대 분대 처리 시간과 갱신 지연을 별도로 기록한다. Map/Pawn/Job 처리는 메인 스레드에 남는다.

| 종류 | 기본 주기 | 처리 내용 |
| --- | --- | --- |
| 빠른 검사 | 10틱＋예산 지연 | 관측 예정 확인, 폭발 회피·피격·CQB 접촉 대응, 실제 개구부 통과 |
| 개구부 입장 | 30틱＋예산 지연 | 공간 해제를 확인하고 입장 가능한 대기 분대를 깨움 |
| 일반 전술 단계 | 30틱＋예산 지연 | 돌파·관측·지원·진입·방 정리 |
| 접근 중 | 60틱＋예산 지연 | 이동 지향점·대형·정체 복구 검토 |
| 초기 계획 대기·Hold·Complete | 90틱＋예산 지연 | 결과 조회 및 상태 검토 |
| 안전한 개구부 대기 | 180틱＋예산 지연 | 장비·구성·담당 전체 재검토 |
| 맵 조직 목록 | 60틱 | 맵의 실제 전술 분대를 등록·갱신·정리 |
| 사상자 | 알림 후 맵의 다음 틱 | 일반 기한·예산을 우회해 해당 분대만 재평가 |

교전·경계 전환·접촉 대기·연막 중에는 느린 접근 검토 대신 30틱 검토를 사용한다. 일반 처리 예산이 부족하면 빠른 검사도 늦어질 수 있다. 바닐라 위험 회피와 공병·관측·투척 Job 보호는 유지하고, 폭발 안전을 시간 초과로 완료시키지 않는다.

구성원 목록은 티켓에 보관한다. 전체 검토·조직 목록 갱신·사상자 처리 때 다시 수집하고, 빠른 검사에서는 사망·다운·맵 이탈·분대 전출을 제거한다. 매 빠른 검사마다 조직 트리와 Lord 조건을 다시 수집하지 않는다. 조직 목록 정리 시 로드된 실행 상태에 런타임 티켓이 없더라도 고아 상태를 정리한다. 다운된 조직원이 남아 있으면 공병 장비 회수 기록은 보존한다.

## 폰 명령과 공간 관리

폰 명령 검토는 맵별 기한 대기열에서 틱당 최대 16명을 처리한다. 첫 검토는 Pawn ID로 30틱 구간에 분산하고 이후 30틱마다 예약한다. 이미 설정된 정기 검토 기한을 반복 명령으로 계속 미루지 않는다. 명령 변경·이동 배열 준비 완료에 따른 기존 즉시 Job 검토는 유지한다. 따라서 분대의 한 번의 갱신 자체가 많은 Job을 시작하는 비용은 남아 있다.

개구부 대기 자리 청소는 실제 지난 120틱을 기준으로, 사용권 정리는 지난 30틱을 기준으로 한다. 특정 틱의 나머지가 0인지에 의존하지 않아 분산된 호출에서 청소를 놓치지 않는다. 사용권 정리가 모든 틱에서 반복되지 않게 한다. 공간 대기 자리는 이전 C 작업의 지속 인덱스를 유지한다.

## 관측

정기 관측에 참여하는 인원은 최대 4명이다. 지휘관과 현재 개구부 관측자를 우선 포함하고 나머지는 분대원 목록을 순환한다. 임의의 인원을 계속 제외하지 않는다. 13인 분대·우선 인원 2명 조건의 순환도 자동 검증했다. 후보 적·기존 관측 예산·사격 LOS/연막·개인 보고·LOW 접촉·High 무전 조건은 유지한다. 다른 인원의 관측을 지휘관의 직접 관측으로 취급하지 않는다.

일반 인원의 재관측이 늦어질 수 있다. 개구부의 별도 관측 Job과 투척 판단은 그대로이며, 정기 관측만 줄인다. 관측 설정과 방 확인 보고 작성에서 해당 분대를 찾기 위한 전체 조직 열거를 제거했다.

## 계측과 검증

개발자 전술 보고와 독립 감사 JSON에 반복 작업 수, 일반/긴급 처리 수, 예산 보류 수, 현재/최대 갱신 지연, 최대 분대 처리 시간을 추가했다. 실행 서비스의 `pending`은 미완료 계획 수가 아니라 등록된 반복 작업 수다.

아직 시작하지 못한 이동 의도도 개수·최대 나이·차단 이유로 표시한다. 이미 해당 목적지로 Goto 중이거나 요청 위치에 도착한 경우는 제외한다. 개구부 대기·경계·보호 작업·예약·배열 준비 같은 이유를 함께 읽어야 하며, 모두 AI 정지로 간주하지 않는다.

`Execution` CPU 표본은 이제 맵 전체 순회가 아니라 분대 하나의 처리다. 이전 최대값과 그대로 비교하지 않고 CPU 합계, 별도 `ExecutionMaintenance`, 전체 `GameTick`과 TPS/FPS를 함께 본다. 분대 내부의 하위 CPU 구간은 중복 합산하지 않는다. 사상자 긴급 실행은 목록 관리 콜백 안에서 측정되므로 `ExecutionMaintenance`와 겹친다. 아래 합계는 긴급 실행 0회인 시험에만 사용하며, 사상자 시험에서는 두 구간을 단순 합산하지 않는다. 명령 정기 검토 비용은 전체 틱에 포함된다. `Planning`은 이전 B와 같이 Update에서 처리한다. CPU 합계·최대는 준비 구간을 포함하며 분위수는 최근 최대 2048개 표본이다. 서비스 통계는 시나리오 간 누적된다.

- 빌드: 경고·오류 0개.
- 순수 지도·이동·기한·관측 순환 검증: 962개 통과.
- 실제 게임 클래스의 실행 티켓·중복 틱 방지·사상자 우회·맵 해제·로드된 고아 상태·명령 검토 제한: 신규 9개 통과.
- 기존 전술 바인딩·Security·투척·관측·기억·통신 검증 통과. 기존 전술 정책 검증 통과.

## 시험 환경 보정

중간 Security 실게임 시험에서 두 인원이 시작 칸에 남아 `UnknownJoin`으로 정지했다. 감사 구역의 정리가 비파괴 간헐천을 `Destroy`로 지우려다 실패해 무작위 비정지 칸이 정적 지도에 남을 수 있었다. 감사 구역에서 비파괴 사물은 DeSpawn하도록 고쳤다. 일반 게임의 간헐천은 변경하지 않는다. 실패 시에는 해당 건물과 고정 캐시의 Standable 값도 출력한다.

정리 보정 후 같은 AI 버전의 Security 회귀 5개가 모두 통과했다. 각 11명, 완료까지 468 / 355 / 451 / 198 / 402틱이었다. 이 기능 시험 DLL은 `241937CB12D639192DC62660540067663D0CFC030D37CD36C65CE36552748B39`이다. 이후 변경은 이미 이동 중인 요청을 미시작 통계에서 제외하는 진단 출력 보정뿐이다.

간헐천이 남을 수 있었던 중간 시험과 이전 B 시험은 경로·초기 지형이 같다고 볼 수 없다. 수치는 원자료로 보존하되 최종 시험의 엄밀한 개선율 계산에 사용하지 않는다. [측정 JSON](%EC%A0%84%EC%88%A0%20AI%20%EC%8B%A4%ED%96%89%20%EA%B0%B1%EC%8B%A0%20%EB%B6%84%EC%82%B0%20%EC%B8%A1%EC%A0%95.json)에 DLL별 결과를 구분한다.

400명 첫 회 두 조건 모두 계획 37개가 성공했고 계산 대기는 0개였다. 이동한 인원은 398 / 394명, 생존 400명, 미시작 이동은 0개였다. 명령 정기 검토 지연은 최대 1틱이다. 실행 표본 p99는 5.181 / 4.596ms지만, 첫 회의 단일 실행 최고값은 58.834ms였다. 일반 처리 시작 예산이 단일 작업의 시간을 제한하지 못하는 사례다.

최종 빌드의 400명 시험은 속도별 3회씩 완료했다. 모든 회차에 계획 37개 성공·계산 대기 0개·생존 400명·명령 검토 최대 지연 1틱이었고, 예외 로그는 없었다. TPS 범위는 1배속 37.777~39.340, 3배속 37.989~46.156이었다. 추가 시험의 단일 실행 최고값은 72.371ms까지 올라갔다. 추가 1회 두 조건에는 미시작 이동 1개(예약, 147틱)와 2개(차단 이유 None, 351틱)가 남았다. 이후 두 회차는 0개였다. None은 원인이 밝혀졌다는 뜻이 아니며 D의 추적 대상에 포함한다.

50명 장시간 시험은 예외 없이 완료됐고 50명 모두 이동했으며 생존했다. 종료 단계는 SecureRoom 3개·CrossBreach 1개·Assemble 1개로, 임무 전체 완료를 의미하지 않는다. 성공 계획 5개, 계산 대기 0개, 분대 실행 예산 보류 0회였다. 전체 틱 p95/p99는 4.610 / 5.942ms, 실행 p99는 2.294ms였다.

**장시간 시험의 미시작 이동 18개는 해결 완료로 보지 않는다.** 개구부 대기 12개·목적지 예약 6개이고 가장 오래된 요청은 3,360틱이다. 이동 이력이 전원에게 있어도 현재 요청이 진행 중이라는 뜻은 아니다. 시작된 Goto의 최대 지연 223틱만으로 이 문제를 숨기지 않는다. 현재 기록만으로 각 요청이 의도적인 작업 대기인지 통로/예약 정체인지 확정할 수 없으며, D에서 명령 소유권과 통과 작업을 통합할 때 요청별 추적과 복구를 검증해야 한다.

이번 결과는 실행을 한꺼번에 갱신하는 구조를 제거하고 대기 비용과 계산량을 줄이는 방향을 확인한다. 하지만 전체 틱 최고값의 일관된 감소나 모든 규모의 성능 개선은 아직 입증하지 못했다. 특히 3배속 첫 회의 전체 틱 최고값 275.791ms는 남은 병목이다. 이전 B와 지형 정리 조건이 달라 수치 차이를 통제된 개선율로 해석하지 않는다.

## 남은 범위

모든 긴 단일 실행 호출을 2ms 안에 끊은 것은 아니다. 지역 합류 탐색, 반응 자리 선택, 분대 명령 일괄 변경, 바닐라 경로/사격 처리, 통신 프레임 재구축과 GC 비용은 남는다. 여러 맵·High 실제 13인 편제·다중 진입점·지속 교전·진행 중 저장/로드 시험도 남는다. 역할 작업·명령 소유권·공통 이동 구간과 통로 관리의 책임 통합은 다음 D 범위다.
