## 검증 기록

최종 측정과 한계는 [실게임 검증 결과](Security%20이동과%20대규모%20전술%20최적화%20실게임%20검증.md)에 기록한다. 이 문서 아래의 기록은 작업 순서별 이력이므로 “후속 구현”, “게임 검증 필요” 등의 과거 문구는 위 상태표와 최종 측정 문서를 기준으로 해석한다.

2026-10-05: 생산 DLL 빌드 경고 0/오류 0. 실제 게임 클래스에 연결한 `RaidTacticalBindings` 전체 통과. Security 검증은 기존 20개에서 24개로 증가했으며, 활성 경계 인원 제외, Withdraw/이탈 인원 제외, 만료·해제 후 진행 복귀를 검사한다.

후방 합류: 지형/이동 정책 326개와 게임 연결 테스트 전체 통과(Security 29개). 알려지지 않은 문/벽은 합류 경로에 포함하지 않고, 문 자체의 방 번호와 파괴된 벽의 방 번호 0을 해당 연결 칸에서만 허용한다. 기존 외부 진입점과 외부 바닥은 개인 실내 합류 구역에 포함하지 않는다. 분대가 직접 연 개구부는 이후 방 계획에서도 기억하며, 개인 관측 보고도 본인의 합류 판단에 사용할 수 있다.

동일한 연결 칸 규칙을 일반 접근 노드에도 적용했다. 실내 구간에서 부서진 벽 때문에 방 번호 0 전체가 허용되는 것을 막고, 문/벽 칸 위에 있을 때도 그 칸의 번호를 현재 방 전체의 탈출 권한으로 쓰지 않는다. 실제 외부 바닥에서 접근할 때의 외부 이동은 유지한다.

이동 진단: 실제 Goto 시작 시점은 `Pawn_JobTracker.StartJob` 이후에 기록한다. 명령이 반복되어도 원래 대기 시작 시점을 보존한다. 준비되지 않은 경로, 점유, 잘못된 목적지, 도달 불가, 재시도, 보호된 작업과 바쁜 상태를 구분한다. 합류 연결을 찾지 못한 폰은 이전 이동 명령을 계속 수행하지 않고 현재 위치에서 대기한다. 개발자 창의 조직 목록/문자열 갱신은 초당 4회로 제한했다. 게임 연결 테스트 전체 통과(Security 32개).

조회 인덱스: 동일 조직 트리에 대해 그룹/폰/분대 열거가 같은 분대 뷰와 ID를 재사용한다. 조직 트리 복구 시 세대가 바뀌어 캐시를 갱신하며, 현재 구성원/지휘관 상태는 기존 실제 객체를 조회한다. 실행 상태의 배정과 개인 노드 진행은 사전으로 찾고, 명령 검증은 실제 소속 그룹만 검사한다. 배정 목록 교체·인원 추가와 트리 복구의 무효화 테스트를 추가했다. 생산 빌드 경고 0/오류 0, 게임 연결 테스트 전체 통과(편제/소유권 36개), 편제 순수 검증 2180개 통과.

준비 대기열: 맵마다 FIFO와 실제 대기자 연결을 관리한다. 명령의 목적지가 바뀌면 이전 배열의 대기 연결을 해제한다. 준비 완료 통지는 당시 해당 배열을 기다리는 폰에게만 보낸다. 1,000개 요청 폭주, 64개 처리 묶음, 요청 반복, 목적지 변경, 임무 해제와 정리 검증을 추가했다. 지형/이동/대기열 순수 검증 333개 및 게임 연결 테스트 전체 통과. 배열의 중복 생성과 최종 메모리 상한은 다음 작업에서 해결하며, 이 변경만으로 전체 캐시 메모리가 제한된다는 의미는 아니다.

Native 수명: 바닐라 `PathFinderMapData.ParameterizeGridJob`이 비용 배열을 작업에 전달하는 것을 확인했다. 경로 요청 생성 시 참조를 보유하고, Resolve/Dispose 시 요청 참조를 해제한다. 배열 읽기 시작은 별도로 보유하며 바닐라 `ForceCompleteScheduledJobs`가 반환한 뒤에만 종료한다. 따라서 취소 자체는 회수 조건이 아니다. 이 단계는 안전한 회수를 위한 추적만 추가하며, 캐시의 실제 회수/상한은 후속 구현이다. 순수 수명/대기열/지형 검증 339개와 설치 게임의 실제 Harmony 대상/필드 바인딩 검증을 통과했다.

배열 공유: Plan/UnitId/개인 연결 번호를 키에서 제거했다. 정적 구조와 실제 허용 방/연결 칸/국소 칸, 이동 모드/활동 범위가 같으면 동일 배열을 사용한다. 정보가 다른 조직의 허용 조건은 별도 배열로 남으며, 관측 기억 자체는 공유하지 않는다. 제한 없는 이동은 관련 없는 방/개구부/구조 버전을 키에서 제외해 맵당 하나의 0 비용 배열로 모인다. 허용 목록은 정렬/중복 제거 후 불변 입력으로 보관하고 원본이 같은 목록은 다시 변환하지 않는다. 512개 복합 조건에서 키 정규화 전후 전체 배열이 동일함을 검사했다. 생산 빌드 경고 0/오류 0, 순수 검증 855개 및 게임 연결 테스트 전체 통과.

메모리 회수: 일반 배열 준비는 Native 메모리 64MiB 예산에 들어갈 때만 계산/게시하며, 공간이 없으면 준비를 보류한다. 요청 참조/Native 읽기가 끝나고 최근 2프레임 동안 쓰지 않은 완성 배열을 오래된 순서로 회수한다. 캐시 항목 목표는 128개이며 사용 중인 항목을 강제로 해제하지 않는다. 실제 대기자 없는 300프레임 이상 미요청 예비 작업만 미게시 상태에서 취소한다. 긴급 회피는 안전한 회수가 불가능해도 즉시 준비할 수 있어 64MiB를 일시적으로 넘길 수 있다. 이 초과까지 막는 절대 상한은 아니며, 현재/최대 바이트와 회수/메모리 대기를 개발자 창에 표시한다. 순수 수명/예산/이동 검증과 게임 연결 테스트를 통과했으며, 실제 Unity 작업에서의 실행 검증은 최종 게임 검증 단계에 남아 있다.
