# CQB 자율 실행과 전환 지연 개편 검토 — 2026-10-14

**개편 가능하다.** 돌파 지점·대형·관측·투척·안전 대기·진입·후속 방 소탕의 방향성을 유지하면서, 분대 지휘가 개인 동작을 하나씩 재발행하는 구간을 줄이는 것이 적절하다. 권장안은 바닐라처럼 임무/개인 판단/실행을 분리하되 CQB 안전·개구부 통과는 전용 실행을 남기는 혼합 구조다. 일반 Assault AI 전체에 넘기면 스택업·관측·투척·정한 개구부 사용을 잃는다.

이번에는 소스 검토와 개편안만 작성했다. 코드·JobDef·세이브를 변경하지 않았고 게임 재현/CPU 프로파일링도 수행하지 않았다. 아래는 확인한 조건과 그 조건에서 가능한 지연 경로이며, 특정 플레이 장면의 유일한 원인을 확정한 결과는 아니다. [야전 설계](야전%20AI%20최종%20목표와%20바닐라%20기반%20설계.md)의 구현 우선순위는 바꾸지 않는다.

## 현재 구조의 장점과 문제

이미 모든 개인 행동을 분대 판단으로 처리하는 것은 아니다. TacticalJobDriver.CombatMove는 같은 Job 안에서 이동↔개별 교전을 전환하며 후속 폰은 자기 Driver로 이동한다. Observe는 적 발견 즉시 관측을 끝내고 복귀한다. Throw도 준비→이동→18틱 투척→복귀를 한 Job 안에서 이어 간다. Ingress는 outside→opening→inside→lane을 통과한 뒤에만 개별 사격 정지를 허용한다. 이 실행을 보존해야 한다.

문제는 **이 개인 실행 위에 정확한 전원 자리 도착, 제한된 Job 발급, 단계별 controller 재확인, 광범위한 복귀/재시도 조건이 겹치는 것**이다. 현재 DecisionTicks는 이미10이다. 전부1틱 판단으로 바꾸면 실제 필요한 준비를 없애지 못하면서 CPU만 늘릴 수 있다.

|---|---|---|
| 전역 scheduler | 한 틱 최대4 command 확인·2개 Advance, 통신과 약1.5ms 예산 공유 | Wake로 Due=다음 틱이어도 실제 다음 틱 실행 보장은 없음. 인원/분대가 늘면 차례가 더 늦어질 수 있음 |

| 안전 중 사격 | SafeToFire는 command 전체의 BlastWait/ChargeAction/미해소 투척 효과에서false | 안전한 후방 경계자의 별도 방향 교전도 막힐 수 있음. 진입 금지와 모든 개인 사격 금지의 적용 범위를 구분할 후보 |
| Job 교체 | Issue는 InterruptForced＋cancelBusyStances:true | 실제 교체 때 조준/스탠스를 취소할 수 있음. 동일/진행 가능한 임무를 재발행하지 않는 것이 중요 |
| 실패/중단 | 소유한 Job 비성공 종료는 폭발 안전 중단 예외 외에 RetryTick+180 | 회피/정상 전환과 실제 길찾기 실패를 구분할 필요. 이미 새 Job이 소유권을 바꾼 이전 Job 알림은 무시하므로 모든 교체가180틱 페널티인 것은 아님 |

## 권장 개편: 지휘는 허가, 개인은 지속 실행

분대/화력조 단위로 **OpeningOrder**를 두는 설계가 적절하다. 선택 개구부/방·계획 버전·참가자·후방 경계·공병/관측/투척 담당·진입 허가·폭발 위험을 가진다. 이는 설계용 이름이며 아직 구현된 클래스가 아니다.

개인에게는 **CqbActorOrder**로 역할·다음 목적지·안전하게 활동 가능한 국소 구역·작업 버전만 준다. actor의 이동/도착/개별 교전/가까운 엄폐/일시 중단은 Driver 또는 제한된 JobGiver가 처리한다. 분대 controller는 매번 전원 Post→Observe→Post→Throw→Post→Ingress를 다시 발급하지 않고 필요한 담당/허가 변경만 기록한다.

기존 RaidLord·편제·통신·의료·확보 기록은 유지한다. 폰별로 새로운 Lord를 만들지 않는다. 논리적 주문을 기존 command/byPawn에 저장하고 현재 Duty의 CQB Job 공급 분기 또는 좁은 전용 JobGiver에 연결한다. 실제 구현에서는 야전의 단일 Job 공급 설계와 공유할 공통 안전 우선순위가 필요하다. 전역 DetermineNextJob을 광범위하게 우회하여 강제 작업/큐/constant 안전 판단을 지우는 방법은 피한다.

### 단계별 자율성

| 상태/역할 | 개인이 독립적으로 할 수 있는 것 | 지휘가 제한하는 것 |
|---|---|---|
| 스택업 접근 | 같은 Job에서 개별 적 대응·재개, 막힌 슬롯의 작은 대체 요청 | 정한 접근/스택업 구역 유지. 후속 인원 전체 정지 금지 |
| 스택업 완료/경계 | 현재 자리 표적 선택·사격·보는 방향·회피 후 복귀 | 일반 상황의 자리/연결 대형 유지. 적이 있다는 이유로 임의 추격·자리 왕복 금지 |
| 공병 작업 | 같은 장애물 작업 지속, 작업 진행/개방 통보, 급박한 위험 중단 | 선택 개구부 잠금, C4 설치/후퇴/기폭 소유권과 안전 제어 유지 |

| 투척 담당 | 허가된 목표/수단으로 준비→이동→투척→안전 복귀 | 준비 중 총기 금지, 실제 발사/아군 안전 검증. 바닐라 전투가 덮어쓰지 않음 |

| 내부 도착/교전 | 현재 표적 사격, 같은 진입 방의 작은 구역에서 엄폐 선택 | 과도한 깊은 추격·다른 방 이동 금지. 후속 진입을 막지 않음 |
| 후방 경계/낙오 | 근처 확보 구역에서 따라가며 경계·개별 교전 | 혼자 먼 다음 방으로 출발하지 않음. 본대 준비를 불필요하게 막지 않음 |

“자율성”은 모든 행동을 자유 전투 AI에 넘긴다는 뜻이 아니다. **전술 임무와 안전 제약은 고정하고, 그 안의 순간 반응을 개인에게 맡기는 것**이다. 스택업 중 무작위 이동·문 너머 엄폐 선택을 다시 허용하는 개편은 하지 않는다.

## 행동 사이의 텀을 줄이는 방법

### 1. 전체 준비 대신 필요한 역할 준비

Stack→Breach는 공병과 해당 개구부의 필수 가까운 지원/경계가 준비됐는지를 본다. 외곽 경계/치료/낙오자의 정확한 슬롯 도착을 모두 요구하지 않는다. 초기 스택업의 실제 참가자와 대기/경계 인원을 분리하며, 무조건 인원 비율 하나만 만족하면 출발시키는 방식도 피한다.

Support는 투척자·관련 진입 인원·폭발/투척 경로 주변 아군이 안전한지 확인한다. 모든 active 인원의 AtPost를 요구하는 대신 **실제 위험에 관련된 인원의 위치/이동 상태**를 확인한다. 아직 이동 중인 폰이 예정 위험 구역에 들어갈 수 있으면 멈추거나 투척을 보류한다. 전체 대기를 줄여도 기존 SafeOpeningThrow·아군 방/문 인접 검사·최종 발사 직전 검증은 유지한다.

Enter 이후에는 **통과 이력 / 입구를 비웠는지 / 현재 역할 준비 / 최종 슬롯 도착**을 다른 상태로 관리한다. 한번 실제 들어온 폰이 엄폐를 바꾸거나 회피했다는 이유로 아직 진입 안 한 폰으로 되돌리지 않는다. HIGH 선행 조가 물리적으로 통과한 뒤 다음 조를 보내는 현재 원칙은 유지한다.

다음 방의 예비 계획은 선두/다수 진입과 동시에 계산할 수 있지만, 그것만으로 현재 방을 확보했다고 공유하지 않는다. 실제 진입 증거·현재 교전·필요한 경계 확보와 조사 결과로 확보를 확정한다. 교전 중에는 계속 싸우고, 교전 종료 유예90틱 이후 준비된 돌파조만 다음 임무로 진행할 수 있다. 후방 정리/치료를 남길 경우 명시적으로 담당 인원을 분리한다. 단순히 첫 한 명이 들어왔다고 방 전체 확보나 전원 다음 방 이동을 허가하지 않는다.

### 2. 사건 통보와 저비용 전환 큐

현재도 Wake/Observed/Launched/SupportReturned/JobFinished 통보가 있다. 이를 없애지 않고, `도착`, `필수 역할 준비`, `장애물 개방`, `관측 종료/복귀`, `투척 발사`, `폭발 해소`, `입구 통과`, `작업 실패`의 유형과 계획 버전을 함께 기록하도록 정리한다.

이벤트에서 전체 AdvanceCore를 재귀 호출하지 않는다. 중복 제거된 준비/전환 큐에 넣고 다음 scheduler 기회에 **값 비교·허가 갱신 같은 싼 전환만** 먼저 처리한다. 한 번에 연속2~3개 싼 전환을 처리할 수 있지만, 새 후보 탐색/자리 계산/Job 시작은 각각 기존 예산을 사용한다. 구조 탐색을 반복 호출하는 무제한 while은 금지한다.

HIGH 부모의 자식1개 순환은 무거운 계획에 남기되, 각 자식의 도착/안전 완료 통보는 부모 순환을 기다리지 않고 가벼운 큐에서 병합한다. 안전 여부와 발사체/폭발 정보는 메인 스레드의 실제 상태로 검증한다. 전체 분대 판단 횟수를 올리는 대신 동작 완료가 중간 단계의10틱/부모 순환을 매번 누적하지 않도록 한다.

### 3. 한 번 받은 명령을 같은 Job에서 이어 실행

Ingress/Observe/Throw가 이미 사용하는 Toil 연결을 확대한다. 예를 들어 개인의 스택업 도착 이후 다음 허가가 있는 경우 기존 Job의 대기 Toil에서 다음 실행으로 넘어갈 수 있다. 실제 path 시작은 AdmitMovement의 전역 예산을 계속 사용하되, 불필요한 StartJob/Driver 재생성·예약 정리·warmup 취소를 줄인다.

논리적 주문을 전원에게 부여하는 싼 작업과 실제 StartJob을 분리한다. 전원 주문 배정이 JobLimit에 의해2명씩10틱으로 늦어지지 않게 하고, 새 Driver가 필요한 사람만 큐에서 시작한다. 현재 Driver가 유효한 다음 허가를 읽을 수 있는 사람은 재발행하지 않는다. 경로 요청은 PathLimit과 바닐라 큐로 분산한다. 모든 폰을 같은 틱에 StartJob하는 상한 해제가 아니다.

서로 다른 담당/장비가 필요한 Observe·Throw·C4까지 전부 하나의 거대한 개인 Job으로 합치지는 않는다. **역할이 유지되는 이동/대기/사격 연결은 지속 Job**, 역할/장비가 바뀌면 명시 Job 전환으로 처리한다. 같은 계획 버전·역할·유효 목표면 continuation으로 유지하고 정상 인계는 실제 실패와 구분한다.

### 4. Retry와 대기 이유를 분리

예산 부족은 다음 기회까지 보류하면서 현재 유효 Job을 유지한다. 정상 교전/안전 중단은 재개 상태를 보존한다. 길찾기 실패·슬롯 점유·도구 상실만 해당 실패의 bounded 대체/재선정/backoff로 처리한다. 모든 비성공 Job을 같은180틱 retry로 묶는 구간을 줄인다.

관측90틱·투척 준비의 실제 시간·18틱 release·폭발 해소와30틱 settle·90틱 교전 유예는 전술 행동/안전의 시간이다. scheduler 차례/낙오/자리가 없어 생기는 대기와 분리해 디버그에 이유를 보여야 한다. 투척자 원래 자리 복귀는 현재 안전 소유권의 일부이므로 먼저 유지한다. 이후 정확한 원래 칸을 못 쓰는 경우는 **대체 엄폐 복귀를 확인**해 해결하고 단순히 Returned=true로 넘기지 않는다.

## 개인 사격과 엄폐는 어디까지 바닐라에 맡길까

스택업/통과/관측/투척의 실행은 전용 Driver를 유지한다. 현재 TryPostFire의 첫째 목적은 그 임무를 버리지 않고 현재 자리에서 싸우는 것이다. 이를 무조건 JobGiver_AIFightEnemy 전체 호출로 바꾸면 가까운 적 추격/자기 엄폐 이동이 대형과 lane을 깨뜨릴 수 있다.

폭발 안전은 공통 진입 허가를 잠그되 개인 사격까지 무조건 전부 잠글 필요가 있는지 분리해 검토한다. 투척/관측/C4 담당의 독점 실행과 위험 개구부 방향 사격 제한은 유지하고, 안전한 후방 경계자가 다른 방향의 적에게 현재 자리에서 대응하는 것은 허용할 수 있다. 위험 구역·역할·실제 사격선을 확인하는 제한된 정책으로 처리하며 BlastWait가 끝났다고 허위 표기해 사격을 허용하지 않는다. 폭발 대기 중 전원에게 일반 전투 이동을 허용하는 변경도 아니다. [현재 사격 안전 조건](../../Source/Helodrace/Tactics/TacticalEntryCombat.cs)을 이 기준으로 나누는 것이 자율성 개선 후보다.

현재 자리 사격의 표적·Verb·stance 실행은 가능한 바닐라 공통 함수로 모으되 관측 정보를 쓰는 후보 검증/배치 소유권을 유지한다. 사주경계 방향은 시각적 경계 기본값이며 바닐라 FOV 원뿔이 아니다. 사격 가능한 적에게는 실제 CanHit/lean LOS를 적용하고 사격 중 방향은 공격에 맡긴다.

입구/lane을 비운 뒤에만 **같은 방의 작은 연결된 구역**에서 CastPositionFinder/CoverUtility 또는 기존13칸 저비용 cover 후보를 허용한다. 초기1회와 엄폐 상실/지속 사격 불가 같은 사건에서만 재선정한다. 선택된 엄폐 위치를 실제로 사용해도 `Crossed`/`EverEntered`는 유지하고 현재 post readiness만 바꾼다. 정확한 plan.Positions 칸으로 돌아가라고 매번 EnsurePost하지 않는다.

후속 폰은 자기 개구부 통과를 계속하며 앞선 폰의 개인 사격이 전체 진입 중단 조건이 되지 않게 한다. 실제 폭발·입구 물리 차단·긴급 근접 위험은 예외다. room-clear·다음 목표 선택은 개인 전투 JobGiver에 맡기지 않는다. 기억만 있는 숨은 적을 실제 표적으로 만들어 사격하거나 문 개폐를 전지적으로 읽어 계획을 바꾸지 않는다.

## CPU·안전·구현 난이도

이벤트 기반으로 바꾸면 모든 개인의 매 틱 전술 계획이 필요해지는 것은 아니다. Driver는 current order의 몇 개 값과 기존 공격/경로 실행을 확인하고 무거운 판단은 공유 계획 큐에서 한다. 전원 재평가·LINQ active 생성·정확한 슬롯 복귀를 줄일 수 있지만, 자율 교전마다 CastPositionFinder를 반복 호출하면 오히려 비용이 늘 수 있다.

초기에는 후보/계획/Job/path의 전역 예산을 유지하고, 싼 상태 갱신을 무거운 계획 예산과 분리한다. global TryObserve 한도에 관측자·각 Post의 반응이 경쟁하는 현재 구조도 역할별 우선순위/공유 후보로 정리할 후보지만 무조건 상한을 늘리지 않는다. 이미 바닐라 경로는 비동기 worker를 사용하므로 이 CQB 제어를 별도 thread로 옮기는 것을 우선안으로 삼지 않는다.

| 개편 | 기대 효과 | 난이도/주요 위험 |
|---|---|---|
| 준비 인원과 실제 통과 이력 분리 | 낙오·엄폐 이동 때문에 전체가 계속 기다리는 경우 감소 | 중간. 필수 경계를 빠뜨리거나 확보를 너무 일찍 확정할 위험 |
| 싼 이벤트 전환 우선 처리 |10틱/부모 순환이 동작마다 누적되는 지연 감소 | 중간. 중복/오래된 이벤트·재진입·예산 회피 주의 |
| 지속 Job/개인 주문 | 발급 대기와 stance 취소 감소, 개인 행동 연결 개선 | 높음. Toil/Job 소유권·예약·save 복원·역할 교체 정리 필요 |
| 제한된 내부 엄폐/개별 교전 | 최종 자리 고정으로 자연스러움이 줄어드는 문제 개선 | 중간. 개구부 정체·다른 방 선택·기존 claim 충돌 주의 |
| HIGH 준비/명령과 무거운 계획 분리 | 자식 전체가 부모 순환만 기다리는 현상 감소 | 중간~높음. 형제 C4/수류탄 위험과 공유 claim 충돌 유지 |

실제 지연/CPU 감소율은 측정하지 않았다. 이상적인13인 발급60틱 차이는 설명용 하한 사례이지 개편 후 절감 보장이 아니다. 핵심 이득은 안전 시간을 줄이는 것이 아니라 **이미 끝난 행동의 재확인·무관한 인원 대기·필요 없는 Job 시작을 제거하는 것**이다.

## 권장 후속 순서

| 단계 | 작업 | 확인할 변화 |
|---|---|---|
| C0 | 디버그 대기 이유·필수 참가자/실제 통과/자리 readiness 분리 | 어떤 이유로 멈추는지 드러남. 엄폐 이동으로 진입 이력 초기화하지 않음 |
| C1 | 전체 barrier를 관련 역할/위험 준비로 교체 | 경계/낙오가 돌파·투척·후속 준비를 불필요하게 막지 않음. 안전은 유지 |
| C2 | 버전 있는 사건 통보·싼 전환 큐·HIGH readiness 병합 | 완료 후 다음 준비까지의 빈 대기 감소. 후보 계산 상한 유지 |
| C3 | 단일 개인 Job 공급과 지속 명령, 정상 중단/실패 구분 | StartJob 반복과 조준 취소 감소. 예산 대기 중 유효 작업 유지 |
| C4 | 입구 통과 후 국소 엄폐/교전 자율성 | 앞선 폰 교전 중 후속 진입 지속. 좁은 방/문 너머 자리 오인 없음 |

C0~C2부터 작은 변경으로 진행할 수 있고 전투 AI 전체 재작성은 필요하지 않다. C3는 야전 W0의 단일 Job 공급 설계와 공통 소유권을 맞춘 뒤 진행하는 편이 중복 리팩토링을 줄인다. 기존 대형 생성·도구/의료 회수·확보 공유·적 기억·분대 통신의 기능을 새로 만들지 않고 활용한다. 이전 save 형식의 하위 호환은 요구하지 않지만 새 상태의 save/load 소유권과 safety 상태는 검증한다.

향후 약식 게임 확인은 사용자에게 맡길 목록으로 분리한다: 낙오가 있는 스택업/투척, 관측 직후 즉시 후퇴, 폭발 전 진입 금지, 투척자 대체 복귀, 입구에서 안 멈추기, 내부 교전 중 후속 진입, 엄폐 이동 뒤 이력 유지, HIGH3개 작업의 연속 진행, C4 작업 중단/공병 사망, 교전 종료90틱 후 다음 방 진행. 에이전트는 메서드/전환/소유권 및 필요한 저장 상태 분석을 담당하며 전체 성능/세이브 재생을 단계별 필수 검사로 추가하지 않는다.
