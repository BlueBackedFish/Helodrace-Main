# 습격 설계 추가 계획 검토

2026-10-11. [사용자 설계](습격%20설계.md)를 현재 구현과 대조한 후속 설계의 세부 검토 기록이다. 구현 순서는 [확정 로드맵](습격%20시스템%20후속%20로드맵.md)을 따른다. 사용자가 정정한 스폰 편제(LOW 3분대＋4인 지휘부, High 3분대＋4인 지휘부)를 반영했다. 계획 검토 시점에는 게임 코드·정의 변경과 테스트 재개를 수행하지 않았다. 이후 A1 구현과 관련 검증은 [구현 기록](A1%20관측과%20기본%20교정%20구현.md)에 반영했다. 기존 R7은 사용자 판단으로 완료했으며 이전 수집 큐는 재개하지 않는다.

## 판단과 범위

설계의 방향은 현재 최적화 구조 위에 추가할 수 있다. 기존 전술 동작 수정 → 임무 지속과 정보 공유 → High 화력조 CQB → 습격 생성·지원 자원 → 새 습격 종류 순서가 적절하다. CPU 우선순위는 유지하고, 새 기능마다 전체 지도 갱신이나 폰 간 상시 비교를 추가하지 않는다.

사용자가 적은 성능 합격·약 1.3~1.7배의 플레이 관측은 후속 설계의 실용적 출발점으로 받아들인다. 2026-10-11 지침에 따라 성능 테스트와 자동 수집은 계획에서 제외한다. 사용자가 직접 성능을 확인하고 문제가 발견됐을 때만 해당 부분을 조사한다. 기존 R7 반복 CPU 게이트는 미입증 기록을 보존하되 후속 작업의 완료 조건으로 요구하지 않는다.

외벽 직후 해제의 구조적 원인 후보는 지붕 없는 중정에 대한 탐색 종료다. 실제 상황의 `LastPlanFailure`·임무 단계·목표 확보 상태를 확인해야 정확한 종료 경로를 확정할 수 있다. 이 문서는 해당 플레이 사례를 재현해 원인을 확정한 결과가 아니다.

## A1. 저비용 동작 수정

위협 판정, 호 방향, High CS 제외를 먼저 다룬다. 새 전술 단계 없이 기존 조건·대형을 수정하므로 범위를 작게 유지할 수 있다.

- 2026-10-11 정정: 특정 동물에 대한 예외나 관측 이후의 야전 전환 억제가 아니라, 원거리 위협으로 볼 수 없는 대상을 처음부터 적 관측에 등록하지 않는 규칙이다. 적대·생존 여부에 더해 실제 원거리 공격 수단을 확인하며, 근접 DPS만으로 원거리 위협으로 올리지 않는다.
- 원거리 공격 수단은 총기만으로 한정하지 않는다. 실제 공격 가능한 원거리 Verb 등 해당 대상의 공격 구조를 기준으로 판단한다. 사거리 밖에서 접근하는 적을 일찍 감지해야 하므로 현재 관측자에게 즉시 사격 가능한 거리인지는 등록 조건으로 삼지 않는다. 정상 무기의 일시적인 재장전·쿨다운도 관측 제외 사유로 삼지 않는다.
- 일반 접촉 탐색뿐 아니라 개구부 관측과 보고 수신 등 적 관측이 유입되는 경로에 같은 적격성 기준을 적용한다. 부적격 대상은 접촉 기억·보고·야전 반응 계획의 입력에 넣지 않는다. 수신 보고는 발신자가 관측한 적격성 정보를 사용하며 시야 밖 대상의 현재 장비를 조회하지 않는다.
- 실제 공격을 받았을 때의 긴급 회피·반격은 관측 등록 규칙과 별도로 유지한다. 원거리 공격 가능한 메카노이드·포탑 등은 종족이나 대상 종류만으로 배제하지 않는다. 후보별 공격 수단 확인은 제한된 관측 과정에서 수행하고 재사용하며 전 폰의 스탯을 매 틱 구하지 않는다.
- 호는 여러 화력점을 연결한 전체 배치이며 폰을 고정 곡선이나 직선 전선 위에 정렬하는 규칙이 아니다. 측면 화력점의 전진/우회와 중앙 후퇴로 같은 교전 지점에 화력을 집중한다. 각 화력 구역 안에서는 불규칙한 위치와 엄폐를 허용하며 사격선이 막힌 엄폐만 선호하지 않는다. F02 피드백 반영 구현은 A1 기록을 따른다.
- High의 M7A2 지급을 제외하고 자동 장비 선택에서도 CS를 고르지 않게 한다. 이미 존재하는 CS 아이템 자체의 삭제나 효과 변경과는 별도 작업이다.

별도 약식 기능 목록: [F01~F02](습격%20기능%20약식%20테스트%20목록.md). 작업 구간에서 자동 실행하지 않는다.

## A1.4 사격 집중 AI — 구현 완료, 사용자 확인 대기

2026-10-11 사용자 테스트에서 방어막을 사용하는 근접 폰에게 밀리는 문제가 보고되었다. 근접 위협, 특히 방어막을 장착한 근접 폰을 먼저 집중 사격하고 그 위협을 해소한 뒤 일반 원거리 교전 AI에 제어를 넘긴다. A1.1~A1.3의 완료를 되돌리지 않는 후속 교정으로 구현했으며, 실제 수치·메서드/저장 검증과 남은 사용자 확인은 [구현 기록](A1.4%20사격%20집중%20AI%20구현.md)을 따른다. 아래는 설계 근거이며 실제 게임 시험 완료를 의미하지 않는다.

### 입력과 우선순위

- 기존 제한된 LOS 관측에서 적의 현재 근접 공격 행동, 근접 무장/공격 수단, 실제 접근 경향과 접촉 위험을 확인한다. 먼저 피해를 받아야만 반응하는 현재 경로를 보완한다. 현재 Job을 참고한다면 관측한 적의 현재 공격 의도만 읽고 시야 밖 Job·이동 목적지·미래 경로를 조회하지 않는다.
- 비공격적 근접 전용 대상은 계속 원거리 관측에서 제외한다. 접근하는 근접 공격자는 별도의 짧은 근접 위협 입력으로 처리하며 기존 원거리 `RangedThreat` 기억/보고 필터를 풀지 않는다. 동물의 종별 예외는 추가하지 않는다.
- 우선순위는 실제 공격 중/접촉이 임박한 근접 위협 → 공격적으로 접근하는 방어막 근접 폰 → 그 밖의 공격적 근접 폰이다. 같은 위험 구간에서는 방어막 근접 폰을 먼저 집중한다. 멀리 있는 방어막 폰 때문에 바로 옆 공격자를 무시하지 않는다. 일반 원거리 적 교전은 이 우선 단계 이후 일반 AI가 처리한다.
- 방어막 장착/활성은 해당 적을 관측한 시점의 정보로 판정한다. 구현은 바닐라 `CompShield`의 활성 상태와 착용한 본 모드 방탄 방패 컴포넌트를 확인한다. 시야 밖 현재 에너지나 장비 변경을 계속 조회하지 않는다. 방어막이 파괴되어도 그 폰이 계속 근접 접근 중이면 대응을 유지한다.

### 집중 사격과 제어 반환

- 분대가 하나의 우선 표적을 정하고 사거리·사격 LOS·사용 가능한 총기가 있는 인원에게 같은 표적을 제공한다. 중앙·측면 화력 구역을 유지하면서 사격한다. LOS 없는 인원까지 표적을 쫓아 건물 반대편으로 이동하거나 전원이 새 대형으로 집결하지 않는다. 사격 불가능한 인원은 현재 지역의 방어/일반 대응을 유지할 수 있다.
- 새로 더 급한 근접 위협이 생겼을 때만 표적을 전환하고 짧은 유지 시간/전환 문턱으로 매 판단마다 다른 적을 고르는 현상을 억제한다. 기존 표적을 무조건 고집하여 인접 공격자를 무시하지 않는다.
- 표적 사망·다운, 관측한 후퇴, 접촉 위험 해소 또는 시야 단절 후 유효 정보 만료로 현재 표적을 해제한다. 다른 유효한 근접 위협이 있으면 다음 표적을 처리하고, 없으면 집중 사격 단계를 끝낸다. 방어막 파괴만을 종료 조건으로 삼지 않는다.
- 종료 후 일반 원거리 교전 AI로 제어를 반환한다. 바닐라 적 선택·엄폐·사격 작업을 우선 활용하고, 집중 사격용 지속 경비 Job이 평상 교전을 계속 붙잡지 않게 한다. 조직의 임무·돌파/확보 이력·화력 구역은 보존하며 전술 명령 유지 루프가 일반 교전 Job을 즉시 덮어쓰지 않도록 실행 소유권을 구분한다.
- 집중 표적의 ID·마지막 관측 좌표·관측 시각·유효 시간·교전 단계와 제어 소유권을 저장한다. 로드 후 표적 검증에 실패하면 집중 제어를 해제하고 정상 임무/교전으로 복귀한다. 시야 밖 Pawn 참조를 통해 현재 위치를 얻지 않는다.
- 수류탄 회피·이미 투척한 수류탄/C4의 안전 대기 등 즉각 안전 행동이 우선이다. 투척 중인 인원과 의료/특수 작업 소유권을 존중하며, 사격 준비가 가능한 인원만 집중 사격에 참여한다. 이미 발사한 공격을 취소한다고 간주하지 않는다.

### CPU와 정보 공유

분대마다 제한된 관측 후보/스냅샷에서 한 번 표적을 선정하고 폰별로 같은 후보 순위를 다시 계산하지 않는다. 구현은 근접 후보 최대 6개·유효 기간 180틱·표적 판단 30틱·같은 위험도 표적 유지 90틱을 사용한다. 실제 인접 공격과 사격 시 관측한 위협 해제는 다음 판단을 깨우며, 일반 관측/수신은 기존 판단 간격·전역 예산 안에서 처리한다. 방어막 피격마다 전체 분대·맵을 다시 검색하거나 폰 쌍별 전수 비교를 추가하지 않는다.

분대 내 공통 표적은 해당 분대가 관측/수신한 정보만 사용한다. 다른 분대에 전달할 경우 LOW 접촉·High 유효 무전 규칙과 기존 제한된 큐/지연을 유지하며, 일반 원거리 보고와 별도의 근접 위협 값을 전달한다. 동시 집중을 위한 전역 표적 게시판이나 자동 정보 공유는 만들지 않는다.

근접 위협 입력/우선 표적 → 제한된 집중 사격 실행 → 일반 교전 제어 반환·소유권/저장 복구를 구현했다. 에이전트는 관련 메서드 흐름·필요한 저장 안정성을 확인했고, 게임 기능은 2026-10-11 [사용자 F16](습격%20기능%20약식%20테스트%20목록.md) 정상 작동 확인을 받았다. 정기 성능 수집은 추가하지 않는다.

## A2. 소탕 임무 지속과 확보 정보 공유

### A2.0 목표 구조물 구분 — 추가 계획, 미구현

2026-10-11 F16은 사용자가 정상 작동을 확인했다. 같은 테스트에서 정착지 밖 자연 생성 구조물도 돌파하는 별도 문제를 보고했다. 최초 접근과 다음 건물 선택 모두에 대상 구조물 구분을 먼저 적용하는 것을 추천한다. 명시 목표/대상 세력 소유 벽·문을 강한 근거로 삼고, 무주인 벽은 이미 알려진 침대·관측한 실사용 설비·제한된 국소 연결 근거로 점유 여부를 판단한다. 소유권 없는 유적은 우회를 먼저 시도하며 단순 통과 돌파가 유적 전체 소탕으로 확장되지 않게 한다. 실제 관측한 적은 기존 접촉 대응으로 처리한다. `Faction == null`, 홈 영역, 지붕, 거리만으로 정착지를 구분하지 않는다.

공통 분류를 최초 직선 후보·개구부 재사용·후속 방 후보·대기 목표 선택에 적용한다. 분대별 결과를 재사용하고 애매한 국소 연결만 기존 계획 예산으로 분산한다. 별도 전역 방 지도나 폰별 반복 검사 없이 적용하며 분류 대기를 임무 종료로 잘못 넘기지 않는다. [상세 근거·예외·적용 순서](정착지와%20자연%20생성%20구조물%20구분%20방안.md), [사용자 F17 초안](습격%20기능%20약식%20테스트%20목록.md)을 따른다. 이 제안의 코드 변경/게임 시험은 아직 수행하지 않았다.

### A2.1~A2.2 소탕 지속과 확보 보고

소탕 완료를 한 개구부 통과나 한 건물 정리와 분리한다. 이름 있는 침대는 최초 목표이고, 해당 목표 확보 이후에는 알려진 미확보 구역을 계속 정리한다. 침대가 없는 경우의 대체 목표는 명시 목표를 우선하고 별도 정책으로 정한다.

분대가 사용하는 현재 국소 계획은 유지한다. 상위 임무에는 최초 목표·다음 이동 목적지·정리한 구역·남은 알려진 입구·진행 실패 사유를 둔다. 외벽 너머가 야외라면 방 클리어로 끝내지 않고 중정 통과/야전 대응 구간으로 넘어간 뒤 다음 건물 입구를 계획한다. 열린 지역을 무제한 flood fill 하거나 전역 전략 가치 맵을 다시 만들지 않는다.

다음 건물 선택은 목표 방향과 실제로 확인한 가까운 경계 후보에 한정한다. 후보를 다 소진해도 임무를 바로 해제하지 않고, 제한된 재탐색·진행 불가·퇴각을 구분한다. 전체 정착지의 숨은 방을 미리 아는 완벽한 소탕은 목표로 하지 않는다. 임무 완료는 알려진 미확보 구역 소진과 제한된 추가 탐색 종료를 기준으로 하며, 발견하지 못한 공간이 남을 수 있다.

확보 보고는 개구부 좌표·연결 방향·구역 범위의 작은 묶음·보고 시각·원본 분대를 포함한다. LOW는 실제 접촉, High는 유효한 장착 무전이 있어야 전달한다. 모든 분대가 전역 `SecuredCells`를 읽게 하지 않는다. 이미 보낸 보고는 변경분만 전달하고 패킷 크기·큐 길이·틱당 적용량에 상한을 둔다.

자신이 확보한 상태와 다른 분대가 확보했다고 보고한 상태는 분리한다. 보고된 구역으로 이동할 때 기존 개구부를 재사용하고 불필요한 재돌파를 생략하되, 과거 확보 보고가 현재 적 부재를 보장하지는 않는다. 새 적 관측은 재확인 필요 상태만 만들며 물리 개구부 이력은 보존한다. 문 파괴·방 병합으로 낡은 방 ID가 생기지 않도록 기존 좌표 기반 기록을 사용한다.

별도 약식 기능 목록: [F03~F04](습격%20기능%20약식%20테스트%20목록.md).

## A3. 야전 기동과 의료 담당

### A3.1 초기 호 형성의 조별 집결과 이후 기동 — 추가 계획, 미구현

2026-10-11 사용자 보고: 호 형성에서 이동 방향만 공유한 채 폰들이 산개하여 실제 화력 구역이 만들어지지 않는다. A1의 화력점 배치 후속 교정으로, 임시 화력조가 각자 담당 화력 구역에 모이는 절차를 A3.1에 포함한다. 현재 코드의 공통 화력점만으로 집결이 보장된다고 보지 않는다. 구역 후보가 막히면 폰 현재 위치 근처로 대체하는 처리와 개별 지정 칸 도착 준비 판정을 함께 교체할 계획이며, 이번에는 구현하지 않는다.

- LOW는 자동화기사수 중심의 임시 대응조와 나머지 측면조의 구성원·담당 화력 구역을 야전 대응 시작 때 정한다. HIGH는 기존 4인 화력조를 그대로 사용한다. LOW의 임시 조 편성은 실행 상태에만 두고 조직 트리·스폰 편제를 바꾸지 않는다. 매 판단마다 인원을 서로 다른 구역으로 재배분하지 않으며 사상자·기동 불가 등 필요한 사건에서만 보완한다.
- 분대가 좌·중앙·우의 화력 구역 중심을 정하고, 조마다 하나의 공통 집결 목적지와 연결된 작은 도착 구역을 제공한다. 중앙 후퇴·측면 전진/우회로 구역 중심들이 호를 이루게 한다. 이동 방향만 맞추는 것으로 집결을 대신하지 않는다. 같은 조의 자리가 벽·코너 너머로 분리되지 않게 국소 연결성을 확인한다.
- 조원은 바닐라 이동으로 도착 구역에 모이고, 구역 안에서는 엄폐·사격선에 따라 불규칙한 자리를 허용한다. 한 타일에 모두 모이거나 개별 폰을 고정 곡선에 세우지 않는다. 준비 판정은 정확한 지정 칸 일치 대신 구역 안 도착·허용 거리·사격 가능한 인원 등 조 단위 기준을 사용한다.
- 공통 구역에 접근하지 못한 폰의 현재 위치 근처 자리는 임시 대기일 뿐 집결 완료가 아니다. 제한된 중간 합류 지점 또는 조 전체의 가까운 대체 화력 구역을 선택한다. 조 전체가 이동할 수 없다면 응집된 수비 구역으로 내려가며, 각자 먼 위치를 화력 구역으로 확정하지 않는다. 전 맵 경로 탐색이나 건물 반대편으로 돌아가는 개별 추격은 추가하지 않는다.
- 준비된 인원은 집결 도중에도 사격·엄호할 수 있다. 뒤처진 일부 때문에 전원이 정확한 자리에 도착할 때까지 무기한 대기하지 않는다. 짧은 대기 한도 후 준비된 인원으로 대응하고 남은 인원에게 합류 상태를 유지한다. 재시도 한도를 넘긴 인원은 현재 안전 구역에서 엄호하며 다음 제한된 재계획을 기다린다. 회피·의료·투척 등 우선 작업 중인 폰을 억지로 집결시키지 않는다.
- 초기 집결→화력 구역 유지→조별 기동→새 구역 합류에 같은 조 구성·공통 목적지·준비 판정을 재사용한다. 크게 이탈하거나 진행이 끊긴 경우만 재합류시키고, 작은 자리 이동이나 사격 자세 변경마다 되돌리지 않는다. A1.4의 집중 표적 공유·일반 교전 제어 반환과도 연결하여 근접 긴급 대응 중 집결을 기다리거나 일반 AI 작업을 반복 덮어쓰지 않게 한다.
- 조 구성·구역·합류 상태·지연 한도는 기존 분대 실행 상태에 보존한다. 구역 연결성/후보는 한 번 계산해 재사용하고, 조별 저빈도 응집 판정과 기존 작업 예산으로 처리한다. 폰 간 거리 전수 비교·매 틱 새 경로/슬롯 계산·별도 상시 맵 컴포넌트는 추가하지 않는다. 에이전트는 구현 때 메서드 흐름과 필요한 저장 복구를 확인하며 게임 기능은 F02·F05에 분리한다.

High 기동은 위 집결 구조의 화력조 공통 목적지를 먼저 정하고 그 주변에 4명의 자리를 배치한다. A1에서 추가한 공통 화력점의 짧은 전진을 더 긴 조별 기동으로 확장한다. 최초 조정 후보는 10~15칸의 기동 구간이며, 엄폐·시야·후속조 거리·도착 가능성을 제한된 후보로 확인한다. 이 수치는 검증 전 제안값이다.

기동 중 매 틱 대형으로 복귀시키지 않는다. 목적지와 허용 거리만 주고, 크게 이탈하거나 진행이 끊겼을 때만 재합류 작업을 준다. 한 조가 이동하고 다른 조는 준비된 자리에서 엄호한다. 사상자 후에는 생존 조를 기준으로 교대하며, 기동 불가 시 짧은 접근이나 수비로 내려갈 수 있다.

분대장은 임시로 한 화력조에 붙어 움직인다. 조직 트리의 소속을 바꾸지 않고 실행상 동행 관계만 저장하며, 사망·다운·해당 조 해산 때 재선택한다. 분대장만 뒤에 남거나 별도 네 번째 기동조처럼 행동하지 않게 한다.

의료 담당은 새 PawnKind나 추가 인원 없이 기존 분대 슬롯 중 1명으로 지정한다. 12인/13인 편제 인원수와 기본 무장은 유지한다. 기존 TCCC·가방 처치 작업을 재사용하며, 안전 구간에서 처치하고 위협 시 중단한다. 6인 정찰분대에도 동일하게 1명을 둘지는 편제 정의에서 명시한다.

가방은 소지자 변경에 대한 작업 소유권을 가진다. 다운/사망·실제 드랍 이벤트로 분대가 아는 장비 후보를 등록하고, 한 명만 회수 작업을 소유한다. 장비가 아직 착용 중인 다운 폰에게서 벗겨 가져오는 행동은 바닥 아이템 줍기와 별도다. 최초 구현은 실제 드랍된 장비부터 지원하는 것이 안전하다. 전 맵 장비 검색·처치 가능한 인원의 지속적인 전수 조회는 추가하지 않는다.

쿨타임은 종료 틱을 저장하고 사용 시 비교한다. 매 가방의 별도 틱 업데이트는 필요 없다. 효과 조정은 AI 코드와 독립된 작은 변경으로 검증·커밋한다. 건물 피해 감소는 LOW가 작은 방에도 수류탄을 자주 쓰는 교리를 넣기 전에 적용하는 것이 좋다.

## A5. High CQB 하위 작업과 교리 구분

가장 큰 구조 변경이다. 분대는 임무·통신·접촉 기억·작업 예산을 소유하고, 화력조는 담당 입구/구역·스택·브리치·관측·투척·진입 실행 상태를 가진다. 전체 분대 스케줄러를 화력조 수만큼 복제하지 않는다. 같은 전역 예산 안에서 각 조를 순환 처리한다.

폰별 명령 소유자는 항상 하나여야 한다. 분대의 야전/의료/긴급 회피와 CQB 조의 이동/진입 명령이 동시에 같은 폰을 제어하지 않게 하위 작업 중지·재개 규칙을 둔다. 분대장의 임시 동행 관계, 무전/의료/공병 사상자 승계도 이 소유권을 따른다.

가능한 경우 다른 화력조는 다른 알려진 방·입구를 맡는다. 단일 입구나 한 방뿐이면 직렬 통과하고 다른 조는 경계한다. 세 조를 항상 동시에 돌입시키는 규칙은 두지 않는다. 폭발 안전은 인접 조까지 확인하고 같은 개구부의 사용권·자리 중복 제한은 유지한다.

| 교리 | 제안 적용 |
|---|---|
| LOW CQB | 스택→개척→관측→장비 판단→진입. 문 선호를 낮추고 방 확보 중심으로 진행 |
| High CQB | 스택→가능한 사전 관측 장비→개척→관측→장비 판단→진입. 현재 미구현인 사전 관측 장비는 단계 건너뛰기 |
| High 입구 우선순위 | 알고 있는 국소 후보에서 통로→열린 문→닫힌 문→벽. 미관측 문이 열렸다는 사실로 계획을 바꾸지 않음 |
| LOW 수류탄 | 수감실 예외를 두고 낮은 사용 문턱. 16칸 이하 절약 규칙과의 관계는 아래 미확정 사항 참조 |
| High 살상 도구 | 관측한 무장 위협·교전 상황 등 명시 조건으로 허용. 조건 미충족 시 관측/비살상/직접 진입 선택 |
| LOW 야전 | 자동화기사수 중심 임시 대응조, 수비 선호. 전진 시 연막 우선. 완벽한 저격/고정기총 대응은 요구하지 않음 |
| High 야전 | 화력조별 호 배치·엄호/기동 교대. 각 조 안에서는 응집 유지 |

LOW의 수감실 예외는 관측·이미 알려진 정보로 판단한다. 숨은 수감자의 현재 상태를 매번 조회해 전술 정보를 얻지 않는다.

별도 약식 기능 목록: [F10~F11](습격%20기능%20약식%20테스트%20목록.md).

## A6. 스폰 규칙·지원 포인트·퇴각

사용자가 정정한 스폰 편제를 다음과 같이 적용할 계획이다.

| 세력 | 허용 스폰 편제 | 총인원 |
|---|---|---:|
| LOW | 정찰분대 | 6 |
| LOW | 보병분대 | 12 |
| LOW | 보병분대 3개＋지휘부 4명 | 40 |
| High | 화력조 3개(각 4명)＋분대장 1명 | 13 |
| High | 13인 분대 3개＋지휘부 4명 | 43 |

현재 LOW 소대는 보병분대 3개＋지휘부 2명＋기관총팀 3명＋바주카팀 2명＋저격팀 2명의 45명이다. 이를 위의 40인 소대로 변경하는 작업을 A6에 포함한다. 별도 지원팀은 새 소대의 구성에 포함하지 않으며 지휘부 4명의 구체적인 무장/역할은 구현 전에 정한다. High의 기존 13인 분대/43인 소대는 유지한다. High는 완전한 분대가 최소 스폰 단위이며 화력조만 단독 생성하지 않는다. 의료 담당은 이 인원을 늘리지 않는 슬롯 변경으로 넣는다.

완전한 편제만 생성하는 기존 계획기를 수정해 허용 편제를 명시한다. LOW의 독립 지원팀 생성 허용도 함께 정리한다. 남은 포인트는 이미 지원 잔액으로 계산되지만 실제 지원 소비와 연결된 것으로 간주하지 않는다. 편제 포인트 허용 오차로 원래 포인트를 초과하는 현재 규칙도 새 지원 회계와 함께 검토한다.

CPU 목표에는 최대 1소대 생성이 유리하다. 우선 설정값으로 두고 상한 초과 포인트를 지원으로 전환하는 방식을 추천한다. 단, 대규모 습격의 압박을 지원 효과가 대신해야 하므로 상한과 지원을 함께 검증한다. 예산이 최소 편제 비용보다 낮을 때의 사건 선택/포인트 보정 정책도 명시해야 한다.

지원은 한 습격/조직의 제한된 요청 큐와 잔액을 사용한다. LOW 방탄장비·신식무기는 생성 시 보급부터, 연막 박격포는 교전 중 요청으로 추가한다. 반복 보급으로 장비가 무한히 늘어나거나 초과 포인트를 중복 소비하지 않게 한다. 요청 승인 시 예산을 예약하고 실제 시행 시 소비하며, 취소/실패 환불 기준을 고정한다.

저격 지원은 최근 관측한 한 폰과 알려진 사격 방향을 사용한다. 해당 방향의 LOS·차폐 조건을 통과해야 하며 벽 너머 임의 피해나 시야 밖 현재 위치 추적을 허용하지 않는다. 대상 이탈 시 취소/실패로 처리한다. 무전 재밍은 High의 실제 무전 채널에 한정하고 LOW 접촉 보고까지 중단시키지 않는다. 적용할 플레이어/다른 모드의 무전 체계는 별도 정의가 필요하다.

기존 박격포/CAS 호출 중 전술 수비 전환 연결은 재사용 후보지만, 정착지 피해를 제한하는 새 지원 자원 규칙과 동일한 기능은 아니다. CAS·장거리 포격은 기본 지원에서 제외하고 명시 설정을 켠 경우만 허용한다.

퇴각은 사상자·전력 상실·지연·지원 고갈 같은 사건을 낮은 빈도로 판단한다. 소탕은 보통 약탈/납치/부분 피해만으로 끝내지 않는다. 그러나 전멸할 때까지 계속하는 규칙도 아니며 지연전·전력 손실에 따른 철수는 유지한다. 치료·살아 있는 폭발물 안전·장비 회수는 철수 준비에 제한된 시간을 준다.

## A7. 습격 종류 확장

공통 임무 체계와 철수·지원 회계가 정리된 뒤 추가한다. 각 종류는 새 상시 맵 컴포넌트가 아니라 동일 실행 체계의 임무 정책으로 넣는다.

| 순서 | 종류 | 필요한 별도 동작 |
|---|---|---|
| 1 | LOW/High 소탕 | 이름 있는 침대 최초 목표, 구역 정리, 야외 연결, 일반 약탈/납치 종료 제거 |
| 2 | 박격포·LOW 화학탄 습격 | 설치/사격·교전 시 이른 철수·박격포 회수. 회수 불가 시 포기하는 제한 시간 |
| 3 | LOW 배회·임시기지 | 제한된 순찰 지향점 또는 고정기총 설치/경계/철수. 지원 포인트와 추가 폰 스폰 혼동 금지 |
| 4 | High 사보타주 | 외벽에서 접근 쉬운 소수 알려진 대상 선정·피해 후 철수. 전역 전략 중요도 맵은 재도입하지 않음 |
| 5 | High 암습 | 첫 시끄러운 행동을 사건으로 알람 발생. 단순 알람 지연과 은밀 이동/피탐 제어의 범위를 분리 |
| 6 | High 헬리본 | 운송/착륙/하차/회수 동작과 추가 자산 필요. 드랍포드 금지와 별개의 진입 수단으로 정의 |

암습에서 폭약 설치는 조용하지만 폭발은 알람을 발생시키는 식으로 사건 목록을 명시한다. 대상이 이미 전투를 시작했는데 알람이 계속 숨겨지는 경우도 처리한다. 사보타주의 기지 가치 판단은 실제 발견한 후보 또는 최초 임무 정보 안에서만 수행한다.

## 구현 전에 확정할 사항

1. 최대 1소대는 기본 규칙인지 선택 설정인지. 소대 편제는 LOW 40명/High 43명으로 정정됐으며 LOW 지휘부 4명의 구체적인 무장/역할은 별도 결정한다.
2. 문서의 “3인 화력조”는 현재 4인 화력조와 다르다. 이 초안은 기존 13인 편제를 유지하고 분대장 동행만 추가하는 것으로 해석했다.
3. “퇴각 포인트가 더 낮음”이 사상자 임계값 감소로 더 일찍 철수한다는 뜻인지, 남은 전력/포인트의 다른 기준인지 명시해야 한다.
4. LOW의 거의 항상 수류탄 사용이 기존 16칸 이하 절약 규칙을 대체하는지. 새로운 설계 방향에는 LOW만 작은 방에서도 사용하도록 바꾸는 쪽이 맞지만, 이 초안에서 확정하지 않는다.
5. 매딕가방 쿨타임 길이·조기 사용 비용, 대인 수류탄 건물 피해 0.1과 1/30 중 기본값, High의 살상 장비 허용 조건은 아직 수치/규칙 확정이 필요하다.
6. 의료 담당 장비가 기존 매딕가방인지 새 파우치인지, 다운 폰의 착용 장비까지 즉시 회수할지. 최초에는 기존 가방과 실제 드랍 회수를 추천한다.

## 검증과 성능 비용 관리

검증 역할을 분담한다. 에이전트는 빌드·직접 관련된 기존 검사와 메서드/실행 흐름 분석·세이브 안정성처럼 사용자가 수작업으로 확인하기 어려운 검증을 직접 담당한다. 게임에서 약식 확인 가능한 기능은 [별도 테스트 목록](습격%20기능%20약식%20테스트%20목록.md)에 장면·기대 동작·미실행 상태로 분리해 사용자가 수행한다. 에이전트는 같은 약식 기능을 중복 실행하지 않고 사용자 목록 완료를 기다리며 개발을 멈추지 않는다. 복잡한 검증은 변경과 관련된 범위만 다루며 전체 44개 기능 시험은 반복하지 않는다. 정기 성능 측정·N/V 대조·반복 부하 시험은 계속 계획에서 제외한다.

성능 확인은 사용자가 직접 수행한다. 사용자가 지연이나 높은 CPU 사용을 보고하면 해당 상황과 관련 메서드만 좁혀 조사한다. 그때 측정하는 메서드 경과 시간은 기존 Core 레퍼런스 대비 비율로 기록하고 OS CPU와 구분한다. 자동으로 전체 반복 행렬을 재개하지 않는다.

화력조가 세 개가 돼도 전역 계획·관측·작업 발행 예산을 세 배 늘리지 않는다. 보고 구역 크기, 기동 후보 수, 다음 건물 후보 수, 지원 요청 수에 상한을 두고 여러 틱에 나눠 처리한다. 이 방식은 반응이 조금 늦어질 수 있지만 기존 CPU 우선 목표와 맞는다.
