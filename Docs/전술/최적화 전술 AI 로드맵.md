## 목표와 우선순위

합격 목표는 동일한 지도·폰 수·장비·전투 조건에서 **새 AI의 메인 틱 CPU / 바닐라 습격의 메인 틱 CPU ≤ 2.0**이다. `Update`나 워커로 비용을 숨기지 않도록 틱 밖 메인 작업과 전체 프로세스 CPU도 별도로 확인한다. 정확한 대조 방식은 [검증 기준](최적화%20전술%20AI%20검증%20기준.md)을 따른다.

현재 5~6배라는 값은 사용자의 플레이 관측이다. 새 조건의 재측정값으로 확정하지 않는다. 동일 조건에서 이 값이 확인되면 2배 도달에는 전체 비용 약 60~66.7%, 바닐라를 초과하는 비용 약 75~80% 제거가 필요하다. 이는 목표의 크기를 설명하는 계산이며 달성 예상치가 아니다.

우선순위는 CPU 사용시간·틱 지연 감소 → 이동과 진행의 안정성 → 핵심 전술 행동 → 세밀한 전술 판단이다. 판단 지연, 오래된 상태, 비결정적 결과, 근사 판단, 낮은 갱신 빈도, 폰/분대마다 다른 갱신 시점을 허용한다. 기존 캐시 맵과 알고리즘은 보존 대상이 아니다.

다만 작업 중단·사상자 이후 영구 정지, 코너/벽 너머 스택, 입구 중복 정지, 투척자의 조기 진입은 다시 만들지 않는다. 실제 폭발 안전과 유효한 폰/대상에 대한 작업 적용 검사는 남긴다. LOW의 접촉 없는 정보 공유와 시야 밖 적의 현재 상태를 읽는 전술 판단도 허용하지 않는다.

## 보존할 행동과 바꿀 구현

| 행동 목표 | 새 구현 방향 |
|---|---|
| 분대별 임무와 High 13인/3화력조 편제 | 기존 생성·장비·조직 트리를 사용하고 새 실행 상태를 별도로 구성 |
| 목표 방향의 외벽/문 돌파 | 국소 경계 후보를 소수 확인. 먼 열린 입구 우회보다 직접 돌파를 선호 |
| 벽 옆 연결된 스택, 도착 후 정지·경계 | 작은 대형 템플릿과 고유 자리. 코너 너머 후보 제외. 매 주기 재배치하지 않음 |
| 실제 확보한 개구부로 선두·후미 진입 | 필수 통과 지점과 입구 안쪽 비움. Security도 같은 통과 작업 사용 |
| 짧은 관측과 적절한 지원 | 관측자 1명, 적 하나를 보면 복귀. 실내/야외·방 크기를 국소 확인 |
| 수류탄/연막과 돌파 장비 | 장비 효과는 유지, 준비·투척·폭발 대기·회수의 작업 소유권은 재구성 |
| 방별 정리와 재침입 대응 | 확보한 구역/개구부 이력과 최근 위험을 분리. 전체 정적 방 ID는 요구하지 않음 |
| 관측 기억·LOW 접촉·High 장착 무전 | 짧은 보고와 대표 연락자 중심. 전체 인원 간 그래프는 만들지 않음 |
| 협력 진입·야전·수비 | 성능을 통과한 공통 작업 체계 위에 단계적으로 추가 |

전역 킬존 감지, 전략적 중요도 맵, 숨은 적 작업/목적지 조회는 도입하지 않는다. 이름 있는 침대를 자동 목표의 기본으로 두되 명시 목표가 최종 목표까지 우선하며, AI 대 AI 테스트도 명시 목표로 가능해야 한다.

## R0~R7 구현 순서

각 단계는 의미 있는 단위로 검증하고 커밋한다. 단계별 성능이 기준을 넘으면 다음 기능을 붙이기 전에 빈도·후보·작업 발행량을 줄이거나 구조를 수정한다. 단계 이름은 구현 완료 선언이 아니다.

| 단계 | 범위 | 다음 단계로 넘어갈 조건 | 현재 |
|---|---|---|---|
| R0. 기준 정리 | 이전 문서 보관, 새 구조·검증 계약 확정 | 문서 링크/기존 기록 보존, 구현 범위 구분 | 완료 |
| R1. 대조 실행과 격리 | Vanilla/Legacy/New 선택, 동일 편제 fixture, 구형 실행 차단, CPU·진행 지표 | Vanilla에서 구형 계획·관측·통신·이동 후크가 실제 비활성. 기존 게임/저장을 건드리지 않는 반복 수집 | 완료: 실제 23회 검증 |
| R2. 최소 돌파·진입 | 지속 작업, 분대 지휘, 연결 스택, 해머 외벽/문 1곳, 한 방 진입, 후미 합류 | 일반 이동 및 한 방 돌파가 실제 완료. 소규모 기능 시험과 50/200명 부하에서 CPU ≤2배 | 완료: 30회 실제 검증, 60/204명 각 조건 CPU ≤2배 |
| R3. CQB 행동 완성 | 짧은 관측, 준비 투척, 폭발 대기, C4/절단기, 공병 교체·회수, 인접 구역 정리 | 장비별 안전·중단·뜻밖의 구멍·좁은 방 회귀 통과. 다방 CQB에서도 CPU 기준 유지 | 미착수 |

| R5. 연락·협력 진입 | LOW 접촉, High 무전, 합의/준비/시작/중단, 다른 입구·구역 배분, 아군 조우 지연 | 실제 연락 조건과 단절·승계, 다중 입구/공유 입구 모두 진행. 통신 비용의 급증 없음 | 미착수 |
| R6. 야전·수비·교리 | 사거리 밖 감지, 관측 기반 접근축, 엄폐·계획 연막, LOW 활 모양 대형, High 엄호/기동, 수비 복귀 | 사격을 받으며 무저항 이동하지 않고 적 소실 후 임무 복귀. CQB↔야전 전환 포함 CPU 기준 유지 | 미착수 |

### R1: 먼저 성능을 판정할 수 있게 만들기

- 같은 코드/콘텐츠 빌드에서 전술 엔진만 선택한다. 기존 습격 진입 종류, 장비, 조직 메타데이터를 대조군에서도 동일하게 유지한다.
- Legacy는 기존 성능의 참고 대조다. 합격 분모는 바닐라 AI다. 일반 습격과 공병 습격은 서로 다른 대조군으로 보고하며 하나의 가장 유리한 값으로 합치지 않는다.
- 폰별 이동 후크·일반 작업 조회 후크와 구형 맵 컴포넌트까지 격리한다. New에서 Prefix만 조기 반환하더라도 비용이 남는지 확인한다.
- 기존 Core 기준 수집기와 격리 실행기를 재사용한다. 새 엔진의 선택과 기능 완료 지표를 먼저 추가하고, 기존 시나리오 번호가 새 행동에도 동등한 시험인지 확인한다.
- `MapComponentTick` 전체 호출기와 개별 전술 컴포넌트, `GameComponentTick`, Tick 밖 Map/GameComponentUpdate를 함께 분해한다. R1에서 지도 분석·조직 관리도 기본 등록에 포함했다. 메서드 경과 시간과 전체 틱 실제 CPU를 구분한다. 상세 범위는 [검증 기준](최적화%20전술%20AI%20검증%20기준.md)을 따른다.

### R2: 성능을 증명할 최소 구현

- 해머만 사용하는 한 겹 외벽/일반 문부터 시작한다. 폭발 장비와 동적 적 대응은 이 단계의 완료로 주장하지 않는다.
- 공통 접근 지향점 → 벽 옆 스택 → 한 대상 돌파 → 확보 개구부 통과 → 가까운 실내 벽 자리까지 진행한다. 매 셀 경로 교정과 전체 맵 비용 배열은 만들지 않는다.
- 한 폰에는 한 작업 주체만 있다. Job 완료/실패와 사상자 이벤트는 분대 작업 큐를 깨우고, 이벤트에서 대형/계획을 직접 재계산하지 않는다.
- 선두뿐 아니라 후미 경계 인원의 필수 개구부 통과를 확인한다. 실제 이동 자체는 바닐라에 맡기되 잘못된 우회는 통과 지점의 국소 작업으로 해결한다.
- 2배를 넘으면 R3를 시작하지 않는다. 캐시 전체 재도입이나 워커 추가보다 재발행·실패 재시도·후보 수·관측 여부를 먼저 조사한다.

### R3~R4: CQB와 기억

- 관측은 개구부 옆에서 약 1~2초이며 적 하나 발견 시 즉시 복귀한다. 인접 문칸도 대상 구역으로 해석한다.
- 실내 수류탄/야외 안전 연막, 16칸 이하 실내 절약, 실제 관측 적 예외, 개구부에서 최소 2칸 투척을 유지한다. 준비 중 총 표시/사격 금지와 도착 후 약 0.3초 투척도 유지한다.
- 실제 발사체/폭발 효과와 투척자 복귀를 확인하기 전 진입하지 않는다. 계획을 취소해도 이미 발사한 폭발물 안전 상태는 지우지 않는다.
- 목표가 현재 구역이면 정리로 전환한다. 벽 파괴 후 통행이 가능해지면 진입으로 넘긴다. 새 구멍과 이미 만든 개구부는 재사용한다.
- 후방 적, 다른 문 출현 후 후퇴, 복도 앞뒤 적 소실을 기억 기반으로 처리한다. 과거 확보 이력은 유지하되 현재 위험만 재확인 필요로 바꾼다.

### R5~R6: 연락과 야전

- LOW는 실제 접촉이나 사전 합의로 협력한다. 분리된 분대의 새 상태를 중앙 큐가 안다고 즉시 알려 주지 않는다.
- High는 정상 착용 무전 파츠를 가진 운용자끼리 보고한다. 태블릿은 쓰지 않는다. 보고·확인은 소수 메시지로 표현하고 매 폰 간 통신 그래프를 구성하지 않는다.
- 협력 계획은 입구·담당 구역·준비·시작·실패 조건을 담는다. 같은 입구가 불가피하면 제한된 사용권과 대기 자리를 쓴다. 물리 충돌 방지가 전술 정보 공유가 되지는 않는다.
- 야전은 두 번 이상 관측한 좌표 변화로 접근/횡단/이탈을 추정한다. 숨은 적 `Goto`나 `enemyTarget`으로 미래 행동을 읽지 않는다.
- LOW 임시 대응조의 호는 **활 같은 곡면 사격 대형**이다. 굴착은 포함하지 않는다. High는 기존 3화력조의 엄호 준비→기동→교대를 사용한다.
- 연막은 분대의 이동 구간에 계획하고 그 안에서 접근하며 추가 사용한다. 개별 도주 위치에서 제각각 투척하지 않는다. 수비도 같은 임무/작업 체계로 복귀한다.

## 예상 효과와 중단 판단

가장 큰 후보는 폰의 이동/작업 처리마다 들어가는 전술 조회 제거, 잦은 Job 재발행 제거, 전체 지도·통신·국소 격자의 반복 갱신 제거다. 새 구조가 이 비용을 실제로 없애도 바닐라 길찾기와 실패 재시도를 늘리면 전체 CPU는 줄지 않을 수 있다.

현재 자료만으로 2배 달성률이나 최종 절감률을 약속하지 않는다. R2에서 총 CPU, 기능 완료율, 재경로·작업 발행 빈도를 함께 측정해 구조의 가능성을 판정한다. 작은 규모에서 이미 2배를 넘거나 후미가 멈춘다면 기능 확장을 보류한다. 워커는 측정된 순수 계산이 여전히 큰 경우에만 추가한다.
