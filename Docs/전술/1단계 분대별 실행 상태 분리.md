# 1단계: 분대별 실행 상태 분리

작성일: 2026-10-04. 기준: [분대 협력 진입과 야전 전술 통합 계획](분대%20협력%20진입과%20야전%20전술%20통합%20계획.md)의 1단계.

1단계 구현과 자동 검증을 완료했다. 실제 게임의 동시 이동·철수·저장 후 작업 재개는 아래 플레이 검증으로 확인해야 한다. 2단계 이동 노드 교체와 이후 통신·협력 진입·야전 확장은 아직 적용하지 않았다.

## 실행 단위

`RaidTacticalUnit`은 실제 `CombatOrganization`과 `CombatGroup`을 참조하는 실행 범위다. 조직을 복제하지 않고 기존 조직 트리와 편제·지휘 승계를 사용한다.

| 편제 | 명령 소유자 | 소속 인원 |
|---|---|---|
| LOW 소총 분대/순찰 분대 | 해당 Squad | 분대의 모든 인원 |
| 독립 기관총조·바주카조·저격조 | 해당 Team | 그 조의 인원 |
| 소대 본부 | 소대 직속 단위 | 소대에 직접 배정된 인원만 |
| High 분대 | 해당 Squad | 분대장과 하위 Team 화력조 전체 |
| High 화력조 | 소속 분대의 계획을 사용 | 실제 Team 소속은 별도로 보존 |

실행 키는 `OrganizationId::GroupId`다. 사망·다운·지휘 승계가 발생해도 해당 편제의 키는 유지한다. High 화력조를 별도 분대 계획으로 중복 실행하지 않는다. 향후 화력조별 엄호·기동 진행을 추가할 수 있도록 폰 배정과 명령에 실제 소속 `GroupId`를 보존한다.

## 상태와 저장 소유권

| 정보 | 분리/공유 기준 |
|---|---|
| 계획·최종 목표 진행·단계·브리처·투척자·관측자 | 실행 단위별 |
| 적 접촉 기억·경계 담당·관측한 문 상태·지역 CQB 지식 | 실행 단위별 |
| 클리어한 방·방 보안 우려·재확인 진행 | 실행 단위별 |
| 사상자 재판단·유실 공병 장비 회수 대상 | 실행 단위별 |
| 폰의 지속 명령 | 폰당 하나, 명령 소유 실행 키와 실제 소속 그룹 기록 |
| 습격 시작 정적 구조 버전 | 기존 조직 단위 참조를 유지해 공유 |
| 지원 포인트 | 실제 조직의 예산 하나를 계속 사용 |

계획·실행 상태에는 조직 ID, 실행 키, 소유 그룹 ID를 저장한다. 폰 배정과 명령에는 실제 소속 그룹 ID도 저장한다. 불러올 때 같은 조직의 여러 분대 상태를 실행 키로 각각 복원한다. 접촉 기억·클리어 상태·보안 기록·문 상태와 기존 실행 진행은 각 분대의 저장 데이터에 남는다. 지역 CQB 계산 창은 기존처럼 필요 시 재구성하며, 실행 중 분대 사이에 같은 변경 지식 객체를 넘기지 않는다.

폰의 소속과 다른 명령은 거부한다. 수류탄 준비와 개구부 관측 작업도 시작 당시 실행 단위를 기억하고, 소속이 바뀌면 이전 단위의 작업을 계속하지 않는다. 사상자 알림은 조직 전체가 아닌 해당 실행 단위에 모아서 다음 판단을 요청한다.

목표를 마친 한 분대가 바닐라 습격 `Lord` 전체를 철수시키지 않도록, 다른 인원이 같은 `Lord`에 있으면 철수 인원만 별도 철수 `Lord`로 옮긴다. 조직 자체는 복제하지 않는다.

## 처리와 개발자 표시

기본 계획 생성은 기존 맵 공통의 틱당 한 번 제한을 유지한다. 대기열 순서를 사용해 앞 분대가 계속 재판단하더라도 뒤 분대의 초기 계획을 가로막지 않게 한다. 기존의 국소 방 재계획과 실행 주기는 유지한다.

개발자 전술 창에서 실행 단위를 선택한다. 기존 5개 버튼 제한을 드롭다운으로 바꿔 소대 본부와 지원조를 포함한 모든 단위를 선택할 수 있다. 지도 오버레이는 선택한 폰의 소속 분대로 전환하며, 방 클리어·접촉·노드·실행 로그도 그 단위 상태를 보여 준다. 정적 방 레이아웃은 계속 같은 구조 버전을 볼 수 있다.

이 단계에서 분대별 계획은 독립됐지만 서로 다른 진입점의 사전 배분은 아직 없다. 따라서 두 분대가 각자 같은 최적 진입점을 선택할 수 있다. 경로·담당 구역 분배와 입구 사용 순서는 통합 계획의 4~5단계에서 다룬다. LOW 접촉 전달과 High 전술 무전은 3단계 대상이며, 지금은 다른 분대의 기억을 자동으로 합치지 않는다.

## 검증

자동 검증:

- 모드 빌드: 경고·오류 없음.
- 실제 게임 어셈블리 바인딩/회귀 검증: 기존 308개와 실행 단위 검증 30개.
- 전술 계획 검증: 173개.
- 조직 편제 검증: 1,366개 및 `Verify-SquadSystem.ps1` 정적 통합 검사.
- 새 검증은 소대 본부/분대/지원조 인원 분리, High Team 부모 관계, 사상자 이후 키·정원 유지, 단위별 기억과 방 진행, 실제 사망 알림 대상, 다른 단위 명령 거부, 계획 무효화 범위, 공통 예산·계획 대기열, 네이티브 Scribe 식별자 읽기와 상태 조회표 복원을 확인한다.

실제 게임에서 확인할 항목:

1. 같은 LOW 소대의 두 분대를 떨어뜨린 후 한쪽에만 적을 노출한다. 다른 쪽 접촉 목록과 단계가 바뀌지 않아야 한다. O
2. 한 분대의 공병을 다운시킨다. 해당 분대의 다른 인원이 회수·재판단하고 다른 분대는 자기 작업을 유지해야 한다. O
3. 한 분대만 방을 클리어한 뒤 단위를 전환한다. 다른 분대의 클리어/보안 기록이 자동으로 채워지면 안 된다. O
4. 저장·불러오기 후 각 분대의 목표·단계·접촉·클리어 기록과 수류탄/관측 작업 소유권을 확인한다.
5. High 분대장과 세 화력조는 같은 분대 계획을 사용하면서 배정/명령의 실제 Team 소속을 유지해야 한다. O
6. 관측한 야전 목표를 끝낸 한 분대가 철수할 때 다른 분대의 습격 `Lord` 임무와 진행이 유지돼야 한다. 실제 `Lord` 이동과 바닐라 전역 철수 조건은 Unity 게임 실행에서 검증한다.
