# 통신과 실행 반응 최적화 및 반복 검증 결과

작성: 2026-10-07. 기존 최적화 계획의 2~4단계 후속 기록이다. 성능 수치는 고정 입력의 Core `Verse.GenRadial.NumCellsInRadius` 10,000회 배치 대비 비율로 해석한다. 100%는 게임 전체 CPU 점유율이 아니라 레퍼런스 배치 한 번의 비용이다. 짧은 메서드는 경과 시간을 측정한다. 기준 배치와 함께 느려지는 환경 영향을 줄이지만 GC와 OS 스케줄링 간섭까지 제거하지는 못한다.

## 통신 갱신 변경

통신은 맵 실행 티켓의 분대 목록을 사용한다. 다른 맵과 월드의 전체 조직을 20틱마다 다시 열거하지 않는다. LOW처럼 무전 교리가 없는 조직은 방탄복 파츠 열거와 무전기 목록 구성을 생략하며 무전 연결 검사를 즉시 종료한다.

구성원·지휘관·위치·무전 장비 목록·blackout·물리 구조 버전이 같으면 간선과 CommandDelays를 최대 60틱 동안 재사용한다. 문 개폐, 건물 생성/제거, 지형 변경은 구조 버전을 올린다. 연막 등 별도 버전이 없는 변화는 60틱 만료로 다시 확인한다. 전송 또는 ACK를 기다리는 양쪽 분대는 재사용 대상에서 제외하고 기존 20틱 전송 검사마다 그래프를 다시 계산한다. 따라서 전송 완료 시 사망, 장비 손실, 연막 차단, 느려진 대체 경로를 그대로 검사한다. LOW 분대 사이의 접촉 조건과 HIGH의 실제 방탄복 무전 파츠 조건은 유지한다.

디버그 상태 문자열은 개발자 모드에서 새 프레임을 만들 때 갱신한다. 종료된 분대 프레임은 맵 실행 로스터에서 제외되면 제거한다.

## 실행 반응 변경

사격/CQB 반응 검사는 평상시 30틱 간격으로 수행한다. 직접 관측·보고 수신·접촉 상실·기억 만료에 따른 접촉 버전 변경, 전술 단계 변경, 긴급 사상자 처리는 간격을 기다리지 않는다. 연막 대응·경계 인원·현재 반응이 있으면 기존 빠른 실행 간격으로 검사한다. 같은 틱의 스케줄러와 Update가 동일 대응을 중복 계산하지 않도록 결과를 재사용한다.

수류탄 위협 검사는 이 느린 주기에 포함하지 않는다. 투사체 후보 목록만 맵에서 틱마다 한 번 재사용하고 LINQ로 새 목록을 만드는 작업을 없앴다. 폰의 knownExploder도 계속 검사한다. 적 기억이 없고 경계 해제가 필요 없는 경우 사격/CQB의 비싼 위치 계산은 즉시 반환한다.

폰 공간 인덱스는 10틱마다 재구성한다. 인원 수가 바뀌면 즉시 재구성하고 검색 범위에 16칸 여유를 둔다. 이 인덱스는 후보 선별용이며 실제 위치·적대 관계·거리·사격 LOS는 현재 값을 검사한다. 같은 인원 수를 유지하는 순간이동은 최대 10틱 관측 지연이 생길 수 있다. LOS 결과 자체는 기존처럼 같은 틱에서만 재사용한다.

중간 반복 실행에서 `RefreshContactsCore`가 큰 비중을 유지해 후보 검색을 추가로 수정했다. 분대원마다 같은 공간 버킷과 아군 후보를 반복해서 훑던 방식을 분대 전체를 포함하는 사각형 검색 한 번으로 바꿨다. 각 버킷과 후보는 한 번만 방문한다. 사각형에 추가로 포함된 후보는 기존 정확한 거리 필터에서 제외하므로 실제 관측 범위나 적 우선순위는 늘리지 않는다. 분산된 분대와 지도 경계의 후보 보존을 별도로 검사했다.

## 측정 조건과 검증 방법

최초 시드 지정만으로는 quicktest 지도 해시가 달라져 직접 비교를 거부했다. 그 기록은 개선 근거에서 제외했다. 고정 전장 버전 2는 전체 지도 지형을 콘크리트로 정리하고 동일 외벽·문·배정 침대를 만든다. 물리 지도 해시는 월드 타일 번호를 제외하고 모든 칸의 지형·건물·지붕을 포함한다. 월드 환경과 게임 실행의 완전한 결정성을 주장하지 않으며 준비/시작 단계와 종료 시 이동·생존·진행 상태를 함께 검토한다.

기본 준비는 600틱, 측정은 1200틱이다. LOW 50/100/200/400명과 종료 후 0명, HIGH 52/104/208/403명과 종료 후 0명을 각 2회 반복한다. HIGH는 실제 OrganizationGenerator로 13인 분대와 3개 화력조를 만들고 실제 장착 무전기 인원을 기록한다. 메서드 예외와 dropped, 이동·생존, 미시작 명령, 일정 지연을 함께 확인한다. security, 외벽 개구부, 늦은 합류, 숨은 문, 연막, 중복 없는 대형은 별도의 7단계 게임 감사로 검증한다.

공통 감사 장비 지급 단계는 HIGH에도 해머·MKII·연막을 추가한다. 이는 생성기·무전 편제와 실행 부하를 확인하기 위한 감사 전장이지 실제 HIGH 레이드 전체를 그대로 재현한 것은 아니다. 600틱 후에도 계획이 없는 분대가 있거나, 장착 무전 인원 및 시작 단계가 다르면 비교 그룹이 분리된다. 사상자 발생과 종료 단계 차이는 원본 감사에서 별도로 확인해야 한다. CLI의 조건 일치만으로 행동 부하까지 같다고 보증하지 않는다.

호출 분포는 메서드별 마지막 2048회, 긴 호출은 5ms 이상 중 상위 16개만 보관한다. p95/p99도 Core 배치 대비 비율을 함께 기록한다. 반복 집계는 실행별 분위수의 중앙값이며 전체 호출의 통합 분위수가 아니다. 중첩 메서드의 누적 시간을 합산하지 않는다.

표의 시간과 분위수는 해당 수집 구간의 메서드 프로파일을 사용한다. 감사의 executionService 등 일부 서비스 카운터/최댓값은 준비와 앞선 시나리오를 포함한 누적값이므로 특정 구간의 긴 호출 원인으로 직접 대입하지 않는다. 전역 긴 호출 상위 16개는 부모인 DoSingleTick으로 채워질 수 있어 하위 병목은 메서드별 maxMs와 p95/p99를 함께 확인한다.

## 실행 도구

- [반복 실행기](../../Source/Benchmarks/AgentProfiler/Run-RepeatedBenchmarks.ps1): 동일 시드·조건의 반복 실행과 집계. `-Resume`은 완료된 동일 빌드/시드/준비/시나리오/팩션의 기록을 보존하며 재사용한다.
- [CLI](../../Source/Tools/AgentProfiler/README.md): `aggregate ROOT`, `benchmark-compare BEFORE_ROOT AFTER_ROOT`로 조건이 같은 기록만 묶어 비교한다. 일치하지 않는 시작 단계 등은 unmatched로 남긴다.
- [감사 검사 후 비교](../../Source/Benchmarks/AgentProfiler/Compare-ReviewedBenchmarks.ps1): 사상자, 95% 미만 이동, 메타데이터 불일치, 불완전 수집, 계측 예외가 있는 기록을 원본 변경 없이 제외한다. 자체 동일 기록 비교와 정지/지도 불일치/불완전 감사/예외 거부를 확인했고 실제 100명 중 3명 손실 기록도 제외했다.
- 검증: 메서드 수집기/CLI, 순수 전술 기하 1249개 검사, 실제 게임 클래스 바인딩 및 통신 35개 검사. 실제 게임 반복 감사 결과는 아래에 이어서 기록한다.

## 이동 감사에서 드러난 제한

명시적으로 열린 문을 사용해야 하는 첫 시험에서 폰이 지나가면 바닐라 문 닫힘 타이머가 짧아져 문이 닫혔다. 감사 전장의 문을 실제 `holdOpen` 상태로 유지하도록 수정했다. 이 수정은 테스트 조건에만 적용한다. 수정 후 진단 실행은 7단계 모두 통과했지만, 첫 집결·통과는 1628틱, 외벽 후속 진입은 1118틱, 대형 시험은 1005틱을 소모했다. 또 앞선 holdOpen 실행에서는 전원이 실내로 들어온 후에도 대형 도착 시험이 실패했다. 통과 기록과 실패 기록을 모두 보존한다.

이 결과로 모든 security 이동과 집결 지연이 해결됐다고 판단하지 않는다. 다음 이동 개선에서는 정확한 집결 도착 조건, 입장 후 재집결, 후속 인원의 개구부 통과를 별도 문제로 다뤄야 한다. 성능 측정의 `moved`는 이동 발생 여부이며 목표 방 클리어 완료를 의미하지 않는다.

관측 후보 검색까지 적용한 최종 DLL의 별도 감사도 7단계 모두 통과했다. 아래는 최종 실행의 도착 틱이며 FPS나 실제 초로 변환한 값이 아니다.

## 통신 내부의 호출 감소 확인

같은 전장·시작 단계의 상세 수집은 각각 1회다. 이 자료는 내부 호출이 줄었는지 확인하는 용도이며 경량 수집의 전후 비용과 섞지 않는다. LOW에서 실제 장비 열거가 사라지고 간선·음성 검사가 줄었음을 확인했다. RefreshFrames 진입 수 자체는 getter의 호출 때문에 늘 수 있지만 그 안의 계산량은 줄었다.

LOW의 장비 열거 0회는 교리상 필요 없는 작업을 제거한 결과다. 일반적인 미호출 메서드의 분위수 0을 개선으로 해석한 것은 아니다.

## 중간 실행에서 추가 최적화를 결정한 근거

관측 검색 변경 전의 400명 LOW 반복 실행에서 RunScheduledUnit은 Core 대비 330.79%→370.54%, 호출 p99는 630.97%→722.98%로 악화됐다. 통신과 평상시 반응을 줄인 것만으로 실행 전체의 긴 호출까지 해결되지는 않았다. 해당 after 첫 실행은 FollowNodes 210회/280.862ms였고 before 첫 실행은 9회/5.162ms였다. 접촉 관측 역시 before 615.795ms, after 973.264ms로 달랐다. 시작 단계가 같아도 이동 진행과 대형 복구의 작업량은 같지 않았다.

이를 근거로 관측의 반복 후보 검색을 제거했다. FollowNodes의 재진입 및 실내 합류 탐색은 별도 이동 과제로 남긴다. 중간 실행의 실패·악화 수치를 최종 개선 수치로 덮어쓰지 않고 intermediate 자료로 보존한다.

## 검증 결론과 다음 우선순위

최종 LOW/HIGH는 각 2회씩 완료됐고 사상자 제외 기록은 없었다. 모든 비교 대상에서 95% 이상이 이동했다. HIGH 208명은 before 한 기록의 무전 보유 인원이 206명이어서 조건 일치 그룹의 before 유효 반복이 1회다. 원본과 unmatched를 보존하며 2회 before 결과인 것처럼 합치지 않는다. 최종·중간·상세 수집 총 66개는 complete, dropped=0, 계측 메서드 예외=0이었다. 이는 게임 로그 전체가 무오류라는 뜻은 아니다.

대규모 조건의 실행 틱당 비용은 LOW 400명 약 31.7%, HIGH 403명 약 40.1% 줄었고 실행 p95/p99도 개선됐다. 통신 비용은 각각 약 55.7%와 33.4% 줄었다. 이는 Core로 정규화한 선택 메서드 비용의 관측 결과이며 게임 전체 CPU가 그 비율만큼 감소했다는 뜻은 아니다. 2회 표본과 완전히 같지 않은 종료 행동으로 보편적인 개선율이나 통계적 확신까지 주장하지 않는다.

소규모의 긴 단일 호출 목표는 남아 있다. LOW 50명 실행 틱당 비용과 p99는 악화됐고 HIGH 52명 실행 p99도 소폭 악화됐다. LOW 50명의 전체 게임 틱 p99 역시 악화됐다. 따라서 모든 인원 조건의 p99가 개선됐다고 보고하지 않는다. 큰 인원에서 통신/관측의 반복 비용을 줄인 이번 변경과 단일 활동 분대의 이동·진입 복구 비용을 다음에 줄이는 작업은 구분한다.

다음 우선순위는 다음과 같다.

1. LOW 50명 활동 분대의 FollowNodes, KnownIndoorJoin, RetargetBlockedStackMembersCore를 따로 계측한다. 현재 실내 합류는 최대 49×49칸 입력과 거리 검색을 만들 수 있다. 같은 합류 판단을 반복하는지 먼저 확인하고, 변하지 않은 연결 결과 재사용과 탐색 크기 제한을 검토한다. 이 단계에서 단일 호출 p99와 실제 security 도착 지연을 함께 줄인다.
2. 첫 집결과 외벽 후속 진입의 지연을 별도 기능 시험으로 분리한다. 최종 7단계 통과에도 외벽 후속 진입 1045틱, 대형 재배정 924틱이 남았다. 정확한 도착 조건, 진입 후 경계 자리 복구, 대기 중 명령 교체를 조사한다. 이동 발생만으로 완료 처리하지 않는다.
3. 선택 전술 메서드 밖의 잔여 비용은 바닐라 폰·작업·길찾기 메서드를 소수씩 추가 계측해 확인한다. DoSingleTick 누적 시간을 전술 시스템 전체 비용으로 오인하지 않는다. 네이티브 Mono 샘플러·MCP 래퍼 확대는 해당 비용을 현재 도구로 분리하기 어려울 때 검토한다.
