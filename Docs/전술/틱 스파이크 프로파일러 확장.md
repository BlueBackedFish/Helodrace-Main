# 틱 스파이크 프로파일러 확장

2026-10-08. 이전 분산 수정 이후 남은 TickList 및 바닐라 작업 검색의 긴 호출을 추적하기 위한 개발 도구 변경이다. 전술 판단·이동 동작은 수정하지 않았다.

## 추가한 기능

- `spikes` 프리셋: 틱·컴포넌트 경계, Pawn.TickInterval, 작업 시작/종료/검색, ThinkNode_JobGiver, 교전 JobGiver, PatherTick, PathFinder 완료/요청, New 전술 판단/명령/복귀를 연결한다.
- 느린 틱 상위 8개에 선택된 완료 호출 최대 512개를 보존한다. 기준은 기본 5ms이며 조정 가능하다. 전체 메서드의 긴 호출 상위 16개도 문맥과 함께 보존한다.
- 호출 ID·부모·루트·깊이, 시작 시각·경과 시간·선택 하위 제외 시간, 게임 틱·렌더 프레임, 가능한 폰·맵·분대·단계·현재 작업을 기록한다.
- 루트 틱의 Windows CPU 값과 GC 컬렉션 횟수 차이도 기록한다. 짧은 개별 메서드의 CPU를 경과 시간으로 대체하지 않는다.
- CLI `spikes CAPTURE [TICK]`가 이름과 Core 기준 대비 비용, 폰 호출 비용 상위 목록, 시간순 호출 흐름을 반환한다.
- schema 5. 추적 on/off와 임계값이 다른 실행은 성능 비교에서 같은 조건으로 취급하지 않는다.

추적은 선택 기능이며 coarse/detailed에서는 기본으로 꺼져 있다. 고정 배열을 수집 시작 때 할당하고 호출별 객체·배열·문자열을 생성하지 않는다. 문맥은 typed Harmony prefix와 기존 New byPawn 사전 조회로 읽으며 조직 생성이나 전술 재계산을 하지 않는다. 다른 스레드는 Unity/게임 문맥을 읽기 전에 제외한다. 직렬화는 수집 종료 후 수행한다.

## 약식 검증

New LOW 204명·17분대, sapper-wall, 준비 1200틱·수집 600틱의 격리 실행 **1회**를 사용했다. 등록 대상 52개. 캡처 complete=true, dropped=0, 메서드 예외 0. 5ms 이상 틱은 281개이고 상위 8개를 보존했다. 보존된 틱마다 선택 호출 286~308개로 세부 기록 잘림은 0이었다.

|---|---:|---:|---|---:|---:|
|1584|22.2939ms|8065.81%|Pawn.TickInterval|845|16.5381ms|
|1761|16.2388ms|5875.11%|JobGiver_AIFightEnemy.TryGiveJob|4414|7.2094ms|
|1592|14.2791ms|5166.10%|JobGiver_AIFightEnemy.TryGiveJob|4417|7.8598ms|

Core 기준은 기존 GenRadial.NumCellsInRadius 고정 10,000회 배치이며 이번 중앙값은 0.2764ms였다. 100%는 이 배치 한 번의 비용으로 CPU 점유율이 아니다. 전체 틱의 평균 경과 시간은 5.3341ms, Windows 틱 CPU 평균은 5.2083ms였다. 루트 개별 CPU는 0 또는 15.625ms처럼 거칠게 나타나므로 개별 틱 원인을 CPU 값 하나로 확정하면 안 된다.

상위 세 호출의 폰은 이번 New 전술 명령에 연결된 분대 ID가 없었다. 최대 호출의 진입 당시 작업은 Wait_MaintainPosture였고 두 교전 판단 호출은 Goto였다. 이는 해당 스파이크가 New Advance 내부 호출이라는 추정과 구분되는 관측이다. Pawn.TickInterval의 미계측 하위 호출은 아직 분해되지 않았고 GC 카운터 차이는 보존된 8개 틱 모두 0이었다. 따라서 해당 폰의 세부 트래커를 다음에 필요한 범위만 추가 계측하는 근거로 사용한다. 원인을 특정 전술 기능이나 GC로 확정한 결과는 아니다.

실제 JSON의 모든 부모/루트 ID, 깊이, 틱 번호 통일, 중첩 시간 범위, 폰·분대·단계 문맥을 확인했다. 단위 검증은 상위 8개 교체, 701개 호출 중 512개 보존 및 루트 예약, 중단 후 열린 호출 종료, 예외·집계 유지, JSON 직렬화, 기존 CPU 검증을 통과했다. CLI는 특정 틱 필터·이름 연결·추적 비활성 조회 거부·비교 조건 보호를 통과했다. 게임 및 CLI 빌드는 경고/오류 0개였다.

이번 실행은 도구 검증용이다. 완료 분대는 3/17, 실내 명령 완료 인원은 36명이므로 전체 임무 완료 시험이 아니다. 프리셋과 수집 길이가 이전 시험과 다르고 계측 비용도 포함되어 이전 수치와 성능 개선률을 비교하지 않는다. 2배 CPU 게이트 합격 판정도 하지 않는다.

## 사용과 제한

사용법은 [프로파일러 README](../../Source/Tools/AgentProfiler/README.md#틱-스파이크-추적-schema-5)를 따른다. 원본·감사 결과·실행 옵션·요약은 [검증 결과 폴더](../../Source/Benchmarks/AgentProfiler/Results/2026-10-08-tick-spikes)에 보존했다. 원본은 실제 측정 빌드의 SHA256을 유지한다.

512개 한도를 넘으면 처음 완료된 호출부터 기록되어 후반부나 부모가 누락될 수 있다. detailsDropped/detailsComplete로 이를 표시하며 전체 집계의 dropped와 구분한다. 계측하지 않은 호출, 워커 스레드 작업, 네이티브 내부 연산의 전체 스택은 보이지 않는다. 폰 문맥이 없는 맵/전역 호출은 ID가 -1일 수 있다. Legacy 분대 문맥은 자동 복원하지 않는다. 프리셋은 진단을 위한 것이며 평상시 성능 측정에는 필요한 대상만 선택한다.

## 상세 호출 한도와 별개인 느린 틱 전체 집계

2026-10-08 추가. 많은 폰을 계측하면 처음 완료된 호출부터 512개를 채워, 틱 후반의 전술 판단·맵 컴포넌트가 상세 기록에서 사라지는 문제가 있었다. schema 7에서는 느린 틱별 선택 메서드 합계를 별도 고정 배열에 저장한다. 전술 동작은 변경하지 않았다.

`spikes CAPTURE [TICK]`의 `wholeTickMethods`에는 호출·예외 수, 누적·평균·최대 경과 시간, 선택 하위 제외 시간, 틱 경과 시간 중 비율 및 Core 기준 대비 값이 나온다. 선택 하위 제외 시간 순으로 정렬한다. 모든 값은 선택된 메인 스레드 메서드의 경과 시간이며 개별 메서드 CPU 시간이 아니다. 미계측 작업과 계측 비용은 이를 감싸는 메서드에 남는다.

폰 상세 필터와 512개 한도는 합계에 적용하지 않는다. `methodsComplete`는 해당 틱에서 깊이 제한/스레드 제한에 의한 계측 손실이 없다는 뜻이며, 상세 기록 완전성과 구분한다. 집계도 가장 긴 8개 틱만 보존하므로 모든 틱의 메서드 시계열을 저장하는 기능은 아니다. 추적 활성 시에만 고정 배열을 할당하고 호출당 객체 할당이나 Reflection을 추가하지 않는다. 추적 schema가 다른 캡처는 비교·반복 집계·엔진 비교에서 조건을 분리한다.

약식 실게임 검증은 New LOW 60명/5분대, sapper-wall, fixture v16, 준비 120틱/요청 수집 120틱, pawn-spikes, 기준 0.1ms로 **1회** 실행했다. 실제 수집은 122틱이며 등록 116개, complete=true, dropped=0, 계측 메서드 예외=0, 감사 complete=true/환경 통제 확인이다. 게임 및 CLI 빌드 경고/오류 0개. 초기 로딩 로그의 기존 누락 텍스처 경고는 원본에 보존했다.

보존된 8개 틱 모두 `methodsComplete=true`였다. 최대 2,543개 호출이 발생한 틱에서도 상세 기록 512개를 제외한 2,031개가 합계에 포함됐다. 모든 보존 틱에서 `합계 호출 수 = callsSeen + callsFiltered`, `선택 하위 제외 시간 합계 = 루트 경과 시간`을 확인했다. 150틱은 전체 72종 메서드를 집계했으나 상세 기록에는 56종만 남았다. 빠진 16종에는 TacticalCommands.Advance, MapComponentTick 및 GameComponentTick 호출이 포함됐다.

이 실행에서 150틱 전체 경과 시간은 23.9857ms, NeedsTrackerTickInterval은 6회/19.7334ms/최대 19.7295ms였다. Core 고정 배치 중앙값은 0.28235ms다. 욕구 트래커 범위의 긴 호출을 보여주는 예시이며 특정 Need 내부 원인이나 상시 병목, 전술 AI의 전체 CPU 개선을 확정하지 않는다. OS 루트 CPU는 시간 해상도가 거칠어 31.25ms로 기록됐다.

단위 검증은 상세 한도를 넘은 후반의 긴 호출·예외 보존, 폰 필터와 무관한 합계, 중첩 중복 제외, 다음 틱 초기화, 틱 밖 호출 제외, 깊이 한도 시 불완전 표시, JSON 왕복을 통과했다. 실제 캡처의 CLI 조회·메서드 이름/Core 기준 연결·schema 비교 거부도 통과했다. [사용법](../../Source/Tools/AgentProfiler/README.md#상세-기록이-잘려도-남는-느린-틱-집계-schema-7)과 [원본·검증 요약](../../Source/Benchmarks/AgentProfiler/Results/2026-10-08-tick-method-totals)을 보존했다. 이번 검증은 도구 검증이며 임무 완료나 바닐라 대비 CPU 2배 게이트 시험은 아니다.
