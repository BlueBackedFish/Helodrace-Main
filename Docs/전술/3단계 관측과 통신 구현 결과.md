# 3단계 관측과 통신 구현 결과

상태: 구현과 자동 검증 완료. 실제 게임 플레이 검증은 아래 항목을 별도로 확인해야 한다. 4단계 협력 합의와 5단계 다중 진입 배분은 아직 실행하지 않았다.

## 정보 소유권

일반 병사가 관측한 적과 가까운 문·개구부 정보는 해당 병사의 개인 기억/보고에 먼저 저장한다. LOW의 고립된 병사에게 적이 보였다는 이유로 다른 병사나 분대의 기억을 바로 갱신하지 않는다.

분대장의 직접 관측과 현재 CQB 임무에서 명시적으로 지정한 개구부 관측자의 활성 관측은 기존 단계의 직접 입력으로 유지한다. 개구부 관측 임무가 종료된 이후에는 그 병사를 영구적인 직접 공유 관측자로 취급하지 않는다. 다른 병사의 정보는 실제 연락 경로와 보고 대기를 거쳐 분대 지식이 된다.

분대 사이 공유도 송신·수신 조건을 통과한 보고로만 이루어진다. 같은 팩션·조직·방이라는 사실만으로 적 기억이나 현재 문 상태를 합치지 않는다. 다른 조직의 같은 팩션 또는 동맹 세력 단위와도 실제 연락 조건을 충족하면 보고할 수 있다.

## LOW 구두 보고

- 기본 연락 거리는 8칸이다. 직접 시야가 연결되어야 하며, 벽이나 짙은 연막으로 서로 확인할 수 없으면 구두 보고를 시작하지 않는다.
- 보고 시간은 한 연결당 40틱이다. 분대 안에서는 가까운 인원을 통한 전달 경로를 작은 인원 그래프로 계산하며, 중간 전달 인원도 실제 접촉이 필요하다.
- 다른 분대의 일반 병사가 먼저 받은 정보는 그 병사의 개인 보고함에 들어간다. 자기 분대장에게 다시 전달할 수 있을 때 별도의 대기를 거쳐 분대 지식에 들어간다.
- 지휘자가 없거나 보고 경로가 끊기면 새 보고의 분대 전달이 보류된다. 기존 지휘 승계로 새 지휘자가 생겼을 때 현재 연락 조건을 다시 확인한다.

보고를 위해 이동을 강제로 정지시키지는 않는다. 전달 중 연락이 끊기거나 전달 경로가 더 느린 경로로 바뀌면 아직 전달하지 못한 보고가 중단된다. 무전을 잃은 뒤 구두 경로가 남아 있다는 이유로 무전의 짧은 전달 기한을 그대로 쓰지 않는다. 실내 아군 조우 시 움직임을 잠시 멈추는 식별 행동은 통합 계획의 5단계에서 다룬다.

## High 무전

High 교리에 전술 무전 사용을 명시했고, 기존 군용 태블릿에 실제 무전 컴포넌트를 추가했다. 태블릿은 소지품 또는 장착 장비에서 확인한다. 분대장 1명과 화력조장 3명에게 지급하므로 13인 분대는 4대를 휴대한다. 43인 소대는 본부 지휘자 1대와 분대 3개에 12대, 총 13대다. 기존 총·유탄·수류탄·슬레지 해머 지급은 유지한다.

무전에는 가용한 운용자, 실제 소지 장비, 정상 장비 상태, 같은 통신망과 장비 사거리가 필요하다. 기본 통신망은 `ModernInfantry`, 사거리는 300칸이며 연결 자체에는 LOS를 요구하지 않는다. 군용 태블릿을 장착했을 때의 기존 스위치블레이드 운용 권한은 그대로다.

기본 무전 보고는 20틱, 수신 확인은 별도 20틱이다. 송수신 시점마다 현재 장비·운용자·소속·연락을 재검사한다. 장비 상실, 다운/사망, 통신 장애로 전달이 끊기면 중단한다. 이미 수신한 이후 확인 응답만 실패한 경우에는 받은 정보를 지우지 않는다. 무전이 끊겨도 가까이서 가능한 구두 보고는 사용할 수 있다. LOW는 지원용 무전 장비를 소지했다는 이유만으로 이 High 전술 무전망을 사용하지 않는다.

## 공통 기억과 보고 병합

보고에는 다음 정보가 들어간다.

| 항목 | 내용 |
|---|---|
| 식별 | 원 보고 ID, 수정 세대, 접촉/통로/방 확인 종류 |
| 출처 | 원 관측 단위와 관측자 ID |
| 시간 | 원 관측 시각, 현재 수신 시각 |
| 공간 | 좌표, 방 번호, 정적 구조 버전 |
| 전달 | 전달한 단위들의 경로, 현재 송신·수신자와 확인 응답 상태 |
| 접촉 | 적 ID·이름, 마지막 위치, 실제 관측한 방향·개구부, 무장·사거리 |
| 통로 | 관측한 구조 ID, 통행 가능 상태와 개구부 여부 |

직접 관측과 받은 보고를 구분한다. 수신 보고는 `Visible`로 만들지 않고 적 폰의 실시간 위치를 참조하지 않는다. 전달 정보만으로 정확한 수류탄 표적을 승인하지 않으며, 실제 사격·이동의 기존 물리 검사도 유지한다. CQB와 기존 야전 대응은 공통 접촉 기억을 사용하고, 실제로 보이는 적을 사용할 때 현재 LOS를 다시 확인한다. 무장하지 않은 적과 자기 사거리 밖의 적도 관측할 수 있다.

최신 원 관측이 우선이며 같은 시각이면 직접 관측이 우선한다. 같은 보고/세대는 다시 받아도 수신 시각이나 기억 수명이 갱신되지 않는다. 재전달 경로에 이미 들어간 단위로는 되돌려 보내지 않고 최대 8단위까지 전달한다. 보고와 적 접촉의 전달 가능 수명은 원 관측 후 1,200틱이다. 지휘자/관측자 교체나 끊긴 시야를 이어서 적의 이동 경로를 추정하지 않는다.

방 번호는 정적 버전이 다르면 좌표로 수신 측 방에 대응시킨다. 통로 보고는 수신 측의 마지막 관측 지식에 병합하지만, 새 보고를 받았다는 이유로 현재 진입점이나 목표를 자동 교체하지 않는다. 방 확인 보고는 해당 단위가 확인한 시각과 위치를 보관하고 보안 우려 판단에 사용할 수 있다. 다른 분대의 보고만으로 수신 분대의 `ClearedRoomCells`에 자기 완료 기록을 추가하지 않는다. 담당 구역/클리어 보고를 협력에 적용하는 부분은 4~5단계에서 이어 간다.

## 저장과 개발자 표시

단위 실행 상태에 개인 기억, 분대가 아는 보고, 수신/확인 기록을 저장한다. 맵에는 전달 중인 보고와 원래 전달/확인 기한을 저장한다. 관측한 문·개구부 지식도 저장하고 로드 후 조회 사전을 복구한다. 직접 가시 상태와 연락망은 로드 후 다시 확인하며 원 관측 시각을 로드 시각으로 변경하지 않는다.

기존 전술 개발자 창에 지휘 연락 인원, 무전 운용자, 장애 여부, 개인 기억 개수, 전달 대기/확인 응답, 최근 보고의 출처·원 시각·수신 시각·경로를 추가했다. 기존 적 기억 오버레이는 전달 접촉을 청록색 `REPORT`, 직접 관측을 `DIRECT`로 구분한다. 개발자 화면의 전역 비교 정보는 AI 입력으로 되돌리지 않는다.

## 처리 한도와 자동 검증

접촉 스캔은 단위별 시작 시점을 분산하고 20틱 간격으로 수행한다. CQB는 기존 24칸, 야외 관측은 교리의 기본 90칸을 사용한다. 거리 필터 뒤 가까운 후보 최대 32명을 순회하며 한 번의 적/통로 관측 LOS 예산은 기본 96회다. 야외의 별도 접근 판단·호형 대형·모드 전환은 6~7단계 대상이다.

통신은 20틱 간격으로 단위 쌍 최대 8개, 처리 중 보고 최대 16개, 신규 전송 최대 16개를 다룬다. 맵 전체 대기열은 최대 128개, 단위/개인 보고함은 64개, 기존 접촉 기억은 16개다. 전달/확인 전체가 600틱을 넘기면 중단한다. 아주 많은 단위가 동시에 있을 때의 연락 발견 지연과 큐 포화는 8단계 성능 검증 대상이다.

검증 결과:

- 전체 빌드: 경고·오류 0.
- 보고 병합/격리/재전달/수명과 실제 Scribe 값 로딩: 20개 검사.
- 실제 통신 처리 코드의 지연·수신·확인·장비 상실·병사→지휘자 재전달·경로 지연 증가·장애 및 거리·벽·연막 구두 연락: 17개 검사.
- 통신 정책/지연/연락 그래프/무전 조건/스캔 분산: 19개 검사.
- 기존 CQB 지형 지식 검사에 보고 충돌·직접 재관측·저장된 셀 조회 복구 검사 5개 추가.
- 기존 전술 기하·계획·게임 API 바인딩·분대/장비 편제 및 XML 검증 실행.

독립 테스트에서는 Unity의 체력·몸 내밀기 생성·모드 로더 전체를 실행하지 않는다. 실제 송수신 처리 테스트는 가용 인원/장비 프레임을 제공하고 큐의 실코드를 실행했다. 저장된 셀 검사는 실제 Scribe 필드 로딩과 조회 복구를 검사하며, 전체 게임 저장/로드를 완료했다고 주장하지 않는다.

## 플레이 확인 항목

1. LOW 두 분대를 떨어뜨린 뒤 한쪽만 적을 보게 한다. 미접촉 분대에는 적 기억/현재 문 개폐가 생기지 않아야 한다.
2. 가까이 접근하되 벽으로 가린 경우와 직접 서로 보이는 경우를 비교한다. 보이는 경우 보고 지연 후 공유되어야 한다.
3. 고립된 일반 병사가 적/문을 관측하고 나중에 자기 분대와 접촉하게 한다. 접촉 전에는 개인 기억만, 전달 후에는 분대 보고가 보여야 한다.
4. High 두 분대를 시야가 막힌 상태로 떨어뜨린다. 호환 태블릿이 있을 때 보고/확인이 이루어지고 운용자 다운·장비 제거·태양 플레어 때 새 전달이 중단되어야 한다.
5. 다른 분대 병사에게 먼저 들어간 보고가 그 분대장에게 바로 나타나지 않고 추가 전달 후 나타나는지 확인한다.
6. A→B→C 보고에서 원 관측 시각이 유지되고 A로 순환하지 않는지, 보고만 받은 적에게 수류탄을 자동 승인하지 않는지 확인한다.
7. 열린 문과 현재 진입점, 방 확인 상태를 포함해 전달/확인 중 저장·로드한다. 숨은 문을 새로 읽거나 기억 나이를 초기화하지 않아야 한다.
8. 기존 개구부 관측→후퇴→투척→폭발 대기→진입, 스택업 타일 중복 방지, 외벽 경비 인원의 지정 개구부 합류를 회귀 확인한다.
