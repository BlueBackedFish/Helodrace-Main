# 2단계 수정 방향: 지향점과 은엄폐 접근

2026-10-04. 사용자 플레이 결과와 추가 목적 설명을 반영한 수정 기준이다. 이 문서는 수정 방향을 기록하며, 아래 방식으로 실행 코드를 교체한 상태는 아니다. 기존 2단계 기록의 구현 설명보다 이 문서의 수정 방향을 우선한다.

## 이동 노드를 추가한 목적

주목적은 고정기총과 저격에 대응할 수 있는 돌파점 접근이다. 외부에서 돌아 접근축을 바꾸고, 벽 등 은엄폐물을 끼고 접근한 뒤 선택한 벽/문을 돌파한다. 연막은 유효한 차폐 접근을 보조하거나 피할 수 없는 노출 구간을 건너기 위한 수단이다.

돌파점 선정의 직선 돌파 선호와 접근 이동은 구분한다. 돌파점까지 최단 직선을 무조건 걸어가는 것이 아니라, 외부의 적절한 접근 위치를 먼저 잡은 뒤 마지막 돌파 구간을 직접 연결한다. 열린 입구나 다른 방을 이용해 위험한 통로로 들어가는 방식으로 우회하지 않는다.

노드는 분대를 주기적으로 멈춰 세우는 자리나 개인별 대형 칸이 아니라, 접근 방향을 바꾸거나 차폐 구간으로 들어가기 위한 분대 공통 지향점이다.

## 테스트에서 확인한 문제와 코드 근거

| 항목 | 사용자 결과 | 코드에서 확인되는 구조 |
|---|---|---|
| 중간 정지 | 노드마다 잠시 멈춰 뚝뚝 끊기는 이동 | 먼저 도착한 인원에게 HoldPosition을 발행하고, 도착 조건 충족 후 다음 갱신에서 새 노드를 처리함 |
| 좁은 방 | 스택 접근 노드가 많이 생겨 거의 진행하지 못함 | 문/방 경계·차폐 경계·통행 불가한 직선 연결을 각각 노드로 남기며, 개별 도착 판정과 빈 자리 확보를 요구함 |
| 후미 | 크게 돌아오는 경우 있음 | 개별 과거 노드와 고정 목적지에 대한 바닐라 경로를 따름. 도달 가능 여부와 선택 연결을 따르는 실제 경로는 별개임 |
| 빈 도착 영역 | 노드 주변에 설 공간이 없으면 진행하지 않음 | 중심이 Standable이 아니면 도착 영역이 비고 Capacity=0으로 진행이 막힘 |
| 외벽 접근 | 정상 | 선택 외벽/개구부 제약을 유지해야 함 |
| 수류탄 회피 | 정상 | 긴급 회피와 폭발 안전 진행을 유지해야 함 |

개별 지연의 직접 원인은 실제 작업/경로 로그로 추가 구분해야 한다. 위 표의 코드 구조는 확인했지만 모든 플레이 지연이 같은 원인이라고 확정하지 않는다. 사상자·저장/로드·성능 항목은 아직 사용자 결과가 기록되지 않았다.

## 수정할 실행 방식

1. 분대는 공통 지향점과 현재 통과 구역을 갖는다. 폰에게는 그 방향으로 진행하는 이동 의도를 준다. 바닐라 이동 실행에 필요한 개별 목적지는 분산하지만, 모든 중간 지점에 고정 개인 자리와 도착 대기를 만들지 않는다.
2. 지향점을 통과하기 전에 다음 유효 지향점을 이어 준다. 일반 이동에서는 Wait/Hold를 끼워 넣지 않는다. 실제 대기는 최종 스택업, 교전 준비, 폭발 안전 등 명시적인 사유가 있을 때만 한다.
3. 넓은 진행 구역 안의 작은 장애물 우회는 허용한다. 큰 이탈이 일정 시간 지속될 때만 앞쪽의 유효 지향점으로 보정한다. 현재 벽의 반대쪽이나 이미 지나온 경로 선으로 복귀시키지 않는다.
4. 후미는 선두와의 단순 직선거리나 개인 과거 노드 목록 때문에 돌아가지 않는다. 현재 연결을 따라 도달 가능한 앞쪽 합류 위치를 사용하고, 필수 문/개구부 통과만 순서대로 확인한다.
5. 중간 지향점 주변에 정지 가능한 자리가 부족해도 통과 가능한 연결이면 계속 이동한다. 통행 불가와 집결 공간 부족을 분리한다.
6. 개구부 앞→개구부→너머 공간을 하나의 필수 통과 연결로 취급한다. 개구부 자체를 통로의 일부로 사용하되 문 타일에 대기 자리나 집결 조건을 만들지 않는다.
7. 작은 방 안에서는 연결된 통행 공간을 하나의 통과 구역으로 묶는다. 문/코너마다 도착 노드를 중첩하지 않는다. 출구나 다음 실제 방향 전환이 필요한 지점만 남기고, 다른 문으로 새는 이동은 제한한다.
8. 개인별 정확한 자리·대형 유지·경계 방향은 최종 스택업부터 적용한다. 이동 중 집결 방식과 스택업 대형을 분리한다.

## 지향점과 진행 구역 선택

- 외부 접근에서는 지형 구조와 기존 벽/건물의 차폐 관계로 외곽 우회, 벽을 끼고 접근할 위치, 마지막 돌파 접근 위치를 만든다. 일정 거리마다 이동 칸을 생성하는 방식은 보조적인 연결 길이 제한으로만 사용한다.
- 같은 쪽 벽을 따라 연속으로 진행할 수 있으면 여러 지점을 하나의 접근 구간으로 묶는다. 코너를 돌아 차폐 방향이 바뀌거나 노출 구간을 건너야 할 때 지향점을 바꾼다.
- 엄폐물 근처라는 이유만으로 안전하다고 판단하지 않는다. 관측한 사격 위치/방향과 해당 엄폐물의 가림 관계를 확인한다. 폰은 지나갈 수 있으나 총탄을 충분히 막지 못하는 대상은 은폐와 엄폐를 구분한다.
- 실내는 외곽 우회 기준으로 평가하지 않는다. 현재 방의 통과 연결과 선택한 출구를 중심으로 단순화한다.
- 선택 문/개구부와 방 연결 제약은 유지한다. 실제 길찾기·사격·예약·회피는 바닐라 및 기존 안전 검사에 맡긴다.

적 기총/저격 위치는 직접 관측이나 유효한 보고, 기존의 피격 반응에서 얻은 정보만 사용한다. 숨은 적의 위치를 전역으로 읽거나 제거한 킬존·전략적 중요도 맵을 복원하지 않는다. 적 정보를 못 얻은 초기 접근은 정적 은엄폐 후보를 이용할 수 있지만 특정 사격선에 안전하다는 보장은 하지 않는다.

2단계에서는 연속 이동, 지향점/통과 구역, 차폐 접근 후보와 이탈 보정 기반을 수정한다. 야전 전용 조기 감지·고정기총/저격 대응 상태·화력조 엄호/기동·통신과 협력은 기존 후속 단계와 연결한다. 이 문서 작성으로 후속 단계 전체를 구현했다고 보지 않는다.

## 수정 후 검증 기준

- 장애물 없는 이동에서 중간 지점마다 정지 작업이 발생하지 않는다.
- 작은 방이나 한 칸 폭 통로에 다수의 집결 노드가 생기지 않으며, 입구를 통과한 인원이 후미를 막고 기다리지 않는다.
- 지향점 중심이 막혔거나 정지 공간이 부족해도 유효한 통과 연결이 있으면 진행한다.
- 후미는 이전 개인 노드로 왕복하지 않고 선택한 통로/개구부를 통해 앞쪽으로 합류한다.
- 작은 우회에는 반응하지 않고 큰 이탈에만 보정하며, 보정이 벽에 붙어 비비는 동작을 만들지 않는다.
- 관측한 고정기총/저격 방향에서는 실제 가림 관계가 있는 외곽·벽 쪽 접근을 우선하고, 연막만으로 위험한 직선 이동을 정당화하지 않는다.
- 기존 외벽 돌파점 선택, 스택 대형, 수류탄 회피·폭발 대기, 완료 방 상태와 저장된 목표를 보존한다.
- 개발자 표시에는 공통 지향점, 진행 구역, 필수 개구부, 보정 이유와 관측한 위협 방향을 구분해 표시한다.
