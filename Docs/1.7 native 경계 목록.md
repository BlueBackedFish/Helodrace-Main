# 1.7 native 경계 목록

작업 중인 심볼 목록이다. 수학·기하와 내부 렌더 데이터의 전환은 아직 남아 있으며 이 목록만으로 3단계 완료를 선언하지 않는다.

## 시간·런타임

| 사용처/심볼 | 현재 경계와 근거 |
|---|---|
| UI 갱신·거절 알림·아이콘 안정화·스탯 easing·전신 창 애니메이션의 실시간 값 | `Waylith.Time.RealtimeSinceStartupAsDouble`. 마감 시각·시작 시각도 double로 바꿔 같은 시계에서 차이를 계산한다. |
| 조직/전술 오버레이·아이콘 작업 제한·프로파일러 프레임 | `Waylith.Time.FrameCount`. native 호스트 프레임 기준이다. |
| GenTicks·Verse.Rand | 게임 시뮬레이션/저장/결정성 계약이므로 유지한다. 벽시계로 게임 논리를 실행하지 않는다. |
| 자체 CLI 감사/검사 종료 | `Waylith.EngineApplication.Instance.Quit`. 해당 검사가 결과/저장을 기록한 뒤 호스트 종료를 요청한다. native Dispose의 OnShutdown 및 App.ShuttingDown 수명을 따른다. |
| TacticalAuditNativeErrors | `Waylith.Logging.LogStream.MessageReceived`, 실제 `LogLevel.Error/Critical`. 기존 main-thread 기록 범위와 재귀 방지를 유지한다. 게임 제공 logging abstractions DLL만 참조하며 동봉하지 않는다. |
| TacticalAuditBootstrap의 `Application.runInBackground` | 1.7 native `WaylithAppState`/`EngineApplicationOptions`에는 대응 setter가 없다. 숨긴 감사의 기존 게임 호환 상태와 Prefs를 함께 설정하는 단일 경계로 남긴다. `Waylith.UnityCompat`의 같은 상태를 호출하는 것만으로 native 전환으로 세지 않는다. |
| 저장 경로 `GenFilePaths.SaveDataFolderPath` | `-savedatafolder`의 게임 계약을 따른다. native PersistentDataPath는 사용자 LocalLow이고 CacheDataPath는 시험 Profile이었다. 저장 위치를 PersistentDataPath로 바꾸면 격리가 깨지므로 교체하지 않는다. |
| 엔진 data/log/cache/temp 경로 | `WaylithRuntime.Current.App`의 실제 값을 사용한다. 현재 제품에 직접 Unity Application 경로 호출은 없다. 실제 호스트 값은 `native-runtime17b/Evidence/runtime.json`에 기록했다. |

Unity 호환 시간은 UnityTimeState 생성 시점의 Stopwatch를, native 시간은 Waylith.Time의 정적 시작 시점을 사용한다. 호환 프레임은 BeginFrame, native 프레임은 EndFrame에서 증가한다. 절대 시간·프레임 번호를 섞지 않는다. 실제 검사에서는 8프레임 동안 두 프레임 카운터가 모두 8 증가했고 경과 시간은 각각 약 0.411초였다.

검사 코드의 Unity 시간/경로 사용은 native와 게임 경계를 비교하는 fixture에 한정한다. Blancas의 1.6 fixture 종료는 보존한 1.6 엔진 API를 사용한다.

## 스칼라 수학

`Source/NativeMathAliases.cs`는 제품의 스칼라 `Mathf`를 `Waylith.Math.Mathf`로 직접 바인딩한다. 제품 DLL에는 UnityEngine.Mathf TypeRef가 없다. 명시적으로 작성돼 있던 UnityEngine.Mathf 호출도 native로 바꿨다. 스칼라는 float/int 데이터이므로 이 변경은 벡터·행렬·렌더 데이터의 타입 전환과 구분한다.

native에 없는 각도 보간/이동은 `Core/AngleMath.cs`의 두 수학 연산으로 정의했다. native DeltaAngle·Clamp01·MoveTowards를 사용하며 호출자가 소유하는 각도 정규화 시점을 유지한다. 정수 3~4항 Min은 중첩 BCL Min을 써 float 배열 오버로드로 수량을 변환하지 않는다.

제품 소스를 직접 링크하는 독립 테스트 중 native 스칼라를 쓰는 여섯 프로젝트만 `HelodUsesNativeMath`로 Waylith와 동일 alias를 참조한다. 게임 객체 어셈블리는 추가하지 않는다. 실제 엔진 경계 비교 fixture에서는 UnityEngine.Mathf를 명시적으로 사용한다.

## 미리보기 카메라·드래그

`ModularWeaponPreviewCamera`의 위치·이동량은 `System.Numerics.Vector2`, 내용/뷰포트 경계는 `Waylith.Math.Rect`다. `ModularWeaponPreviewDrag`도 native 벡터만 보관하고 반환한다. 확대 시 커서 고정, 화면 픽셀 이동량, 4픽셀 드래그 임계값을 유지한다.

Verse UI의 Event/Widgets 및 기존 미리보기 렌더러와 연결하는 지점은 `Core/GameGeometry.cs`의 명시적 값 변환을 사용한다. 드래그 결과를 카메라에 넘길 때는 native 값을 그대로 전달한다. 이 단계에서는 나머지 미리보기/월드 렌더 데이터의 전환이 끝나지 않았다.

독립 탐색·카메라·입력 검사가 통과했다. 실제 NoWindow 1.7 `native-preview17`에서 벡터/사각형의 13,284개 컴포넌트 비교가 통과했고, 음수 크기와 signed zero도 보존됐다. 실제 DLL의 카메라/드래그 내부 시그니처가 native 타입인지 확인했다. 마우스를 직접 조작한 외형 검증과는 구분한다.

## 모듈 무기의 부품 기하·2D 렌더 데이터

`ModularTransform2D.cs`의 위치·스케일·변환점·역변환·부품 연결 및 world yaw 계산은 System.Numerics 타입만 사용한다. XML의 `ModularAttachmentTransform`은 게임 파서가 읽는 authoring 경계로 유지하고, snapshot 생성 때 immutable native `ModularAttachmentPose`로 복사한다. 현재 변환점 API는 y를 사용하지 않고 x/z 평면을 사용한다.

`ModularRenderNode`의 transform·레일 양끝·점유 구간·graphic 중심/스케일, 조준기 간섭 판정의 축/구간, 아이콘 합성 레이어의 중심/크기와 픽셀 위치 계산도 native 벡터다. UI의 `WorldToGui`는 native 점을 계산한 뒤 Verse Widgets가 요구하는 게임 벡터를 반환한다. 여러 부품의 드래그는 입력 변환을 반복문 밖에서 한 번 실행한다.

이 타입들은 XML/Scribe에 직접 저장하지 않는 파생 상태다. Def와 현재 설정의 직렬화 형식은 게임 타입 계약을 유지한다. 해당 native 벡터를 근사 equality에 의존하는 key/비교로 사용하지 않으며, 스케일의 0.0001 안전 기준 및 좌표 비교 허용 오차는 명시적 수학 판정으로 유지한다. 다른 계산의 벡터 equality는 후속 감사 대상이다.

`native-attachment17` 실제 NoWindow 검사에서 25,272개 성분이 `98fdf004`의 고정 계산과 맞았다. 중첩 부품, 음수/비균일/0에 가까운 스케일, palette 비율, graph 회전과 world yaw를 포함한다. 기존 무기 수치·조준기·배치 편집 7,190개 검사도 통과했다. `native-attachment-state17`은 새 장비·방어구·석유·탄약 상태를 저장/재로드하는 44개 검사를 통과했다. 3D TRS/그리기 행렬과 그 밖의 기능군 기하는 아직 전환 대상이다.

## 무기 렌더러의 3D 계산·행렬 경계

`ModularWeaponAssemblyRenderer`의 내부 위치·애니메이션 이동·급탄 이동과 TRS 행렬은 System.Numerics 타입이다. DrawAt/Harmony 인자와 public 진입점은 게임 Vector3를 받고 private 계산 진입 때 한 번 변환한다. recoil/aim pose의 게임 계약은 별도 경계로 남아 있다.

`SpatialMath.CreateTransform`은 BCL row-vector 규약으로 scale → rotation → translation을 계산한다. 실제 게임의 quaternion 정규화 및 0에 가까운 quaternion의 identity 처리를 유지한다. 실제 UnityStubs의 Matrix4x4.ToNumerics는 원래 column 행렬 성분을 그대로 반환하므로 BCL 점 변환에 직접 사용하지 않는다. `GameGeometry.ToGame(Matrix4x4)`는 검사한 row→column 성분 대응으로 연결한다.

현재 그리기/section printer는 후속 4~5단계의 게임 리소스·제출 경계이므로 native 계산 결과를 그 호출 직전에 변환한다. native renderer의 행렬 규약은 해당 제출 API 전환 때 다시 확인한다. `native-matrices17` 실제 NoWindow 검사의 3,200개 행렬·점·방향 성분은 게임 TRS와 일치했다. 3축 회전, 비정규/0 quaternion, 음수·비균일·0 스케일, 부모/자식 곱 순서, homogeneous 벡터를 포함한다. 이는 수치/실행 검증이며 프레임 이미지 비교 완료는 아니다.
