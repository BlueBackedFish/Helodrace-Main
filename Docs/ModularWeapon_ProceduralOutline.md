# `_Outline` 파일 없이 총기 외곽선 생성 가능성

가능하다. 원본 텍스처의 알파를 바깥으로 확장하고 원본 알파를 빼면 외곽선 마스크가 된다. 이 검토에서는 원본 파일을 수정하지 않고 M203A2, PointSight T2, P320 가늠쇠로 생성 결과를 확인했다.

## 현재 코드와 연결 지점

- `Dialog_ModularWeaponPreview.DrawPreviewAssembly`: 현재 별도 `_Outline` 텍스처를 먼저 그리고 본체를 그린다. 이 외곽선 패스의 입력을 생성·캐시한 텍스처로 바꿀 수 있다. 선택 파츠를 앞에 그리는 순서는 그대로 사용할 수 있다.
- `ModularWeaponPartImage.Draw`: `_Outline`이 없는 레이어는 이미 원본을 검은 실루엣으로 여러 방향에 조금씩 옮겨 그린다. 별도 이미지 없이 윤곽을 만드는 UI 경로가 존재한다.
- `ModularWeaponTextureData`: 원본 알파를 작은 마스크로 읽는 캐시가 있다. 클릭 판정용 256px 마스크는 확대 윤곽 품질이 충분한지 별도로 판단해야 한다.
- `ModularWeaponRendering.OutlineMaterial`: 게임 내 월드 렌더링은 여전히 별도 `_Outline` 파일을 사용한다. 이번 검토는 이 경로를 전환하거나 기존 텍스처를 삭제하지 않는다.

## 실험 결과

`Source/Verify-ProceduralWeaponOutline.ps1`은 알파 확장으로 외곽선 PNG와 비교 이미지를 만든다. 원본은 읽기만 하며 출력은 기본적으로 무시되는 `.codex-staging/weapon-outline`에 저장한다.

| 원본 | 원본 크기 | 확장 반경 | CPU 생성 시간 예시 |
| --- | --- | --- | --- |
| M203A2 | 1024×1024 | 4px | 38.50ms |
| PointSight T2 | 512×512 | 2px | 4.70ms |
| P320 가늠쇠 | 512×512 | 2px | 4.62ms |

이 값은 정적 PNG에 대한 알고리즘 실행 시간이며 Unity 프레임 시간은 아니다. 원본 읽기, 결과 저장과 비교 이미지 생성 시간은 표에서 제외했다. 원본의 불투명 픽셀 색상·위치 보존, 캔버스 가장자리 바깥으로의 확장, 큰 내부 구멍 보존도 검증한다.

생성 결과는 기존 파일의 두꺼운 장식 테두리를 복제하지 않는다. 실제 본체의 모양을 따라 얇은 윤곽을 만들므로 두께를 명시해서 조절할 수 있다. 추가 그래픽은 같은 정렬 기준으로 합성해야 하며, 외곽선이 캔버스 밖으로 잘리지 않도록 여백과 그에 따른 그리기 크기를 함께 보정해야 한다.

## 적용 방향

1. **파츠별 외곽선**: 원본과 두께를 키로 삼아 최초 사용 시 생성하고 캐시한다. 매 프레임 CPU 생성은 피한다. 생성한 Unity 텍스처는 캐시 퇴출·창 종료 시 정리할 수 있게 소유권을 정해야 한다.
2. **완성 총기의 바깥 윤곽만 표시**: 모든 파츠를 합친 알파에서 외곽선을 만들어야 파츠가 겹치는 안쪽 경계까지 검게 그리는 것을 피할 수 있다. 애니메이션 중인 조립체의 알파가 계속 달라지는 경우에는 GPU 마스크 확장 방식이 별도로 필요하다.

이번 변경에서 실제 모딩 창은 원본 `_Outline` 렌더링을 유지한다. 별도 파일 없는 생성 방식은 실행 가능한 검증 도구와 비교 결과로 확인했다.

재현:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Source/Verify-ProceduralWeaponOutline.ps1
```
