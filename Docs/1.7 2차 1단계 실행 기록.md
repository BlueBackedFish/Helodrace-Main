# 1.7 2차 1단계 실행 기록

대상: [2차 수정 계획](헤로드%202차%201.7%20수정%20계획.md)의 T2-01·07·02·03·16. 엔진: RimWorld 1.7.4995 rev309 / Harmony 3.

2026-11-03: 1단계 5개 항목의 구현·빌드·정적 회귀 검사·실게임 종합 검증을 완료했다.

구현 커밋: 무동력 작업 판정 `e71d5baf`, 의류 작업 배정 `a3546318`, 정련 진행 보존 `07a468b4`, 산업 설비 보충 `51814cf4`.

## 작업대 수정

- 기계 작업대의 사용 가능 조건을 `Building_WorkTable.UsableForBillsAfterFueling`에 연결했다. 이 판정은 작업 생성과 진행 중인 바닐라 `DoBill` 양쪽에서 사용된다.
- 작업 생성 시 무동력인 경우에는 정상적인 작업 불가 사유를 반환한다. 기존 `MakeNewToils` 추가 실패 조건은 바닐라의 공통 판정으로 통합했다.
- 의류작업대에 빠져 있던 재봉 작업의 `WorkGiverDef`와 한국어 작업 문구를 추가했다. 의류 조합법 연결과 작업 배정을 모두 검사하도록 기존 검증 스크립트도 보완했다.
- 제품·테스트 코드에 Unity API 의존성을 추가하지 않았다. 테스트 호스트 종료는 Waylith API를 사용한다.

검증:

- 초기 실게임 기록: `.codex-staging/ProductionStage1/baseline/Evidence/checks.txt`. 무동력 상태에서도 `UsableForBillsAfterFueling=True`, 의류작업대 작업 배정자는 없음.
- 수정 후 실제 Job 검증: `.codex-staging/ProductionStage1/worktable-jobs-7/Evidence/checks.txt`. 동력원·샤프트 연결, 작업 중 연결 제거, 연결 복구 후 단일 제품 완성, 의류 제작, 방탄판 교체, 장비 개조가 모두 통과하고 `COMPLETE`를 기록했다.
- 해당 게임 로그의 오류는 초기 기준에도 있던 미설치 WorkshopItem 경고성 오류뿐이며, 생산·예약·Job 복구 오류는 없었다. 종료 코드는 수집 시 핸들이 없어 `null`로 기록되었으므로 0으로 보고하지 않는다.
- `Source/Verify-ClothingWorkbench.ps1` 통과: 37개 조합법 연결 목록, 작업 배정, 편집 초안 격리, 취소, 물리 부품 보존, 일괄 적용과 작업 지시 복구.
- 최종 종합 검증에서는 실제 저장/불러오기 이후 기계 작업대와 의류작업대에서 새 제품을 제작하는 것까지 확인했다. 의류는 직접 명령과 일반 작업 AI의 자동 제작을 모두 확인했다.

## 정련·연료 수정

- 주철·탄소강의 소·중·대 조합법 6개가 바닐라 미완성품을 사용한다. 작업 중 연료 소진·수동 중단·저장/불러오기 때 재료, 작업자, Bill 연결과 진행량을 유지한다. 기존 탄소강 이미지를 재사용한다.
- 탄소강 조합법의 실행 작업대는 연료가 있는 고로로 한정했다. 전로는 연결 시설 역할을 유지한다.
- 산업 설비 6종은 연료 서비스 전용 작업과 예약 계층을 사용한다. 1.7의 건물 예약은 예약 계층 외에도 일반 상호작용 셀 소유자를 검사하므로, 서비스 예약은 건물의 기준 셀을 전용 계층으로 예약한다. 제작 위치와 연료 아이템의 일반 예약을 해제하거나 무시하지 않는다.
- 기존 일반 보충 작업과 빈 작업대에서 제안하는 보충 작업도 같은 서비스 경로로 맞춰 중복 보충을 막는다. 자동 보충 활성화 버튼을 노출해 플레이어의 설정이 바닐라 저장 규칙에 따라 유지되게 한다.
- 연료통과 일일 소비량은 유지한다. 보충 요청만 앞당기고, 운반 작업 안에서는 일반 보충보다 먼저 검사한다.

## 최종 검증

- 전체 검사: `.codex-staging/ProductionStage1/final-4/Evidence/checks.txt`의 `COMPLETE`, `FAIL` 없음. 실제 게임 로그에는 초기 기준에도 있던 미설치 WorkshopItem 오류만 있고, 새 생산·예약·Job·렌더 오류는 없다.
- 실제 저장: 같은 실행의 `Profile/Saves/ProductionStage1Roundtrip.rws`. 연료 소진으로 멈춘 배치를 저장한 뒤, 게임을 실제로 불러와 첫 시뮬레이션 틱 전에 재료 224개·진행량·작업자·Bill 연결·빈 연료통·자동 보충 꺼짐 상태를 확인했다.
- 보충 후 느린 대량 탄소강 정련이 165개를 완성했다. 보통 작업자도 165개를 추가해 중복·재료 소실 없이 330개가 됐으며, 미완성 배치가 남지 않았다. 별도 측정에서도 6종 × 2속도, 총 12개 배치가 모두 완성됐다.
- 작업 중 고로의 보충은 직접 명령과 일반 운반 AI 모두 통과했다. 제작 작업을 유지하면서 다른 폰이 보충했고, 추가 보충자는 같은 서비스 위치를 동시에 예약할 수 없었다.
- 연속 운전: 다른 주민의 운반 작업을 모두 끄고 보충자 한 명만 사용했다. 이 폰을 매일 정확히 8시간 맵에서 제외한 3일 동안, 매 틱 연료와 열펌프 동력을 검사해 소진·동력 정지가 없음을 확인했다. 각 동력원의 최저 연료는 소형 증기기관 3.10509, 대형 증기기관 31.82074, 디젤기관 30.76372였고 실제 보충은 각각 14·5·2회였다.
- 냉장 검증은 밀폐된 25칸 방과 기존 열펌프의 냉각 설정 40 W를 사용했다. 초기 냉각 이후 5°C 미만을 유지했다. 연료를 금지하거나 사용할 수 없을 때 보충 Job을 만들지 않는 것도 확인했다.
- `Source/Verify-RecipePlacement.ps1`, `Source/Verify-ClothingWorkbench.ps1`, 제품·검증 모듈 빌드가 통과했다. 제품 DLL에는 테스트용 GameComponent가 포함되지 않는다.
- 테스트 절차와 실행 옵션은 [검증 모듈 설명](../Source/Tests/ProductionStage1/README.md)에 있다. `launcher.json`에 해당 호스트와 DLL 해시를 기록했다. 최종 종료 수집 시 프로세스 핸들이 없어 종료 코드는 `null`이며, 이를 0으로 간주하지 않았다.
