# 통합 방어력·탄도 피해 시스템 설계

2026-11-08. 설계 문서이며 코드는 아직 없다. 대상은 헤로드 본체(인간형·공통 코어)와 Lobos Arsenal(기갑차량)이다. 이 시스템은 현재의 `ArmorUtility` 확률 방어, 방탄판 확정 방어 컷, `BradleyRules.Resolve` ERA 판정을 대체한다. 배포 전이므로 구형 저장·DefName 호환은 두지 않는다(AGENTS.md).

## 0. 근거 등급 표기

모든 계산 단계에 근거 등급을 붙인다. 등급이 다른 값을 한 공식 안에서 섞지 않고, 섞어야 하면 경계를 문서와 코드 주석에 남긴다.

| 표기 | 의미 | 예 |
|---|---|---|
| **[물리]** | 보존법칙·기하로 직접 계산 | LOS 두께, 운동에너지, 좌표 변환, 구면 착탄각 분포 |
| **[실험]** | 공개 시험자료에 맞춘 경험식. 계수는 출처의 값을 데이터로 입력하고 문서에 임의값을 적지 않는다 | Lanz–Odermatt, De Marre, THOR, Kingery–Bulmash, Gurney 상수, Cunniff 계수 |
| **[게임]** | 자료가 없거나 비공개라 밸런스로 정한 근사 | ERA 잔여 계수, 유폭 확률 곡선, 승무원 무력화 문턱, RimWorld 상처량 환산 |

[게임] 값은 "현실값"으로 표시하지 않는다. 툴팁에도 실측처럼 쓰지 않는다. 확립되지 않은 현상(예: 특정 복합장갑의 실제 구성, ERA 정량 효율, 탄약 반응 확률)은 공식을 단정하지 않고 [게임] 파라미터로 둔다.

## 1. 기존 구조와의 관계

| 파편화(방어구 통과 후 상처 예산) | `Core/BulletFragmentation.cs` | 탄체 파편화(§5.2)의 인간형 근사로 흡수. 예산 상한 규칙 유지 |
| 방향성 방패 | `ModernWar/DirectionalBallisticShield.cs` | 방패를 "들고 있는 장갑판"(§6.2)으로 동일 파이프라인에 등록 |
| Bradley ERA: 모듈 선택·`BradleyThreat`·잔여 계수 | Lobos `CompBradley.cs`, `BradleyRules.cs`, `BradleyEraEffects.cs` | 범용 반응장갑 모듈(§3.3)로 일반화. 위협 분류는 탄종 메커니즘(§4)에서 받음 |
| 개방부 판정(램프·해치) | `BradleyRules.RearAperture/RoofAperture` | 장갑 구역의 상태 플래그(개방 = 두께 0 셀)로 일반화 |

| VF 장갑: `VehicleStatHandler.ApplyDamage`, `VehicleComponent.ReduceDamageFromArmor` | Lobos `BradleyPatches.cs` | 차량 어댑터의 진입점. VF 구성품은 기능 손상 저장소로 재사용(§7.5) |

**CE 공존.** Combat Extended가 켜져 있으면 CE가 자체 탄도·장갑을 처리한다. 이 시스템은 CE 활성 시 전체를 비활성화하고(현재 탄도 표시를 숨기는 방식과 동일), 차량 부분만 Helodrace-CombatExtended에서 별도 어댑터로 연결할지 나중에 결정한다.

**API 규칙.** 계산 코어는 `System.Numerics`·`System.MathF`·Waylith 타입만 쓴다. Unity·Verse 타입은 어댑터 경계(Harmony 패치, Def 로드, Fleck 생성)에서만 변환한다. 현재 `BradleyRules`처럼 코어는 게임 의존성 없이 회귀 테스트 실행 파일에서 돈다.

의존 방향은 아래로만 흐른다. 모델은 대상 모델을 모르고, 대상 모델은 어댑터를 모른다. Lobos는 Main의 코어·파이프라인에 의존하고 Main은 Lobos를 모른다(현재 모드 의존 관계와 같다). 차량 전용 단계는 Lobos가 파이프라인에 단계로 등록한다.

### 2.2 핵심 데이터 구조

정적 데이터와 동적 상태를 분리한다. 정적 데이터는 Def에서 한 번 컴파일해 불변 객체로 캐시하고, 동적 상태는 Thing/Comp에 저장한다.

```text
// 착탄 사건 (불변, 단계 사이 전달)
ImpactEvent
  attacker: ThingRef, projectileDef, ammoProfile: ProjectileProfile(컴파일됨)
  seed: ulong                      // §9 결정론
  worldPoint: Vector3              // 3D (x, 높이 y, z)
  velocity: Vector3                // m/s, 3D. 2D 진행 + 고도 성분
  attitude: 탄체 축 벡터, yaw(편요각) // 일반탄은 velocity와 같다고 둠
  massKg, lengthM, diameterM       // 잔여 탄체 갱신에 따라 바뀜
  state: Intact | Deformed | Eroded | Fragmented | Jet | Detonated

// 장갑 단면 (한 착탄점에서 탄 경로를 따라 만나는 층들)
ArmorStack
  layers[]: { material: MaterialModel, thicknessM, normal: Vector3,
              gapToNextM, damageState: LayerDamageRef, role: Plate|Spaced|Reactive|Backing|Liner }
  owner: 피복 부위 / 장갑 구역 id

// 관통 상태 (단계마다 갱신)
PenetratorState
  kind: KE | Jet | Blast | Fragment | Shot
  residual: 질량, 속도, 길이(장봉), 제트 길이·끝단속도(성형작약)
  direction: Vector3

// 결과
ImpactOutcome
  result: Ricochet | Shatter | Stopped | PartialPenetration | Perforation | Overmatch
  residualPenetrator?: PenetratorState
  secondaries[]: SecondaryEvent { kind: Spall|ProjectileFrag|WarheadFrag|Blast|Trauma, ... }
  layerDamage[]: 층별 영구 손상
  trace: ImpactTrace
```

단계 사이에는 `PenetratorState`와 `ArmorStack`만 넘긴다. 단계가 RimWorld 객체를 직접 읽지 않게 해서 회귀 테스트와 재현이 가능하다.

## 3. 장갑 시스템

### 3.1 재료 정의: 물성과 경험 계수의 분리

`ArmorMaterialDef`는 두 블록을 따로 갖는다.

```xml
<Helodrace.Ballistics.ArmorMaterialDef>
  <defName>HD_Armor_RHA</defName>
  <family>Metal</family>                       <!-- Metal / Ceramic / Fiber / Polymer / Glass / Energetic -->
  <properties>                                  <!-- [물리] 측정 가능한 물성 -->
    <densityKgM3>7850</densityKgM3>
    <hardnessBHN>...</hardnessBHN>
    <yieldStrengthMPa>...</yieldStrengthMPa>
    <elongation>...</elongation>                <!-- 연성 지표 -->
    <soundSpeedMs>...</soundSpeedMs>            <!-- 응력파, 스폴/HESH 근사용 -->
  </properties>
  <empirical>                                   <!-- [실험] 출처가 있는 계수 -->
    <li Class="KEPenetrationCoefficients"> <source>…</source> ... </li>
    <li Class="ThorCoefficients"> <source>…</source> ... </li>
  </empirical>
  <gameResponse>                                <!-- [게임] -->
    <massEfficiencyVsKE>1</massEfficiencyVsKE>  <!-- RHA 기준 1 -->
    <massEfficiencyVsJet>1</massEfficiencyVsJet>
    <spallProfile>HD_Spall_DuctileSteel</spallProfile>
    <crackModel>Ductile</crackModel>            <!-- Ductile / Brittle / Fiber / Laminate -->
    <multiHitModel>...</multiHitModel>
  </gameResponse>
</Helodrace.Ballistics.ArmorMaterialDef>
```

- 물성 블록에는 측정값만 둔다. 밀도·경도는 실제 재료 범위에서 고른다.
- 경험 블록의 계수는 `source` 없이는 로드 검증에서 경고한다. 출처를 못 찾으면 경험 블록을 비우고 게임 블록만 쓴다.
- 질량효율(RHA 대비 같은 면밀도에서의 방호)은 탄종별로 따로 둔다. 세라믹·복합장갑이 KE와 제트에 다른 효율을 갖는 현상을 이 값으로 표현한다. 실제 복합장갑 구성은 공개 자료가 없으므로 [게임]이다.

재료 계열별로 서로 다른 `IMaterialResponse` 구현을 쓴다. 공통 배율 하나로 처리하지 않는다.

| 계열 | 응답 모델 | 근거 |
|---|---|---|
| 금속(RHA, 주조강, 고경도강, Al 합금, Ti) | 관통 깊이/탄도한계 경험식 + 연성 소성 변형, 플러깅·꽃잎형 파단, 스폴 | [실험] De Marre·Lanz–Odermatt 계열, 파단 양상은 [게임] 분류 |
| 세라믹(Al₂O₃, SiC, B₄C) | 2단계: 경화면이 탄심을 파쇄·침식(드웰) → 백킹이 운동량 흡수. 피격점 주변 원뿔 균열로 다중 피격 약화 | Florence 모델 [물리 근사], 균열 반경·약화량 [실험]/[게임] |
| 섬유(아라미드, UHMWPE, 나일론) | 섬유 인장 에너지 흡수, 면밀도와 Cunniff 계수로 V50 스케일, 둔상(후면 변형) | Cunniff 무차원 스케일 [물리+실험], 후면 변형 [실험] |
| 적층·복합(세라믹+섬유, 강+세라믹+강) | 층별 응답을 순서대로 적용. "복합 재료" 하나로 뭉개지 않는다 | 층 순서는 [물리], 층간 결합 효과는 [게임] |
| 투명(유리-폴리카보네이트 적층) | 세라믹과 같은 2단계 + 시야 손상 상태 | [게임] 계수 |
| 에너지형(ERA 폭약층) | §3.3 반응 모듈 | — |

### 3.2 장갑 손상 상태

정적 `ArmorLayup`과 동적 `LayerDamageState`를 분리한다.

- **금속**: 피격점 기록 목록(위치, 반경, 소성 변형량, 관통공 여부). 다음 착탄이 기록 반경 안이면 국소 두께·강도를 낮춘다. 전체 체력을 깎지 않는다.
- **세라믹**: 피격점마다 균열 원뿔 반경. 반경 안은 세라믹층 효율을 [게임] 감소 곡선만큼 낮춘다. 다중 피격 성능은 실제 판 시험 결과(NIJ 0101.07의 다중 피격 조건 등)에 맞춘다.
- **섬유**: 국소 섬유 파단과 전체 흡습·열화(현재 내구도와 연결).
- **인간형 판**: 현재 앞/뒤 독립 내구도는 "판 전체 상태"로 남기고, 국소 균열은 2~3단계 근사 격자(예: 판을 3×3 영역)로 저장한다. 격자 크기는 성능 예산으로 결정한다.
- **차량 장갑**: 구역(§7.1)마다 피격점 목록을 최대 N개(예 32)로 제한하고, 오래된 기록은 합쳐서 영역 약화값으로 축약한다.

기록은 저장되며, 수리 작업이 기록을 지운다.

### 3.3 반응장갑

반응장갑은 수치를 더하는 층이 아니라 **관통 상태를 바꾸는 단계**다. `ReactiveModuleDef`가 다음을 정의한다.

| 항목 | 내용 | 근거 |
|---|---|---|
| 작동 조건 | 탄종 메커니즘별 문턱: 제트(끝단 속도·직경), KE(충격 압력 ∝ 탄속·밀도), 소화기·파편(미작동 기준) | 작동 여부의 경향은 [실험], 문턱값은 [게임] |
| 작동 지연 | 작동 후 비판(flyer plate)이 움직이기 시작하기까지의 시간. 제트는 선단이 지나간 뒤 후속부만 교란, 탠덤은 선구 탄두가 소모 | 원리는 [물리], 시간값은 [게임] |
| 교란 효과 | 제트: 비판이 제트를 가로지르는 동안 끊어 먹은 길이 = 비판 속도·경사·제트 속도의 기하로 계산 [물리 근사]. KE 장봉: 측면 충격으로 요/굴곡 유발 → 유효 길이 감소 [게임] | 혼합 |
| 설치 방향·경사 | 모듈 법선과 탄 진행 각이 비판의 교차 길이를 정한다. 정면 수직 착탄에서 효율이 낮고 경사 착탄에서 높다 | [물리] 기하 |
| 소모·손상 | 작동 시 모듈 제거. 미작동 피격은 손상 누적. 손상 모듈은 불완전 작동(효율 감소) 가능 | [게임] |
| 주변 영향 | 인접 모듈 연쇄 작동 확률, 부착 볼트·외부 장비 손상, 주변 보병 피해 | 차단 설계(격자 간격)에 따른 [게임] |
| 기본 장갑과의 상호작용 | 반응층을 지난 잔여 관통체가 기본 장갑 `ArmorStack`으로 이어진다. 반응 모듈의 폭발이 기본 장갑에 충격을 주는지 여부는 모듈 정의 | 순서는 [물리] |

NERA(비폭발 반응장갑)는 같은 인터페이스를 쓰되, 작동이 소모성이 아니고 효율이 낮으며 다중 피격에 열화된다. 판의 팽창(bulging)이 제트를 가로지르는 기하를 ERA와 같은 식으로 계산하고 비판 속도를 낮게 둔다.

현재 Bradley 구현의 모듈 선택(가중치 = 부피 × 법선·방향 정합), 작동 후 Fleck·파편, 운반 차량 자기 피해 제외 규칙은 그대로 옮긴다. `BradleyThreat` 이름 추측 금지 규칙("이름으로 성형작약을 추측하지 않는다")도 유지한다. 위협 분류는 `ProjectilePhysics.mechanism`으로만 정한다.

## 4. 탄종과 관통 모델

### 4.1 탄종 데이터

탄 Def에 `ProjectilePhysicsExtension`을 붙인다. 현재 `BulletBallisticsExtension` 필드(질량·기준 탄속·총열 지수·탄속 반감거리)를 포함한다.

```text
mechanism: KE_Bullet | KE_HardCore | KE_LongRod | ShapedCharge | Tandem | HE | HESH | HEFrag | Shot | Fragment
core: 관통자 재료(ArmorMaterialDef: 강, WC, W합금, DU, 납), 질량, 직경, 길이
jacket: 피갑 재료와 질량(일반탄·AP의 피갑 벗겨짐)
incendiary: 소이 충전량 (API)
warhead: 작약 종류·질량, 라이너(직경·재질·원추각), 스탠드오프, 케이스 질량(파편)
fuze: 착발 / 지연 / 근접 / 그레이즈 민감도
tandem: 선구 탄두 → 주 탄두 지연
flight: 하강각 프로필(직사 / 포물선 / 탑어택 다이브 각), 고도 프로필
```

### 4.2 메커니즘별 모델

모든 모델은 같은 인터페이스를 구현한다.

```text
IPenetrationModel
  bool Applies(PenetratorState, LayerResponse)
  LayerResult Resolve(PenetratorState in, ArmorLayer layer, ImpactGeometry g, IRng rng)
     → { outcome, PenetratorState out, secondaries[], layerDamage }
```

단일 관통 공식으로 통합하지 않는다. 각 모델은 자기 메커니즘에 필요한 단계만 수행한다.

#### KE 탄환 (FMJ/Ball, AP, API, 경심)

1. **착탄각·도탄** — 임계각 이상이면 도탄 판정. 도탄 확률은 임계각 근처를 부드럽게 넘는 곡선으로 두고 임계각은 탄종·재료 경도·탄속에 따라 [실험]/[게임]. 도탄 시 잔여 속도와 반사 방향은 §4.3.
2. **탄체 파손** — 표적 경도 > 탄심 경도 기준이면 탄심 파쇄(연강 탄심 vs 세라믹). 세라믹의 드웰·침식을 이 단계에서 처리.
3. **관통** — 금속: 탄도한계 속도 기반(De Marre형 [실험]). 섬유: V50 스케일(Cunniff [물리+실험]). 세라믹+백킹: Florence [물리 근사].
4. **잔여 속도** — 탄도한계 위 잔여 속도는 Lambert–Jonas 형식 `v_r = a·(v^p − v_bl^p)^(1/p)` [실험]. 계수는 재료·탄종 쌍 데이터로 입력, 없으면 `p=2`(에너지 보존 근사, [물리 근사])와 플러그 질량 손실.
5. **API**: 관통 실패에도 소이제 점화 가능(연료·탄약 위험 증가). 점화 여부 [게임].

수직화/역수직화(normalization): 경심이 무딘 탄과 피갑이 있는 탄은 경사면에서 법선 쪽으로 꺾이는 경향이 있고, 장봉은 반대로 경사 쪽으로 미끄러지는 경향이 있다. 정량은 [실험] 자료가 있는 탄종만 각도 보정으로 쓰고, 없으면 0°(순수 LOS)로 둔다. 경사에 의한 LOS 증가와 실제 방호 증가를 구분해 별도 항으로 기록한다.

#### APFSDS (장봉)

- **관통 깊이**: Lanz–Odermatt 경험식 [실험]. 구조는 `P/L = f(L/D) · cos^m(θ) · √(ρp/ρt) · exp(−k·BHN_t/(ρp·v²))` 형태이며, 계수는 원 논문 값을 데이터로 입력한다. 적용 범위(재료, L/D, 탄속, 경사각) 밖이면 트레이스에 경고를 남기고 범위 끝값으로 고정한다.
- **고속 극한**: 탄속이 높을 때는 유체역학 극한 `P → L·√(ρp/ρt)` [물리 근사]로 수렴하는지 회귀 테스트로 확인한다.
- **도탄**: 장봉의 도탄 판정은 Tate 도탄 기준(장봉 굴곡 모멘트 vs 표적 저항) [물리 근사]. 대부분의 실전 경사(60~70°)에서는 장봉이 도탄하지 않는 쪽으로 계산되는지 확인 테스트를 둔다.
- **침식과 잔여**: 각 층에서 소비된 길이를 빼고 남은 길이로 다음 층을 계산한다. 간격장갑 사이 간격에서는 요(yaw)가 생겨 다음 층 효율이 달라질 수 있다 — 요 성장량은 [게임].
- **반응장갑**: §3.3의 측면 충격 → 유효 길이·요 변화.

#### 성형작약 (HEAT, 탠덤)

- **제트 모델**: 제트를 선단 속도 v_tip ~ 말단 속도 v_tail 의 연속 선형 속도 분포 막대로 근사. 관통은 유체역학 근사 `P = L_jet·√(ρj/ρt)` [물리 근사]에 표적 강도 보정 [실험]을 적용한다. 스탠드오프에 따른 제트 신장·파단 시간은 [실험] 곡선.
- **경사**: 제트는 경사에서 거의 도탄하지 않는다. LOS 두께로 계산하고, 극단 경사(그레이즈)는 신관 미작동 판정으로 처리한다(신관 민감도 [게임]).
- **간격장갑·슬랫**: 조기 기폭으로 스탠드오프가 지나치게 길어지거나 신관 회로가 끊겨 불발. 슬랫 아머는 확률적 결과(통과/불발/기폭)를 갖는다 — 확률 [게임]·공개 시험 경향 참고.
- **탠덤**: 선구 탄두가 ERA를 소모시키고, 지연 후 주 탄두가 남은 스택에 대해 다시 계산한다. ERA 작동 지연보다 탠덤 지연이 짧으면 주 탄두도 교란된다.
- **관통 후**: 잔여 제트 + 장갑 스폴(§5.1)이 좁은 원뿔로 내부에 진입. 성형작약 자체 폭압은 외부에서 대부분 발생하고 내부 과압은 관통공 크기에 비례하는 작은 값으로 둔다 [게임].

#### 고폭 (HE, HE-FRAG)

- 관통자가 아니라 **폭발원**을 생성한다. 피해는 폭압(§5.4)과 폭발 파편(§5.3)으로 분리.
- 장갑에 대해서는 직접 관통을 계산하지 않고, 근접 폭발이 외부 장비·얇은 장갑·개방부에 주는 피해를 계산한다. 매우 얇은 장갑(경차량 지붕 등)은 폭압 하중에 의한 판 파열 여부를 [게임] 문턱으로 판정.
- 탄체가 큰 고폭탄(대구경)은 운동 에너지로 인한 충격도 별도 KE 사건(무딘 관통자)으로 생성할 수 있다.

#### 점착유탄 (HESH)

- 표면에 퍼진 작약이 응력파를 장갑 내부로 보내고, 뒷면에서 반사된 인장파가 스캡(scab)을 떼어낸다. 메커니즘은 [물리]지만 정량(스캡 질량·속도, 두께 대비 효과)은 [실험]/[게임].
- 관통이 없어도 내부 스폴 사건을 생성하는 것이 핵심이다. 간격장갑·라이너가 있으면 효과가 크게 줄어든다.

#### 산탄·다중 발사체

- 한 발당 KE 탄환 모델을 소탄 단위로 적용하되, 같은 표적의 소탄은 한 사건으로 묶어 계산한다(§9.2 집계). 소탄의 분산은 현재 `ShotgunSpread`를 따른다.

#### 파편 (2차 사건)

- 파편은 질량·속도·형상 계수만 갖는 관통자. 장갑 관통은 THOR 식 [실험] 또는 섬유에 대해 V50 스케일.

### 4.3 관통 결과 분류

| 결과 | 의미 | 후속 |
|---|---|---|
| Ricochet | 도탄 | 잔여 탄체 방향·속도 갱신 후 계속 이동. 착탄면 손상·둔상 |
| Shatter | 탄체 파쇄, 비관통 | 탄체 파편 일부가 외부로 비산. 경미한 면 손상 |
| Stopped | 비관통 | 변형·둔상·스폴(뒷면) 가능 |
| PartialPenetration | 일부 층 관통, 뒷면 미천공 | 뒷면 변형(BFD), 스폴, 둔상 |
| Perforation | 완전 관통 | 잔여 관통체 + 2차 피해 내부 진입 |
| Overmatch | 관통 여유가 매우 큼 | Perforation과 같으나 장갑 영구 손상·스폴 감소를 반영할 수 있다(관통공이 깨끗해 스폴이 적은 경향 — [게임]) |

도탄 후 진행: 반사 방향은 입사 방향을 표면 법선에 대해 반사한 뒤 마찰 손실로 법선 성분을 줄인다 [물리 근사]. 잔여 속도 비율은 [실험]/[게임]. 도탄된 탄체는 같은 투사체를 새 방향으로 다시 날리되, 남은 사거리가 짧거나 속도가 일정 비율 아래면 생략한다.

## 5. 2차 피해

같은 착탄에서 여러 종류가 동시에 생길 수 있고, 각각 독립 객체로 생성한다.

### 5.1 장갑 스폴

- 생성: 관통 또는 부분 관통 시 뒷면에서, HESH는 비관통에서도. 생성량·질량 분포·원뿔 각은 재료의 `spallProfile`([실험] 자료 기반 범위 + [게임] 값). 연성 강판보다 고경도강·세라믹이 많다. 스폴 라이너(아라미드 등)는 원뿔 각과 파편 수를 줄인다 — 라이너 효과는 라이너 층의 섬유 모델로 직접 계산한다.
- 방향: 잔여 관통체 진행 방향을 축으로 하는 원뿔. 잔여 관통체가 없으면 장갑 뒷면 법선.

### 5.2 탄체 파편화

- 탄체 자체가 부서진 조각. 탄체 재료·속도·파손 상태에서 생성. 인간형 연조직 내부 파편화는 현재 `BulletFragmentation`의 확률·예산 규칙을 그대로 쓴다(§6.4).
- 장갑 관통 후 탄심만 남고 피갑은 벗겨지는 경우: 피갑을 외부 파편으로 처리하고 탄심이 잔여 관통체가 된다.

### 5.3 폭발 파편

- 초기 속도: Gurney 식 [물리 근사], 작약·케이스 질량비와 형상(원통·구) 계수 [실험].
- 개수·질량 분포: Mott 분포 [실험 통계]. 사전 파편화 탄두는 Def에 개수·질량을 직접 기입.
- 방향: 탄두 축 기준 측면 분사 띠(원통형 탄두) — 각도 범위는 Def.
- 감속: 공기 저항 `dv/dx = −k·v`(파편 형상 계수 [실험]).

### 5.4 폭압·충격파

- 개방 공간: Hopkinson–Cranz 축척 거리 `Z = R / W^(1/3)`, 입사·반사 과압과 임펄스는 Kingery–Bulmash 곡선 [실험]. 지면 반사는 반구 폭발 계수로 처리.
- 인체 피해: 과압·임펄스와 인체 손상 관계(고막, 폐 손상 등)는 Bowen 계열 곡선 [실험]을 참고하되 RimWorld 부위 피해로 바꾸는 환산은 [게임].
- 엄폐·차폐: 폭발원과 대상 사이에 벽(RimWorld 건물)이 있으면 회절 감쇠 [게임].
- 밀폐 공간: §7.3.

### 5.5 둔상·충격 전달

- 비관통 시 뒷면 변형(BFD)이 신체에 전달하는 둔상. 섬유 백킹의 BFD는 탄 에너지·운동량과 백킹 강성으로 [실험] 근사하고, 시험 규격 상한(NIJ 계열 BFS 한계)을 기준점으로 RimWorld 둔기 피해(타박상·늑골 골절)로 환산 [게임].
- 헬멧 비관통: 헬멧 변형 + 경부·두부 가속에 의한 둔상(뇌진탕 헤디프) [게임].

## 6. 인간형 캐릭터

### 6.1 자세와 몸통 방향

현재 판 방향은 `pawn.Rotation`(Rot4)과 공격자 셀 위치로 90° 구역을 고른다. 이를 연속 방위로 바꾼다.

**`CompBodyOrientation` (폰 동적 상태)**

```text
torsoYaw, headYaw: float(도)      // 연속, 0 = 북, 시계 방향 (HullHeading과 같은 규약)
targetYaw: float                  // 조준 대상 방위
stance: StanceProfileDef          // 현재 총기군 자세
lastUpdateTick
```

**`StanceProfileDef` (총기군별 데이터)**

| 필드 | 의미 |
|---|---|
| `torsoOffsetDeg` | 조준 방향 대비 몸통 각(블레이드 자세 정도). 예: 소총 견착, 권총 정면 자세 |
| `headOffsetDeg` | 조준 방향 대비 머리 각(대체로 0, 조준경 사용 시 소폭) |
| ~~`torsoTurnRateDegPerTick`, `headTurnRateDegPerTick`~~ | 2026-11-10 삭제: 인간형 회전 속도 제한을 두지 않는다(3단계 후속 결정) |
| `updateIntervalTicks` | 방위 갱신 주기(성능). 조준 중 짧게, 비전투 길게 |
| ~~`moveAimFactor`~~ | 2026-11-10 삭제: 회전 속도 제한과 함께 삭제 |
| `proneHeightProfile`, `crouchHeightProfile` | 자세별 부위 높이(§6.2 수직각 계산) |

수치는 [게임]이다. 실제 사격 자세 교범의 경향(소총 견착 시 몸통이 약간 비스듬함, 현대 판 장구 사용 시 정면을 향하는 자세 선호)을 반영하되 각도를 현실값으로 표기하지 않는다.

**시각과 판정의 일치.** 판정은 연속 `torsoYaw`를 쓰고, 화면의 Rot4 스프라이트는 같은 `torsoYaw`에서 고른다(가장 가까운 방위, ±5° 히스테리시스). RimWorld 폰은 정면 그림이라 스프라이트를 기울이면 사람이 넘어지는 모양이 되므로 잔여 각 회전은 그리지 않는다(3단계 결정). 화면에 보이는 면은 몸통 방위와 최대 50° 차이 안에 있고, 정확한 조준 방향은 무기 그림이 이미 보여 준다. `pawn.Rotation`은 이 상태에서 파생되어 기록된다.

**갱신.** 조준 대상·무기 자세는 `updateIntervalTicks`마다 다시 읽는다. 회전은 마지막 갱신 틱부터 해석적으로 적분하므로 매 틱 갱신하든 여러 틱을 건너뛰든 같은 값이 나온다. 피격 판정은 그 틱까지 적분한 값을 쓴다.

**엄폐.** RimWorld 엄폐는 명중 판정에서 이미 처리한다. 이 시스템은 엄폐물에 맞은 탄을 다루지 않고, 몸에 도달한 탄에 대해서만 계산한다. 다만 엎드림·웅크림 자세는 부위 높이와 노출 면 방향(§6.2)을 바꾼다.

### 6.2 착탄 기하

RimWorld는 피격 부위를 피복률 가중으로 무작위 선택한다. 이 분포는 유지한다(밸런스·타 모드 호환). 대신 **선택된 부위 위의 착탄점과 국소 법선**을 기하로 만든다.

1. 탄 진행 벡터(3D): 2D 진행 방향 + 수직 성분. 수직 성분은 사수 사격 높이 → 대상 부위 높이와 거리로 계산 [물리]. 박격포·고각 사격은 투사체 프로필의 하강각.
2. 몸통 좌표계: `torsoYaw`로 회전. 머리는 `headYaw`.
3. 부위 형상: 몸통 = 타원기둥, 머리 = 타원체, 사지 = 원기둥으로 근사. 진행 방향에서 본 투영 면 위에 균일하게 착탄점을 뽑고, 그 점의 법선을 구한다 [물리]. 구면에 평행광선이 균일하게 맞으면 착탄각 분포는 `p(θ) = 2·sinθ·cosθ`가 된다 — 이 분포가 회귀 테스트 기준이다.
4. 방호장비 피복: 착탄점이 어느 장비의 피복 영역(아래)에 있는지 판정.

### 6.3 개인 방호장비

`ProtectiveCoverageDef`로 장비의 실제 덮는 영역을 정의한다. 현재 `ModularArmorPositionDef`(부위 + 보호 방향 + 방향 호)를 다음으로 바꾼다.

```text
coverage:
  bodyPart: Torso
  region: 몸통 좌표계의 각 범위(방위 −40°~+40°) × 높이 범위(어깨 아래~배꼽)   // 판의 실제 크기
  layup: ArmorLayupDef (예: SAPI = 세라믹 타격면 + UHMWPE 백킹)
  shape: Flat | SingleCurve | MultiCurve (판 곡률 → 국소 법선)
```

- 착탄점이 판 영역 밖이면 판을 지나지 않는다(현재의 90° 구역 규칙 대체). 연질 조끼는 넓은 영역, 판은 좁은 영역을 덮는다.
- 착탄각에 따른 성능 변화: LOS 두께와 재료 모델(세라믹은 경사에서 효율 변화, 섬유는 경사에서 섬유 인장 경로 변화)로 계산.
- 관통 실패 시 둔상: §5.5.
- 반복 피격: 판 국소 균열 격자(§3.2).
- 방패: 손에 든 `coverage`로 등록하고, 방위는 몸통이 아니라 방패 자세 각을 따른다.

현재 등급 기준표(HG1~RF3)와 탄종별 확정 방어 표는 **검증 목표**로 바꾼다. 재료 모델이 각 판에 대해 "M855A1 정면 착탄은 ESAPI에서 정지" 같은 기존 표의 결과를 내는지 회귀 테스트로 확인하고, 다르면 [게임] 계수를 조정한다. 표 자체를 판정에 쓰지 않는다.

### 6.4 관통 후 인체 피해와 RimWorld 환산

- 잔여 관통체의 운동에너지·질량·직경·상태(변형/파편화)로 상처를 만든다.
- **보정 기준점(anchor)**: 방호장비가 없고 기준 거리일 때 상처량이 현재 [탄약 표](Ammunition_Balance.md)의 피해량과 같아야 한다. 즉 `wound = baseDamage × g(잔여 에너지 / 기준 에너지, 상태)`이고 `g(1, Intact) = 1`이다. g는 단조 증가 [게임] 곡선. 현재 `r^0.7` 거리 보정은 g에 흡수된다.
- 관통 깊이가 얕으면 내부 장기 선택 가중을 낮추고(현재 바닐라는 부위만 고른다), 깊으면 내부 장기로 이어지게 한다 — 바닐라 `DamageWorker_AddInjury`의 하위 부위 선택에 가중치를 주는 방식.
- 파편화: 기존 규칙 유지(파편 1개당 상한 5, 총량 ≤ 통과 후 주 상처 × damageFraction × 강도). 입력 탄속만 이 시스템의 잔여 탄속으로 바꾼다.
- 관통 후 몸 뒤로 나간 잔여 탄(과관통)은 남은 에너지가 문턱 이상일 때만 같은 방향으로 계속 날아간다(뒤의 아군 위험).

### 6.5 헬멧 도탄

- 헬멧 셸을 타원체로 두고 §6.2의 방법으로 착탄점·법선을 구한다. 정수리·측면 가장자리는 착탄각이 커서 도탄 확률이 자연히 높다 — 분포는 기하에서 나온다.
- 도탄 확률: 착탄각, 탄속, 탄 경도 대비 셸 재료, 셸 재료(아라미드·UHMWPE 헬멧은 금속 헬멧과 다른 곡선). 임계각 근처의 곡선 형태와 위치는 [실험]이 있으면 쓰고, 없으면 [게임].
- 도탄 성공 시에도: 셸 국소 변형·균열 기록, 경부 가속 둔상, 탄의 새 방향·잔여 속도로 계속 비행(§4.3). 도탄된 탄은 같은 폰을 다시 맞히지 않는다.
- 바이저·투명 방탄재는 별도 층(투명 재료 모델). 손상 시 시야 손상 헤디프.

## 7. 기갑차량 (Lobos Arsenal)

### 7.1 차량 좌표계와 장갑 형상

`VehicleArmorModelDef`가 차량 하나의 정적 모델을 정의한다.

```text
frames:
  hull   : 차체 좌표계 (CompHullHeading의 연속 방위)
  turret : 포탑 좌표계 (차체 위, VF 포탑 각), 피벗 오프셋
armorShell:   // 저폴리곤 볼록 판 목록, 프레임별
  - id: UFP (상부 전면판), frame: hull
    polygon: [로컬 3D 꼭짓점 …]        // 법선·경사(수평·수직)는 꼭짓점에서 계산 [물리]
    layup: HD_Layup_M1A2_HullFront     // 복합장갑 구성 [게임]
    reactive: [모듈 슬롯 id …]
    flags: Hatch / Ramp / Vision / Skirt …   // 개방 시 두께 0
interior:
  compartments: Driver / Fighting / Turret / Engine / AmmoBustle …
    volume: 볼록 상자 목록, 압력 체적(m³)
    connections: 격벽(두께·재료), 해치(상태), 통로
  occupants: 좌석 → VF 역할(운전수·사수·차장·탑승병)과 좌석 위치·자세(캡슐)
  equipment: 관측장비, 사격통제, 포탑 구동, 주포, 부무장, 엔진, 변속기, 궤도, 통신, 연료탱크, 탄약고
    shape: 상자, function: VF 구성품 id
    ammoStorage: 탄종, 수량, 저장 방식(격리 탄약고 / 노출 랙), 블로아웃 패널 id
```

- 형상은 차량 로컬 좌표에 한 번만 둔다. 착탄 시 **탄 경로를 차량 로컬로 변환**하고(행렬 1개), 형상을 회전시키지 않는다. 포탑 판은 포탑 프레임으로 한 번 더 변환. 내부 구획·승무원·장비도 같은 프레임을 따르므로 차량 회전 시 자동으로 함께 회전한다.
- 착탄점: 현재 `BradleyImpact.Current`의 투사체 위치 + 3D 진행 벡터로 광선을 만들고 볼록 판들과 교차 [물리]. 판에 닿는 첫 교점이 착탄점이며, 2D 게임의 위치 오차는 판 표면으로 투영해 보정한다. 광선 교차 대상은 차량당 판 30~80개 수준이므로 착탄당 비용은 작다.
- 상부 공격: 별도 유형이 아니다. 탑어택 다이브각, 박격포 하강각, 직사 수평각이 모두 같은 광선 교차에서 지붕판·측면판 중 무엇에 닿을지를 결정한다. 현재 `topAttack`/`flyOverhead` 플래그는 하강각 데이터로 바뀐다.
- 구역 분류(정면/측면/후면/상부)는 데이터 관리·UI 표시에만 쓴다. 판정에는 실제 판을 쓴다.
- 데이터 작성: 수작업 XML 대신 차량 텍스처 구조와 같은 방식으로 편집 도구(기존 Python 툴 계열)에서 판을 찍어 XML로 내보낸다.

### 7.2 내부 진입과 승무원 피해

관통 후 내부 사건을 공간 기하로 처리한다.

1. **진입 광선**: 잔여 관통체를 관통점에서 내부 진행 방향으로 진행. 내부 물체(장비 상자, 좌석 캡슐, 격벽)와 교차하며 각 물체에서 에너지를 소모한다. 장비·격벽도 `ArmorStack`처럼 얇은 재료층으로 취급해 같은 관통 모델을 쓴다.
2. **스폴·파편 원뿔**: 개별 투사체를 만들지 않는다. 원뿔을 N개 대표 광선(정밀도 단계에 따라 8~32)으로 표본화하고, 각 광선은 파편 묶음(개수·평균 질량·속도)을 나른다. 광선이 승무원 캡슐을 지나면 묶음의 "기대 명중 수"를 투영 면적 비로 계산하고 결정론 난수로 실제 명중 수를 뽑는다 [물리 근사 + 통계].
3. **차폐**: 광선 경로의 장비·좌석·격벽이 파편을 막거나 감속한다.
4. **거리 감쇠**: 원뿔 확산에 따른 면적 밀도 감소(1/r²) [물리]와 파편 공기 감속.
5. **승무원 개별 피해**: 각 승무원에 대해 명중 파편을 그 승무원의 개인 방호장비(§6.3)를 거치는 인간형 파이프라인으로 넘긴다. 승무원 자세(좌석 방향)는 차량 프레임에서 파생된 `torsoYaw`.
6. **균등 피해 금지**: 현재 VF의 탑승자 피해 분배를 이 계산으로 교체한다.

### 7.3 내부 폭압

- 내부 폭발(내부로 들어간 HE, 유폭, 성형작약 관통 후 소량)은 개방 공간 모델 대신 **구획 압력 모델**을 쓴다.
- 충격파 첫 피크: 개방 공간 값에 벽 반사 증폭 [실험/게임].
- 준정적 가스 압력: 작약 질량 / 구획 체적에 따른 가스 압력 곡선(UFC 3-340-02 계열 차트) [실험]. 개구부(열린 해치, 관통공, 블로아웃 패널)를 통한 배기로 감쇠 [물리 근사: 구멍 면적 기반 유출].
- 구획 간 전달: 격벽 상태(손상·두께)와 해치 열림에 따라 연결된 구획에 압력이 나뉜다. 구획 수가 작으므로(3~6) 닫힌 형태 계산으로 충분하다.
- 피해: 승무원은 위치한 구획의 피크·임펄스로 폭압 피해(인간형 §5.4 환산), 장비는 압력 문턱으로 파손.

### 7.4 탄약 유폭

유폭은 고정 확률 이벤트가 아니라 **탄약 저장 객체의 손상 상태로부터 발생하는 사건**이다.

```text
AmmoStorageState (저장 위치별)
  rounds: 탄종·수량
  damage: 누적 손상, 점화원 노출 기록(제트/소이/고온 파편/화재)
  temperature: 화재 시 누적 열 [게임]
```

1. **손상 입력**: 저장 위치를 지난 관통체·파편·제트가 탄약에 준 피해를 기록. 제트·소이 파편은 장약 점화원으로, 일반 파편은 기계 손상으로 구분.
2. **점화 판정**: 탄종별 감도(장약 종류, 연소성 케이스, 둔감 탄약 여부)와 점화원 종류·에너지로 결정 [게임 — 실제 취약성 자료는 대부분 비공개]. 현재 본체의 `CompInsensitiveExplosive`의 둔감 개념을 탄종 플래그로 재사용.
3. **반응 단계**: 점화 → 장약 연소(화재) → 연소가 다른 탄으로 전파 → (조건 충족 시) 작약 폭굉. 각 단계 전이 시간은 [게임], 단계마다 내부 압력·화재 생성.
4. **격리 구조**: 격리 탄약고 + 블로아웃 패널이면 연소 가스가 외부로 배출되어 승무원 구획 압력이 크게 낮다(§7.3 구획 모델에서 패널이 큰 개구부가 됨). 탄약고 문이 열려 있으면 격리가 깨진다(장전 중 상태와 연결). M1A2의 블로아웃 패널 손상 오버레이를 이 사건의 시각 출력으로 쓴다.
5. **연쇄**: 화재 지속 중 다른 저장 위치와 연료로 전파. 연료 화재는 별도 사건.
6. **결과**: 차량 기능 손상, 승무원 피해(구획 압력·화재), 최악의 경우 완전 파괴(포탑 이탈 연출은 선택).

### 7.5 차량 기능 손상

- 장비는 VF `VehicleComponent`에 연결해 체력과 기능 상실을 저장한다. VF 스탯 시스템(이동·사격·관측)이 장비 상태를 그대로 반영하므로 별도 체력 체계를 만들지 않는다.
- 관통 여부와 무관하게: 외부 장비(관측장비, CITV, 조준경, 궤도, 안테나, 슬랫)는 외부 폭압·파편·소화기 명중으로 손상된다. 외부 장비 상자도 형상에 포함해 착탄 광선이 먼저 맞힐 수 있다.
- 상태 구분: 다음을 별도 판정해 UI와 AI가 구분한다.

| 상태 | 조건(예) |
|---|---|
| 기동 불능 | 엔진·변속기·궤도 중 하나가 기능 0 |
| 화력 상실 | 주포 또는 포탑 구동 또는 사격통제 기능 0 (부무장만 남은 상태 구분) |
| 관측 상실 | 모든 관측 장비 기능 0 → Observation 레이어의 센서 시야 제거 |
| 승무원 무력화 | 운전·사격에 필요한 역할을 맡을 의식 있는 승무원 없음 |
| 완전 파괴 | 유폭 폭굉, 구조 손상 한계 초과 |

## 8. 공통 처리 파이프라인

```text
 1 CollisionResolve      어댑터: 투사체 Impact → ImpactEvent (위치·3D 속도·시드)
 2 HitLocation           인간형: 부위 선택(바닐라) + 착탄점 / 차량: 광선-판 교차
 3 FrameTransform        대상 프레임(몸통·머리 / 차체·포탑)으로 변환
 4 ImpactGeometry        표면 법선, 착탄각, LOS 두께, 탄 요(yaw)
 5 ArmorStackLookup      착탄점의 층 목록 + 동적 손상 상태 적용
 6 ReactiveStage         반응 모듈 작동 여부·교란 → PenetratorState 갱신   (반응층 없으면 생략)
 7 LayerInteraction      층마다 메커니즘별 모델 실행
 8 OutcomeClassify       Ricochet / Shatter / Stopped / Partial / Perforation / Overmatch
 9 ResidualUpdate        잔여 질량·속도·길이·방향
10 SecondaryGenerate     스폴, 탄체 파편, 폭발 파편, 폭압, 둔상
11 SecondaryPropagate    잔여 관통체·2차 사건의 이동·충돌 (내부 광선 / 외부 재발사)
12 TargetDamage          신체 부위·승무원·내부 장비 피해 (승무원은 인간형 파이프라인 재귀)
13 PermanentDamage       장갑·구조물 손상 기록
14 FunctionalAndEvents   기능 손상, 유폭·화재·연쇄 사건 예약
```

- 각 단계는 `IImpactStage { bool Applies(ctx); void Run(ctx); }`. 성형작약은 9의 요 계산을, HE는 6~9 전체를, 무장갑 폰은 5~9를 생략한다.
- 재귀는 깊이 제한(예: 승무원 파이프라인 1단계, 도탄 재발사 1회). 2차 사건이 다시 2차 사건을 만들지 않게 생성 깊이를 기록한다.
- 지연 사건(탠덤 주 탄두, 유폭 단계 전이, 화재)은 틱 스케줄러에 예약하고 저장한다.
- 어댑터는 파이프라인 결과를 바닐라 `DamageInfo`로 바꾸어 기존 경로로 적용한다. 바닐라 장갑 롤은 이 시스템이 처리한 피해에 대해 다시 돌지 않게 막는다(현재 판 패치가 `ApplyArmor`를 우회하는 방식과 같다).

## 9. 성능

### 9.1 계산 위치

- 고비용 계산은 착탄 시점에만 한다. 비행 중에는 아무것도 계산하지 않는다(현재처럼 발사 시 탄속·감쇠만 캡처).
- 폰 방위는 갱신 주기마다 보간 상태만 갱신하고, 착탄 시 해석적으로 평가한다.
- 차량 형상은 로컬 좌표 불변이므로 캐시가 무효화되지 않는다. 포탑 각·해치 상태만 동적이다.

### 9.2 정밀도 단계

정밀도는 **사건 종류**로 결정한다. 카메라 거리나 화면 표시로 정하지 않는다(결정론이 깨짐).

| 단계 | 대상 | 계산 |
|---|---|---|
| T0 | 무장갑 폰에 대한 소화기 | 기하·장갑 단계 생략. 상처 환산만 |
| T1 | 방호장비 폰에 대한 소화기 | 닫힌 형태 식(탄도한계·잔여 속도), 층 1~3개 |
| T2 | 차량 외부에 대한 소화기·파편 | 광선-판 교차 + 외부 장비 손상. 대부분 Stopped로 조기 종료(관통 여유가 큰 음수면 상세 계산 생략) |
| T3 | 차량에 대한 KE·성형작약·HESH | 전체 파이프라인, 내부 광선 표본 N=16 |
| T4 | 내부 폭발·유폭 | 구획 압력 모델, 화재 지속 사건 |

조기 종료 규칙: 관통 모델이 "관통 여유가 확실히 음수"를 보장할 수 있으면 잔여 계산·스폴을 생략한다(예: 5.56 FMJ vs 전차 정면). 보장 조건은 모델별로 정의하고 테스트한다.

### 9.3 할당·집계

- `ImpactContext`는 풀링한다. 단계 내부는 구조체·스택 배열만 쓴다.
- 파편·스폴은 개별 `Projectile`을 생성하지 않고 묶음 광선으로 처리한다. 차량 외부로 튀는 파편은 화면 연출용 Fleck만 만들고, 주변 폰 피해는 묶음 광선 → 맵 셀 교차로 계산한다. 현재 `BradleyEraEffects`처럼 실제 투사체를 쓰는 경로는 개수가 적은 경우(≤4)에만 남긴다.
- 산탄·연사가 같은 틱에 같은 대상을 맞히면 같은 `ArmorStack` 조회 결과를 재사용한다.
- 틱당 T3/T4 예산을 둔다. 초과 사건은 다음 틱으로 넘기되 결과에는 영향이 없다(시드 고정).

### 9.4 정확성 유지 영역과 근사 허용 영역

| 정확성 유지 | 근사 허용 |
|---|---|
| 좌표 변환, 법선·착탄각, LOS | 신체·헬멧 형상(타원체) |
| 관통 깊이식의 적용 범위·단조성 | 파편 개별 궤적(묶음 광선) |
| 층 순서와 잔여 관통체 전달 | 요 성장, 정규화 각 |
| 에너지·질량이 층을 거치며 늘지 않음 | 폭압 반사 계수, 구획 간 전달 |
| 시각과 판정 방향 일치 | 유폭 단계 전이 시간 |

## 10. 결정론과 추적

- 시드: `BallisticSeed.ForImpact(투사체 thingIDNumber, 발사 틱, 대상 thingIDNumber)`, 2차 사건은 `ForChild(부모 시드, 자식 번호, 대상)`. 각 단계는 `BallisticSeed.Stream(사건 시드, 단계 id)`로 만든 자체 SplitMix64 스트림(`BallisticRng`)만 쓴다. `Verse.Rand`를 쓰지 않으므로 전역 난수 상태를 진전시키지 않고, 단계를 추가·생략해도 다른 단계의 난수가 바뀌지 않는다. 문자열 해시는 프로세스마다 달라지는 `GetHashCode` 대신 FNV-1a를 쓴다. 같은 저장에서 같은 조건이면 같은 결과가 나온다.
- 순서 독립: 묶음 광선·승무원 처리 순서는 id 순으로 고정한다. `HashSet` 열거 순서에 의존하지 않는다.
- `ImpactTrace`: 단계별 입력·출력 요약(착탄점, 법선, 착탄각, LOS, 층별 결과, 잔여 상태, 생성된 2차 사건, 승무원별 피해 원인). 기본은 링 버퍼(최근 64건, 저장 안 함). 개발 모드에서:
  - 차량 선택 시 마지막 착탄의 판·광선·스폴 원뿔 오버레이(기존 `PersistentTargetingOverlay` 계열).
  - 트레이스를 텍스트로 복사.
  - "같은 시드로 다시 실행" 디버그 명령 — 회귀 테스트 케이스로 내보낼 수 있게 JSON 출력.
- 현재 Bradley의 `lastImpact` 문자열은 트레이스로 대체한다.

## 11. 확장

- **신규 장갑재**: `ArmorMaterialDef` XML만 추가. 새 계열(예: 새로운 섬유)은 기존 `IMaterialResponse` 중 하나를 지정하고, 정말 다른 응답이면 응답 클래스 하나를 추가한다(`Class=` 속성으로 XML에서 선택).
- **신규 탄종**: 탄 Def에 `ProjectilePhysicsExtension` 추가. `mechanism`이 기존 모델 중 하나면 코드 수정 없음. 새 메커니즘(예: EFP)은 `IPenetrationModel` 구현 하나 추가.
- **신규 방호장비**: `ProtectiveCoverageDef` + `ArmorLayupDef`.
- **신규 차량**: `VehicleArmorModelDef` XML(편집 도구로 생성). 차량별 C# 코드는 차량 고유 기믹(Bradley 장전 램프 같은 것)에만 둔다. 현재 `CompBradley`의 ERA·개방부 로직은 범용 데이터로 옮겨 Bradley 전용 코드에서 제거한다.
- **파이프라인 단계 추가**: `ImpactStageDef`로 순서를 데이터화하고, Lobos·호환 모드가 단계를 삽입한다.
- **로드 검증**: Def 로드 시 형상(볼록성, 법선 방향 바깥쪽), 층 두께 > 0, 경험 계수 출처 유무, 탄종-재료 조합의 모델 적용 범위를 검사하고 오류를 한 번에 보고한다.

`Source/Helodrace/Ballistics/Core/`에 게임 의존성 없는 코어를 추가했다. 아직 어떤 Harmony 패치도 이 코어를 호출하지 않으므로 게임 동작은 바뀌지 않는다.

### 2단계 구현 (2026-11-10)

탄도 자료(`diameterMillimeters` > 0)가 있는 탄이 폰을 맞히면 방호층 모델로 판정한다. 그 밖의 피해(바닐라·타 모드 탄, 산탄, 근접, 폭발)는 기존 확률 판정을 그대로 쓴다.

**구성**

| 파일 | 내용 |
|---|---|
| `Ballistics/Core/KineticBulletModel.cs` | 탄심 등급 `PenetratorClass`(Soft/MildSteel/HardSteel/Tungsten), 재료 응답 `KineticMaterial`, 층·적층 판정, 상처 환산, 피복 영역 `CoverageRegion`, 신체 착탄점 `BodyHitGeometry` |
| `Ballistics/Defs/ArmorMaterialDef.cs` | `ArmorMaterialDef`, `ArmorLayupDef`, `BallisticLayupExtension` |
| `Ballistics/Humanoid/HumanoidBallisticImpact.cs` | 착탄 범위(`Bullet.Impact`), 피격 부위 기록, `ApplyArmor` 안의 물리 층 처리, 모듈형 판 처리 |
| `Ballistics/Humanoid/BallisticsDebugActions.cs` | 개발자 모드: 최근 착탄 추적 로그·JSON 복사 |
| `Defs/Ballistics/ArmorMaterials.xml`, `ArmorLayups.xml` | 탄화붕소·UHMWPE·아라미드, 방탄판·연질 패널·방패 7종 |

**모델** — 층마다 `V50 = k(재료, 탄심 등급) × √(LOS 면밀도 × 탄 단면적 / 탄 질량)`. 기본 형태는 에너지 균형이고 Cunniff 스케일과 같은 무차원 묶음을 쓰지만 계수 `k`는 [게임] 보정값이다. 관통 판정은 `V50 × (1 + 0.06 z)`, `z ~ N(0,1)`(±2.5에서 자름)이고, 잔여 탄속은 `√(v² − V_bl²)`(Lambert–Jonas, p = 2)이다. 세라믹은 탄심 등급별로 질량을 깎고(침식) 단면을 넓힌다(변형). 상처는 `기존 피해 × √(E_out/E_in)`이라 무장갑 피해는 탄약 표와 같다. 정지하면 멈춘 층의 `traumaTransfer`만큼 둔상이 남는다. 물리 층을 지난 뒤의 바닐라 층에는 `(v_out/v_in)^1.2`로 줄인 관통력을 넘긴다.

**착탄 기하** — 몸통 방위는 아직 `pawn.Rotation`(Rot4)이다(3단계에서 교체). 탄 진행 방향은 투사체 회전각이고 수평 사격으로 둔다. 피격 부위(타원체)에서 균일 빔으로 착탄점을 뽑아 방위·높이를 구한다. 방탄판은 `ModularArmorPositionDef`의 방향·호에 새 `coverageHeight`(전·후면 −0.25~0.85, 측면 −0.40~0.40)를 더한 영역 안에서만 맞는다. 판은 평판이므로 착탄각은 판 법선 기준이고, 연질 패널은 몸 표면 법선 기준이다.

**층 순서** — 방패(`PostPreApplyDamage`) → 바닐라의 의복 순회(바깥부터). 판 캐리어는 장착 판을 먼저, 자기 연질 패널을 나중에 판정한다. 캐리어가 덮지 않는 부위의 부속(어깨 보호대 등)은 `GetPostArmorDamage` 후처리에서 판정한다. 바닐라는 의복 컴프에 피해 정보의 복사본을 넘기므로, 방패를 관통한 탄의 상처 감소는 착탄 범위에 실어 몸 적층 시작 때 적용한다.

**내구도** — 판: `흡수 J × 재료 wearPerJoule(1/300) × 판 소재 계수`를 해당 방향 판에 적용한다. 효율은 `0.4 + 0.6 × 판 내구도 비율`이다. 의복 연질 패널은 흡수 에너지에 비례해 의복 자체가 손상된다. 방패는 기존 차단/관통 내구도 감소를 쓰고, 효율은 `0.4 + 0.6 × 기존 내구도 계수`다.

**삭제** — `guaranteedBlockPenetration`(판·방패 Def·XML·UI·번역 키), `BallisticArmorRules.CanGuaranteeBlock`과 관련 상수. `PlateWear`와 90° 구역 판정은 탄도 자료가 없는 피해 경로에서 계속 쓰므로 남겼다.

**보정과 목표** — 방탄판은 IBTV HG2 연질 패널 위에 착용한 적층(판 + 아라미드 4 mm)으로 보정했다. 게임에서 판은 항상 이 캐리어에 들어가기 때문이다. 판만으로 보정하면 판을 지난 탄을 연질 패널이 잡아 SAPI가 M855A1을 사실상 전부 막았다. 목표는 정면·기준 탄속·무손상에서 정지 ≤1%, 관통 ≥60%다.

### 3단계 구현 (2026-11-10)

인간형 폰의 몸통·머리 방위를 연속 각으로 관리한다. 탄도 판정(2단계)의 착탄 좌표계도 이 방위로 바꾸었다.

**구성**

**동작**

- 방패를 든 폰은 자세 각 없이 의도 방향을 유지한다.
- 무기 판별: 명시 `weaponDefs` → 규칙(근접·빈손 → 맨손, 산탄 → 산탄총, 폭발탄 → 발사기, ≤1.6 kg → 권총, ≥7 kg이면서 연사 ≥3 → 기관총, 사거리 ≥39이면서 단발 → 정밀 소총, 나머지 → 소총). M47 Dragon은 유도탄이 `Projectile_Explosive`가 아니어서 명시 목록으로 발사기에 넣었다.

- 탄도: 머리 부위는 머리 방위, 나머지는 몸통 방위의 좌표계로 착탄점을 뽑는다. 방패 착탄각도 몸통 방위를 쓴다. 추적에 `torsoYawDeg`/`headYawDeg`를 남긴다.

### 4단계 구현 (2026-11-10)

헬멧 셸 도탄과 둔상, 도탄된 탄의 재비행, 안면 바이저를 추가했다.

**모델**
- **타격면 도탄:** 헬멧 셸 또는 금속 타격면에서는 관통 계산 전에 도탄을 먼저 판정한다.
  - 확률 = 1 / (1 + exp(−(θ − θc)/w)). θ는 착탄각, θc는 재료의 임계각, w는 전이 폭이다 [게임].
  - 도탄된 탄의 속도: 접선 성분 × 마찰 보존률, 법선 성분 × 반발률(반대 방향). 형태는 [물리 근사], 계수는 [게임].
  - 탄속·탄심 경도에 따른 임계각 변화는 출처 있는 자료가 없어 넣지 않았다.
- **둔상:** 도탄 시 머리 둔상 = 상처 × 재료 `traumaTransfer` × (셸이 흡수한 에너지 비율). 정지 시 둔상은 2단계와 같다.
- **헬멧 범위(`shell`):** 머리 좌표계에서 `heightMin` 위를 덮고, 정면 얼굴 창(방위 ±`faceHalfWidthDegrees`, 높이 < `faceTopHeight`)은 비워 둔다. 눈·코·턱 부위는 셸이 덮지 않는다. 덮지 않은 착탄은 헬멧 판정 없이 지나가며, 추적에 `Uncovered`로 남는다.
- **재비행(`Projectile_Ricochet`):**
  - 도탄 후 속도가 120 m/s 이상이고 수평 성분이 절반 이상이면 새 투사체로 계속 날아간다. 정수리에서 위로 튄 탄과 땅으로 박히는 탄은 끝난다.
  - 피해는 기존 피해 × 속도비, 관통은 × 속도비^1.2. 사거리는 속도/25 칸(3~30)이다 [게임].
  - 자기 물리 상태를 가지고 날아가므로 다음에 맞은 방호구도 같은 모델로 판정한다. 재비행은 한 번만 일어난다.
