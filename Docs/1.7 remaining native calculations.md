## Review and limits

- The previously converted tactical, presentation, howitzer, smoke/explosion, turret, power-cutter trajectory/scatter/coverage and appendage/armor/installed-charge offset and modular snapshot/sight methods have no owned arithmetic calls in this narrower queue. The original 82f97ed7 matching/no-PDB audit had identical targets/offsets/counts; this snapshot is a fresh matching-PDB audit. An actual mismatched bridge PDB is rejected before report output.
- This table is only a queue. Color/Rect-only calculations, fields/locals/signatures and other Unity calls still require the full JSON/source review. Hair palette ownership, current XML parsing and boundary marshalling cannot be decided from call names alone.
- A matching portable PDB supplies nearest preceding visible call-site locations; locals/signatures use the first visible method location where available. Source files must still match that build. Generated methods, inlining and source-level aliases require inspection.
- The reader does not discover reflection/string/dynamic/native internals or prove ownership/data-flow, runtime behavior, GPU/input/resource correctness or performance. A lower count is not evidence of correctness.
- Convert owned calculations to Waylith/BCL values, retain current game/XML/callback inputs at explicit boundaries and validate relevant geometry/state. No blanket UI/render exception or generic Unity facade.
- Stages 0-3 also retain their build/new-state gates, Blancas B2 published-state regression and R7 door gate. This audit does not replace those requirements.
