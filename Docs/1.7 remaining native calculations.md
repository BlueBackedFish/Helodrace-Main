## Review and limits

- Completed tactical, presentation, howitzer, smoke/explosion, turret, power-cutter, trajectory, appendage/armor/charge, snapshot/sight and small-effect conversions have no owned arithmetic calls in this narrower call queue. Zaper/sniper wire/Euler/trail/aim math has also been converted. The component table is a separate check; it does not exempt other methods in the same files. The original 82f97ed7 matching/no-PDB audit had identical targets/offsets/counts; this snapshot is a fresh matching-PDB audit. An actual mismatched bridge PDB is rejected before report output.
- This table is only a queue. Color/Rect-only calculations, fields/locals/signatures and other Unity calls still require the full JSON/source review. Palette ownership, current XML parsing and boundary marshalling cannot be decided from call names alone.
- A matching portable PDB supplies nearest preceding visible call-site locations; locals/signatures use the first visible method location where available. Source files must still match that build. Generated methods, inlining and source-level aliases require inspection.
- The reader does not discover reflection/string/dynamic/native internals or prove ownership/data-flow, runtime behavior, GPU/input/resource correctness or performance. A lower count is not evidence of correctness.
- Convert owned calculations to Waylith/BCL values, retain current game/XML/callback inputs at explicit boundaries and validate relevant geometry/state. No blanket UI/render exception or generic Unity facade.
- Stages 0-3 also retain their build/new-state gates and Blancas B2 published-state regression completion audit.
