# 1.7 전환 실행 기록

2026-10-30 시작, 2026-11-01 갱신. 전환 진행 중이며 0~3단계 전체 완료 기록이 아니다.

## 추가 검증: native 기하와 1.7 실행기

미리보기 카메라·드래그, 부품 연결/레일/조준기/아이콘의 2D 내부 데이터와 무기 렌더러의 3D 위치·애니메이션·TRS 계산을 native로 옮겼다. `native-preview17`, `native-attachment17`, `native-matrices17`의 실제 NoWindow 비교는 각각 경계 성분 13,284개, 연결/회전 성분 25,272개, 행렬/점/방향 성분 3,200개를 통과했다. 7,190개 무기 계산 검사와 `native-attachment-state17`의 새 저장/재로드 44개도 통과했다. 파일별 잔여 경계는 [native 경계 목록](1.7%20native%20경계%20목록.md)에 기록한다. 이 범위의 완료가 모든 기능군의 3단계 완료를 뜻하지 않는다.

`Source/Tests/Game17Runtime.ps1`은 현재 1.7 호스트의 hardlink/junction 기반 독립 Game/Profile/Evidence를 만들고 Harmony 3·Blancas·Main을 필수 구성으로 사용한다. 정확한 실행 DLL 해시·인자·PID/시작 시각과 native 전역 로그를 기록한다. 관찰 제한 시간에는 게임을 강제로 종료하지 않으며 같은 PID를 이어서 확인한다. 성공한 시험의 재생성 가능한 profile 캐시만 정리한다. JSON 날짜를 다시 문자열 파싱하면서 시간대 정보가 소실되던 기존 migration 로그 시각 비교도 DateTime 값 비교로 수정했다.

산탄총 실행기는 1.6 exe/Unity 옵션 대신 실제 1.7 Headless와 위 공통 실행기를 사용한다. `shotgun-controlled17` 및 `shotgun-controlled17-repeat`는 각각 **92개 실제 검사**를 통과했고, 두 실행의 숙련도별 입력·산탄 통계가 모두 동일했다. 기존 검사는 각 샘플의 Pawn을 무작위로 새로 생성해 장비/건강/유전자 등 다른 조건이 함께 달랐으며 최초 실행에서 숙련도 비교가 실패했다. 비교용 fixture만 고정 seed·성인 Baseliner·폭력 가능·장비/건강 초기화 및 명시적 stat cache 갱신으로 통제했다. 제품의 약물·무기 밸런스는 바꾸지 않았다.

`shotgun-precision17`의 정밀 조준 96개 검사와 종료 코드 0을 확인한 뒤, 로그에서 무작위로 생성한 전투 불가 시험 Pawn의 ShootingAccuracyPawn 접근 오류를 발견했다. 일반 사격 fixture에도 폭력 가능 생성 조건과 유효 Shooting 검사 조건을 추가한 `shotgun-precision-capable17`은 104개 검사·종료 코드 0을 통과했고 해당 오류가 사라졌다. 공통 실행기는 시작한 Process handle을 보관해 종료 코드를 수집하고, Get-Process 관찰이 누락될 때 CIM으로 실행 중인 호스트를 다시 확인한다.

연구 화면 실행기도 공통 1.7 환경으로 전환했다. 현재 소스로 Main/검사 DLL을 별도 빌드하며 과거 staging DLL을 재사용하거나 시간 초과에 실행 중 게임을 강제 종료하지 않는다. `research-layout17`은 실제 NoWindow에서 1600×900 캡처 9개와 노드 71개·경로 108개·섹션 37개의 배치/교차/접기/선택/레시피 조건 검사를 통과했다. queue·advanced-ammunition·synthetic-chemistry 캡처를 직접 확인했다. 직접 마우스 입력을 요구하는 Interactive 모드는 이 자동 실행에 포함하지 않았다.

기존 연구 UI 검사에서는 explicit section에 속하지 않은 Blancas의 자동 배치 연구까지 authored 좌표와 비교해 실패했다. Main의 고정 배치와 외부 연구의 자동 배치를 구분해 검사하며, 실제 모든 좌표는 Evidence/Screenshots/layout.tsv에 남긴다.

필수 통합 구성에서 빈 `BD_HelodTechTab`이 중복 표시되던 문제도 수정했다. Main의 연구 창 PostOpen에서 이 탭에 남은 연구가 없을 때 navigation entry만 숨긴다. 배포된 Blancas Def와 identity는 유지하며, 다른 모드가 해당 탭을 계속 사용하면 표시한다. `research-blancas-tab17`은 이 두 조건을 실제 Def 변경/복원으로 검사했고, 앞선 배치·레시피 검사와 9개 캡처, 종료 코드 0을 통과했다. queue 캡처에서 중복 탭이 사라진 것을 확인했다. Blancas 단독 배포 파일은 수정하지 않았다. 전술 감사 실행기·큐/감시기의 1.7 전환과 다른 기능군 native 내부 데이터 정리는 계속 필요하다.

## 실제 환경

전술 실행기 전환은 `Run-EngineAudit.ps1`·`Run-EngineMatrix.ps1`·R2/R7 큐부터 적용했다. 설치된 Main에 DLL/Defs를 복사하거나 구형 Def 파일을 삭제하던 코드를 제거하고 공통 1.7 Game/Profile을 사용한다. 기존 수집기용 Player.log는 `Wait-Game17Host.ps1`가 종료 후 native 전역 로그에서 복사한다. CIM의 마이크로초 단위 생성 시각과 Process의 100ns 단위 생성 시각 차이를 처리하면서 PID·실행 경로를 함께 확인한다. 관찰 시간 초과에는 실행 중인 게임을 보존한다. 프로파일 실행에는 기본 disabled 인자를 넣지 않는다.

`tactical-runner17`의 빈 맵 120틱은 시작·격리·환경·속도 3 조건을 통과했다. CreatorTemp의 `hd-migration17-matrix-zero-20261030`은 vanilla/new 두 전술 엔진의 실제 순차 큐와 로그 수집·콘텐츠 해시 검사를 통과했다. 이는 빈 맵 실행 제어 검사다. `tactical-profiler17`의 실제 CoreCLR 10.0.13 캡처는 180틱(1→181), native 프레임 2532→2692, dropped=0을 기록했고 TickManager 호출도 정확히 180회였다. 성능 향상이나 전체 전술 기능 완료 근거로 사용하지 않는다.

실제 R7 door 12명·10,000틱 기능 검사는 **실패 상태로 보존**했다(`CreatorTemp/hd-migration17-functional-door-20261030`). 시작/격리/환경/속도·예외 검사는 맞았지만 임무 완료 및 door fault 조건을 충족하지 못했다. 별도 6,000틱 진단에서는 12명 모두 진입 할당을 완료했지만 Enter 단계에 머물렀고 contact shots=301이었다. 보호된 목표에 대한 지속 교전 여부를 포함해 원인 확인이 필요하며, 현재 증거만으로 1.7 회귀인지 기존 fixture/로직 문제인지 단정하지 않는다. 완료 판정은 완화하지 않았다. 큐 제어 mock 5개도 통과했으며 이 mock을 실제 게임 증거로 세지 않는다.

`tactical-entry-gates17`의 진단 출력은 tick=6002에서 wait=CombatQuiet, combatUntil=6092를 확인했다. actor별 route leg·revision·path goal·stance·진입 version/owner도 기록한다. 실제로 평가한 actor의 LaneCleared와 진입 version/owner가 유효한 상태였으며, 이동 경로 오류라고 단정하지 않는다. 이는 조회용 진단 추가이며 전술 행동이나 합격 조건을 바꾸지 않는다.

전환 전 `c14bdac995df9093dddb6f660d504b9261752b80`의 소스·Defs·패치·번역을 별도 무시된 디렉터리에 고정하고, 보존한 실제 1.6.4871 rev590 참조로 net48/C#13 빌드를 만들었다(경고·오류 0). `tactical-baseline16`의 같은 seed·12명·sapper-door·6,000틱 실행은 종료 코드 0·격리/환경 조건을 통과했지만 **같은 Enter 정체와 미완료**를 재현했다. 진입 할당 11명, contact shots=264, door fault=0이었다. 따라서 관찰한 정체를 새 1.7 회귀로만 분류하지 않는다. 보호 목표와 지속 교전 정책의 영향은 별도 기존 기능 문제로 남겨 두며, 이 결과를 R7 합격으로 세지 않는다. 비교는 1.6 nographics와 1.7 NoWindow의 기능 상태 비교이며 동일 렌더링/CPU 성능 비교가 아니다. 재현 명령·소스/게임/Blancas/Harmony DLL 해시는 해당 launcher.json에 보존했다. 제품에 1.6 빌드나 실행 분기를 추가하지 않았다.

`Run-SavedMapAudit.ps1`·`Prepare-ManualRaidTests.ps1`의 남은 1.6 경로 전환과 기능 실패 조사는 계속 필요하다.

- 사용자 승인 후 Steam을 1.7 unstable로 전환했다.
- 실제 버전: `1.7.4990 rev1069`, Steam build ID `26222807`.
- 실제 `Assembly-CSharp.dll` SHA-256: `4E61D57205944C113631234BC55136A1A7C1679667B26008BEE5425BCFFA1463`.
- 호스트는 `RimWorld.exe`와 게임 전용 CoreCLR `10.0.13-waylithclr.dev`를 사용한다. 일반 .NET 10에서 실행하는 계산 시험과 실제 호스트 실행 시험을 구분한다.

## 빌드 기반

Main과 실제 게임을 참조하는 시험 프로젝트를 net10.0/C# 14로 옮겼다. `Source/Directory.Build.props`와 `.targets`에서 게임·Harmony 경로를 공유하며 `RimWorldPath`, `RimWorldReferencePath`, `HarmonyAssemblyPath`로 지정할 수 있다. 기본 경로는 설치된 실제 게임이다. 참조 전용 패키지의 메서드를 실행하지 않는다.

`dotnet build Source/Helodrace/Helodrace.csproj -p:IntermediateOutputPath=obj/Migration17/ -v:minimal`은 경고·오류 0으로 통과했다. 기존 obj 파일을 열어 둔 도구가 있어 새 중간 출력 경로를 사용했다. 추적하던 obj는 Git 관리에서만 제거하고 작업 파일은 보존했다.

실제 엔진 참조 시험의 DLL 해석은 `Source/Tests/GameRuntime.cs`가 담당한다. `HELODRACE_GAME_ROOT`와 `HELODRACE_HARMONY_ASSEMBLY` 환경 변수로 실행 경로를 바꿀 수 있다. 독립 시험에는 게임 참조를 추가하지 않았다.

## 실제 실행 및 저장 증거

`Source/Tests/EngineMigration/Run-Migration.ps1`은 `.codex-staging` 아래 새 폴더에 실행 파일과 별도 Profile을 만들고 게임 데이터와 모드 콘텐츠를 연결한다. `-Case baseline -Legacy16`으로 보존한 1.6에서 fixture를 만들며, `-Case load -FixtureRoot <baseline>`으로 1.7에서 읽는다. `-Case main`은 Main+Blancas 새 게임을 확인한다. `-Wait` 또는 `Wait-Migration.ps1`으로 완료 상태와 로그를 수집한다.

1.7은 `-Headless`와 `-NoWindow`를 사용한다. Headless 성공은 렌더링 검증을 뜻하지 않는다. 초기 Waylith 로그는 `-savedatafolder`와 별개로 사용자 LocalLow의 `Ludeon Studios/RimWorld by Ludeon Studios/Logs/Player.log`에 기록된다. Unity의 `-logFile` 인자를 사용하지 않고 종료 후 해당 로그를 증거 폴더에 복사한다. 로그가 공유되므로 게임 시험은 동시에 실행하지 않는다.

| 증거 폴더 (`.codex-staging/migration17/` 아래) | 결과 |
|---|---|
| `legacy-fixture` | 실제 1.6에서 약물·수면·중독·내성·MKultra 상태의 14개 Pawn 저장 생성 |
| `native-legacy-check` | 실제 1.7에서 기존 Blancas DLL로 fixture 읽기·상태 확인·재저장 통과 |
| `blancas-net10-load` | 새 net10.0 Blancas DLL로 동일 fixture의 Def·severity·Comp 타입·수면 저장 플래그 확인·재저장 통과 |
| `main-startup17` | Main DLL 로드, 필수 연동 Def, 새 게임 저장 확인 통과. 시작 Def 오류는 별도 수정 중 |

Blancas의 배포 DLL SHA-256 `7070F6E9167B7332F02B006ABFFAB69D9FE036F66BBFABEAA5B69044D1858838`은 보존한 `1.6/Assemblies/HelodBlancasDrug.dll`과 같다. 1.6 콘텐츠는 별도로 동결하고 1.7 빌드는 `1.7/Assemblies`로 분리했다. 저장 로딩 성공만으로 전체 약물 기능 회귀 완료를 선언하지 않는다.

## 확인한 시험과 남은 문제

- 실제 게임 참조 전술 바인딩 및 전술 규칙 시험 통과. by-ref 인자 판정과 오래된 TCCC 경계 fixture를 수정했다.
- 산탄 366개, 탄환 분열 102개 시험 통과.
- Harmony 3을 참조하는 독립 시험: 통행권 29개, 전신망 227개, 상인 손실 61개 통과.
- 모듈 무기 시험의 stock normal-quality accuracy 기준값에서 실패했다. 원인을 확인하기 전 기준값을 갱신하지 않는다.
- 실제 시작 로그에서 Main Def 검증 오류와 Blancas의 빈 설명·잘못된 단독 연구 탭 참조를 발견했다. 별도 수정·재실행이 필요하다.
- 설치된 Workshop 항목 `3781143823`의 폴더 누락과 호스트 종료 시 native allocation 경고는 별도 관찰 항목이다. 사용자 Workshop 파일을 변경하지 않는다.
- 2단계 구형 코드 정리 및 3단계 native 계산/시간 전환은 아직 완료되지 않았다.

## Blancas 후속 검증과 첫 구조 개선

Blancas 저장소 main의 `e991dd1`은 1.6 배포본 보존·1.7 빌드 분리·단독 Def 오류 수정을, `b2937a0`은 경쟁 약물 검사 최적화를 반영했다. `1.6-manifest.json`의 50개 파일 해시를 다시 비교해 기존 배포본이 그대로임을 확인했다. `legacy-version-route2`는 실제 1.6에서 `Mods/Blancas/1.6/Assemblies/HelodBlancasDrug.dll`을 선택하고 14개 Pawn fixture를 저장하는 데 성공했다.

`HediffComp_ExclusiveGroup`은 매 60틱·추가 시점의 검사 의미를 유지하면서 전체 Hediff를 LINQ/익명 객체/List로 변환하던 부분을 pooled snapshot으로 바꿨다. 제거 콜백이 목록을 바꾸므로 단순한 원본 목록 직접 순회는 사용하지 않는다. 반환은 finally에서 참조를 비운 뒤 수행한다. stage·severity·offset·동률·순서·재진입·OnRemoval 억제 비교 670개가 통과했다.

실제 엔진 시험 `blancas-exclusive17`에서도 HealthTracker를 통한 16개 조합 및 OnRemoval 후속 효과 억제가 통과했다. 80개 실제 Hediff에서 준비 실행 후 1만 회 검사의 할당은 28,960,000B에서 0B로 줄었다. 단일 시간 표본은 88.228ms에서 30.048ms였다. 합성된 해당 반복 경로의 측정이며 전체 게임 TPS 개선치가 아니다. SleepLogic은 침대 수면 전이 시점과 저장 키를 보존하기 위해 매 틱 검사를 유지한다.

실행 환경 복사 중 디스크 공간 부족을 발견했다. 종료한 시험의 설치본과 해시가 같은 중복 엔진 파일만 하드링크로 전환해 약 1,994MiB를 확보했다. 새 실행기도 엔진 파일을 읽기 전용 입력으로 연결한다. 저장·로그·1.6 실행 환경 보존본은 유지한다.

### 비중독성 placeholder의 새 생성 차단과 저장 호환

위 시작 오류는 Blancas의 비중독성 Modafinil/Caffeine chemical에 `canBeAddicted=false`가 없어 무작위 중독 후보에 들어가는 경로로 좁혔다. 실제 1.7 `PawnAddictionHediffsGenerator`는 이 필드로 후보를 거른다. `StartingPawnUtility.GeneratePossessions`는 해당 Need의 `fallPerDay`로 약물 수량을 계산하므로, 감소율 0인 호환용 Need가 선택되면 0개가 생긴다. root ChemicalDefs의 두 chemical만 생성 대상에서 제외했다. 기존 중독/Need DefName·클래스·저장 키와 동결된 1.6 파일은 유지한다.

`blancas-generation17b`는 Main 없는 실제 1.7에서 64회의 무작위 중독 생성(일반 중독 192개)을 실행해 두 placeholder가 제외되고 정상 중독은 유지됨을 확인했다. 두 기존 placeholder 중독/Need를 명시적으로 추가해 저장/로드하는 검사까지 총 15개가 통과했다. 첫 `blancas-generation17`은 payload는 통과했으나 시험 DLL의 Main 타입 참조 때문에 별도 시작 오류가 있어 유효한 단독 시작 근거로 세지 않는다.

이를 위해 `EngineMigration.Blancas.csproj`를 분리했다. 단독 DLL의 AssemblyRef에는 Main이 없으며 기존 DLL과 같은 시험 assembly/type 이름을 사용해 이전 fixture를 읽는다. 빌드는 `dotnet build Source/Tests/EngineMigration/EngineMigration.Blancas.csproj -p:BaseIntermediateOutputPath=obj/Blancas17/`이다. Main 통합/native 검사는 기존 `EngineMigration.csproj`를 사용한다. 실행기가 Case별 DLL을 선택하고, 실제 1.6 fixture 생성은 보존한 net48 DLL을 `BridgeAssembly`로 명시한다.

`legacy-placeholders16`은 동결된 실제 1.6 배포본에서 기존 14개 상태와 두 placeholder 중독을 포함한 16개 Pawn을 저장했다. `legacy-placeholders-load17`은 수정된 1.7 단독 구성에서 Def·severity·Comp·수면 상태와 chemical Need 타입/수치를 확인하고 재저장하는 64개 검사를 통과했다. 두 유효한 1.7 단독 실행의 ERROR는 기존 Workshop 항목 누락뿐이었다. 이는 기존 저장/생성 결함에 대한 검증이며 모든 약물·수술·장기 유전자 동작의 B2 완료를 뜻하지 않는다.

수정 후 `blancas-fixed-integration17`의 실제 Main+Blancas 투여·제작 41개 검사도 통과했다. 이 실행의 ERROR 역시 기존 Workshop 항목 누락뿐이며 0개 스택 오류는 없었다. chemical 유전자/생각 Def 생성은 별도 `generateAddictionGenes` 필드를 사용함을 실제 `GeneDefGenerator`에서 확인했다. 그 필드는 변경하지 않아 기존 자동 생성 Def도 유지한다.

## 계산 기준과 API 검증 후속 결과

모듈 무기의 정확도 실패는 1.7 계산 변화가 아니었다. 같은 제품 소스를 보존한 실제 1.6 참조로 net48 빌드한 뒤 같은 시험 입력으로 비교했다. 10개 기본 무기의 정확도·준비·회복 시간 JSON은 1.7 결과와 바이트 단위로 같았으며 SHA-256은 `882283871027B2EE1D63C1F078BBB459344CBE178CA9643ED586389493BA3D9C`다. 증거는 `balance16/snapshot16.json`, `snapshot17.json`이다. 기존 정확도 목표는 M855A1 등 교정용 탄약 기준이었지만 일부 기본 프리셋은 M855 등을 사용했다. 기존 교정 목표와 현재 구성의 전환 회귀 기준을 분리했다. 제품 밸런스는 바꾸지 않았고 무기 시험 7,190개가 통과했다.

실제 1.7 API 검증 스크립트는 `Source/Import-Game17.ps1`로 .NET 10·게임 버전·Harmony 3을 확인하고 DLL 경로를 1.7 구조로 전환했다. CROWS API/정확도, 전신망 메뉴/보상, HAM 및 통행권·손실 Harmony 바인딩, 분대 조직, 방어구 스탯·미리보기, 의류 작업대, 레이어/텍스처 검증이 통과했다. 탄약 주머니·탄도 방어구·통신·CROWS·사회적 대치·종족 렌더링·산업 연기·연구 연결·프로파일러·모듈 탐색·석유 설비·무전기·연구 화면·분대 독립 시험도 통과했다.

기존 두 기준 시험은 별도 확인이 남는다. StandaloneRace의 귀 가림 fixture는 14개지만 현재 XML에는 KidHelmet을 포함한 15개가 있다. 동반 Facial 모드의 현재 패치는 이전 비교 fixture의 컨트롤러 구성과 다르다. 해당 비교 실패를 1.7 호환 성공으로 세지 않는다.

후속 확인으로 두 검사 자체를 복구했다. KidHelmet 추가는 Main `2099d568`, 삭제된 머리 제거는 `58a2e208`, 아기용 Facial 컨트롤러 교체는 Facial `2b650b3`에 이미 반영된 의도된 변경이다. 동시에 상대/절대 머리 오프셋 조회의 현재 입력/반환 계약, XML 텍스트 노드 처리, 양수 열 제거량과 음수 clamp fixture를 바로잡았다. `Verify-StandaloneRace.ps1 -PatchSmokeTest`는 정책·캐시 재구성·나이 경계·기존 동작과 실제 Harmony 3 패치 41개 설치를 통과했다. `Verify-RaceCompatibility.ps1`은 원래 패치 fixture를 유지하고 검토한 아기 컨트롤러 변경만 기대 출력에 적용해 CE/Facial의 네 순서와 반복 적용을 통과했다. 이는 1.7 DLL의 관리 코드/패치 검사이며, 외부 CE·Facial의 1.7 실행과 화면 호환성 전체를 의미하지 않는다.

## Main 시작 Def 오류 수정

`main-defs-final17`은 실제 Main+Blancas+Harmony 3 구성의 시작·연동 Def·새 게임 저장 7개 검사를 통과했다. 로그에 Main/Blancas Def·타입·Harmony 오류 및 플레이어 팩션 조기 조회 오류가 없었다. 남은 ERROR는 기존 Workshop 항목 `3781143823`의 폴더 누락이다.

- Main의 숫자로 끝나는 ThingDef 9개를 유효한 이름으로 바꾸고 코드·참조·한국어 번역을 함께 갱신했다. 4개 산업 설비에는 `Bench`, CROWS M249/MK19에는 `Weapon`, A10 탄에는 `Round`, W48 포탄에는 `Nuclear` 접미사를 썼다. 실제 텍스처 경로는 유지했다. Main은 배포 전이므로 구형 이름 별칭을 만들지 않는다.
- 빈 연구 설명 3개, 잘못된 연막 폭발 SoundDef, Sledgehammer의 내구도 없는 물건에 적용된 부식률, 전신기의 사용 시 연료 소비 조건, 현대 병종의 저항/의지 범위와 팩션의 비용 곡선을 수정했다.
- 해당 무기의 최저 가격보다 낮던 병종 장비 예산을 올려 무장 없이 생성될 수 있는 경우를 제거했다. M1911의 기존 전용 레시피와 같은 비용 메타데이터를 추가했다. P320은 기본 프리셋 물리 부품의 기존 제작비 합계인 Steel 24 + ComponentIndustrial 3을 지정해 비용 없는 자동 제작을 막았다.
- CROWS Mk19의 폭발 탄에 M79와 같은 `forcedMissRadius=1.2`를 지정했다. 이는 실제 산포 동작을 바로잡는 변경이다.
- 목제 방망이는 실제 재질 후보가 WoodLog 하나였다. 1.7의 성유물 생성은 같은 물건에 이미 쓴 재질을 제외하므로 반복 선택 때 후보가 비어 월드 생성 오류가 생길 수 있었다. 이 물건을 임의의 다른 재질로 만들게 하는 대신 성유물 후보에서 제외했다.
- Blancas 단독은 기존 `BD_HelodTechTab`을 사용하고, Main이 있을 때는 Main 패치가 `HelodTechTab`에 배치한다. Blancas의 DefName·필수 방향은 바꾸지 않았다.

수정 후 XML 500개가 파싱됐고, CROWS·산업 설비·연구·모듈 무기 관련 독립/API 검증이 통과했다. 새 모드 구성의 렌더링·저장 재로드 및 후속 native 전환 검증은 별도 단계로 계속한다.

## 2단계: 가스·석유·탄약 이행 제거

가스 효과는 실제 `GasUtility.PawnGasEffectsTickInterval`에 직접 패치하며 1.5 탐색·1.6 이름의 분기를 제거했다. 석유는 개발 완료 때 명시적으로 만든 기록만 조회하고, 지형만 보고 품질/압력을 1로 복원하던 경로와 구형 지형·번역을 제거했다. 크기가 다른 펌프의 footprint에서 현행 기록을 찾는 동작은 유지한다. 탄약 가방은 현재 `desiredAmmo`와 Pawn의 실제 inventory만 사용하며, 이전 `storedAmmo`/`storedRockets` 읽기·매 틱 이행·미사용 용량 설정을 제거했다.

제품 빌드는 경고·오류 0, 석유 설비 시험 및 탄약 주머니 122개 시험이 통과했다. 실제 시험 `main-state17-render`는 **NoWindow 호스트에서 새 상태를 만들고 저장한 다음 재로드하는 26개 검사**를 통과했다. 석유 셀·품질·압력, 기록 없는 지형의 비복구, 탄약 목표와 실물 7발의 비중복 보존, 가스 interval 패치 설치 및 구형 스키마 부재를 확인했다. 모드 관련 ERROR가 없었고 기존 Workshop 폴더 누락만 남았다. 이는 저장·호스트 검증이며 외형 비교 완료를 뜻하지 않는다.
